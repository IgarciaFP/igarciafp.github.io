UD02. Fundamentos de CSS

Cómo decide el navegador qué estilo aplicar y cómo dar forma a cajas, colores y texto.

1. Qué es CSS y cómo se aplica

Al crear una página, HTML identifica el contenido y su estructura: un título, un párrafo, una lista o un enlace. El navegador ya les aplica una apariencia básica, pero necesitamos controlar cómo se muestran para construir nuestro diseño.

CSS permite definir esa presentación. Sus siglas significan Cascading Style Sheets (hojas de estilo en cascada). Con CSS elegimos colores, tipografías, tamaños, espacios y la distribución de los elementos.

Por ejemplo, HTML indica que un texto es un título mediante <h1>. CSS permite mostrarlo en azul, darle más tamaño y separarlo del párrafo siguiente. El contenido sigue siendo el mismo; cambia su presentación.

Separar ambas tareas facilita el trabajo:

  • Mantener la web: una hoja CSS compartida permite cambiar el aspecto de los títulos de todas las páginas desde un único archivo.
  • Conseguir coherencia: botones, menús y tarjetas pueden reutilizar los mismos estilos.
  • Adaptar el diseño: el mismo HTML puede mostrarse en una columna en el móvil y en varias en una pantalla grande.
  • Facilitar la lectura: podemos ajustar el contraste, el tamaño del texto y la separación entre elementos.

CSS aplica reglas a los elementos del HTML. Cuando varias reglas afectan al mismo elemento, el navegador necesita decidir cuáles usar. Por eso estudiaremos la cascada, la herencia y la especificidad. Primero veremos cómo incorporar esas reglas a una página.

Qué aprenderás en esta unidad

  • Enlazar una hoja de estilos externa y escribir reglas CSS correctas.
  • Explicar qué declaración gana cuando varias reglas afectan al mismo elemento: cascada, herencia y especificidad.
  • Seleccionar elementos por tipo, clase, atributo, relación, estado o parte.
  • Controlar el tamaño de las cajas, sus márgenes, sus límites y el contenido que no cabe.
  • Elegir unidades, colores y variables para construir un sistema visual coherente.
  • Dar formato a fondos, bordes, sombras y texto sin perder legibilidad.

La maquetación (Flexbox, Grid y diseño responsive) se estudia en la UD03 · Maquetación y diseño responsive.

¿Cuál es la primera hoja de estilo que se aplica a nuestro código HTML?

Incluso en una página HTML sin CSS propio, los títulos suelen verse más grandes que los párrafos y los enlaces aparecen subrayados. ¿De dónde salen esos estilos? Puedes descubrirlo si inspeccionas un título y buscas el origen de la regla que fija su tamaño.

Comprobar la explicación

El navegador incorpora una hoja de estilos predeterminada, llamada hoja de estilos del agente de usuario (user agent stylesheet). Esa es la base que da aspecto al HTML aunque no hayamos escrito CSS: márgenes, tamaños de títulos, marcadores de listas y otros estilos iniciales.

Las reglas del autor se combinan con esa base mediante la cascada. Hablar de «primera» sirve para reconocer el punto de partida, pero el resultado no se decide solo por el orden de carga: también intervienen el origen, la importancia y los demás criterios que estudiaremos.

1.1. Formas de incluir CSS

Para aplicar estilos a una página, el navegador necesita saber dónde están escritas las reglas CSS. Podemos guardarlas en un archivo independiente, incluirlas en la cabecera del HTML o escribirlas directamente en un elemento. Las tres formas funcionan, pero la elección influye en lo fácil que será mantener la web.

Cuando construimos un sitio con varias páginas, lo más práctico es utilizar una hoja de estilos externa. Escribimos las reglas en un archivo, como estilos.css, y lo enlazamos desde la cabecera de cada página mediante <link>:

<!-- Dentro de head, en el archivo HTML -->
<link rel="stylesheet" href="css/estilos.css">

El atributo href indica la ruta del archivo. En este caso, el navegador buscará estilos.css dentro de la carpeta css. En ese archivo escribimos únicamente CSS, sin etiquetas <style>:

/* Archivo css/estilos.css */
p { color: navy; }

Si varias páginas enlazan esa misma hoja, todas compartirán sus estilos. Para cambiar el color de sus párrafos bastará con modificar una regla. Esta será la forma habitual de trabajar en nuestras prácticas.

También podemos escribir CSS en el propio documento, dentro de una etiqueta <style> situada en <head>. Es una hoja de estilos interna: resulta cómoda para probar una idea o preparar un ejemplo en un solo archivo.

<style>
  p { color: navy; }
</style>

Estas reglas se aplican a esa página. Si copiamos el bloque en varios documentos, después tendremos que modificarlos uno a uno; por eso conviene pasar los estilos compartidos a una hoja externa.

La tercera posibilidad es el estilo en línea, escrito en el atributo style de una etiqueta. Aquí no indicamos un selector: las declaraciones afectan directamente a ese elemento.

<p style="color: navy;">Texto de ejemplo</p>

Aunque permite un cambio rápido, repetir atributos style mezcla la presentación con el contenido y dificulta mantener los estilos. Evítalo como forma habitual de maquetar: utiliza clases y reglas en una hoja externa. Sigue teniendo usos concretos, como ciertos correos HTML o valores que JavaScript cambia durante la interacción.

1.2. Anatomía de una regla

Una regla CSS combina un selector y un bloque de declaraciones. El selector localiza elementos del documento; cada declaración asigna un valor a una propiedad.

<link rel="stylesheet" href="css/estilos.css">

/* estilos.css */
.tarjeta {
  color: #1e3a8a;
  padding: 1rem;
}

Los comentarios se escriben entre /* y */ y pueden ocupar varias líneas. Úsalos para separar bloques de la hoja (reset, base, componentes) y para explicar decisiones que no se deducen del código.

1.3. Cascada

Un mismo elemento puede recibir declaraciones de distintas reglas. La cascada es el proceso que resuelve esos conflictos y determina el valor que se aplica a cada propiedad. El navegador considera, entre otros factores, el origen de los estilos, su importancia, las capas de cascada y la especificidad de los selectores. Cuando las declaraciones empatan en los criterios anteriores, gana la que aparece después.

/* Ambas reglas tienen el mismo origen, importancia y especificidad. */
p { color: navy; }
p { color: teal; } /* Esta declaración aparece después y gana. */

En este ejemplo, los párrafos se muestran en color verde azulado. Escribir una regla al final no garantiza que siempre prevalezca: el orden de aparición resuelve el empate, pero no sustituye a los demás criterios de la cascada.

Ampliación

Capas de cascada con @layer

Las capas permiten ordenar grupos de estilos completos (reset, base, componentes…) antes de comparar la especificidad. Es útil cuando el proyecto crece o se combinan estilos de terceros.

Ver explicación y ejemplos
/* Se declara el orden: la última capa tiene más prioridad. */
@layer reset, base, componentes;

@layer base {
  #principal a { color: navy; }   /* especificidad alta, pero capa anterior */
}
@layer componentes {
  .boton { color: white; }        /* gana: está en una capa posterior */
}

Un enlace con id="principal" en su contenedor y clase boton será blanco: entre capas, el orden de las capas se decide antes que la especificidad. Los estilos escritos fuera de cualquier capa tienen prioridad sobre todos los que están dentro de capas. Con !important el orden se invierte: las declaraciones importantes de las primeras capas ganan.

Los estilos que escribes fuera de cualquier bloque @layer se agrupan en una capa anónima implícita que tiene la máxima prioridad por encima de todas las capas nombradas (excepto si usas !important). Esto te permite hacer ajustes rápidos de emergencia sin romper toda la arquitectura de capas.

1.4. Herencia

La herencia permite que ciertas propiedades pasen de un elemento a sus descendientes cuando estos no tienen un valor propio que las sustituya. Propiedades como color y font-family se heredan por defecto; otras, como margin, padding y border, no.

<article class="noticia">
  <p>Este texto hereda el color y la fuente del artículo.</p>
</article>

.noticia {
  color: navy;
  font-family: sans-serif;
  border: 1px solid navy;
}

El párrafo hereda el color y la fuente, pero no recibe un borde propio. Si añadimos .noticia p { color: teal; }, el párrafo utiliza su declaración de color en lugar del valor heredado. La palabra clave inherit permite pedir explícitamente el valor del padre, incluso en propiedades que no se heredan por defecto.

1.5. Especificidad

La especificidad es el peso de un selector y ayuda a resolver qué declaración gana cuando corresponde comparar selectores dentro de la cascada. Se comparan tres grupos en este orden: identificadores; clases, atributos y pseudoclases; y tipos de elemento y pseudoelementos.

  • #aviso: un identificador → 1-0-0.
  • .destacado: una clase → 0-1-0.
  • p: un tipo de elemento → 0-0-1.
<p id="aviso" class="destacado">Información importante</p>

#aviso { color: navy; }      /* 1-0-0 */
.destacado { color: teal; }  /* 0-1-0 */
p { color: maroon; }        /* 0-0-1 */

Si estas reglas son declaraciones normales del autor en la misma capa, gana #aviso, aunque esté escrito antes. La comparación se hace por grupos, de izquierda a derecha: no se suman como si fueran un número decimal. El selector universal * y los combinadores, como >, no añaden especificidad. !important modifica la importancia de una declaración, no la especificidad de su selector.

Ampliación: valores globales de las propiedades

Además de los valores propios de cada propiedad, CSS ofrece palabras clave comunes para decidir de dónde debe proceder su valor. Nos permiten heredar el del padre, recuperar el valor inicial o dejar que intervengan otras reglas de la cascada.

Valores globales de CSS
ValorQué haceEjemplo
inheritToma el valor calculado de la misma propiedad en el elemento padre, incluso si esa propiedad no se hereda normalmente.border-color: inherit;
initialUsa el valor inicial definido por CSS para esa propiedad. No equivale a recuperar los estilos del navegador para una etiqueta concreta.display: initial; da el valor inicial inline, incluso en un div.
unsetActúa como inherit en las propiedades heredables y como initial en las demás.color: unset; hereda el color; margin: unset; recupera su valor inicial, cero.
revertDescarta el valor del origen actual para esa propiedad. En estilos del autor deja que se apliquen los estilos del usuario o del navegador, según la cascada.h2 { font-size: revert; } permite recuperar el tamaño que corresponda a un h2 sin las reglas del autor para esa propiedad.
revert-layerDescarta el valor de la capa de cascada actual para esa propiedad y permite resolverlo con las demás capas. Las capas se declaran con @layer; no son elementos ni capas visuales.color: revert-layer;

La diferencia clave: initial consulta el valor inicial de la propiedad; revert permite recuperar estilos de otros orígenes. Por eso no producen necesariamente el mismo resultado.

1.6. ¿Qué hace !important?

Da prioridad a una declaración frente a las declaraciones normales del mismo origen. Se escribe después del valor y no aumenta la especificidad.

<p id="aviso">Hola</p>

/* CSS */
#aviso { color: blue; }
p { color: red !important; }

El texto será rojo: la declaración importante vence a la normal, aunque esta use un selector con ID.

Cuando añadir !important no cambia el resultado

Para el mismo párrafo, prueba estos dos casos por separado, en la misma hoja y sin capas:

/* Antes: el texto es azul. */
#aviso { color: blue !important; }
p { color: red; }

/* Después: sigue siendo azul. */
#aviso { color: blue !important; }
p { color: red !important; }

En el segundo caso, ambas declaraciones son importantes. Gana #aviso por su mayor especificidad: 1-0-0 frente a 0-0-1 de p. Añadir !important no cambia esos valores, aunque la regla de p esté escrita después.

No abuses de él: dificulta cambiar los estilos después. Primero revisa los selectores y su orden. Resérvalo para excepciones justificadas.

1.7. Propiedades abreviadas (shorthands)

Una propiedad abreviada (shorthand) permite definir varias propiedades relacionadas en una sola declaración. Por ejemplo, con border puedes dibujar un borde en los cuatro lados de una caja.

/* Sin abreviar el grosor, el estilo y el color */
.caja {
  border-width: 2px;
  border-style: solid;
  border-color: blue;
}

/* Con la propiedad abreviada */
.caja {
  border: 2px solid blue;
}

Ambas reglas dibujan el mismo borde. Lee los valores de la segunda de izquierda a derecha. 2px indica el grosor, solid dibuja una línea continua y blue le da color azul. Si después solo quieres cambiar el color, basta con escribir border-color: red;.

A lo largo de la unidad encontrarás tarjetas Shorthand con la abreviatura de cada grupo de propiedades. Recuerda que una abreviatura restablece los valores que no escribes.

1.8. Legibilidad del código

El navegador entiende igual una hoja ordenada que una escrita en una sola línea, pero las personas no. Una hoja CSS se lee muchas más veces de las que se escribe: la revisarás tú dentro de unas semanas, la corregirá el profesorado y, en un equipo, la ampliarán otras personas. Escribir código legible es parte del trabajo, no un adorno.

Indentación y formato

Sigue siempre el mismo formato. Estas convenciones son las más extendidas y las que aplican de forma automática los formateadores como Prettier:

  • Una declaración por línea, con dos espacios de indentación dentro de las llaves.
  • Un espacio después de los dos puntos y un punto y coma al final de cada declaración, también de la última.
  • La llave de apertura en la línea del selector y la de cierre sola, alineada con el selector.
  • Una línea en blanco entre reglas; si agrupas varios selectores, uno por línea.
  • Minúsculas en propiedades, valores y colores hexadecimales.

Comentarios y orden de la hoja

Los comentarios (/* … */) sirven para dos cosas: separar bloques de la hoja y explicar decisiones que no se deducen del código. No repitas lo que ya dice la declaración.

/* ==========================================================
   1. Variables (tokens de diseño)
   ========================================================== */
:root {
  --color-marca: #6d28d9;
  --espacio: 1rem;
}

/* ==========================================================
   2. Base: estilos de elementos HTML
   ========================================================== */
body {
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}

/* ==========================================================
   3. Componentes
   ========================================================== */
.tarjeta {
  padding: var(--espacio);
  /* min-width: 0 evita que un nombre largo desborde la rejilla. */
  min-width: 0;
}

Ordena la hoja de lo general a lo particular: variables, reset y estilos base, después componentes y, al final, utilidades y consultas de medios. Ese orden coincide con el de la cascada: las reglas más concretas quedan después y pueden ajustar a las generales sin recurrir a !important.

Curiosidad

Un comentario útil explica el porqué
  • Inútil: /* color rojo */ encima de color: red;.
  • Útil: /* El rojo de marca no alcanza 4,5:1 sobre crema: usamos uno más oscuro. */

Nombres de clases: kebab-case

En CSS los nombres de clases y variables se escriben en kebab-case: todo en minúsculas y las palabras separadas por guiones, como las propias propiedades (background-color, font-size). Las clases distinguen mayúsculas de minúsculas: .Tarjeta y .tarjeta son clases distintas, así que una regla fija evita errores difíciles de encontrar.

Además del formato, cuida el significado: nombra las clases por su función, no por su aspecto. .aviso sigue siendo correcto si el aviso pasa de rojo a naranja; .texto-rojo deja de serlo. Usa nombres en un solo idioma y sin tildes ni eñes para evitar problemas de codificación.

Metodología BEM

BEM (Block, Element, Modifier) es una convención para nombrar clases que hace visible la estructura de cada componente en el propio nombre:

ParteQué representaSintaxisEjemplo

  <p class="producto__precio">3,20 €</p>

</article>

  padding: var(--espacio);
  border: 1px solid #e7d8c4;
  border-radius: .75rem;
}

.producto__precio {
  font-weight: 700;
}

/* El modificador acompaña a la clase del bloque, no la sustituye. */
.producto--agotado {
  background-color: #f3f4f6;
  border-style: dashed;
}

Ventajas que se notan pronto:

  • Especificidad baja y uniforme: casi todas las reglas usan una sola clase (0-1-0), así que los conflictos se resuelven con el orden y no con selectores cada vez más largos (1.5).
  • Independencia del HTML: .producto__precio funciona aunque cambies la etiqueta o lo muevas dentro de la tarjeta, cosa que no ocurre con .producto div p.
  • Lectura inmediata: al ver la clase sabes a qué componente pertenece y qué papel tiene.

Error frecuente

No encadenes elementos

Un elemento pertenece al bloque, no a otro elemento: escribe .producto__boton, no .producto__pie__boton. Si una parte crece y se reutiliza fuera del bloque, conviértela en un bloque nuevo. Y no uses un modificador sin la clase base: class="producto--agotado" sola pierde todos los estilos de .producto.

Atomic Design en tu hoja de estilos

En la UD01 estudiaste Atomic Design como forma de pensar una interfaz a partir de piezas pequeñas. En CSS se traduce en una organización de la hoja y de los nombres: cada nivel se apoya en el anterior y cada componente BEM ocupa un nivel.

Una organización de archivos que sigue esta idea:

css/
├── tokens.css        /* variables de la guía de estilo */
├── base.css          /* reset y estilos de elementos HTML */
├── atomos.css        /* .boton, .campo, .etiqueta */
├── moleculas.css     /* .buscador, .precio */

└── estilos.css       /* importa los anteriores en este orden */

Para proyectos pequeños basta con una sola hoja dividida con comentarios en esos mismos bloques. Lo importante es que los átomos no dependan de dónde se colocan: un .boton debe verse igual en la cabecera que dentro de una tarjeta.

2. Selectores

El selector es la parte de la regla que decide a qué elementos se aplican las declaraciones. Empezaremos por los selectores simples y después combinaremos condiciones, estados y partes de un elemento. El objetivo es seleccionar con precisión sin añadir clases innecesarias ni crear reglas difíciles de mantener.

2.1. Selectores básicos

Un selector indica a qué elementos HTML se aplica una regla. Para empezar, podemos seleccionar por el nombre de la etiqueta, por una clase, por un identificador o por un atributo. El selector universal permite seleccionar cualquier elemento.

Los combinadores describen relaciones, pero no suman especificidad. Evita cadenas excesivamente largas que dependan de cada contenedor intermedio: un pequeño cambio en el HTML podría dejar la regla sin efecto.

2.3. Selectores de atributo

Los corchetes permiten seleccionar por la presencia de un atributo o por su valor. Son útiles para distinguir campos de formulario y tipos de enlace.

/* Elementos que tienen el atributo required. */
[required] { border-left: 3px solid #b45309; }

/* Campos cuyo tipo es exactamente email. */
input[type="email"] { background-color: #eff6ff; }

/* Enlaces cuyo href empieza por https://. */
a[href^="https://"] { text-decoration: underline; }

/* Enlaces cuyo href termina en .pdf. */
a[href$=".pdf"] { font-weight: bold; }

/* Enlaces cuyo href contiene /recursos/. */
a[href*="/recursos/"] { color: #0f766e; }

= compara el valor completo; ^=, su comienzo; $=, su final; y *=, una parte del valor. Estos selectores comparan el atributo: [href$=".pdf"] no coincidirá con un enlace que termine en .pdf?descarga=1.

2.4. Agrupar y combinar condiciones

La coma permite compartir declaraciones entre varios selectores. En cambio, escribir selectores juntos y sin espacio exige que un mismo elemento cumpla todas esas condiciones.

/* Selecciona todos los h1 y todos los h2. */
h1, h2 { color: #1e3a8a; }

/* Solo los párrafos que tengan la clase destacado. */
p.destacado { font-weight: bold; }

/* Elementos que tengan las dos clases. */
.tarjeta.destacado { border: 2px solid #0f766e; }

Fíjate en el espacio: p.destacado selecciona un párrafo con esa clase; p .destacado selecciona un elemento con esa clase que esté dentro de un párrafo. Esta segunda forma utiliza una relación de descendencia.

Agrupar con :is()

:is() selecciona los elementos que coincidan con cualquiera de los selectores entre paréntesis. Permite agrupar alternativas sin repetir la parte común.

/* Sin :is(): repetimos .tarjeta. */
.tarjeta h2,
.tarjeta h3 {
  color: #1e3a8a;
}

/* Con :is(): seleccionamos los mismos elementos. */
.tarjeta :is(h2, h3) {
  color: #1e3a8a;
}

Ambas reglas seleccionan los h2 y h3 que estén dentro de .tarjeta.

Especificidad: :is() toma la del selector más específico de su lista. Por ejemplo, :is(.aviso, #principal) aporta el peso de un ID, incluso cuando coincide por la clase. Evita mezclar IDs y clases sin necesitarlo.

CSS nesting: anidar reglas relacionadas

La anidación permite escribir los estilos de un componente dentro de su regla, evitando repetir el selector. Es CSS nativo: el navegador lo interpreta sin Sass ni compilación.

.tarjeta {
  padding: 1rem;
  border: 2px solid #6d28d9;

  & h3 {
    color: #6d28d9;
  }

  &:hover {
    border-color: #4c1d95;
  }
}

/* Equivalente sin anidación: */
.tarjeta { padding: 1rem; border: 2px solid #6d28d9; }
.tarjeta h3 { color: #6d28d9; }
.tarjeta:hover { border-color: #4c1d95; }

& representa el selector de la regla exterior. & h3 selecciona sus encabezados descendientes; &:hover, la propia tarjeta al pasar el puntero. El espacio cambia el significado.

Mantén pocos niveles para facilitar la lectura. La especificidad de & se calcula como en :is(): una lista que mezcle una clase y un ID toma la especificidad mayor. No concatena nombres: &__titulo no sirve para formar .tarjeta__titulo.

Cómo leer padding y margin

padding separa el contenido del borde, por dentro. margin deja espacio por fuera del borde. Las dos abreviaturas asignan los cuatro lados en el mismo orden: arriba → derecha → abajo → izquierda.

La misma lectura para las dos propiedades
RellenoMargenArriba · derecha · abajo · izquierda (px)

padding: 8px 16px 24px;margin: 8px 16px 24px;8 · 16 · 24 · 16
padding: 8px 16px 24px 32px;margin: 8px 16px 24px 32px;8 · 16 · 24 · 32

Con un valor se repiten los cuatro lados. Con dos, se reparten entre el eje vertical y el horizontal. Con tres, los laterales comparten el segundo valor. Con cuatro, cada lado recibe el suyo.

/* Equivale a: */
.ficha {
  padding-top: 8px;
  padding-right: 16px;
  padding-bottom: 24px;

}

/* Equivale a: */
.ficha {
  margin-top: 8px;
  margin-right: 16px;
  margin-bottom: 24px;
  margin-left: 32px;
}

Para modificar solo el relleno izquierdo, escribe padding-left después de padding en la misma regla. Si inviertes el orden, la abreviatura vuelve a fijar los cuatro lados.

3.2. Uso de «auto»

¿Qué calcula el navegador cuando escribes auto? Depende de la propiedad. Compara estos casos en un bloque de texto en flujo normal y con escritura horizontal.

  • width: auto ajusta el ancho al espacio disponible teniendo en cuenta márgenes, borde y relleno. Con height: auto, la altura crece con el texto. En una foto con ancho definido, la altura automática conserva su proporción original.
  • margin-left: auto absorbe el espacio horizontal libre si el margen derecho vale cero. Si ambos márgenes laterales son automáticos, se reparten ese espacio. En este mismo contexto, los márgenes verticales automáticos valen cero.
  • El relleno admite longitudes y porcentajes no negativos. El navegador descarta padding: auto.

3.3. Colapso de márgenes y márgenes negativos

En el flujo normal, los márgenes verticales de dos bloques consecutivos pueden colapsar: en lugar de sumarse, se aplica el mayor.

.titulo  { margin-bottom: 24px; }
.parrafo { margin-top: 16px; }
/* Separación real entre ambos: 24 px, no 40 px. */

El colapso no ocurre con los márgenes horizontales ni entre elementos de Flexbox o Grid. Si necesitas una separación que siempre se sume, usa padding en el contenedor o gap en una distribución (UD03).

Un margen negativo reduce la separación entre cajas y puede hacer que se solapen. Prueba con dos bloques consecutivos en el flujo normal. El primero deja 24 px debajo. Si el segundo tiene un margen superior de −8 px, entre ambos quedan 16 px.

.primero { margin-bottom: 24px; }
.segundo { margin-top: -8px; }

Cambia el segundo margen a -32px. Ahora las cajas se solapan 8 px. Comprueba que el contenido siga siendo legible si utilizas este efecto.

3.4. Box model reset y CSS Reset

*, *::before, *::after {
  box-sizing: border-box;
}

Esta regla, habitual en los resets CSS, aplica border-box a todos los elementos (*) y a sus pseudoelementos ::before y ::after.

¿Por qué se hace así? Para que el relleno y el borde estén incluidos en el tamaño indicado.

Por ejemplo, con width: 100% y padding: 20px:

  • Con content-box: la caja ocupa el 100% del ancho del contenedor más 40 px de relleno y puede desbordarse.
  • Con border-box: esos 40 px quedan dentro del 100%; se reduce el espacio para el contenido.

Así resulta más sencillo controlar el tamaño de las cajas al maquetar.

Mantener una proporción

aspect-ratio: 16 / 9 expresa ancho dividido entre alto: una caja de 320 px de ancho tendrá una altura preferida de 180 px. Deja al menos una dimensión en auto; si fijas ambas, la proporción no calcula ninguna. El contenido y los límites mínimos o máximos pueden modificar el resultado. Para recortar una imagen dentro de una caja proporcionada, usa object-fit: cover; para mostrarla entera, contain.

Repasa cómo se calcula el valor automático en dimensiones y márgenes.

/* Se adapta a la pantalla y limita el ancho de lectura. */
.articulo {
  width: calc(100% - 2rem);
  max-width: 65ch;
  margin-inline: auto;
}

/* Puede crecer cuando se añade texto. */
.tarjeta { min-height: 12rem; height: auto; }

/* La imagen se reduce si hace falta, sin perder su proporción. */
img { max-width: 100%; height: auto; }

/* Caja de proporción 16:9, cuya altura se calcula. */
.portada { width: 100%; height: auto; aspect-ratio: 16 / 9; }
Valores y conflictos habituales
  • auto deja que el navegador calcule el tamaño según el contexto. height: auto suele permitir crecer con el contenido; no equivale a una altura fija.
  • Los porcentajes necesitan una referencia: width: 100% suele tomar el ancho del bloque contenedor. Un height: 100% no significa «toda la pantalla» y, en el flujo normal, necesita una altura de referencia definida para funcionar como esperas.
  • min-content, max-content y fit-content permiten tamaños relacionados con las necesidades del contenido, en lugar de una medida fija.
  • Un máximo puede limitar el tamaño declarado y un mínimo puede ampliarlo. Si el mínimo supera al máximo, prevalece el mínimo. Evita un min-width mayor que la pantalla.
  • En elementos Flexbox o Grid, el mínimo automático puede impedir que una caja se reduzca. Cuando el diseño lo necesite, min-width: 0 o min-inline-size: 0 permite que ceda espacio; después debes decidir cómo tratar su contenido.

Prueba las dimensiones con texto largo, zoom e imágenes de distintos tamaños. No fijes una altura solo porque encaja con el texto de ejemplo: limita la capacidad del diseño para adaptarse.

4. Valores: unidades, colores y variables

Cada declaración termina en un valor. Elegir bien las unidades decide si la interfaz se adapta al tamaño de letra o a la pantalla; elegir bien los colores decide si se lee. Las variables permiten nombrar esas decisiones y reutilizarlas en toda la hoja.

4.1. Unidades

Una medida combina un número y una unidad, sin espacios: 16px o 1.5rem. Las unidades absolutas, como px, mantienen una relación fija entre sí. Las relativas dependen de otra medida, como el tamaño de la fuente. Para las primeras prácticas trabajaremos con estas cuatro opciones.

4.3. Variables y cálculos en CSS

Imagina que el color de marca cambia o que una tarjeta debe caber tanto en un móvil como en un escritorio. Una variable permite nombrar una decisión de diseño y reutilizarla. Una función de cálculo permite obtener una medida a partir del espacio disponible.

Declarar, reutilizar y redefinir una variable

Las propiedades personalizadas evitan repetir colores, espacios y otros valores. Se declaran con --nombre y se utilizan mediante var(). Así puedes cambiar una decisión visual desde un único lugar.

:root {
  --color-marca: #6d28d9;
  --espacio: 1rem;
}

.tarjeta {
  border: 2px solid var(--color-marca);
  padding: var(--espacio);
  border-radius: var(--radio, .5rem);
}

.tarjeta--oferta {
  --color-marca: #9a3412;
}

:root establece valores generales. En una tarjeta con las clases tarjeta tarjeta--oferta, el borde será marrón porque se redefine --color-marca en ese elemento. Las propiedades declaradas con -- participan en la cascada y se heredan por defecto.

var(--radio, .5rem) usa .5rem si la variable no está definida o tiene un valor inválido como propiedad personalizada. No corrige cualquier error de tipo: si --radio: rojo, ese texto no sirve como radio y la declaración de border-radius será inválida.

Abreviar la tipografía con font y text-decoration

Ver cómo escribir las propiedades abreviadas

font reúne estilo, variante, peso, anchura, tamaño, interlineado y familia. Tamaño y familia son obligatorios. Los opcionales van antes del tamaño; el interlineado va después de /; la familia, al final.

.entradilla {
  font-style: italic;
  font-weight: 600;
  font-size: 1.125rem;
  line-height: 1.6;
  font-family: system-ui, sans-serif;
}
/* Mismo resultado con las demás opciones de fuente iniciales: */
.entradilla { font: italic 600 1.125rem/1.6 system-ui, sans-serif; }
.texto { font: 1rem/1.6 "Mi Fuente", sans-serif; }

Lo omitido se restablece: font: 1rem system-ui elimina una negrita o cursiva anterior y devuelve el interlineado a normal. No incluye color, text-align ni letter-spacing. No carga fuentes: para eso se utiliza @font-face.

text-decoration agrupa línea, estilo, color y grosor. text-underline-offset queda fuera y se escribe aparte.

a {
  text-decoration: underline solid #6d28d9 .1em;
  text-underline-offset: .2em;
}
/* Las cuatro propiedades agrupadas son: */
a {
  text-decoration-line: underline;
  text-decoration-style: solid;
  text-decoration-color: #6d28d9;
  text-decoration-thickness: .1em;
}

font-variant reúne variantes tipográficas: font-variant: small-caps activa versalitas y restablece las otras variantes. Si solo quieres cambiar las mayúsculas, usa font-variant-caps: small-caps.

6.2. Cargar una fuente propia con @font-face

Si queremos utilizar una fuente que no tiene por qué estar instalada en el equipo del usuario, podemos proporcionar su archivo con @font-face. Esta regla registra una fuente con un nombre; después debemos aplicar ese mismo nombre mediante font-family.

/* En css/estilos.css; el archivo está en la carpeta fuentes. */
@font-face {
  font-family: "Mi Fuente";
  src: url("../fuentes/mi-fuente-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

body {
  font-family: "Mi Fuente", system-ui, sans-serif;
}

8. Repaso

Intenta responder antes de desplegar cada pregunta.

¿Por qué conviene usar una hoja de estilos externa en lugar de estilos en línea?

Porque varias páginas comparten las mismas reglas y un cambio se hace en un solo archivo. Los estilos en línea mezclan presentación y contenido y obligan a modificar cada elemento.

Dos reglas dan color a un mismo párrafo: p { color: red; } y .aviso { color: blue; }. La primera está escrita después. ¿De qué color se ve un párrafo con clase aviso?

Azul. La clase tiene más especificidad (0-1-0) que el tipo (0-0-1); el orden de aparición solo decide cuando hay empate.

¿Qué propiedades se heredan normalmente: color, margin, font-family, border?

color y font-family. Las propiedades de caja, como margin y border, no se heredan.

¿Qué diferencia hay entre una pseudoclase y un pseudoelemento?

La pseudoclase (:hover, :focus-visible) selecciona un elemento según su estado o posición. El pseudoelemento (::before, ::first-line) permite estilizar una parte de un elemento.

¿Qué diferencia hay entre un margen y un relleno?

El relleno separa el contenido del borde; el margen separa la caja de su entorno.

Una caja tiene width: 300px, padding: 20px y un borde de 5 px. ¿Cuánto ocupa de ancho con content-box y con border-box?

Con content-box, 350 px (300 + 40 + 10). Con border-box, 300 px: el contenido se reduce a 250 px.

¿Cuándo usarías rem, % y px?

rem para texto y espacios que deben escalar con la preferencia de tamaño de letra; % para anchos que dependen del contenedor; px para detalles finos como bordes.

¿Por qué opacity: .5 en una tarjeta no es lo mismo que un fondo con alfa?

opacity atenúa toda la tarjeta, texto incluido. Un color con alfa en background-color solo hace transparente el fondo.

¿Qué hace overflow: auto?

Muestra barras de desplazamiento solo cuando el contenido no cabe en la caja.
