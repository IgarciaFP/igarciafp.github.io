1. Dar vida a la interfaz

Usarás el CSS de la UD02 para integrar efectos, imágenes, audio, vídeo y gráficos. Cada recurso debe tener una función: comunicar información, explicar una acción o reforzar la jerarquía visual.

  • Integrar audio y vídeo con controles, subtítulos y alternativas textuales.
  • Dibujar en Canvas y reconocer cuándo conviene usar SVG, WebGL o una biblioteca 3D.

Conserva siempre los archivos fuente y los recursos necesarios para reproducir el proyecto.

2. Filtros y composición visual

filter modifica la representación visual del elemento: puedes desenfocar, variar brillo o contraste y aplicar escala de grises. No reduce el peso del archivo descargado. El orden de las funciones puede cambiar el resultado. opacity afecta a toda la composición del elemento, mientras que un color con alfa permite una transparencia localizada.

.foto {
  filter: grayscale(1) contrast(1.1);
  object-fit: cover;
  object-position: center;
}
.foto:hover { filter: none; }

object-fit: cover rellena el contenedor recortando la imagen si es necesario; contain la muestra completa y puede dejar espacio libre. clip-path recorta visualmente una región, pero no modifica las dimensiones de la caja ni convierte la imagen en un recurso más pequeño.

3. Transformaciones y origen

transform cambia la representación de una caja: translate() desplaza, scale() escala, rotate() gira y skew() inclina. Estos cambios no reorganizan el espacio reservado en el flujo. Una tarjeta ampliada puede solaparse con sus vecinas.

.tarjeta { transform-origin: bottom left; }
.tarjeta:hover,
.tarjeta:focus-visible {
  transform: translateX(.5rem) rotate(5deg) scale(1.05);
}

El punto definido por transform-origin actúa como referencia de giros y escalados. El orden de las transformaciones importa: no debes considerar equivalentes dos listas con las mismas funciones en distinto orden.

Si la tarjeta activa una acción, usa un botón; si solo muestra un efecto, añade un control de demostración separado. Documenta dos casos donde cambiar el origen o el orden modifica el resultado.

4. Transiciones entre estados

Una transición interpola una propiedad entre dos estados. Define la propiedad, duración, curva y retraso. El cambio puede proceder de una pseudoclase o de una clase añadida con JavaScript. Declara las propiedades concretas para evitar animar cambios imprevistos con all.

.boton {
  background-color: #1e3a8a;
  transform: translateY(0);
  transition: background-color .2s ease, transform .2s ease;
}
.boton:hover, .boton:focus-visible {
  background-color: #0f766e;
  transform: translateY(-2px);
}
@media (prefers-reduced-motion: reduce) {
  .boton { transition: none; transform: none; }
  .boton:hover, .boton:focus-visible { transform: none; }
}

No todas las propiedades admiten interpolación continua. Para fundir un fondo sólido con una imagen, superpone capas y cambia su opacidad. Repetir transform dos veces en la lista de transiciones no crea una secuencia de dos transformaciones: utiliza keyframes o elementos anidados cuando necesites fases independientes.

5. Animación con keyframes

@keyframes describe estados de una secuencia. animation controla duración, curva, repeticiones y dirección; animation-play-state permite pausar. Usa el movimiento para explicar cambios, sin obligar a seguir animaciones decorativas continuas.

@keyframes entrada {
  from { opacity: 0; transform: translateY(1rem); }
  to { opacity: 1; transform: translateY(0); }
}
.aviso { animation: entrada .4s ease-out both; }
@media (prefers-reduced-motion: reduce) {
  .aviso { animation: none; }
}

6. Imágenes adaptables y formatos

Antes de insertar una imagen decide su función, dimensiones de visualización y nivel de detalle. Compara formatos según el contenido: fotografías, gráficos con transparencia o ilustraciones vectoriales requieren decisiones diferentes. Un formato moderno no garantiza por sí solo el mejor resultado: mide el peso y revisa la calidad visual.

srcset ofrece candidatos y sizes describe el ancho previsto de visualización; el navegador elige según el contexto. picture permite alternativas de formato o composición. El elemento img sigue siendo obligatorio como respaldo y contiene el texto alternativo.

<picture>
  <source type="image/avif" srcset="foto-640.avif 640w, foto-1280.avif 1280w"
          sizes="(min-width: 48rem) 50vw, 100vw">
  <source type="image/webp" srcset="foto-640.webp 640w, foto-1280.webp 1280w"
          sizes="(min-width: 48rem) 50vw, 100vw">
  <img src="foto-640.jpg" srcset="foto-640.jpg 640w, foto-1280.jpg 1280w"
       sizes="(min-width: 48rem) 50vw, 100vw"
       width="1280" height="853"
       alt="Escenario del grupo con iluminación azul" loading="lazy">
</picture>

Este ejemplo requiere generar los archivos indicados y ajustar sizes al diseño real. width y height proporcionan una relación de aspecto para reservar espacio. El texto alternativo comunica la función o información de la imagen; una imagen puramente decorativa usa alt="". figure agrupa el recurso con un pie figcaption, útil para contexto y atribución.

7. Carga, medición y optimización

Compara resultados con condiciones equivalentes: mismo dispositivo, red, URL y estado de caché. Repite las pruebas y registra la variación. Examina bytes transferidos, recursos descargados y estabilidad del diseño, además de las métricas del informe. Una mejora en una puntuación aislada no explica por sí sola la causa.

Aplica loading="lazy" a imágenes fuera de la vista inicial cuando proceda. No retrases la imagen principal que necesita verse inmediatamente. La carga de scripts usa otros mecanismos: defer aplaza la ejecución de scripts clásicos externos hasta terminar el análisis del documento; async permite ejecutarlos cuando estén disponibles y no conserva su orden. No existe un atributo loading="lazy" equivalente para scripts.

<script src="interfaz.js" defer></script>
<!-- Los scripts de módulo se difieren por defecto. -->
<script type="module" src="app.js"></script>

La precarga con preload se reserva para recursos prioritarios identificados mediante medición. Precargar toda la galería consume ancho de banda que puede necesitar el contenido inicial.

9. Dibujar con Canvas

canvas ofrece una superficie de dibujo que se maneja con JavaScript. Sus atributos width y height definen las dimensiones del mapa de bits. CSS controla el tamaño visual; cambiar solo CSS puede estirar o emborronar el dibujo. En pantallas de alta densidad puedes ajustar el mapa de bits y la escala del contexto.

<canvas id="lienzo" width="400" height="240"
        role="img" aria-label="Rectángulo azul y círculo verde">
  Rectángulo azul a la izquierda y círculo verde a la derecha.
</canvas>

<script>
const canvas = document.querySelector("#lienzo");
const ctx = canvas.getContext("2d");
if (ctx) {
  ctx.fillStyle = "#1e3a8a";
  ctx.fillRect(30, 50, 120, 120);
  ctx.beginPath();
  ctx.arc(280, 110, 60, 0, Math.PI * 2);
  ctx.fillStyle = "#0f766e";
  ctx.fill();
}
</script>

Ejemplo dibujado

Rectángulo azul y círculo verde.

Las coordenadas parten de la esquina superior izquierda; x crece a la derecha e y hacia abajo.

beginPath() inicia un trazado; moveTo(), lineTo() y arc() construyen su geometría. fill() rellena y stroke() dibuja el contorno. Usa save() y restore() para aislar estilos y transformaciones; no guardan una copia de los píxeles. Si una escena cambia, limpia la zona pertinente con clearRect() y vuelve a dibujar.

El texto y los controles dibujados no se convierten automáticamente en elementos HTML accesibles. Acompaña el lienzo de una descripción y usa controles HTML reales para interactuar.

10. SVG, WebGL y Three.js

Escoge la herramienta según el resultado. SVG representa gráficos vectoriales con elementos que pueden formar parte del DOM. Canvas 2D dibuja píxeles y requiere mantener el estado de la escena en tu código. WebGL ofrece renderizado acelerado mediante la GPU. Three.js es una biblioteca que facilita construir escenas 3D sobre tecnologías de renderizado del navegador.

En una escena 3D aparecen geometrías, materiales, cámara, luces y un renderizador. Antes de añadir un visor al proyecto, decide qué información aporta y ofrece una alternativa estática. Una escena decorativa pesada puede empeorar la experiencia en equipos modestos.

Actividad de multimedia 03-08 · Elegir una tecnología gráfica

Compara tres casos: logotipo adaptable, reloj dibujado y vista de un producto en 3D. Elige SVG, Canvas o una solución 3D en cada caso y justifica la decisión por calidad, interacción, accesibilidad y coste. Como ampliación, prepara una escena 3D sencilla con una alternativa estática; documenta la versión utilizada y los recursos cargados.

11. Comprobación final

¿Una transformación reduce el peso de una imagen?

No. Modifica su representación. Para reducir bytes debes trabajar sobre el recurso y su entrega.

¿Cuándo necesitas una transición y cuándo keyframes?

Una transición conecta un cambio de estado; keyframes permite describir una secuencia de estados intermedios.

¿Basta con que el vídeo se vea para dar por terminada la integración?

No. Comprueba controles, teclado, subtítulos, transcripción, adaptación y carga de recursos.

13. Modelo de caja accesible

Una tarjeta de producto puede tener espacio suficiente en español y quedarse pequeña al traducir el nombre o ampliar el texto. Deja que su altura crezca con el contenido y reserva la separación siguiendo el sentido de lectura.

13.1. Dejar espacio para el texto

Si el diseño pide que todas las tarjetas tengan al menos cierta altura, usa min-height. Con la altura automática, una segunda línea puede hacer crecer la caja y desplazar el contenido siguiente. Prueba a ampliar el texto al 200 % y comprueba que puedes leer el precio completo y usar el botón.

.producto {
  box-sizing: border-box;
  min-height: 6rem;
  padding: 1rem;
}

Distinguir el punto de inserción con caret-color

Al editar una nota de pedido, la barra parpadeante indica dónde aparecerá la siguiente letra. La propiedad caret-color permite darle un color propio. Su valor inicial es auto: el navegador elige el color, normalmente el del texto. También admite un color CSS y se hereda.

.nota-pedido {
  background-color: white;
  color: #172033;
  caret-color: #87452e;
}


Entra en el campo con Tab y mueve el punto de inserción con las flechas. La barra marrón señala la posición dentro del texto. El contorno de foco identifica el campo activo, incluso cuando la barra parpadea.

El color de selección con accent-color

En un pedido, una casilla marcada debe distinguirse de otra vacía. accent-color permite aplicar el color de la panadería al indicador que dibuja el navegador. Su valor inicial es auto. También admite un color CSS y se hereda, de modo que puedes definirlo una vez para varios controles.

.opciones-pedido {
  accent-color: #87452e;
}

Marca y desmarca esta opción. El color aparece en la casilla seleccionada y la marca permite reconocer su estado también por la forma.

También puedes usar esta propiedad en botones de opción, controles de rango y barras de progreso. El navegador decide qué partes del control reciben el color.

13.2. Márgenes modernos

El diseño web moderno ya no piensa estrictamente en «arriba/abajo» y «izquierda/derecha», sino en la dirección del flujo de escritura (writing-mode).

  • Inline sigue la dirección en la que fluyen las palabras dentro de una línea. En escritura horizontal, la línea empieza a la izquierda en español y a la derecha en árabe.
  • Block sigue la dirección en la que se apilan los bloques o párrafos. En escritura horizontal se suceden de arriba abajo. En escritura vertical, las columnas avanzan hacia la izquierda o hacia la derecha.

Piensa en un aviso traducido al árabe. El atributo lang="ar" identifica el idioma y dir="rtl" indica que la lectura empieza a la derecha. Para disponer el texto en columnas verticales, se utiliza writing-mode. Una vez indicado el flujo, margin-inline y margin-block se adaptan a él sin tener que reescribir margin-left ni margin-right.

Cómo se colocan las líneas con writing-mode
ValorDónde aparece la línea siguiente
horizontal-tbDebajo de la anterior (top to bottom). En árabe se conserva este modo y se indica dir="rtl" en el HTML.
vertical-rlEn una columna a la izquierda de la anterior (right to left).
vertical-lrEn una columna a la derecha de la anterior (left to right).

En este aviso en español, margin-block deja espacio antes y después del bloque. margin-inline lo separa de los bordes donde empieza y termina la línea.

Uno o dos valores por eje

Con un valor, los dos extremos del eje reciben el mismo margin. Este aviso tiene 16 px arriba y abajo, y 24 px a izquierda y derecha.

.aviso {
  margin-block: 16px;
  margin-inline: 24px;
}

Con dos valores, el primero corresponde al inicio del eje y el segundo al final. Para que el aviso destaque, puedes dejar más espacio después del bloque y una sangría solo donde empieza la línea.

.aviso {
  margin-block: 8px 24px;
  margin-inline: 16px 0;
}

margin-block: 8px 24px equivale a margin-block-start: 8px y margin-block-end: 24px. margin-inline: 16px 0 equivale a margin-inline-start: 16px y margin-inline-end: 0. Si el texto horizontal pasa a leerse de derecha a izquierda, la sangría de 16 px pasa a la derecha. Los 8 px de arriba y los 24 px de abajo siguen en su sitio. Con writing-mode: vertical-rl, los 8 px del inicio de bloque quedan a la derecha y los 24 px del final, a la izquierda.

Mantener una proporción

aspect-ratio: 16 / 9 expresa ancho dividido entre alto: una caja de 320 px de ancho tendrá una altura preferida de 180 px. Deja al menos una dimensión en auto; si fijas ambas, la proporción no calcula ninguna. El contenido y los límites mínimos o máximos pueden modificar el resultado. Para recortar una imagen dentro de una caja proporcionada, usa object-fit: cover; para mostrarla entera, contain.

.articulo {
  width: calc(100% - 2rem);
  max-width: 65ch;
  margin-inline: auto;
}

/* Puede crecer cuando se añade texto. */
.tarjeta { min-height: 12rem; height: auto; }

/* La imagen se reduce si hace falta, sin perder su proporción. */
img { max-width: 100%; height: auto; }

/* Caja de proporción 16:9, cuya altura se calcula. */
.portada { width: 100%; height: auto; aspect-ratio: 16 / 9; }
Valores y conflictos habituales
  • auto deja que el navegador calcule el tamaño según el contexto. height: auto suele permitir crecer con el contenido; no equivale a una altura fija.
  • Los porcentajes necesitan una referencia: width: 100% suele tomar el ancho del bloque contenedor. Un height: 100% no significa «toda la pantalla» y, en el flujo normal, necesita una altura de referencia definida para funcionar como esperas.
  • min-content, max-content y fit-content permiten tamaños relacionados con las necesidades del contenido, en lugar de una medida fija.
  • Un máximo puede limitar el tamaño declarado y un mínimo puede ampliarlo. Si el mínimo supera al máximo, prevalece el mínimo. Evita un min-width mayor que la pantalla.
  • En elementos Flexbox o Grid, el mínimo automático puede impedir que una caja se reduzca. Cuando el diseño lo necesite, min-width: 0 o min-inline-size: 0 permite que ceda espacio; después debes decidir cómo tratar su contenido.

Prueba las dimensiones con texto largo, zoom e imágenes de distintos tamaños. No fijes una altura solo porque encaja con el texto de ejemplo: limita la capacidad del diseño para adaptarse.

13.6. Flotantes según la dirección de lectura y contención con flow-root

Una receta muestra la foto junto al comienzo de la primera línea. En español queda a la izquierda. En árabe, con dir="rtl", ese mismo lugar está a la derecha. float: inline-start sigue el inicio de la línea y float: inline-end sitúa la foto en el extremo final.

Aplica esta regla a una imagen dentro de un artículo con la clase noticia. El texto del párrafo siguiente rodea la foto y margin-inline-end deja espacio entre ambos.

.noticia img {
  width: 8rem;
  height: auto;
  float: inline-start;
  margin-inline-end: 1rem;
}

Para colocar la foto al final de la línea, cambia la regla a float: inline-end y sustituye margin-inline-end por margin-inline-start. Así la separación sigue quedando del lado del texto. Prueba ambos ejemplos cambiando el atributo dir del artículo.

Hacer que el fondo del artículo envuelva la foto

Cuando la foto es más alta que el texto, el fondo del artículo puede terminar antes que la foto. Para que también la envuelva, aplicamos display: flow-root al contenedor. Crea un contexto de formato de bloque (BFC), una región que organiza sus bloques y flotantes: el padre incluye los flotantes internos al calcular su altura automática, y el texto sigue rodeando la foto.

.noticia {
  display: flow-root;
  background: #dbeafe;
}

Compruébalo en la noticia: compara el fondo sin contención, con clearfix y con flow-root, usando una solución cada vez.

flow-root no centra, no distribuye columnas y no obliga a recortar el contenido ni a mostrar barras. También impide que los márgenes del padre colapsen con los de sus hijos; los de hermanos dentro de él aún pueden colapsar. Su caja evita solaparse con flotantes externos: queda a su lado si cabe o debajo si no cabe.

Historia

La solución tradicional: clearfix

Antes de flow-root se usaba un pseudoelemento para que el padre envolviera el flotante. Aún lo encontrarás en muchas hojas de estilo.

Ver cómo funciona el clearfix

Se añadía al final un elemento vacío con clear: both. Para evitar ese HTML extra se popularizó el clearfix: generar con ::after una caja final que baja por debajo del flotante y hace crecer el contenedor.

.noticia::after {
  content: "";
  display: block;
  clear: both;
}

Ese pseudoelemento no añade texto: sirve para cerrar la distribución después del flotante. Otra solución era overflow: hidden, pero podía recortar menús, sombras o contenido que sobresaliese; con overflow: auto podían aparecer barras.

Antes de Flexbox y Grid también se usaron flotantes para colocar columnas y menús uno junto a otro. Funcionaba, pero trasladaba a la maquetación un comportamiento pensado para que el texto rodease imágenes.

13.7. Variables y cálculos en CSS

Imagina que el color de marca cambia o que una tarjeta debe caber tanto en un móvil como en un escritorio. Una variable permite nombrar una decisión de diseño y reutilizarla. Una función de cálculo permite obtener una medida a partir del espacio disponible.

Declarar, reutilizar y redefinir una variable

Las propiedades personalizadas evitan repetir colores, espacios y otros valores. Se declaran con --nombre y se utilizan mediante var(). Así puedes cambiar una decisión visual desde un único lugar.

:root {
  --color-marca: #6d28d9;
  --espacio: 1rem;
}

.tarjeta {
  border: 2px solid var(--color-marca);
  padding: var(--espacio);
  border-radius: var(--radio, .5rem);
}

.tarjeta--oferta {
  --color-marca: #9a3412;
}

En una tarjeta con las clases tarjeta tarjeta--oferta, el borde será marrón porque --color-marca se redefine en ese elemento.

:root es el lugar habitual para los valores generales, pero cualquier elemento puede redefinir una variable para sí mismo y sus descendientes. Las propiedades declaradas con -- participan en la cascada y se heredan por defecto.

var(--radio, .5rem) usa .5rem si la variable no está definida o tiene un valor inválido como propiedad personalizada. No corrige cualquier error de tipo: si --radio: rojo, ese texto no sirve como radio y la declaración de border-radius será inválida.

Utiliza nombres por función, como --color-marca. var() sustituye valores, no nombres de propiedades ni selectores.

Calcular medidas y elegir límites

Una medida no tiene por qué ser fija: CSS puede calcularla o elegirla entre varias opciones cuando aplica el estilo. Consulta en la tabla las cuatro funciones que lo permiten.

14. Flexbox: distribuir en un eje

Flexbox organiza los hijos directos del contenedor sobre un eje principal. flex-direction define ese eje; justify-content reparte el espacio sobre él y align-items alinea en el transversal. Con flex-wrap aparecen nuevas líneas. Los elementos pueden crecer o encogerse mediante flex.

14.1. Contenedor, elementos y ejes

Flexbox se activa en el contenedor con display: flex. A partir de ese momento, sus hijos directos se convierten en elementos flexibles; los nietos siguen en flujo normal salvo que su propio padre también sea flexible.

<nav class="menu">
  <a href="index.html">Inicio</a>
  <a href="productos.html">Productos</a>
  <a href="contacto.html">Contacto</a>
</nav>
.menu {
  display: flex;   /* los tres enlaces se colocan en fila */
  gap: 1rem;       /* separación entre ellos, sin márgenes */
}

Todo en Flexbox se entiende a partir de dos ejes. El eje principal es la dirección en la que se colocan los elementos; el eje transversal es el perpendicular.

14.2. Repartir y alinear

Las propiedades se dividen en dos grupos: las del contenedor (dirección, salto de línea, reparto y alineación) y las de cada elemento (crecimiento, reducción, tamaño base, orden y alineación individual). Prueba los ejes con el control y consulta la tabla cuando necesites un valor concreto.

14.3. Cómo crecen y se encogen los elementos

Cada elemento parte de un tamaño base (flex-basis). Después, el navegador compara la suma de los tamaños base con el espacio del contenedor:

  • Si sobra espacio, lo reparte según flex-grow. Con el valor inicial, 0, nadie crece y el espacio queda libre.
  • Si falta espacio, reduce los elementos según flex-shrink. Con el valor inicial, 1, todos pueden encogerse.
/* Contenedor de 600 px y tres tarjetas con base de 150 px. */
.tarjeta { flex: 1 1 150px; }          /* crece, encoge, base 150 px */
.tarjeta.destacada { flex-grow: 2; }   /* recibe el doble de espacio libre */

Los tamaños base suman 450 px, así que sobran 150 px. Hay cuatro partes de crecimiento (1 + 1 + 2): cada tarjeta normal recibe 37,5 px y la destacada 75 px. Resultado: 187,5 px, 187,5 px y 225 px. Observa que flex-grow: 2 no hace la tarjeta el doble de ancha: le da el doble del espacio sobrante.

Si añades flex-wrap: wrap, los elementos que no caben en su tamaño base pasan a otra línea en lugar de encogerse. Esta combinación es la base de muchas galerías adaptables sin consultas de medios.

Error frecuente

Un elemento que no se encoge

Un elemento flexible no se hace más pequeño que su contenido mínimo (por ejemplo, una palabra o una URL larga). Si desborda, añade min-width: 0 al elemento y decide qué hacer con el texto (overflow-wrap: anywhere, recorte con text-overflow…).

14.4. Patrones habituales

Empujar un elemento al final. Un margen automático en el eje principal absorbe todo el espacio libre. Es la forma más sencilla de separar el logotipo del menú o de llevar un botón al extremo:

.cabecera { display: flex; align-items: center; gap: 1rem; }
.cabecera .cesta { margin-inline-start: auto; }  /* se va a la derecha */

Pie de tarjeta siempre abajo. En tarjetas de distinta altura, el botón queda alineado si la tarjeta es un contenedor en columna:

.tarjeta { display: flex; flex-direction: column; }
.tarjeta .boton { margin-block-start: auto; }

Imagen junto a texto. La imagen conserva su ancho y el texto ocupa el resto:

.ficha { display: flex; gap: 1rem; align-items: flex-start; }
.ficha img { flex: none; width: 6rem; }
.ficha .texto { flex: 1; min-width: 0; }

Galería que salta de línea. Cada tarjeta tiene un ancho base y el contenedor permite varias líneas:

.galeria { display: flex; flex-wrap: wrap; gap: 1rem; }
.galeria > article { flex: 1 1 15rem; min-width: 0; }
.barra { display: flex; align-items: center; justify-content: space-between; }

Cambiar el orden visual no cambia automáticamente el orden del DOM ni la navegación con teclado. Mantén un orden lógico en el HTML.

15. Grid: filas y columnas

Grid permite definir filas y columnas de forma conjunta. fr reparte espacio disponible; minmax() establece un intervalo. repeat() evita repetir pistas y auto-fit ajusta el número de columnas que caben. En diseños con textos extensos, minmax(0, 1fr) evita que el mínimo intrínseco de una pista fuerce un desbordamiento.

15.1. Pistas, líneas y celdas

Una cuadrícula se define en el contenedor. grid-template-columns y grid-template-rows crean las pistas (columnas y filas); entre ellas quedan las líneas, que sirven para colocar elementos.

.rejilla {
  display: grid;
  grid-template-columns: 1fr 1fr 1fr;  /* tres columnas iguales */
  gap: 1rem;
}

La unidad fr reparte el espacio disponible después de restar los huecos y las pistas fijas. En 200px 1fr 2fr con 800 px y sin huecos, la primera columna mide 200 px y las otras se reparten 600 px: 200 px y 400 px. repeat(3, 1fr) abrevia la lista anterior y minmax(12rem, 1fr) fija un intervalo: nunca menos de 12 rem, como mucho una fracción.

Si hay más elementos que celdas definidas, Grid crea filas nuevas automáticamente (la cuadrícula implícita). Su altura se controla con grid-auto-rows.

Sin indicaciones, los elementos ocupan las celdas en orden, fila a fila. Para colocar uno en concreto se indican la línea inicial y la final, o cuántas pistas abarca con span:

.destacada { grid-column: 2 / 4; }     /* de la línea 2 a la 4 */
.ancha     { grid-column: span 2; }    /* dos columnas desde donde caiga */
.completa  { grid-column: 1 / -1; }    /* de la primera a la última línea */

Los números negativos cuentan desde el final: -1 es siempre la última línea de la cuadrícula explícita.

15.4. Cuadrículas automáticas: auto-fit y auto-fill

Combinando repeat(), minmax() y auto-fit, la cuadrícula calcula cuántas columnas caben sin necesidad de consultas de medios:

.rejilla {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(100%, 15rem), 1fr));
  gap: 1rem;
}
@media (min-width: 48rem) {
  .destacada { grid-column: span 2; }
}

Cada columna mide al menos 15 rem; si caben cuatro, hay cuatro; si solo cabe una, una. min(100%, 15rem) evita que la columna desborde en pantallas más estrechas que 15 rem.

  • auto-fill crea todas las columnas que caben, aunque queden vacías.
  • auto-fit también las crea, pero colapsa las vacías, de modo que los elementos existentes se estiran para ocupar la fila.

La diferencia solo se aprecia cuando hay pocos elementos y mucho espacio. Pruébalo con dos tarjetas en una ventana ancha.

Si la caja ocupa todo el ancho, no queda espacio que repartir. En el flujo normal, margin-block: auto tampoco centra una caja en vertical.

16.2. Grid: un elemento en el centro del panel

Para una tarjeta o un mensaje dentro de un panel, Grid permite centrar el hijo en los dos ejes. place-items: center abrevia align-items: center y justify-items: center. La altura mínima deja espacio para centrar y permite que el panel crezca si aumenta el texto.

<div class="panel-centrado">
  <p>Tu pedido está preparado.</p>
</div>
.panel-centrado {
  display: grid;
  place-items: center;
  min-height: 16rem;
  padding: 1rem;
}
.panel-centrado p { margin: 0; }

Para una portada que ocupe al menos la altura visible de la ventana, puedes sustituir 16rem por 100dvh. No fijes una altura rígida si el contenido puede crecer.

16.3. Flexbox: centrar desde el contenedor

Aplica estas tres propiedades al padre: display: flex activa Flexbox; justify-content: center centra en horizontal y align-items: center, en vertical. Esto corresponde a la dirección predeterminada de Flexbox y a la escritura horizontal del ejemplo.

<div class="panel">
  <article class="tarjeta">Tu pedido está preparado.</article>
</div>
.panel {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 16rem;
  padding: 1rem;
}

La altura mínima deja espacio para centrar y permite que el panel crezca si aumenta el texto. Para este ejemplo basta con estas reglas; estudiaremos la distribución, los ejes y las demás opciones en el apartado de Flexbox.

Recuerda que justify-content actúa sobre el eje principal y align-items sobre el transversal: si cambias a flex-direction: column, el centrado se mantiene pero cada propiedad controla el otro eje. El contenedor debe disponer de espacio libre para que se aprecie el centrado. Consulta los ejes en 14.1.

16.4. Centrar una superposición

Reserva el posicionamiento absoluto para un elemento que deba superponerse, como un distintivo sobre una imagen. El padre establece la referencia con position: relative. El desplazamiento del 50 % se calcula respecto al padre; translate compensa la mitad del tamaño del propio hijo.

.marco { position: relative; }
.distintivo {
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%);
}

El distintivo queda fuera del flujo y no aumenta la altura del padre. Para centrar contenido normal, utiliza márgenes automáticos, Grid o Flexbox según el caso; evita ajustes manuales con espacios, márgenes fijos o una altura de línea forzada.

Comprueba el resultado estrechando la ventana, añadiendo texto y aumentando el zoom. El centrado debe conservar la lectura sin ocultar contenido.

Historia

Cómo se centraba antes de Flexbox y Grid

Durante años, centrar en vertical exigía trucos con condiciones. Conocerlos ayuda a entender código antiguo; para proyectos nuevos, usa las técnicas anteriores.

Ver las técnicas tradicionales

Tenemos una tarjeta de Migas Amigas y queremos colocarla en el centro de un panel. Parece sencillo: escribimos text-align: center… y se centra el texto, pero la tarjeta sigue en su sitio. Centrar el contenido de una caja y centrar la propia caja son problemas distintos. Esta diferencia explica muchos de los trucos que se utilizaron antes de disponer de herramientas de distribución.

Primero, centrar en horizontal

Para centrar un título bastaba con text-align. Para centrar un bloque, había que darle un ancho menor que el de su contenedor y repartir el espacio sobrante con márgenes automáticos. Ambas soluciones siguen siendo válidas.

/* Centrar el texto dentro de la tarjeta. */
.tarjeta { text-align: center; }

/* Centrar la tarjeta dentro de la página. */
.tarjeta {
  width: 80%;
  max-width: 24rem;
  margin-inline: auto;
}

Antes se escribía habitualmente margin: 0 auto. margin-inline: auto expresa los márgenes del eje de escritura y no modifica los del otro eje. Otra solución para una caja en línea era display: inline-block en el hijo y text-align: center en el padre.

¿Y en vertical? Cada solución tenía condiciones

El flujo normal coloca unos bloques después de otros; no reparte automáticamente el espacio vertical libre. Por eso se recurrió a soluciones diferentes según el contenido. Estos fragmentos muestran alternativas: no se aplican todos a la vez.

17. Diseño responsive

Un diseño responsive combina medidas flexibles, recursos adaptables y cambios de distribución. Mobile first parte de la pantalla estrecha y añade reglas con min-width cuando el contenido lo necesita. Los puntos de ruptura son decisiones del diseño, no una lista universal de dispositivos.

17.1. Viewport y mobile first

Sin indicación, los navegadores móviles simulan una pantalla ancha y reducen la página. Esta etiqueta, dentro de <head>, les pide usar el ancho real del dispositivo:

<meta name="viewport" content="width=device-width, initial-scale=1">

Con mobile first escribimos primero los estilos de la pantalla estrecha, que suelen ser los más sencillos (una columna, flujo normal), y añadimos reglas para pantallas mayores cuando el contenido lo pide:

  1. Maqueta en una columna, con medidas flexibles y sin anchos fijos.
  2. Ensancha la ventana poco a poco hasta que el diseño empiece a verse mal: líneas demasiado largas, huecos enormes, tarjetas estiradas.
  3. Ese ancho es un punto de ruptura. Añade una consulta con min-width y reorganiza.
  4. Repite hasta el ancho máximo que quieras admitir.

17.2. Consultas de medios

Una consulta de medios aplica un bloque de reglas solo cuando se cumple una condición sobre el dispositivo o la ventana.

/* Desde 48rem de ancho de ventana (768 px con la letra por defecto). */
@media (min-width: 48rem) { … }

/* Sintaxis de rango, equivalente y más legible. */
@media (width >= 48rem) { … }

/* Entre dos anchos. */
@media (40rem <= width < 64rem) { … }

/* Combinar condiciones. */
@media (min-width: 48rem) and (orientation: landscape) { … }

/* Dispositivos con puntero preciso que permite pasar por encima. */
@media (hover: hover) and (pointer: fine) { … }

Expresa los puntos de ruptura en rem o em: en las consultas de medios se calculan a partir del tamaño de letra inicial del navegador, así que la distribución también cambia si la persona amplía la letra por defecto.

Un ejemplo completo: una columna como punto de partida, dos columnas desde 48 rem y una versión para imprimir sin navegación ni decoraciones.

<meta name="viewport" content="width=device-width, initial-scale=1">

/* CSS: una columna como punto de partida */
.contenido { display: grid; gap: 1rem; }
@media (min-width: 48rem) {
  .contenido { grid-template-columns: 2fr 1fr; }
}
@media print {
  nav, .decoracion { display: none; }
  body { color: #000; background: #fff; }
}

17.3. Diseño intrínseco: menos consultas, más flexibilidad

Muchas adaptaciones no necesitan una consulta de medios. Si las medidas expresan límites en lugar de valores fijos, la interfaz se adapta de forma continua:

17.4. Consultas de contenedor

Una tarjeta puede aparecer en una columna estrecha o en una zona amplia de la misma página. ¿Debe tener el mismo aspecto en ambas? Las consultas de contenedor permiten adaptar sus estilos al espacio de su contenedor, no al ancho de la ventana.

Un elemento envolvente agrupa la tarjeta. Para consultar su tamaño, declara container-type: inline-size; en escritura horizontal permite consultar su ancho. container-name le asigna un nombre opcional para identificarlo en la consulta.

Shorthand

Abreviar la definición de un contenedor

Ver cómo escribir las propiedades abreviadas

Si utilizas unidades de contenedor, container reúne container-name y container-type. Escribe el nombre y, tras /, el tipo.

.ficha {
  container-name: ficha;
  container-type: inline-size;
}
/* Forma abreviada equivalente: */
.ficha { container: ficha / inline-size; }

El nombre identifica el contenedor para las consultas; inline-size permite consultar su tamaño en el eje en línea. Si escribes solo container: ficha, el tipo vuelve a normal. No basta para crear un contenedor de consultas de tamaño.

Referencia: container · MDN ↗

<div class="zona-producto">
  <article class="producto">
    <h3>Pan de masa madre</h3>
    <p>Consulta los tamaños disponibles.</p>
  </article>
</div>
.zona-producto {
  container-type: inline-size;
  container-name: ficha;
}
.producto { padding: 1rem; }
.producto h3 { font-size: 1.25rem; }

/* Se aplica cuando el contenedor ficha mide al menos 480 px. */
@container ficha (min-width: 480px) {
  .producto { padding: 2rem; }
  .producto h3 { font-size: 1.75rem; }
}

Cómo comprobarlo: cambia el ancho de .zona-producto entre 300px y 600px. El relleno y el título cambian sin modificar el tamaño de la ventana.

La consulta modifica los descendientes, no el propio contenedor consultado. Las unidades cqi siguen su tamaño en línea: 1cqi equivale al 1 %. Por ejemplo, padding: 4cqi adapta el relleno al espacio disponible.

17.5. Imágenes y medios adaptables

Una imagen no debe desbordar su contenedor. Esta regla base, habitual en los resets, la reduce cuando no cabe y conserva su proporción:

img, video { max-width: 100%; height: auto; display: block; }

Para no descargar una foto de 2000 px en un móvil, srcset ofrece varias versiones y sizes indica cuánto ocupará la imagen. El navegador elige la más adecuada según el ancho de pantalla y la densidad de píxeles:

<img src="hogaza-800.jpg"
     srcset="hogaza-400.jpg 400w, hogaza-800.jpg 800w, hogaza-1600.jpg 1600w"
     sizes="(min-width: 48rem) 50vw, 100vw"
     width="800" height="600"
     alt="Hogaza de masa madre recién horneada">

Los atributos width y height permiten reservar el espacio antes de que la imagen cargue y evitan saltos en la página. Si necesitas otro encuadre según el tamaño (dirección de arte) o un formato moderno con alternativa, usa <picture>:

<picture>
  <source media="(min-width: 48rem)" srcset="obrador-panoramica.avif" type="image/avif">
  <source media="(min-width: 48rem)" srcset="obrador-panoramica.jpg">
  <img src="obrador-vertical.jpg" alt="Elena amasando en el obrador">
</picture>

Para recortar una imagen dentro de un marco proporcionado, recuerda aspect-ratio y object-fit (Encuadre de imágenes). Los formatos, la compresión y la medición del peso se estudian en la unidad de animación y multimedia.

17.6. Preferencias de la persona usuaria

Define colores mediante variables para crear temas coherentes. prefers-color-scheme permite respetar la preferencia del sistema; si añades un botón, debe expresar el estado y permitir volver al modo automático. Comprueba todos los componentes en ambos temas, incluidos formularios y foco.

Propiedades y valores de referencia
PropiedadValores y significadoEjemplo
color-schemeIndica los esquemas que puede usar la interfaz nativa del navegador: normal, light, dark o combinaciones como light dark; only impide la sustitución automática del esquema indicado. No define por sí sola todos los colores de la página.color-scheme: light dark;
:root { --fondo: #fff; --texto: #172033; color-scheme: light; }

Además de prefers-color-scheme y prefers-reduced-motion, existe prefers-contrast para quien pide más contraste. Respetar estas preferencias es parte del diseño, no un añadido.

17.7. Comprobar la interfaz

Un diseño responsive no está terminado hasta que se comprueba. Las herramientas de desarrollo del navegador incluyen un modo de dispositivo para simular anchos, pero no sustituyen a probar en un móvil real.

  • Anchos: 320 px (el mínimo que exige WCAG 1.4.10, «Reflujo», sin desplazamiento horizontal), anchos intermedios y escritorio. No pruebes solo los puntos de ruptura.
  • Zoom: amplía al 200 % (WCAG 1.4.4); nada debe solaparse ni quedar oculto.
  • Contenido real: textos largos, nombres sin espacios, imágenes de otras proporciones.
  • Teclado: recorre la página con Tab; el orden visual y el del foco deben coincidir.
  • Preferencias: tema oscuro y movimiento reducido activados en el sistema.
  • Impresión: vista previa de impresión con @media print.

Prueba anchos intermedios, orientación, zoom y textos largos. Un menú móvil debe poder abrirse con un botón y teclado, indicar su estado y mantener enlaces alcanzables. Oculta decoraciones cuando proceda, pero conserva la información necesaria. Comprueba también la vista de impresión.

Para trabajar accesibilidad, revisa HTML semántico, nombres de controles, orden de lectura y navegación por teclado. Comprueba que la interfaz conserva un orden de lectura claro y que todos sus controles se pueden utilizar con teclado.

19. Repaso

Intenta responder antes de desplegar cada pregunta.

En un contenedor con flex-direction: column, ¿qué propiedad centra los elementos horizontalmente?

align-items: center, porque en columna el eje horizontal es el transversal.

¿Qué significa flex: 1 1 15rem?

El elemento parte de 15 rem, puede crecer para ocupar espacio libre y puede encogerse si falta.

¿Qué hace grid-column: 1 / -1?

Extiende el elemento desde la primera hasta la última línea de columna: ocupa todo el ancho de la cuadrícula.

¿Flexbox sustituye a Grid?

Son complementarios: se pueden combinar para resolver distintas relaciones de distribución.

¿Por qué se recomienda empezar por la versión móvil?

Porque suele ser la más sencilla (una columna en flujo normal) y obliga a priorizar el contenido. Después se añaden reglas con min-width solo cuando hacen falta.

¿Cuándo es mejor una consulta de contenedor que una de medios?

Cuando un componente puede aparecer en huecos de distinto tamaño dentro de la misma página: debe adaptarse al espacio que recibe, no al ancho de la ventana.

¿Por qué una interfaz de escritorio reducida no es necesariamente responsive?

Porque también hay que adaptar distribución, lectura e interacción, y comprobar que el contenido sigue siendo utilizable.
