1. Dar vida a la interfaz

Usarás los diseños flexibles de la UD02 para integrar efectos, imágenes, audio, vídeo y gráficos. Cada recurso debe tener una función: comunicar información, explicar una acción o reforzar la jerarquía visual.

  • Distinguir filtros, transformaciones, transiciones y animaciones.
  • Preparar imágenes adaptables y comparar su coste de carga.
  • Integrar audio y vídeo con controles, subtítulos y alternativas textuales.
  • Dibujar en Canvas y reconocer cuándo conviene usar SVG, WebGL o una biblioteca 3D.

Conserva siempre los archivos fuente y los recursos necesarios para reproducir el proyecto.

2. Filtros y composición visual

filter modifica la representación visual del elemento: puedes desenfocar, variar brillo o contraste y aplicar escala de grises. No reduce el peso del archivo descargado. El orden de las funciones puede cambiar el resultado. opacity afecta a toda la composición del elemento, mientras que un color con alfa permite una transparencia localizada.

.foto {
  filter: grayscale(1) contrast(1.1);
  object-fit: cover;
  object-position: center;
}
.foto:hover { filter: none; }

object-fit: cover rellena el contenedor recortando la imagen si es necesario; contain la muestra completa y puede dejar espacio libre. clip-path recorta visualmente una región, pero no modifica las dimensiones de la caja ni convierte la imagen en un recurso más pequeño.

Prueba un filtro

filter: grayscale(0%);

3. Transformaciones y origen

transform cambia la representación de una caja: translate() desplaza, scale() escala, rotate() gira y skew() inclina. Estos cambios no reorganizan el espacio reservado en el flujo. Una tarjeta ampliada puede solaparse con sus vecinas.

.tarjeta { transform-origin: bottom left; }
.tarjeta:hover,
.tarjeta:focus-visible {
  transform: translateX(.5rem) rotate(5deg) scale(1.05);
}

El punto definido por transform-origin actúa como referencia de giros y escalados. El orden de las transformaciones importa: no debes considerar equivalentes dos listas con las mismas funciones en distinto orden.

Actividad 03-02 · Nueve tarjetas

Crea nueve tarjetas que comparen escala, rotación, inclinación, traslación y combinaciones. En tres de ellas cambia el origen a centro, esquina inferior izquierda y esquina superior derecha. Si la tarjeta activa una acción, usa un botón; si solo muestra un efecto, añade un control de demostración separado. Documenta dos casos donde cambiar el origen o el orden modifica el resultado.

4. Transiciones entre estados

Una transición interpola una propiedad entre dos estados. Define la propiedad, duración, curva y retraso. El cambio puede proceder de una pseudoclase o de una clase añadida con JavaScript. Declara las propiedades concretas para evitar animar cambios imprevistos con all.

.boton {
  background-color: #1e3a8a;
  transform: translateY(0);
  transition: background-color .2s ease, transform .2s ease;
}
.boton:hover, .boton:focus-visible {
  background-color: #0f766e;
  transform: translateY(-2px);
}
@media (prefers-reduced-motion: reduce) {
  .boton { transition: none; transform: none; }
  .boton:hover, .boton:focus-visible { transform: none; }
}

No todas las propiedades admiten interpolación continua. Para fundir un fondo sólido con una imagen, superpone capas y cambia su opacidad. Repetir transform dos veces en la lista de transiciones no crea una secuencia de dos transformaciones: utiliza keyframes o elementos anidados cuando necesites fases independientes.

Actividad 03-03 · Estados y transiciones

Crea cuatro demostraciones: botón que cambia de color, imagen que cambia de opacidad, tarjeta que rota y escala, y fondo que se funde mediante capas. Incluye interacción por teclado y una variante para reducir movimiento. Añade una secuencia de dos fases usando keyframes y explica por qué no has duplicado transform en la propiedad transition.

5. Animación con keyframes

@keyframes describe estados de una secuencia. animation controla duración, curva, repeticiones y dirección; animation-play-state permite pausar. Usa el movimiento para explicar cambios, sin obligar a seguir animaciones decorativas continuas.

@keyframes entrada {
  from { opacity: 0; transform: translateY(1rem); }
  to { opacity: 1; transform: translateY(0); }
}
.aviso { animation: entrada .4s ease-out both; }
@media (prefers-reduced-motion: reduce) {
  .aviso { animation: none; }
}

La demostración está detenida.

CSS resuelve secuencias visuales declarativas. JavaScript puede iniciar o pausar estados y actualizar una escena de Canvas. Para una animación dibujada utiliza requestAnimationFrame(), mide el tiempo transcurrido y evita asumir que todos los equipos dibujan a la misma frecuencia.

6. Imágenes adaptables y formatos

Antes de insertar una imagen decide su función, dimensiones de visualización y nivel de detalle. Compara formatos según el contenido: fotografías, gráficos con transparencia o ilustraciones vectoriales requieren decisiones diferentes. Un formato moderno no garantiza por sí solo el mejor resultado: mide el peso y revisa la calidad visual.

srcset ofrece candidatos y sizes describe el ancho previsto de visualización; el navegador elige según el contexto. picture permite alternativas de formato o composición. El elemento img sigue siendo obligatorio como respaldo y contiene el texto alternativo.

<picture>
  <source type="image/avif" srcset="foto-640.avif 640w, foto-1280.avif 1280w"
          sizes="(min-width: 48rem) 50vw, 100vw">
  <source type="image/webp" srcset="foto-640.webp 640w, foto-1280.webp 1280w"
          sizes="(min-width: 48rem) 50vw, 100vw">
  <img src="foto-640.jpg" srcset="foto-640.jpg 640w, foto-1280.jpg 1280w"
       sizes="(min-width: 48rem) 50vw, 100vw"
       width="1280" height="853"
       alt="Escenario del grupo con iluminación azul" loading="lazy">
</picture>

Este ejemplo requiere generar los archivos indicados y ajustar sizes al diseño real. width y height proporcionan una relación de aspecto para reservar espacio. El texto alternativo comunica la función o información de la imagen; una imagen puramente decorativa usa alt="". figure agrupa el recurso con un pie figcaption, útil para contexto y atribución.

7. Carga, medición y optimización

Compara resultados con condiciones equivalentes: mismo dispositivo, red, URL y estado de caché. Repite las pruebas y registra la variación. Examina bytes transferidos, recursos descargados y estabilidad del diseño, además de las métricas del informe. Una mejora en una puntuación aislada no explica por sí sola la causa.

Aplica loading="lazy" a imágenes fuera de la vista inicial cuando proceda. No retrases la imagen principal que necesita verse inmediatamente. La carga de scripts usa otros mecanismos: defer aplaza la ejecución de scripts clásicos externos hasta terminar el análisis del documento; async permite ejecutarlos cuando estén disponibles y no conserva su orden. No existe un atributo loading="lazy" equivalente para scripts.

<script src="interfaz.js" defer></script>
<!-- Los scripts de módulo se difieren por defecto. -->
<script type="module" src="app.js"></script>

La precarga con preload se reserva para recursos prioritarios identificados mediante medición. Precargar toda la galería consume ancho de banda que puede necesitar el contenido inicial.

Actividad 03-05 · Galería antes y después

Prepara una galería de doce imágenes con origen y permiso de uso documentados. Conserva una versión inicial y otra optimizada. En la segunda ajusta dimensiones, compara formatos, usa picture o srcset, reserva espacio y aplica carga diferida donde corresponda. La disposición debe adaptarse a móvil y escritorio.

8. Audio, vídeo y subtítulos

Utiliza controles nativos para disponer de reproducción, pausa y ajustes básicos. Ofrece alternativas de fuente si necesitas compatibilidad con distintos formatos. No fuerces reproducción automática con sonido. Un póster permite anticipar el contenido del vídeo antes de reproducirlo.

<video controls preload="metadata" poster="portada.jpg"
       width="1280" height="720" style="max-width:100%;height:auto">
  <source src="presentacion.webm" type="video/webm">
  <source src="presentacion.mp4" type="video/mp4">
  <track kind="captions" src="subtitulos-es.vtt" srclang="es"
         label="Español" default>
  Tu navegador no puede reproducir este vídeo.
</video>
<p><a href="transcripcion.html">Leer la transcripción</a></p>
<audio controls preload="metadata" src="entrevista.mp3"></audio>

Los subtítulos accesibles incluyen diálogo y sonidos relevantes; una transcripción permite consultar el contenido como texto. WebVTT usa marcas de tiempo, texto y una cabecera. Sirve los archivos desde un servidor HTTP y verifica que el navegador los carga correctamente.

9. Dibujar con Canvas

canvas ofrece una superficie de dibujo que se maneja con JavaScript. Sus atributos width y height definen las dimensiones del mapa de bits. CSS controla el tamaño visual; cambiar solo CSS puede estirar o emborronar el dibujo. En pantallas de alta densidad puedes ajustar el mapa de bits y la escala del contexto.

<canvas id="lienzo" width="400" height="240"
        role="img" aria-label="Rectángulo azul y círculo verde">
  Rectángulo azul a la izquierda y círculo verde a la derecha.
</canvas>

<script>
const canvas = document.querySelector("#lienzo");
const ctx = canvas.getContext("2d");
if (ctx) {
  ctx.fillStyle = "#1e3a8a";
  ctx.fillRect(30, 50, 120, 120);
  ctx.beginPath();
  ctx.arc(280, 110, 60, 0, Math.PI * 2);
  ctx.fillStyle = "#0f766e";
  ctx.fill();
}
</script>

Ejemplo dibujado

Rectángulo azul y círculo verde.

Las coordenadas parten de la esquina superior izquierda; x crece a la derecha e y hacia abajo.

beginPath() inicia un trazado; moveTo(), lineTo() y arc() construyen su geometría. fill() rellena y stroke() dibuja el contorno. Usa save() y restore() para aislar estilos y transformaciones; no guardan una copia de los píxeles. Si una escena cambia, limpia la zona pertinente con clearRect() y vuelve a dibujar.

El texto y los controles dibujados no se convierten automáticamente en elementos HTML accesibles. Acompaña el lienzo de una descripción y usa controles HTML reales para interactuar.

10. SVG, WebGL y Three.js

Escoge la herramienta según el resultado. SVG representa gráficos vectoriales con elementos que pueden formar parte del DOM. Canvas 2D dibuja píxeles y requiere mantener el estado de la escena en tu código. WebGL ofrece renderizado acelerado mediante la GPU. Three.js es una biblioteca que facilita construir escenas 3D sobre tecnologías de renderizado del navegador.

En una escena 3D aparecen geometrías, materiales, cámara, luces y un renderizador. Antes de añadir un visor al proyecto, decide qué información aporta y ofrece una alternativa estática. Una escena decorativa pesada puede empeorar la experiencia en equipos modestos.

Actividad 03-08 · Elegir una tecnología gráfica

Compara tres casos: logotipo adaptable, reloj dibujado y vista de un producto en 3D. Elige SVG, Canvas o una solución 3D en cada caso y justifica la decisión por calidad, interacción, accesibilidad y coste. Como ampliación, prepara una escena 3D sencilla con una alternativa estática; documenta la versión utilizada y los recursos cargados.

11. Comprobación final

¿Una transformación reduce el peso de una imagen?

No. Modifica su representación. Para reducir bytes debes trabajar sobre el recurso y su entrega.

¿Cuándo necesitas una transición y cuándo keyframes?

Una transición conecta un cambio de estado; keyframes permite describir una secuencia de estados intermedios.

¿Basta con que el vídeo se vea para dar por terminada la integración?

No. Comprueba controles, teclado, subtítulos, transcripción, adaptación y carga de recursos.

Entrega cada actividad con su código nuevo, archivos fuente y recursos, evidencias de las pruebas y explicación de las decisiones. Respeta las licencias de los materiales. El canal y la fecha se indicarán en clase.
