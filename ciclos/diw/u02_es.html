UD02. Fundamentos de CSS

Cómo decide el navegador qué estilo aplicar y cómo dar forma a cajas, colores y texto.

1. Qué es CSS y cómo se aplica

Al crear una página, HTML identifica el contenido y su estructura: un título, un párrafo, una lista o un enlace. El navegador ya les aplica una apariencia básica, pero necesitamos controlar cómo se muestran para construir nuestro diseño.

CSS permite definir esa presentación. Sus siglas significan Cascading Style Sheets (hojas de estilo en cascada). Con CSS elegimos colores, tipografías, tamaños, espacios y la distribución de los elementos.

Por ejemplo, HTML indica que un texto es un título mediante <h1>. CSS permite mostrarlo en azul, darle más tamaño y separarlo del párrafo siguiente. El contenido sigue siendo el mismo; cambia su presentación.

Separar ambas tareas facilita el trabajo:

  • Mantener la web: una hoja CSS compartida permite cambiar el aspecto de los títulos de todas las páginas desde un único archivo.
  • Conseguir coherencia: botones, menús y tarjetas pueden reutilizar los mismos estilos.
  • Adaptar el diseño: el mismo HTML puede mostrarse en una columna en el móvil y en varias en una pantalla grande.
  • Facilitar la lectura: podemos ajustar el contraste, el tamaño del texto y la separación entre elementos.

CSS aplica reglas a los elementos del HTML. Cuando varias reglas afectan al mismo elemento, el navegador necesita decidir cuáles usar. Por eso estudiaremos la cascada, la herencia y la especificidad. Primero veremos cómo incorporar esas reglas a una página.

¿Cuál es la primera hoja de estilo que se aplica a nuestro código HTML?

Incluso en una página HTML sin CSS propio, los títulos suelen verse más grandes que los párrafos y los enlaces aparecen subrayados. ¿De dónde salen esos estilos? Puedes descubrirlo si inspeccionas un título y buscas el origen de la regla que fija su tamaño.

Comprobar la explicación

El navegador incorpora una hoja de estilos predeterminada, llamada hoja de estilos del agente de usuario (user agent stylesheet). Esa es la base que da aspecto al HTML aunque no hayamos escrito CSS: márgenes, tamaños de títulos, marcadores de listas y otros estilos iniciales.

Las reglas del autor se combinan con esa base mediante la cascada. Hablar de «primera» sirve para reconocer el punto de partida, pero el resultado no se decide solo por el orden de carga: también intervienen el origen, la importancia y los demás criterios que estudiaremos.

1.1. Formas de incluir CSS

Para aplicar estilos a una página, el navegador necesita saber dónde están escritas las reglas CSS. Podemos guardarlas en un archivo independiente, incluirlas en la cabecera del HTML o escribirlas directamente en un elemento. Las tres formas funcionan, pero la elección influye en lo fácil que será mantener la web.

Cuando construimos un sitio con varias páginas, lo más práctico es utilizar una hoja de estilos externa: un archivo, como estilos.css, que contiene solo CSS y que cada página enlaza desde su cabecera mediante <link>. Si varias páginas enlazan la misma hoja, todas comparten sus estilos y basta con modificar una regla para cambiar el aspecto de todo el sitio. Esta será la forma habitual de trabajar en nuestras prácticas.

En la cabecera de cada página HTML, enlaza la hoja de estilos con <link>:

<!-- Dentro de head, en el archivo HTML -->
<link rel="stylesheet" href="css/estilos.css">

El atributo href indica la ruta del archivo: en este caso, el navegador buscará estilos.css dentro de la carpeta css.

En ese archivo escribimos únicamente CSS, sin etiquetas <style>:

/* Archivo css/estilos.css */
p { color: navy; }

Esta regla pinta de azul marino los párrafos de todas las páginas que enlacen la hoja.

También podemos escribir CSS en el propio documento, dentro de una etiqueta <style> situada en <head>. Es una hoja de estilos interna: sus reglas solo afectan a esa página. Resulta cómoda para probar una idea en un solo archivo, pero si copiamos el bloque en varios documentos tendremos que modificarlos uno a uno; por eso conviene pasar los estilos compartidos a una hoja externa.

<style>
  p { color: navy; }
</style>

Estas reglas solo se aplican a la página que contiene el bloque <style>.

La tercera posibilidad es el estilo en línea, escrito en el atributo style de una etiqueta. No lleva selector: las declaraciones afectan directamente a ese elemento. Aunque permite un cambio rápido, mezcla la presentación con el contenido y dificulta mantener los estilos, así que evítalo como forma habitual de maquetar y utiliza clases y reglas en una hoja externa. Sigue teniendo usos concretos, como ciertos correos HTML o los valores que JavaScript cambia durante la interacción.

<p style="color: navy;">Texto de ejemplo</p>

El párrafo se muestra en azul marino sin ninguna regla en la hoja de estilos: la declaración está en su propio atributo style.

1.2. Anatomía de una regla

Una regla CSS combina un selector y un bloque de declaraciones. El selector localiza elementos del documento; cada declaración asigna un valor a una propiedad.

Los comentarios se escriben entre /* y */ y pueden ocupar varias líneas. Úsalos para separar bloques de la hoja (reset, base, componentes) y para explicar decisiones que no se deducen del código.

1.3. Cascada

Un mismo elemento puede recibir declaraciones de distintas reglas. La cascada es el proceso que resuelve esos conflictos y determina el valor que se aplica a cada propiedad. El navegador considera, entre otros factores, el origen de los estilos, su importancia, las capas de cascada y la especificidad de los selectores. Cuando las declaraciones empatan en todos esos criterios, gana la que aparece después.

Por eso escribir una regla al final no garantiza que prevalezca: el orden de aparición solo resuelve el empate, no sustituye a los demás criterios.

/* Ambas reglas tienen el mismo origen, importancia y especificidad. */
p { color: navy; }
p { color: teal; } /* Esta declaración aparece después y gana. */

Las dos reglas empatan en origen, importancia y especificidad, así que gana la última: los párrafos se muestran en color verde azulado.

Ampliación

Capas de cascada con @layer

Las capas permiten ordenar grupos de estilos completos (reset, base, componentes…) antes de comparar la especificidad. Es útil cuando el proyecto crece o se combinan estilos de terceros.

/* Se declara el orden: la última capa tiene más prioridad. */
@layer reset, base, componentes;

@layer base {
  #principal a { color: navy; }   /* especificidad alta, pero capa anterior */
}
@layer componentes {
  .boton { color: white; }        /* gana: está en una capa posterior */
}

Un enlace con id="principal" en su contenedor y clase boton será blanco: entre capas, el orden de las capas se decide antes que la especificidad. Los estilos escritos fuera de cualquier capa tienen prioridad sobre todos los que están dentro de capas. Con !important el orden se invierte: las declaraciones importantes de las primeras capas ganan.

Los estilos que escribes fuera de cualquier bloque @layer se agrupan en una capa anónima implícita que tiene la máxima prioridad por encima de todas las capas nombradas (excepto si usas !important). Esto te permite hacer ajustes rápidos de emergencia sin romper toda la arquitectura de capas.

1.4. Herencia

La herencia permite que ciertas propiedades pasen de un elemento a sus descendientes cuando estos no tienen un valor propio que las sustituya. Propiedades como color y font-family se heredan por defecto; otras, como margin, padding y border, no.

Una declaración propia del elemento siempre sustituye al valor heredado. Y, al revés, la palabra clave inherit permite pedir explícitamente el valor del padre, incluso en propiedades que no se heredan por defecto.

<article class="noticia">
  <p>Este texto hereda el color y la fuente del artículo.</p>
</article>

.noticia {
  color: navy;
  font-family: sans-serif;
  border: 1px solid navy;
}

El párrafo hereda el color y la fuente del artículo, pero no recibe su borde. Si añadimos .noticia p { color: teal; }, el párrafo utiliza esa declaración en lugar del valor heredado.

1.5. Especificidad

La especificidad es el peso de un selector y ayuda a resolver qué declaración gana cuando corresponde comparar selectores dentro de la cascada. Se comparan tres grupos en este orden: identificadores; clases, atributos y pseudoclases; y tipos de elemento y pseudoelementos.

  • #aviso: un identificador → 1-0-0.
  • .destacado: una clase → 0-1-0.
  • p: un tipo de elemento → 0-0-1.

Aplica los tres selectores al mismo párrafo. Antes de abrirlo en el navegador, predice qué color tendrá.

<p id="aviso" class="destacado">Información importante</p>

#aviso { color: navy; }      /* 1-0-0 */
.destacado { color: teal; }  /* 0-1-0 */
p { color: maroon; }        /* 0-0-1 */

Si estas reglas son declaraciones normales del autor en la misma capa, gana #aviso, aunque esté escrito antes.

La comparación se hace por grupos, de izquierda a derecha: no se suman como si fueran un número decimal. El selector universal * y los combinadores, como >, no añaden especificidad. !important modifica la importancia de una declaración, no la especificidad de su selector.

Ampliación

Valores globales de las propiedades

Además de los valores propios de cada propiedad, CSS ofrece palabras clave comunes para decidir de dónde debe proceder su valor. Nos permiten heredar el del padre, recuperar el valor inicial o dejar que intervengan otras reglas de la cascada.

1.6. ¿Qué hace !important?

Da prioridad a una declaración frente a las declaraciones normales del mismo origen. Se escribe después del valor y no aumenta la especificidad.

<p id="aviso">Hola</p>

/* CSS */
#aviso { color: blue; }
p { color: red !important; }

El texto será rojo: la declaración importante vence a la normal, aunque esta use un selector con ID.

Cuando añadir !important no cambia el resultado

!important solo decide entre declaraciones de distinta importancia. Si las dos declaraciones en conflicto son importantes, la cascada vuelve a sus criterios habituales: gana la de mayor especificidad y, si empatan, la última.

Para el mismo párrafo, prueba estos dos casos por separado, en la misma hoja y sin capas:

/* Antes: el texto es azul. */
#aviso { color: blue !important; }
p { color: red; }

/* Después: sigue siendo azul. */
#aviso { color: blue !important; }
p { color: red !important; }

En el segundo caso, ambas declaraciones son importantes. Gana #aviso por su mayor especificidad: 1-0-0 frente a 0-0-1 de p. Añadir !important no cambia esos valores, aunque la regla de p esté escrita después.

No abuses de él: dificulta cambiar los estilos después. Primero revisa los selectores y su orden. Resérvalo para excepciones justificadas.

1.7. Propiedades abreviadas (shorthands)

Una propiedad abreviada (shorthand) permite definir varias propiedades relacionadas en una sola declaración. Por ejemplo, con border puedes dibujar un borde en los cuatro lados de una caja.

/* Sin abreviar el grosor, el estilo y el color */
.caja {
  border-width: 2px;
  border-style: solid;
  border-color: blue;
}

/* Con la propiedad abreviada */
.caja {
  border: 2px solid blue;
}

Ambas reglas dibujan el mismo borde. Lee los valores de la segunda de izquierda a derecha. 2px indica el grosor, solid dibuja una línea continua y blue le da color azul. Si después solo quieres cambiar el color, basta con escribir border-color: red;.

A lo largo de la unidad encontrarás tarjetas Shorthand con la abreviatura de cada grupo de propiedades. Recuerda que una abreviatura restablece los valores que no escribes.

1.8. Legibilidad del código

El navegador entiende igual una hoja ordenada que una escrita en una sola línea, pero las personas no. Una hoja CSS se lee muchas más veces de las que se escribe: la revisarás tú dentro de unas semanas, la corregirá el profesorado y, en un equipo, la ampliarán otras personas. Escribir código legible es parte del trabajo, no un adorno.

Indentación y formato

Sigue siempre el mismo formato. Estas convenciones son las más extendidas y las que aplican de forma automática los formateadores como Prettier:

  • Una declaración por línea, con dos espacios de indentación dentro de las llaves.
  • Un espacio después de los dos puntos y un punto y coma al final de cada declaración, también de la última.
  • La llave de apertura en la línea del selector y la de cierre sola, alineada con el selector.
  • Una línea en blanco entre reglas; si agrupas varios selectores, uno por línea.
  • Minúsculas en propiedades, valores y colores hexadecimales.

Comentarios y orden de la hoja

Los comentarios (/* … */) sirven para dos cosas: separar bloques de la hoja y explicar decisiones que no se deducen del código. No repitas lo que ya dice la declaración.

Una hoja dividida en bloques mediante comentarios de sección:

/* ==========================================================
   1. Variables (tokens de diseño)
   ========================================================== */
:root {
  --color-marca: #6d28d9;
  --espacio: 1rem;
}

/* ==========================================================
   2. Base: estilos de elementos HTML
   ========================================================== */
body {
  font-family: system-ui, sans-serif;
  line-height: 1.6;
}

/* ==========================================================
   3. Componentes
   ========================================================== */
.tarjeta {
  padding: var(--espacio);
  /* min-width: 0 evita que un nombre largo desborde la rejilla. */
  min-width: 0;
}

Ordena la hoja de lo general a lo particular: variables, reset y estilos base, después componentes y, al final, utilidades y consultas de medios. Ese orden coincide con el de la cascada: las reglas más concretas quedan después y pueden ajustar a las generales sin recurrir a !important.

Un comentario útil explica el porqué
  • Inútil: /* color rojo */ encima de color: red;.
  • Útil: /* El rojo de marca no alcanza 4,5:1 sobre crema: usamos uno más oscuro. */

Nombres de clases: kebab-case

En CSS los nombres de clases y variables se escriben en kebab-case: todo en minúsculas y las palabras separadas por guiones, como las propias propiedades (background-color, font-size). Las clases distinguen mayúsculas de minúsculas: .Tarjeta y .tarjeta son clases distintas, así que una regla fija evita errores difíciles de encontrar.

Metodología BEM

BEM (Block, Element, Modifier) es una convención para nombrar clases que hace visible la estructura de cada componente en el propio nombre:

Marca como agotado un producto de Migas Amigas. En el HTML, identifica la clase que representa la tarjeta, las de sus elementos y la que indica su estado.

<article class="producto producto--agotado">
  <img class="producto__foto" src="hogaza.jpg" alt="Hogaza de masa madre">
  <h3 class="producto__nombre">Hogaza de masa madre</h3>
  <p class="producto__precio">3,20 €</p>
  <button class="producto__boton" type="button" disabled>Agotado</button>
</article>

Ventajas que se notan pronto:

  • Especificidad baja y uniforme: casi todas las reglas usan una sola clase (0-1-0), así que los conflictos se resuelven con el orden y no con selectores cada vez más largos (1.5).
  • Independencia del HTML: .producto__precio funciona aunque cambies la etiqueta o lo muevas dentro de la tarjeta, cosa que no ocurre con .producto div p.
  • Lectura inmediata: al ver la clase sabes a qué componente pertenece y qué papel tiene.

Error frecuente

No encadenes elementos

Un elemento pertenece al bloque, no a otro elemento: escribe .producto__boton, no .producto__pie__boton. Si una parte crece y se reutiliza fuera del bloque, conviértela en un bloque nuevo. Y no uses un modificador sin la clase base: class="producto--agotado" sola pierde todos los estilos de .producto.

Atomic Design en tu hoja de estilos

En la UD01 estudiaste Atomic Design como forma de pensar una interfaz a partir de piezas pequeñas. En CSS se traduce en una organización de la hoja y de los nombres: cada nivel se apoya en el anterior y cada componente BEM ocupa un nivel.

css/
├── tokens.css        /* variables de la guía de estilo */
├── base.css          /* reset y estilos de elementos HTML */
├── atomos.css        /* .boton, .campo, .etiqueta */
├── moleculas.css     /* .buscador, .precio */

Esa organización puede repartirse en varios archivos, uno por nivel, o, en proyectos pequeños, en una sola hoja dividida con comentarios. Lo importante es que los átomos no dependan de dónde se colocan: un .boton debe verse igual en la cabecera que dentro de una tarjeta.

2. Selectores

El selector es la parte de la regla que decide a qué elementos se aplican las declaraciones. Empezaremos por los selectores simples y después combinaremos condiciones, estados y partes de un elemento. El objetivo es seleccionar con precisión sin añadir clases innecesarias ni crear reglas difíciles de mantener.

2.1. Selectores básicos

2.3. Selectores de atributo

Los corchetes permiten seleccionar por la presencia de un atributo o por su valor. Son útiles para distinguir campos de formulario y tipos de enlace.

Selectores de atributo aplicados a campos de formulario y enlaces:

/* Elementos que tienen el atributo required. */
[required] { border-left: 3px solid #b45309; }

/* Campos cuyo tipo es exactamente email. */
input[type="email"] { background-color: #eff6ff; }

/* Enlaces cuyo href empieza por https://. */
a[href^="https://"] { text-decoration: underline; }

/* Enlaces cuyo href termina en .pdf. */
a[href$=".pdf"] { font-weight: bold; }

/* Enlaces cuyo href contiene /recursos/. */
a[href*="/recursos/"] { color: #0f766e; }

= compara el valor completo; ^=, su comienzo; $=, su final; y *=, una parte del valor. Estos selectores comparan el atributo: [href$=".pdf"] no coincidirá con un enlace que termine en .pdf?descarga=1.

2.4. Agrupar y combinar condiciones

La coma permite compartir declaraciones entre varios selectores. En cambio, escribir selectores juntos y sin espacio exige que un mismo elemento cumpla todas esas condiciones.

/* Selecciona todos los h1 y todos los h2. */
h1, h2 { color: #1e3a8a; }

/* Solo los párrafos que tengan la clase destacado. */
p.destacado { font-weight: bold; }

/* Elementos que tengan las dos clases. */
.tarjeta.destacado { border: 2px solid #0f766e; }

Fíjate en el espacio: p.destacado selecciona un párrafo con esa clase; p .destacado selecciona un elemento con esa clase que esté dentro de un párrafo. Esta segunda forma utiliza una relación de descendencia.

Agrupar con :is()

:is() selecciona los elementos que coincidan con cualquiera de los selectores entre paréntesis. Permite agrupar alternativas sin repetir la parte común.

/* Sin :is(): repetimos .tarjeta. */
.tarjeta h2,
.tarjeta h3 {
  color: #1e3a8a;
}

/* Con :is(): seleccionamos los mismos elementos. */
.tarjeta :is(h2, h3) {
  color: #1e3a8a;
}

Ambas reglas seleccionan los h2 y h3 que estén dentro de .tarjeta.

Especificidad: :is() toma la del selector más específico de su lista. Por ejemplo, :is(.aviso, #principal) aporta el peso de un ID, incluso cuando coincide por la clase. Evita mezclar IDs y clases sin necesitarlo.

Ampliación

CSS nesting: anidar reglas relacionadas

La anidación permite escribir los estilos de un componente dentro de su regla, evitando repetir el selector. Es CSS nativo: el navegador lo interpreta sin Sass ni compilación.

.tarjeta {
  padding: 1rem;
  border: 2px solid #6d28d9;

  & h3 {
    color: #6d28d9;
  }

  &:hover {
    border-color: #4c1d95;
  }
}

/* Equivalente sin anidación: */
.tarjeta { padding: 1rem; border: 2px solid #6d28d9; }
.tarjeta h3 { color: #6d28d9; }
.tarjeta:hover { border-color: #4c1d95; }

& representa el selector de la regla exterior. & h3 selecciona sus encabezados descendientes; &:hover, la propia tarjeta al pasar el puntero. El espacio cambia el significado.

Mantén pocos niveles para facilitar la lectura. La especificidad de & se calcula como en :is(): una lista que mezcle una clase y un ID toma la especificidad mayor. No concatena nombres: &__titulo no sirve para formar .tarjeta__titulo.

4.2. Espaciado con padding y margin

Piensa en dos tarjetas de productos. Si el precio queda pegado al borde de su tarjeta, aumenta el padding: aparecerá espacio entre el texto y el borde, y el fondo de la tarjeta cubrirá esa zona. Si las dos tarjetas se tocan, ajusta el margin: el espacio quedará fuera del borde y se verá el fondo del contenedor.

Los lados físicos, como padding-left, siempre se refieren al mismo borde. Si quieres que el espacio siga la dirección de lectura, usa padding-inline-start: en escritura horizontal añade relleno a la izquierda en español y a la derecha en árabe.

Abreviar el espaciado con padding y margin

Qué agrupa: padding reúne padding-top, padding-right, padding-bottom y padding-left, el relleno interior. margin reúne los cuatro márgenes exteriores equivalentes.

Orden de los valores: de uno a cuatro, en el sentido de las agujas del reloj: arriba → derecha → abajo → izquierda. Con un valor se repiten los cuatro lados; con dos, se reparten entre el eje vertical y el horizontal; con tres, los laterales comparten el segundo valor.

4.3. Uso de «auto»

¿Qué calcula el navegador cuando escribes auto? Depende de la propiedad. Compara estos casos en un bloque de texto en flujo normal y con escritura horizontal.

4.4. Colapso de márgenes y márgenes negativos

En el flujo normal, los márgenes verticales de dos bloques consecutivos pueden colapsar: en lugar de sumarse, se aplica el mayor.

.titulo  { margin-bottom: 24px; }
.parrafo { margin-top: 16px; }
/* Separación real entre ambos: 24 px, no 40 px. */

El título deja 24 px debajo y el párrafo pide 16 px encima. Como los márgenes colapsan, la separación entre ambos es de 24 px, no de 40.

El colapso no ocurre con los márgenes horizontales ni entre elementos de Flexbox o Grid. Si necesitas una separación que siempre se sume, usa padding en el contenedor o gap en una distribución.

El margen superior del primer hijo también puede colapsar con el de su padre cuando nada los separa, como un borde o un relleno. Si buscas distancia entre el texto y el borde de una tarjeta, usa relleno en la tarjeta.

Un margen negativo reduce la separación entre cajas y puede hacer que se solapen. Si utilizas este efecto, comprueba que el contenido siga siendo legible.

Dos bloques consecutivos en el flujo normal: el primero deja 24 px debajo y el segundo tiene un margen superior de −8 px. Entre ambos quedan 16 px.

.primero { margin-bottom: 24px; }
.segundo { margin-top: -8px; }

Cambia el segundo margen a -32px. Ahora las cajas se solapan 8 px. Comprueba que el contenido siga siendo legible si utilizas este efecto.

4.5. Box model reset y CSS Reset

En el apartado 4.1 ya hemos definido el ancho de una caja con width y su altura con height. Ahora vamos a decidir para toda la página si esas medidas incluyen el padding y el borde.

Un reset es un pequeño conjunto de reglas que se coloca al principio de la hoja para partir de una base común en todos los navegadores. La regla más habitual cambia el modelo de caja de todos los elementos, y de sus pseudoelementos ::before y ::after, a border-box, para que el relleno y el borde queden incluidos en el tamaño indicado.

Si dos tarjetas tienen el mismo ancho declarado pero distinto relleno, sus bordes pueden quedar desalineados. Aplica esta regla y vuelve a medir sus anchos exteriores.

*, *::before, *::after {
  box-sizing: border-box;
}

El selector universal * aplica border-box a todos los elementos, y *::before y *::after, a sus pseudoelementos.

Por ejemplo, con width: 100% y padding: 20px:

  • Con content-box: la caja ocupa el 100% del ancho del contenedor más 40 px de relleno y puede desbordarse.
  • Con border-box: esos 40 px quedan dentro del 100%; se reduce el espacio para el contenido.

Así resulta más sencillo controlar el tamaño de las cajas al maquetar.

5. Fondos, bordes y sombras

Con la caja ya definida, decidimos cómo se pinta: qué hay detrás del contenido, cómo se delimita la caja y qué profundidad sugiere. Ninguno de estos recursos debe ser el único portador de información.

5.1. Fondos e imágenes de fondo

Si el fondo es transparente, se ve el del elemento que queda detrás. Cada caja conserva su propio color de fondo.

El fondo decora una caja y no determina su tamaño. Reserva el espacio mediante contenido, relleno o dimensiones. Si la imagen transmite información, utiliza HTML con <img> y un texto alternativo adecuado.

background-size decide la escala de la imagen: cover llena toda la caja aunque recorte parte de la foto, y contain la muestra entera aunque deje zonas con el color de base. background-position decide qué parte queda visible.

Una foto horizontal como fondo de una caja cuadrada:

.cabecera {
  aspect-ratio: 1;
  background-color: #172033;
  background-image: url("foto-horizontal.jpg");
  background-repeat: no-repeat;
  background-size: cover;
  background-position: center;
}

Alterna cover y contain y observa cuándo aparece el color de base. Cambia después background-position para recuperar otros detalles de la foto.

background-origin decide desde qué caja se coloca la imagen; background-clip decide hasta dónde se pinta. Si solo quieres cambiar el color, usa background-color.

Shorthand

Abreviar los fondos con background

Qué agrupa: background-color, background-image, background-position, background-size, background-repeat, background-attachment, background-origin y background-clip.

Orden de los valores: casi libre, con tres reglas: el tamaño va justo después de la posición, separado por /; el color solo puede aparecer en la última capa; y las capas se separan con comas, de modo que la primera se dibuja encima. Una palabra de caja, como padding-box, fija origen y recorte; con dos, la primera es background-origin y la segunda, background-clip.

Equivalencia: las dos reglas producen el mismo resultado, con los demás componentes en su valor inicial.

.portada {
  background-color: #fff4cc;
  background-image: url("imagenes/pan.jpg");
  background-position: center;
  background-size: cover;
  background-repeat: no-repeat;
}
/* Equivale a: */
.portada {
  background: #fff4cc url("imagenes/pan.jpg") center / cover no-repeat;
}

/* Dos capas: el gradiente queda encima de la foto */
.portada {
  background:
    linear-gradient(rgb(0 0 0 / 50%), rgb(0 0 0 / 50%)),
    #fff4cc url("imagenes/pan.jpg") center / cover no-repeat;

Cuidado: lo que omites se restablece. background: white también elimina la imagen anterior; para cambiar solo el color y conservarla, utiliza background-color: white. Del mismo modo, para mover la imagen en un solo eje usa background-position-x o background-position-y.

5.2. Bordes, redondeo de esquinas y sombras

El borde delimita la caja y ocupa espacio; la sombra se dibuja alrededor o dentro de ella sin reservar espacio en la distribución. Empezaremos por un borde sencillo, esquinas redondeadas y una única sombra.

Dibuja una tarjeta con un borde redondeado y una sombra exterior. Desactiva la sombra en el inspector y comprueba si cambia el espacio que ocupa la tarjeta.

.tarjeta {
  padding: 1rem;
  border: 2px solid #1e3a8a;
  border-radius: .5rem;
  box-shadow: 0 4px 12px rgb(0 0 0 / .15);
}

En esa sombra, 0 es el desplazamiento horizontal, 4px el vertical y 12px el desenfoque. El color es negro con un 15 % de opacidad. Cambia un valor cada vez para observar su efecto.

Cómo elegir el borde, el contorno y la sombra

El borde delimita una caja y forma parte de su tamaño. La sombra añade profundidad visual sin reservar espacio en el diseño. Un contorno outline tampoco ocupa espacio y resulta útil para señalar el foco de teclado.

Grosor, estilo y color del borde

La declaración border: 2px solid #1e3a8a aplica esos tres componentes a los cuatro lados. Si no indicas un estilo visible, el borde no aparecerá aunque hayas elegido grosor y color.

Para cambiar solo el color del borde superior, usa border-top-color. Para definir varios lados a la vez, consulta la tarjeta de bordes.

Redondeo de esquinas con border-radius

Para suavizar las cuatro esquinas de una tarjeta, aplica un único radio. Con border-radius: 0 quedan rectas. Con border-radius: 1rem la curva se aprecia incluso si la tarjeta solo tiene color de fondo. Su ancho y su alto se mantienen.

Cada esquina tiene su propio radio. Por ejemplo, border-top-left-radius: 12px redondea solo la superior izquierda. Las otras tres son border-top-right-radius, border-bottom-right-radius y border-bottom-left-radius.

El redondeo del padre no recorta automáticamente su contenido: una imagen con esquinas rectas puede sobresalir de una tarjeta redondeada.

Compara tres formas. En el avatar cuadrado, el 50 % produce un círculo. En la tarjeta, los cuatro radios se leen desde la esquina superior izquierda en sentido horario. En la elipse, la barra separa los radios horizontales de los verticales.

.avatar {
  width: 5rem;
  height: 5rem;
  border-radius: 50%;
}
.tarjeta { border-radius: 1rem 1rem 0 0; }
.elipse { border-radius: 50% / 30%; }

Sombras de caja

En box-shadow, los dos primeros números, los desplazamientos horizontal y vertical, son obligatorios; el desenfoque y la expansión son opcionales. Se pueden superponer varias sombras separándolas con comas: combinar una sombra corta y otra amplia suele resultar más natural que una sola.

Compara la sombra exterior de una tarjeta con la sombra interior de un campo. Después usa Tab para observar el contorno del botón cuando recibe el foco.

.tarjeta {
  border: 1px solid #cbd5e1;
  border-radius: .75rem;
  box-shadow: 0 4px 12px rgb(15 23 42 / .15);
}
.campo { box-shadow: inset 0 2px 4px rgb(0 0 0 / .15); }
.boton:focus-visible {
  outline: 3px solid #1e3a8a;
  outline-offset: 3px;
}

Cambia cada valor por separado. Prueba también box-shadow: 0 1px 3px #0004, 0 8px 20px #0002 y elimina una de las dos sombras: la primera marca el borde cercano y la segunda añade una sombra más amplia.

Una sombra exterior puede quedar recortada por un contenedor con overflow: hidden. Evita cambiar el grosor del borde en :hover si eso desplaza el contenido; puedes reservarlo desde el principio con un borde transparente.

Alinear, separar y decorar el texto

Con la fuente elegida, otras propiedades ajustan cómo se coloca el texto dentro de su bloque: alineación, sangría, separación entre letras y palabras, cambios de mayúsculas y decoraciones como el subrayado.

Usa start para seguir la dirección de escritura. Justificar párrafos estrechos puede producir huecos incómodos. No elimines el subrayado de los enlaces sin otra señal clara.

Una base tipográfica para el cuerpo de una página:

body {
  font-family: system-ui, sans-serif;
  font-size: 1rem;
  line-height: 1.6;
  color: #172033;
}
.articulo { max-width: 65ch; margin-inline: auto; }
h1 { font-size: clamp(2rem, 1.5rem + 2vw, 3.5rem); line-height: 1.15; }
h2 { font-size: 1.5rem; }
p { margin-block: 0 1em; }
a { text-underline-offset: .2em; }

El interlineado sin unidad se hereda como factor, el título escala con la ventana entre 2 y 3,5 rem y el subrayado de los enlaces se separa un poco del texto para facilitar la lectura.

Shorthand

Abreviar la tipografía con font, text-decoration y font-variant
font

Qué agrupa: font-style, font-variant, font-weight, font-stretch, font-size, line-height y font-family.

Orden de los valores: los opcionales (estilo, variante, peso y anchura) van antes del tamaño; el interlineado, justo después, tras /; la familia, al final. El tamaño y la familia son obligatorios.

Equivalencia: las dos reglas producen el mismo resultado, con las demás opciones de fuente en su valor inicial.

.entradilla {
  font-style: italic;
  font-weight: 600;
  font-size: 1.125rem;
  line-height: 1.6;
  font-family: system-ui, sans-serif;
}
/* Equivale a: */
.entradilla { font: italic 600 1.125rem/1.6 system-ui, sans-serif; }

Cuidado: lo omitido se restablece: font: 1rem system-ui elimina una negrita o cursiva anterior y devuelve el interlineado a normal. No incluye color, text-align ni letter-spacing, y no carga fuentes: para eso se utiliza @font-face.

text-decoration

Qué agrupa: text-decoration-line, text-decoration-style, text-decoration-color y text-decoration-thickness.

Orden de los valores: en cualquier orden. Sin un tipo de línea, como underline, no se dibuja nada.

Equivalencia: las dos reglas producen el mismo resultado.

a { text-decoration: underline solid #6d28d9 .1em; }
/* Equivale a: */
a {
  text-decoration-line: underline;
  text-decoration-style: solid;
  text-decoration-color: #6d28d9;
  text-decoration-thickness: .1em;
}

Cuidado: text-underline-offset queda fuera de la abreviatura y se escribe aparte.

font-variant

Qué agrupa: las variantes tipográficas, como font-variant-caps (mayúsculas) o font-variant-numeric (cifras).

Orden de los valores: una o varias palabras clave, en cualquier orden.

Equivalencia: en este caso, las dos reglas producen el mismo resultado.

.titular { font-variant: small-caps; }
/* Equivale a: */
.titular { font-variant-caps: small-caps; }

Cuidado: font-variant: small-caps activa versalitas y restablece las demás variantes. Si solo quieres cambiar las mayúsculas, usa font-variant-caps.

6.2. Cargar una fuente propia con @font-face

Si queremos utilizar una fuente que no tiene por qué estar instalada en el equipo del usuario, podemos proporcionar su archivo con @font-face. Esta regla registra una fuente con un nombre; después debemos aplicar ese mismo nombre mediante font-family.

/* En css/estilos.css; el archivo está en la carpeta fuentes. */
@font-face {
  font-family: "Mi Fuente";
  src: url("../fuentes/mi-fuente-regular.woff2") format("woff2");
  font-weight: 400;
  font-style: normal;
  font-display: swap;
}

body {
  font-family: "Mi Fuente", system-ui, sans-serif;
}

Sustituye la ruta de ejemplo por un archivo WOFF2 real que tengas permiso para utilizar en la web. font-display: swap muestra el texto con la fuente de reserva mientras se descarga la propia.

7. Flujo normal y display

Hasta ahora has dado forma a cada caja: tamaño, relleno, bordes, color y texto. Falta decidir dónde se coloca. El punto de partida es el flujo normal: sin CSS de distribución, los bloques se apilan uno debajo de otro y los elementos en línea se colocan uno tras otro dentro de las líneas de texto. En este apartado y en los dos siguientes verás cómo lo modifican display, float y position.

display determina cómo participa la caja en el flujo. Por defecto, un párrafo empieza en una línea nueva y un enlace puede compartir línea con el texto. Cambiar su presentación conserva el significado del elemento HTML.

Ampliación

Otros valores de display

Los valores display: flex y display: inline-flex crean un contenedor flexible.

  • flow-root crea un contexto de formato de bloque que contiene a sus hijos flotantes.
  • contents elimina la caja del elemento y deja participar a sus hijos. No lo uses como sustituto general de un contenedor: comprueba su efecto en la accesibilidad y en los estilos del propio elemento.
Elementos de lista
  • display: list-item: genera una caja de bloque principal y una caja de marcador, que puede mostrar una viñeta o un número según list-style.
Comportamientos de tabla (CSS)
  • display: table: hace que el elemento se comporte visualmente como un <table>.
  • display: table-row: hace que el elemento se comporte visualmente como un <tr>.
  • display: table-cell: hace que el elemento se comporte visualmente como un <td>.

Estos valores cambian la presentación, no la semántica HTML. Para listas utiliza ul u ol con li; para datos tabulares, una tabla HTML con sus encabezados.

7.2. Ocultar elementos

Hay varias formas de ocultar un elemento y no producen el mismo resultado: unas retiran la caja del diseño y otras solo la vuelven invisible, conservando su espacio o incluso su interacción. Antes de elegir, decide si el elemento debe seguir ocupando sitio y si debe seguir siendo accesible.

Curiosidad

Ocultar no siempre significa lo mismo
  • display: none elimina las cajas del elemento y sus descendientes del diseño y, normalmente, del árbol de accesibilidad. No conserva su espacio. El HTML permanece en el DOM.
  • visibility: hidden oculta el elemento conservando su espacio. El valor inicial es visible. En filas y columnas de tabla, collapse también permite retirar el espacio que ocupan.
  • opacity: 0 lo hace transparente, pero conserva su espacio y puede mantener clics y foco. No basta por sí solo para ocultar un control interactivo.

8. Flotantes: texto alrededor de una imagen

Hoy float tiene un uso concreto: que el texto rodee una imagen, como en una noticia o una receta. Para colocar columnas o centrar componentes se usan Flexbox y Grid.

float lleva una caja a un lado de su contenedor y permite que las líneas de texto fluyan a su alrededor. Admite left y right; none desactiva la flotación. No existe float: center: los flotantes no se diseñaron para centrar cajas.

Queremos colocar una foto de pan a la izquierda y que la descripción la rodee. Partimos de esta noticia:

<article class="noticia">
  <img src="hogaza.jpg" alt="Hogaza de pan de masa madre">
  <p>Hoy horneamos pan de centeno con fermentación lenta.</p>
</article>

Aplica float: left a la imagen de la noticia del ejemplo anterior. Reduce el ancho de la ventana y observa cómo las líneas del párrafo rodean la foto.

.noticia { background: #dbeafe; }

  float: left;
  width: 8rem;
  height: auto;
  margin: 0 1rem .5rem 0;
}

Sustituye hogaza.jpg por una imagen disponible. Después acorta la descripción a una línea y observa dónde termina el fondo del artículo.

8.1. Empezar debajo del flotante

Un flotante sale del flujo normal, y un bloque ordinario no lo incluye por sí solo en su altura automática. Por eso, si el texto es más corto que la foto, el fondo del contenedor puede terminar antes que ella; si solo contiene flotantes, su altura de contenido puede ser cero.

Si un bloque posterior debe empezar debajo de la foto, se le aplica clear: both deja atrás los flotantes de ambos lados del mismo contexto, y left y right actúan solo sobre el lado indicado.

Añade a la noticia un párrafo de ingredientes con class="ingredientes" y aplica:

.ingredientes { clear: both; }

9.1. Indicar la posición

top, right, bottom y left indican distancias desde cada lado, e inset reúne las cuatro. Admiten auto, longitudes y porcentajes; con auto dejas ese lado sin fijar. Su referencia depende de position: con relative, la distancia se mide desde la posición original de la caja; con fixed, desde los bordes de la ventana.

/* Baja 12 px desde su lugar original; conserva el hueco. */
.aviso {
  position: relative;
  top: 12px;
}

/* Queda a 16 px de la esquina inferior derecha de la ventana. */
.ayuda {
  position: fixed;
  right: 16px;
  bottom: 16px;
}

Prueba right: 16px y bottom: 16px en el botón de ayuda y observa desde qué bordes se mide.

Shorthand

Abreviar top, right, bottom y left con inset

Qué agrupa: top, right, bottom y left. inset-inline e inset-block reúnen los dos extremos de un eje lógico.

Orden de los valores: de uno a cuatro, como en margin: arriba, derecha, abajo e izquierda. Con dos se agrupan vertical y horizontal; con tres, arriba, laterales y abajo. inset-inline e inset-block aceptan uno para ambos extremos o dos, para inicio y fin.

Equivalencia: las dos reglas producen el mismo resultado.

.etiqueta {
  position: absolute;
  inset: .5rem .5rem auto auto;
}
/* Equivale a: */
.etiqueta {
  position: absolute;
  top: .5rem;
  right: .5rem;
  bottom: auto;
  left: auto;
}

.capa { position: absolute; inset: 0; } /* Cubre todo su bloque contenedor */

Cuidado: al usar inset se sustituyen los cuatro desplazamientos anteriores. Solo tiene efecto en un elemento posicionado, y no cambia position ni z-index.

9.2. absolute: colocar una etiqueta dentro de una tarjeta

Una caja con position: absolute sale del flujo y se coloca respecto a su bloque contenedor: el antepasado más cercano con position distinto de static. Por eso se suele dar position: relative, sin desplazamiento, al elemento que debe servir de referencia. Sin ningún antepasado posicionado, absolute usa el bloque inicial del documento.

Coloca una insignia en la esquina de una tarjeta. Usa la tarjeta como referencia y observa qué ocurre al quitarle position: relative.

<div class="tarjeta">
  <span class="insignia">Nuevo</span>
  <p>Contenido de la tarjeta</p>
</div>

.tarjeta {
  position: relative;
  padding: 3rem 1rem 1rem;
}
.insignia {
  position: absolute;
  top: .5rem;
  right: .5rem;
}

La tarjeta sirve de referencia sin desplazarse. La etiqueta ocupa su esquina superior derecha, y el relleno superior de la tarjeta deja sitio para que no tape el texto.

9.3. sticky: mantener una navegación visible

Una caja con position: sticky se desplaza con el contenido hasta alcanzar un umbral, como top: 0. A partir de ahí queda adherida al borde de su zona de desplazamiento hasta llegar al límite de su contenedor. Necesita ese umbral y espacio para desplazarse. Revisa los antepasados con overflow: auto, scroll o hidden: pueden cambiar la zona de referencia.

Sitúa una navegación antes de varios párrafos que ocupen más de una pantalla. Desplázate y observa en qué momento su borde superior deja de subir.

.navegacion {
  position: sticky;
  top: 0;
  z-index: 10;
  background: white;
}

La navegación sube con la página hasta tocar el borde superior y allí se queda. z-index (9.4) y el fondo blanco evitan que el texto que pasa por debajo se vea a través de ella.

Un antepasado con transform distinto de none también puede convertirse en referencia para absolute y fixed; en este último caso, la caja deja de fijarse a la ventana.

9.4. Superposición: z-index

z-index admite auto o un entero y controla qué caja aparece delante al solaparse. Dentro del mismo contexto de apilamiento, un valor mayor se dibuja por encima. Los contextos agrupan elementos: un hijo no puede superar otra agrupación solo por tener un número enorme.

10. Proyecto de la unidad

El proyecto reúne todo lo trabajado: cascada, selectores, cajas, valores, decoración, tipografía y colocación de las cajas. Ve construyéndolo a medida que avances por los apartados.

Proyecto de la unidad

Proyecto UD02 · Artículo y sistema visual

Crea un artículo con título, dos subtítulos, tres párrafos, lista y tabla con encabezados. Define una paleta en :root, una escala tipográfica y dos fondos diferentes. Compara un fondo con canal alfa y un contenedor con opacity. Incluye el código y explica la diferencia observada. Verifica legibilidad al ampliar el texto.

Requisitos

  1. Organización: HTML semántico y una hoja externa css/estilos.css, enlazada después de un reset (4.5).
  2. Sistema visual: variables en :root para al menos tres colores, dos espacios y un radio. Ningún color de la paleta se repite escrito a mano.
  3. Tipografía: familia con alternativas y familia genérica final, escala en rem, interlineado sin unidad y ancho de lectura limitado (por ejemplo, max-width: 65ch) (6).
  4. Selectores: además de tipos y clases, utiliza al menos un combinador, un selector de atributo, una pseudoclase de estado y un pseudoelemento (2).
  5. Cajas: una tarjeta o nota destacada con relleno, borde, esquinas redondeadas y sombra; usa border-box (4, 5.2).
  6. Fondos: dos fondos distintos, uno con degradado; la comparación entre alfa y opacity debe verse en la página (3.2, 5.1).
  7. Tabla y enlaces: tabla legible con encabezados; enlaces con estados :hover y :focus-visible distinguibles sin depender solo del color.

Entrega

Carpeta comprimida con el HTML, el CSS comentado y los recursos, más un breve documento (o un comentario al inicio del CSS) que explique la diferencia entre alfa y opacity e indique una decisión de cascada o especificidad que hayas tenido que resolver.

Criterios de evaluación

  • El CSS es externo, está ordenado por bloques y no usa style en línea ni !important sin justificar.
  • Las variables se reutilizan de verdad y los cambios de paleta se hacen desde un único lugar.
  • El texto se lee bien al 200 % de zoom, sin solaparse ni desbordar.
  • Los contrastes de texto cumplen 4,5:1 y el foco de teclado es visible.
  • La explicación demuestra que entiendes qué regla gana y por qué.

11. Repaso

Intenta responder antes de desplegar cada pregunta.

¿Por qué conviene usar una hoja de estilos externa en lugar de estilos en línea?

Porque varias páginas comparten las mismas reglas y un cambio se hace en un solo archivo. Los estilos en línea mezclan presentación y contenido y obligan a modificar cada elemento.

Dos reglas dan color a un mismo párrafo: p { color: red; } y .aviso { color: blue; }. La primera está escrita después. ¿De qué color se ve un párrafo con clase aviso?

Azul. La clase tiene más especificidad (0-1-0) que el tipo (0-0-1); el orden de aparición solo decide cuando hay empate.

¿Qué propiedades se heredan normalmente: color, margin, font-family, border?

color y font-family. Las propiedades de caja, como margin y border, no se heredan.

¿Qué diferencia hay entre una pseudoclase y un pseudoelemento?

La pseudoclase (:hover, :focus-visible) selecciona un elemento según su estado o posición. El pseudoelemento (::before, ::first-line) permite estilizar una parte de un elemento.

¿Qué diferencia hay entre un margen y un relleno?

El relleno separa el contenido del borde; el margen separa la caja de su entorno.

Una caja tiene width: 300px, padding: 20px y un borde de 5 px. ¿Cuánto ocupa de ancho con content-box y con border-box?

Con content-box, 350 px (300 + 40 + 10). Con border-box, 300 px: el contenido se reduce a 250 px.

¿Cuándo usarías rem, % y px?

rem para texto y espacios que deben escalar con la preferencia de tamaño de letra; % para anchos que dependen del contenedor; px para detalles finos como bordes.

¿Por qué opacity: .5 en una tarjeta no es lo mismo que un fondo con alfa?

opacity atenúa toda la tarjeta, texto incluido. Un color con alfa en background-color solo hace transparente el fondo.

¿Qué hace overflow: auto?

Muestra barras de desplazamiento solo cuando el contenido no cabe en la caja.

¿Qué diferencia hay entre display: none y visibility: hidden?

display: none retira la caja del diseño y no conserva su espacio. visibility: hidden la oculta pero mantiene su hueco.

Un elemento tiene position: absolute. ¿Respecto a qué se coloca?

Respecto al antepasado posicionado más cercano (con position distinta de static). Si no hay ninguno, respecto al bloque contenedor inicial del documento.
