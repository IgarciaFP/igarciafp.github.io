De los selectores a la maquetación: construye interfaces legibles, flexibles y adaptables.

1. CSS Cascade Style Sheets

Al crear una página, HTML identifica el contenido y su estructura: un título, un párrafo, una lista o un enlace. El navegador ya les aplica una apariencia básica, pero necesitamos controlar cómo se muestran para construir nuestro diseño.

CSS permite definir esa presentación. Sus siglas significan Cascading Style Sheets (hojas de estilo en cascada). Con CSS elegimos colores, tipografías, tamaños, espacios y la distribución de los elementos.

Por ejemplo, HTML indica que un texto es un título mediante <h1>. CSS permite mostrarlo en azul, darle más tamaño y separarlo del párrafo siguiente. El contenido sigue siendo el mismo; cambia su presentación.

Separar ambas tareas facilita el trabajo:

  • Mantener la web: una hoja CSS compartida permite cambiar el aspecto de los títulos de todas las páginas desde un único archivo.
  • Conseguir coherencia: botones, menús y tarjetas pueden reutilizar los mismos estilos.
  • Adaptar el diseño: el mismo HTML puede mostrarse en una columna en el móvil y en varias en una pantalla grande.
  • Facilitar la lectura: podemos ajustar el contraste, el tamaño del texto y la separación entre elementos.

CSS aplica reglas a los elementos del HTML. Cuando varias reglas afectan al mismo elemento, el navegador necesita decidir cuáles usar. Por eso estudiaremos la cascada, la herencia y la especificidad. Primero veremos cómo incorporar esas reglas a una página.

¿Cuál es la primera hoja de estilo que se aplica a nuestro código HTML?

Antes de escribir CSS, piensa por qué un título aparece más grande que un párrafo y los enlaces suelen estar subrayados. Escribe tu hipótesis y compruébala: crea un HTML con un título, un párrafo, un enlace y una lista, sin incluir estilos propios. Abre el inspector y busca de dónde proceden sus estilos.

Comprobar la explicación

El navegador incorpora una hoja de estilos predeterminada, llamada hoja de estilos del agente de usuario (user agent stylesheet). Esa es la base que da aspecto al HTML aunque no hayamos escrito CSS: márgenes, tamaños de títulos, marcadores de listas y otros estilos iniciales.

Las reglas del autor se combinan con esa base mediante la cascada. Hablar de «primera» sirve para reconocer el punto de partida, pero el resultado no se decide solo por el orden de carga: también intervienen el origen, la importancia y los demás criterios que estudiaremos.

1.1. Formas de incluir CSS

Para aplicar estilos a una página, el navegador necesita saber dónde están escritas las reglas CSS. Podemos guardarlas en un archivo independiente, incluirlas en la cabecera del HTML o escribirlas directamente en un elemento. Las tres formas funcionan, pero la elección influye en lo fácil que será mantener la web.

Cuando construimos un sitio con varias páginas, lo más práctico es utilizar una hoja de estilos externa. Escribimos las reglas en un archivo, como estilos.css, y lo enlazamos desde la cabecera de cada página mediante <link>:

<!-- Dentro de head, en el archivo HTML -->
<link rel="stylesheet" href="css/estilos.css">

El atributo href indica la ruta del archivo. En este caso, el navegador buscará estilos.css dentro de la carpeta css. En ese archivo escribimos únicamente CSS, sin etiquetas <style>:

/* Archivo css/estilos.css */
p { color: navy; }

Si varias páginas enlazan esa misma hoja, todas compartirán sus estilos. Para cambiar el color de sus párrafos bastará con modificar una regla. Esta será la forma habitual de trabajar en nuestras prácticas.

También podemos escribir CSS en el propio documento, dentro de una etiqueta <style> situada en <head>. Es una hoja de estilos interna: resulta cómoda para probar una idea o preparar un ejemplo en un solo archivo.

<style>
  p { color: navy; }
</style>

Estas reglas se aplican a esa página. Si copiamos el bloque en varios documentos, después tendremos que modificarlos uno a uno; por eso conviene pasar los estilos compartidos a una hoja externa.

La tercera posibilidad es el estilo en línea, escrito en el atributo style de una etiqueta. Aquí no indicamos un selector: las declaraciones afectan directamente a ese elemento.

<p style="color: navy;">Texto de ejemplo</p>

Aunque permite un cambio rápido, repetir atributos style mezcla la presentación con el contenido y dificulta mantener los estilos. Evítalo como forma habitual de maquetar: utiliza clases y reglas en una hoja externa. Sigue teniendo usos concretos, como ciertos correos HTML o valores que JavaScript cambia durante la interacción.

1.2. Cascada

Un mismo elemento puede recibir declaraciones de distintas reglas. La cascada es el proceso que resuelve esos conflictos y determina el valor que se aplica a cada propiedad. El navegador considera, entre otros factores, el origen de los estilos, su importancia, las capas de cascada y la especificidad de los selectores. Cuando las declaraciones empatan en los criterios anteriores, gana la que aparece después.

/* Ambas reglas tienen el mismo origen, importancia y especificidad. */
p { color: navy; }
p { color: teal; } /* Esta declaración aparece después y gana. */

En este ejemplo, los párrafos se muestran en color verde azulado. Escribir una regla al final no garantiza que siempre prevalezca: el orden de aparición resuelve el empate, pero no sustituye a los demás criterios de la cascada.

1.3. Herencia

La herencia permite que ciertas propiedades pasen de un elemento a sus descendientes cuando estos no tienen un valor propio que las sustituya. Propiedades como color y font-family se heredan por defecto; otras, como margin, padding y border, no.

<article class="noticia">
  <p>Este texto hereda el color y la fuente del artículo.</p>
</article>

.noticia {
  color: navy;
  font-family: sans-serif;
  border: 1px solid navy;
}

El párrafo hereda el color y la fuente, pero no recibe un borde propio. Si añadimos .noticia p { color: teal; }, el párrafo utiliza su declaración de color en lugar del valor heredado. La palabra clave inherit permite pedir explícitamente el valor del padre, incluso en propiedades que no se heredan por defecto.

1.4. Especifidad

La especificidad es el peso de un selector y ayuda a resolver qué declaración gana cuando corresponde comparar selectores dentro de la cascada. Se comparan tres grupos en este orden: identificadores; clases, atributos y pseudoclases; y tipos de elemento y pseudoelementos.

  • #aviso: un identificador → 1-0-0.
  • .destacado: una clase → 0-1-0.
  • p: un tipo de elemento → 0-0-1.
<p id="aviso" class="destacado">Información importante</p>

#aviso { color: navy; }      /* 1-0-0 */
.destacado { color: teal; }  /* 0-1-0 */
p { color: maroon; }        /* 0-0-1 */

Si estas reglas son declaraciones normales del autor en la misma capa, gana #aviso, aunque esté escrito antes. La comparación se hace por grupos, de izquierda a derecha: no se suman como si fueran un número decimal. El selector universal * y los combinadores, como >, no añaden especificidad. !important modifica la importancia de una declaración, no la especificidad de su selector.

Ampliación

¿Qué hace !important?

Da prioridad a una declaración frente a las declaraciones normales del mismo origen. Se escribe después del valor y no aumenta la especificidad.

<p id="aviso">Hola</p>

/* CSS */
#aviso { color: blue; }
p { color: red !important; }

El texto será rojo: la declaración importante vence a la normal, aunque esta use un selector con ID.

Cuando añadir !important no cambia el resultado

Para el mismo párrafo, prueba estos dos casos por separado, en la misma hoja y sin capas:

/* Antes: el texto es azul. */
#aviso { color: blue !important; }
p { color: red; }

/* Después: sigue siendo azul. */
#aviso { color: blue !important; }
p { color: red !important; }

En el segundo caso, ambas declaraciones son importantes. Gana #aviso por su mayor especificidad: 1-0-0 frente a 0-0-1 de p. Añadir !important no cambia esos valores, aunque la regla de p esté escrita después.

No abuses de él: dificulta cambiar los estilos después. Primero revisa los selectores y su orden. Resérvalo para excepciones justificadas.

2. Selectores CSS

Una regla CSS combina un selector y un bloque de declaraciones. El selector localiza elementos del documento; cada declaración asigna un valor a una propiedad. Enlaza una hoja externa desde <head> para reutilizar los estilos entre páginas.

<link rel="stylesheet" href="css/estilos.css">

/* estilos.css */
.tarjeta {
  color: #1e3a8a;
  padding: 1rem;
}

2.1. Selectores básicos

Un selector indica a qué elementos HTML se aplica una regla. Para empezar, podemos seleccionar por el nombre de la etiqueta, por una clase, por un identificador o por un atributo. El selector universal permite seleccionar cualquier elemento.

Selectores básicos y elementos seleccionados

De clase.tarjetaLos elementos cuyo atributo class contiene la clase tarjeta.
De identificador#cabeceraEl elemento con id="cabecera". Ese identificador debe ser único en el documento.
Universal*Todos los elementos. No añade especificidad.
De atributo: presencia[required]Los elementos que tienen el atributo required.
De atributo: valor exacto[type="email"]Los elementos cuyo atributo type vale email.

<p>Párrafo de introducción.</p>
<p class="destacado">Aviso importante.</p>
<article class="tarjeta destacado">Próximo taller</article>

/* CSS */
p { line-height: 1.6; }
.destacado { color: #0f766e; }
#cabecera { background-color: #eff6ff; }
* { box-sizing: border-box; }

En este ejemplo, .destacado selecciona tanto el segundo párrafo como el artículo. Una clase puede reutilizarse en varios elementos y un elemento puede tener varias clases, separadas por espacios en el HTML. Utiliza clases para estilos reutilizables y reserva los identificadores para elementos concretos.

Agrupar selectores y combinar condiciones

La coma permite compartir declaraciones entre varios selectores. En cambio, escribir selectores juntos y sin espacio exige que un mismo elemento cumpla todas esas condiciones.

/* Selecciona todos los h1 y todos los h2. */
h1, h2 { color: #1e3a8a; }

/* Solo los párrafos que tengan la clase destacado. */
p.destacado { font-weight: bold; }

/* Elementos que tengan las dos clases. */
.tarjeta.destacado { border: 2px solid #0f766e; }

Fíjate en el espacio: p.destacado selecciona un párrafo con esa clase; p .destacado selecciona un elemento con esa clase que esté dentro de un párrafo. Esta segunda forma utiliza una relación de descendencia.

Agrupar con :is()

:is() selecciona los elementos que coincidan con cualquiera de los selectores entre paréntesis. Permite agrupar alternativas sin repetir la parte común.

/* Sin :is(): repetimos .tarjeta. */
.tarjeta h2,
.tarjeta h3 {
  color: #1e3a8a;
}

/* Con :is(): seleccionamos los mismos elementos. */
.tarjeta :is(h2, h3) {
  color: #1e3a8a;
}

Ambas reglas seleccionan los h2 y h3 que estén dentro de .tarjeta.

Especificidad: :is() toma la del selector más específico de su lista. Por ejemplo, :is(.aviso, #principal) aporta el peso de un ID, incluso cuando coincide por la clase. Evita mezclar IDs y clases sin necesitarlo.

3. Modelo de caja y flujo

Cada caja tiene contenido, relleno, borde y margen. El relleno separa el contenido del borde; el margen establece separación exterior. Los márgenes verticales de algunos bloques en flujo normal pueden colapsar, de modo que no siempre se suman.

box-sizing decide cómo se calcula el tamaño de una caja:

Propiedades y valores de referencia

  • border-box: el relleno y el borde están incluidos en el ancho indicado. La caja mantiene ese ancho.

Cálculo del ancho sin contar márgenes
ModeloAncho del contenidoAncho hasta el borde exterior
content-box280 px280 + 40 + 4 = 324 px
border-box280 − 40 − 4 = 236 px280 px

3.1.1. Box Model Reset

*, *::before, *::after {
  box-sizing: border-box;
}

Esta regla, habitual en los resets CSS, aplica border-box a todos los elementos (*) y a sus pseudoelementos ::before y ::after.

¿Por qué se hace así? Para que el relleno y el borde estén incluidos en el tamaño indicado.

Por ejemplo, con width: 100% y padding: 20px:

  • Con content-box: la caja ocupa el 100% del ancho del contenedor más 40 px de relleno y puede desbordarse.
  • Con border-box: esos 40 px quedan dentro del 100%; se reduce el espacio para el contenido.

Así resulta más sencillo controlar el tamaño de las cajas al maquetar.

3.2. Dimensiones, mínimos y máximos

Definir un tamaño exacto y establecer un límite son operaciones distintas. Una tarjeta puede crecer con su texto y tener una altura mínima; un artículo puede adaptarse al ancho de pantalla sin superar una anchura cómoda para leer.

Ampliación

¿Qué significa auto?

auto deja que el navegador calcule el valor según la propiedad y el contexto. No significa siempre «ocupar el 100 %».

  • width: auto: en un bloque normal, el ancho suele aprovechar el espacio disponible, teniendo en cuenta márgenes, relleno y borde.
  • height: auto: en un bloque de texto normal, la altura se adapta al contenido.
  • En una imagen, height: auto permite conservar su proporción cuando cambia el ancho.
.texto { height: auto; }
img {
  max-width: 100%;
  height: auto;
}

Los límites mínimos y máximos siguen aplicándose. Otros modos de distribución pueden calcular auto de otra manera.

Ampliación

Centrar una caja horizontalmente

Para centrar un bloque en el flujo normal, dale un ancho menor que su contenedor y usa margin-inline: auto. En escritura horizontal, los márgenes izquierdo y derecho se reparten por igual el espacio sobrante.

.caja-centrada {
  box-sizing: border-box;
  width: 80%;
  max-width: 40rem;
  margin-inline: auto;
}

Si el contenedor mide 500 px y la caja ocupa 400 px, sobran 100 px: quedan 50 px a cada lado. Si la caja ocupa todo el ancho, no habrá espacio sobrante que repartir.

text-align: center centra el texto y el contenido en línea dentro de la caja; margin-inline: auto centra la propia caja. Este ejemplo no realiza centrado vertical.

/* Se adapta a la pantalla y limita el ancho de lectura. */
.articulo {
  width: calc(100% - 2rem);
  max-width: 65ch;

.tarjeta { min-height: 12rem; height: auto; }

/* La imagen se reduce si hace falta, sin perder su proporción. */
img { max-width: 100%; height: auto; }

/* Caja de proporción 16:9, cuya altura se calcula. */
.portada { width: 100%; height: auto; aspect-ratio: 16 / 9; }

Valores y conflictos habituales

  • auto deja que el navegador calcule el tamaño según el contexto. height: auto suele permitir crecer con el contenido; no equivale a una altura fija.
  • Los porcentajes necesitan una referencia: width: 100% suele tomar el ancho del bloque contenedor. Un height: 100% no significa «toda la pantalla» y, en el flujo normal, necesita una altura de referencia definida para funcionar como esperas.
  • min-content, max-content y fit-content permiten tamaños relacionados con las necesidades del contenido, en lugar de una medida fija.
  • Un máximo puede limitar el tamaño declarado y un mínimo puede ampliarlo. Si el mínimo supera al máximo, prevalece el mínimo. Evita un min-width mayor que la pantalla.
  • En elementos Flexbox o Grid, el mínimo automático puede impedir que una caja se reduzca. Cuando el diseño lo necesite, min-width: 0 o min-inline-size: 0 permite que ceda espacio; después debes decidir cómo tratar su contenido.

Prueba las dimensiones con texto largo, zoom e imágenes de distintos tamaños. No fijes una altura solo porque encaja con el texto de ejemplo: limita la capacidad del diseño para adaptarse.

3.3. Overflow: contenido que no cabe

overflow decide qué ocurre cuando el contenido rebasa el área disponible. Es independiente de definir el tamaño: para observar desbordamiento vertical en un bloque de texto, limita primero su altura o altura máxima.

Propiedades y valores de referencia

Valores de overflow

  max-height: 15rem;

/* Una tabla ancha puede desplazarse dentro de su contenedor. */
.tabla-scroll { overflow-x: auto; }

/* Dos valores: primero el eje horizontal, después el vertical. */
.panel-ejes { overflow: hidden auto; }

overflow-x y overflow-y controlan cada eje. No todas las combinaciones se comportan de manera independiente: si un eje usa visible y el otro un valor distinto de visible o clip, ese visible se calcula como auto.

Para URLs o palabras largas, considera overflow-wrap: anywhere. Para mostrar puntos suspensivos en una línea necesitas combinar text-overflow con un ancho limitado, recorte y ausencia de salto de línea:

.titulo-breve {
  max-width: 20rem;
  white-space: nowrap;
  overflow: hidden;
  text-overflow: ellipsis;
}

No ocultes el desbordamiento de toda la página para disimular un problema de anchura. Comprueba el origen y conserva el acceso a la información. Si creas una región desplazable, verifica su uso con teclado; cuando necesite foco propio, añade tabindex="0" y un nombre accesible, por ejemplo mediante role="region" y aria-labelledby.

3.4. Unidades

Una medida combina un número y una unidad, sin espacios: 16px, 1.5rem o 50vw. La unidad indica cómo interpretar ese número. Las absolutas mantienen una relación fija entre sí; las relativas se calculan a partir de una fuente, la ventana o un contenedor.

Para empezar, usa rem en texto y espacios, % en anchos adaptables y px en detalles como un borde. Las tablas siguientes reúnen las familias de unidades de longitud; las menos frecuentes quedan como consulta.

3.5. Colores y fondos

Una caja puede tener texto, un color de fondo y varias imágenes superpuestas. color establece el color del texto y se hereda; background-color pinta el fondo de esa caja. Un fondo transparente deja ver lo que hay detrás, pero no significa que haya heredado el fondo del padre.

Selectores de atributo

Los corchetes permiten seleccionar por la presencia de un atributo o por su valor. Son útiles para distinguir campos de formulario y tipos de enlace.

= compara el valor completo; ^=, su comienzo; $=, su final; y *=, una parte del valor. Estos selectores comparan el atributo: [href$=".pdf"] no coincidirá con un enlace que termine en .pdf?descarga=1.

Otros valores de display

Los valores display: flex y display: inline-flex se estudiarán más adelante, en el apartado de Flexbox.

  • flow-root crea un nuevo contexto de formato de bloque. Resulta útil para contener elementos flotantes y evitar que los márgenes de los hijos colapsen con los del contenedor.
  • list-item genera una caja de lista con marcador. table, table-row y table-cell permiten comportamientos de tabla; para datos tabulares, utiliza HTML de tabla semántico.
  • contents elimina la caja del elemento y deja participar a sus hijos. No lo uses como sustituto general de un contenedor: comprueba su efecto en la accesibilidad y en los estilos del propio elemento.

Ocultar no siempre significa lo mismo

  • display: none elimina las cajas del elemento y sus descendientes del diseño y, normalmente, del árbol de accesibilidad. El HTML permanece en el DOM.
  • visibility: hidden oculta el elemento conservando su espacio. No es equivalente a eliminarlo del flujo.
  • opacity: 0 lo hace transparente, pero conserva su espacio y puede mantener clics y foco. No basta por sí solo para ocultar un control interactivo.

Sticky: mantener una navegación visible

.navegacion {
  position: sticky;
  top: 0;
  z-index: 10;
  background: white;
}

Se adhiere al borde superior de su zona de desplazamiento y deja de avanzar al llegar al límite de su contenedor. Necesita un umbral como top: 0 y espacio para desplazarse. Revisa los antepasados con overflow: auto, scroll o hidden: pueden cambiar esa zona de referencia.

Un antepasado con transform distinto de none también puede convertirse en referencia para absolute y fixed; en este último caso, la caja deja de fijarse a la ventana.

Superposición: z-index

z-index controla qué caja aparece delante al solaparse. Dentro del mismo contexto de apilamiento, un valor mayor se dibuja por encima. Los contextos agrupan elementos: un hijo no puede superar otra agrupación solo por tener un número enorme.

8. Preferencias y comprobación de la interfaz

Define colores mediante variables para crear temas coherentes. prefers-color-scheme permite respetar la preferencia del sistema; si añades un botón, debe expresar el estado y permitir volver al modo automático. Comprueba todos los componentes en ambos temas, incluidos formularios y foco.

9. Diseño responsive y medios

Un diseño responsive combina medidas flexibles, recursos adaptables y cambios de distribución. Mobile first parte de la pantalla estrecha y añade reglas con min-width cuando el contenido lo necesita. Los puntos de ruptura son decisiones del diseño, no una lista universal de dispositivos.

<meta name="viewport" content="width=device-width, initial-scale=1">

/* CSS: una columna como punto de partida */
.contenido { display: grid; gap: 1rem; }
@media (min-width: 48rem) {
  .contenido { grid-template-columns: 2fr 1fr; }
}
@media print {
  nav, .decoracion { display: none; }
  body { color: #000; background: #fff; }
}

Prueba anchos intermedios, orientación, zoom y textos largos. Un menú móvil debe poder abrirse con un botón y teclado, indicar su estado y mantener enlaces alcanzables. Oculta decoraciones cuando proceda, pero conserva la información necesaria. Comprueba también la vista de impresión.

10. Repaso y entrega

¿Qué diferencia hay entre un margen y un relleno?

El relleno separa el contenido del borde; el margen separa la caja de su entorno.

¿Por qué una interfaz de escritorio reducida no es necesariamente responsive?

Porque también hay que adaptar distribución, lectura e interacción, y comprobar que el contenido sigue siendo utilizable.

¿Flexbox sustituye a Grid?

Son complementarios: se pueden combinar para resolver distintas relaciones de distribución.
