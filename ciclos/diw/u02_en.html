UD02. CSS and responsive design

From selectors to layout: build readable, flexible and adaptable interfaces.

1. CSS: Cascading Style Sheets

When creating a page, HTML identifies the content and its structure: a heading, paragraph, list or link. The browser already gives them a basic appearance, but we need to control how they look to build our design.

CSS defines that presentation. CSS stands for Cascading Style Sheets . With CSS we choose colours, fonts, sizes, spacing and the layout of elements.

For example, HTML marks text as a heading using <h1>. CSS can make it blue, enlarge it and separate it from the following paragraph. The content stays the same; its presentation changes.

Separating these tasks makes it easier to:

  • Maintain the website: a shared stylesheet lets you change headings on every page from a single file.
  • Keep things consistent: buttons, menus and cards can reuse the same styles.
  • Adapt the design: the same HTML can appear in one column on mobile and several columns on a larger screen.
  • Improve readability: we can adjust contrast, text size and spacing between elements.

CSS applies rules to HTML elements. When several rules affect the same element, the browser must decide which to use. That is why we will study the cascade, inheritance and specificity. First, we will see how to add those rules to a page.

1.1. Ways to include CSS

To style a page, the browser needs to know where the CSS rules are written. We can store them in a separate file, include them in the HTML head or write them directly on an element. All three work, but the choice affects how easy the website is to maintain.

For a site with several pages, the most practical choice is an external stylesheet. We write the rules in a file, such as estilos.css, and link it from each page's head using <link>:

<!-- Inside head, in the HTML file -->
<link rel="stylesheet" href="css/estilos.css">

The href attribute specifies the file path. Here, the browser looks for estilos.css inside the cssfolder. This file contains CSS only, without <style>:

/* File css/estilos.css */
p { color: navy; }

If several pages link to the same stylesheet, they share its styles. Changing one rule changes the colour of their paragraphs. This will be our usual approach in practical work.

We can also write CSS inside the document, in a <style> element within <head>. This is an internal stylesheet: useful for trying an idea or creating a self-contained example.

<style>
  p { color: navy; }
</style>

These rules apply to that page. If we copy the block into several documents, we must later edit them one by one, so shared styles should go in an external stylesheet.

The third option is an inline style, written in the style attribute of a tag. No selector is needed: the declarations apply directly to that element.

<p style="color: navy;">Sample text</p>

Although it allows a quick change, repeating style attributes mixes presentation with content and makes styles harder to maintain. Avoid it as your normal layout method: use classes and rules in an external stylesheet. It still has specific uses, such as some HTML emails or values changed by JavaScript during interaction.

1.2. The cascade

An element can receive declarations from several rules. The cascade resolves these conflicts and determines the value applied to each property. The browser considers the styles' origin, importance, cascade layers and selector specificity, among other factors. When declarations tie on earlier criteria, the later declaration wins.

/* Both rules have the same origin, importance and specificity. */
p { color: navy; }
p { color: teal; } /* This declaration comes later and wins. */

Here, paragraphs appear teal. Writing a rule last does not guarantee that it wins: source order breaks a tie, but does not replace the other cascade criteria.

1.3. Inheritance

Inheritance passes certain properties from an element to its descendants when they have no value of their own to replace them. Properties such as color and font-family are inherited by default; others, such as margin, padding and border, are not.

<article class="noticia">
  <p>This text inherits the article colour and font.</p>
</article>

.noticia {
  color: navy;
  font-family: sans-serif;
  border: 1px solid navy;
}

The paragraph inherits the colour and font, but does not get its own border. If we add .noticia p { color: teal; }, it uses that colour declaration instead of the inherited value. The keyword inherit explicitly requests the parent's value, even for properties that are not inherited by default.

1.4. Specificity

Specificity is a selector's weight. It helps determine which declaration wins when the cascade requires a selector comparison. Three groups are compared in order: IDs; classes, attributes and pseudo-classes; element types and pseudo-elements.

  • #aviso: one ID → 1-0-0.
  • .destacado: one class → 0-1-0.
  • p: one element type → 0-0-1.
<p id="aviso" class="destacado">Important information</p>

#aviso { color: navy; }      /* 1-0-0 */
.destacado { color: teal; }  /* 0-1-0 */
p { color: maroon; }        /* 0-0-1 */

If these are normal author declarations in the same layer, #avisowins, even if it appears earlier. Groups are compared from left to right: they are not added as a decimal number. The universal selector * and combinators such as >do not add specificity. !important changes a declaration's importance, not its selector's specificity.

1.5. Global property values

Besides each property's own values, CSS provides common keywords to choose where its value comes from. They let us inherit from a parent, restore an initial value or use other cascade rules.

What does !importantdo?

It gives priority to a declaration over normal declarations from the same origin. It is written after the value and does not increase specificity.

<p id="aviso">Hello</p>

/* CSS */
#aviso { color: blue; }
p { color: red !important; }

The text will be red: the important declaration beats the normal one, even though the latter uses an ID selector.

When adding !important does not change the result

For the same paragraph, try these two cases separately, in the same stylesheet and without layers:

/* Before: the text is blue. */
#aviso { color: blue !important; }
p { color: red; }

/* After: it is still blue. */
#aviso { color: blue !important; }
p { color: red !important; }

In the second case, both declarations are important. #aviso wins because its specificity is higher: 1-0-0 compared with 0-0-1 for p. Adding !important does not change those values, even if the p rule appears later.

Do not overuse it: it makes later changes harder. First check your selectors and their order. Reserve it for justified exceptions.

2. CSS selectors

A CSS rule combines a selector and a declaration block. The selector finds document elements; each declaration assigns a value to a property. Link an external stylesheet from <head> to reuse styles across pages.

.tarjeta {
  color: #1e3a8a;
  padding: 1rem;
}

  • border-box: padding and border are included in the specified width. The box keeps that width.

3.1.1. Box Model Reset

*, *::before, *::after {
  box-sizing: border-box;
}

This rule, common in CSS resets, applies border-box to all elements (*) and their pseudo-elements ::before and ::after.

Why do this? So padding and border are included in the specified size.

For example, with width: 100% and padding: 20px:

  • With content-box: the box occupies 100% of its container's width plus 40 px of padding, and may overflow.
  • With border-box: those 40 px stay within the 100%; the space available for content shrinks.

This makes box sizes easier to control when building layouts.

3.2. Basic units

A measurement combines a number and a unit without spaces: 16px or 1.5rem. Units can be absolute, such as px, with fixed relationships to each other, or relative , depending on another measurement such as font size. Our first exercises use these four options.

Unit or valueReference and useExample
pxCSS pixel. Useful for details such as borders; not necessarily a physical pixel.border-width: 2px;
%Percentage of a reference that depends on the property. A normal block's width is relative to its containing block's width.width: 80%;
remRoot element's font size. Useful for a shared scale of text and spacing.padding: 1rem;
emElement's own font size; in font-size it uses the parent's size. Useful for spacing that scales with text.padding: .5em;

If the root font size is 16 px, 1.5rem equals 24 px. If a button's font size is 20 px, .5em equals 10 px. In contrast, width: 80% changes when the container's width changes.

.tarjeta {
  width: 80%;
  margin-inline: auto;
  padding: 1rem;
  border: 2px solid navy;
}

Start with rem for text and spacing, percentages for flexible widths and px for borders. Later we will add viewport and container units and calculation functions.

Common values and conflicts

  • auto lets the browser calculate size according to context. height: auto usually allows growth with content; it is not a fixed height.
  • Percentages need a reference: width: 100% usually uses the containing block's width. A height: 100% does not mean “the whole screen” and, in normal flow, needs a definite reference height to work as expected.
  • min-content, max-content and fit-content allow sizes based on content needs instead of a fixed measurement.
  • A maximum can limit a declared size and a minimum can enlarge it. If the minimum exceeds the maximum, the minimum wins. Avoid a min-width larger than the screen.
  • In Flexbox or Grid items, the automatic minimum may stop a box shrinking. Where the design requires it, min-width: 0 or min-inline-size: 0 allows it to give up space; you must then decide how to handle its content.

4. Advanced selectors

We can refine selection using relationships between elements, attributes, interaction states and positions in the document. The aim is to select what we need without unnecessary classes or rules that are hard to maintain.

Grouping selectors and combining conditions

The comma shares declarations among several selectors. Writing selectors together without a space instead requires one element to meet all those conditions.

/* Selects all h1 and h2 elements. */
h1, h2 { color: #1e3a8a; }

/* Only paragraphs with the destacado class. */
p.destacado { font-weight: bold; }

/* Elements with both classes. */
.tarjeta.destacado { border: 2px solid #0f766e; }

Notice the space: p.destacado selects a paragraph with that class; p .destacado selects an element with that class inside a paragraph. The second form uses a descendant relationship.

Grouping with :is()

:is() selects elements matching any selector in the parentheses. It groups alternatives without repeating the shared part.

/* Without :is(): repeat .tarjeta. */
.tarjeta h2,
.tarjeta h3 {
  color: #1e3a8a;
}

/* With :is(): select the same elements. */
.tarjeta :is(h2, h3) {
  color: #1e3a8a;
}

Both rules select h2 and h3 elements inside .tarjeta.

Specificity: :is() uses the specificity of the most specific selector in its list. For example, :is(.aviso, #principal) contributes an ID's weight even when matching through the class. Avoid mixing IDs and classes unnecessarily.

Other display values

The values display: flex and display: inline-flex will be covered later in the Flexbox section.

  • flow-root creates a new block formatting context. Useful for containing floats and preventing child margins from collapsing with container margins.
  • list-item generates a list-item box with a marker. table, table-row and table-cell enable table behaviour; use semantic table HTML for tabular data.
  • contents removes the element's box and lets its children participate directly. Do not use it as a general container replacement: check its accessibility effects and the element's own styles.

Hiding can mean different things

  • display: none removes the element's and descendants' boxes from layout and normally from the accessibility tree. The HTML remains in the DOM.
  • visibility: hidden hides the element while preserving space. It does not remove it from the flow.
  • opacity: 0 makes it transparent but preserves space and may retain clicks and focus. It is not enough on its own to hide an interactive control.

position determines how a box is positioned. Preserving its space means other elements still leave its original space, even when the box moves.

Position values
ValueDoes it preserve its space?How it is positioned

Absolute: place a label inside a card

<div class="tarjeta">
  <span class="insignia">New</span>
  <p>Card content</p>
</div>

  position: relative;
  padding: 3rem 1rem 1rem;
}

  position: absolute;
  top: .5rem;
  right: .5rem;
}

The card provides a reference without moving. The label occupies its top-right corner; top padding reserves room so it does not cover text. Without an ancestor establishing a reference, absolute uses the document's initial containing block.

Sticky: keep navigation visible

.navegacion {
  position: sticky;
  top: 0;
  z-index: 10;
  background: white;
}

Sticks to the top edge of its scrolling area and stops at its container's boundary. It needs a threshold such as top: 0 and room to move. Check ancestors with overflow: auto, scroll or hidden: they may change that reference area.

An ancestor with transform other than none can also become the reference for absolute and fixed; in the latter case, the box is no longer fixed to the viewport.

Overlapping: z-index

z-index controls which box appears in front when boxes overlap. In the same stacking context, a higher value is drawn above. Contexts group elements: a child cannot escape its group simply by using a huge number.

10. Review and submission

What is the difference between margin and padding?

Padding separates content from the border; margin separates the box from its surroundings.

Why is a scaled-down desktop interface not necessarily responsive?

Layout, reading and interaction must also adapt, and the content must remain usable.

Does Flexbox replace Grid?

They complement each other and can be combined for different layout relationships.
