Unit 1: Web Interface Planning and Design

1. Introduction to Web Design

Modern applications must be planned around human interaction before implementation begins. This unit covers the theoretical, methodological and visual foundations of UI and UX.

Learning outcomes

  • Explain the historical development of web design.
  • Distinguish UI, UX, usability and accessibility.
  • Apply visual-perception principles and design systems.
  • Create an accessible style guide and prototype.

1.1. Historical evolution

The web evolved from static, fixed-width desktop documents to responsive, touch-friendly and component-based experiences. Current work integrates accessibility, performance, mobile-first layouts and reusable systems.

1.2. Timeline of key milestones

  • 1991–1996: HTML documents, links and tables.
  • 1996–2006: CSS, JavaScript and separation of content from presentation.
  • 2007–2015: smartphones, responsive design and mobile-first.
  • 2015–today: components, design systems, SVG, accessibility and Core Web Vitals.

1.3. Current trends

Contemporary interfaces use expressive typography, SVG, gradients, 3D/WebXR, soft UI and hero areas. Trends are valid only when they improve communication and remain usable, accessible and efficient.

2. Human–Computer Interaction

2.1. UI and HCI foundations

2.1.1. Graphical interfaces

A UI is the visible and interactive layer through which a person operates a system. Graphical interfaces changed command-first interaction into object–action interaction: select a visible object, then act on it.

2.1.2. HCI

HCI combines computing, psychology, ergonomics, design, semiotics and sociology to create effective, efficient, safe and inclusive systems.

2.2. UI vs UX

UI covers controls, layout, colour, typography and states. UX covers the entire experience: usefulness, expectations, effort, emotion and satisfaction.

2.3. Usability and accessibility

Usability includes learnability, efficiency, memorability, error prevention and satisfaction. WCAG 2.2 requires content to be perceivable, operable, understandable and robust. Practical design includes keyboard access, visible focus, sufficient contrast, labels, status feedback and understandable errors.

Nielsen's ten heuristics

  1. System-status visibility.
  2. Match with the real world.
  3. User control and freedom.
  4. Consistency and standards.
  5. Error prevention.
  6. Recognition rather than recall.
  7. Flexibility and efficiency.
  8. Minimalist design.
  9. Error recognition and recovery.
  10. Help and documentation.

3. Graphic Design Elements Applied to the Web

3.1. Conceptual elements

Points, lines, planes and volumes become icons, separators, surfaces, cards and layered regions. Their repetition, size and colour create hierarchy.

3.2. Direction, position, space and visual gravity

Direction guides attention; position creates order; space groups or separates; and visual weight creates balance or tension. CSS Grid, Flexbox, gap and alignment translate these decisions into code.

3.3. Design systems and Atomic Design

A design system combines principles, components, patterns, documentation and governance. Atomic Design organises a UI into atoms, molecules, organisms, templates and pages.

3.3.1. Design Tokens

Tokens store design decisions as data. Global tokens hold raw values, semantic tokens express intent, and component tokens apply them to UI elements across Figma, CSS and native platforms.

4. Visual Perception

4.1. Gestalt psychology

People perceive organised wholes. Proximity, similarity, closure, figure–ground, common region and symmetry communicate grouping and hierarchy.

4.2. Laws of UX

  • Fitts: larger, nearer targets are faster.
  • Hick: more choices increase decision time.
  • Jakob: users expect familiar conventions.
  • Miller: working memory is limited.
  • Von Restorff: distinctive items are remembered.
  • Peak–End: peaks and endings shape remembered experience.

4.3. Colour psychology

RGB represents screen colours; hexadecimal writes those channel values as #RRGGBB. Colour meaning depends on culture and context. Semantic palettes should define text, surface, action, success, warning and error roles while meeting contrast requirements.

4.4. Visual identity

Document wordmarks, symbols, combination marks and integrated marks, including clear space, minimum size, variants and forbidden uses.

SVG iconography remains sharp at any resolution and can inherit CSS colour. Icons require consistent geometry and accessible names when their meaning is not obvious.

4.5. Composition, UI states, mobile-first and performance

Balance uses whitespace, alignment, scale, contrast and rhythm. Components need default, hover, focus, active, disabled and loading states. Never remove keyboard focus without an equivalent visible replacement.

Start with small screens and progressively enhance. WCAG 2.2 defines a 24×24 CSS-pixel target-size criterion with exceptions; 44×44 or 48×48 is a robust touch recommendation.

Optimise LCP and INP, reserve media dimensions and avoid unexpected movement to reduce CLS.

4.6. Web components and forms

Reusable components need semantic HTML, keyboard operation and responsive states. Forms need explicit labels, suitable input types, instructions, validation and clear error recovery.

5. Web Style Guide

5.1. Purpose and essential content

A style guide records identity, colour, typography, spacing, imagery, icons, voice, components and accessibility rules.

5.2. Seven-step process

  1. Audit product and brand.
  2. Define principles and users.
  3. Establish colour and typography.
  4. Define spacing and layout.
  5. Specify imagery and icons.
  6. Document components and states.
  7. Test, govern and version.

5.3. Colour system

Record HEX/RGB values, semantic names, contrast ratios and light/dark variants. Never convey meaning by colour alone.

5.4. Typography

Specify families, weights, responsive scale, line height, measure, fallbacks and loading behaviour.

5.5. Images and icons

Define aspect ratios, crops, formats, compression, responsive sources, dimensions and alt-text rules.

5.6. References and tools

Use developer tools, accessibility inspectors, contrast checkers, Lighthouse and established design-system documentation.

5.7. Figma, code and governance

Design libraries and code must share token and component names, with ownership, contribution rules, versions and release notes.

6. UX Research, Design Thinking and Prototyping

Design Thinking iterates through empathise, define, ideate, prototype and test.

6.1. Five phases

Empathise: observe and interview users in context. Define: synthesise evidence into a clear problem. Ideate: generate alternatives. Prototype: build enough fidelity to answer a question. Test: observe realistic tasks, measure and iterate.

6.1.1. Card Sorting

Open card sorting lets users create groups; closed sorting supplies categories; hybrid sorting combines both. Tree testing validates the resulting architecture.

6.2. Navigation map, sitemap.xml and robots.txt

A navigation map models the user experience. sitemap.xml lists URLs for search engines; robots.txt supplies crawler directives.

6.3. Prototype levels

Low fidelity explores structure cheaply; medium fidelity tests flows; high fidelity validates interaction, content and visual detail.

7. Style Guide for Web Interfaces

7.1. What it must solve

Translate brand and UX decisions into testable tokens, layouts, accessible components, states and content patterns.

7.2. Creation and maintenance

Treat the guide as a living product: audit, document, implement, test, release, measure adoption and revise.

8. Practical Examples

Example 1: Atomic Design and tokens

Apply colour, spacing and typography tokens to an atom, molecule, organism, template and page.

Example 2: Accessible focus and target size

Replace placeholder-only labelling and tiny controls with explicit labels, visible focus, feedback and sufficiently large targets.

9. Common Errors

  • Choosing trends before understanding the problem.
  • Removing focus or ignoring keyboard access.
  • Using colour or icons as the only cue.
  • Small targets, poor contrast and placeholder-only labels.
  • Images without dimensions, causing CLS.
  • Unvalidated information architecture and undocumented components.

10. Integrated Case Study: “Migas Amigas”

Guided platform development

Empathise: research customers and staff. Define: create a five-page architecture. Ideate: establish identity, style guide and tokens. Prototype: move from wireframes to a Figma component system. Test and implement: run usability and accessibility checks, then verify performance.

11. Summary

Key ideas

  • UI is the interface; UX is the complete experience.
  • Accessibility, usability and performance are requirements.
  • Gestalt and UX laws help explain perception and behaviour.
  • Tokens, components and style guides create consistency.
  • Research and prototyping reduce uncertainty.

12. Activities

Comprehension
