Theme 1: Web Interface Planning and Design

1. Introduction to Web Design

The development of modern digital applications requires the conception of interaction with people before writing any line of server code or database. In this topic the theoretical, methodological and visual fundamentals of user interface planning are studied (User Interface or IU) and user experience (User Experience or UX).

Figure 1.0: Evolution of technical and methodological approaches in web interface planning.

In the current professional environment of the profile of Senior Technician in Web Application Development (DAW), a developer not only builds functional code; he must ensure that screens are intuitive, accessible, coherent and aesthetically balanced. Understand interaction models, visual perception laws (Gestalt), the fundamental laws of UX, the methodology of Atomic Design, the normative numerical ratios of accessibility and adaptive layout structures is essential for a digital product to be functional and interpretable by any user.

To address this professional module, it is advisable to have previous knowledge of HTML layout and CSS style sheets, as well as general notions about how the web works. The contents are coordinated with Learning Results oriented to the design, planning and prototyping of high quality adaptive interfaces.

By the end of this topic you'll be able to...

  • Differentiate UI, UX concepts, usability and accessibility applying its technical terminology and normative numerical ratios WCAG (4.5:1 / 3:1).
  • Evaluate an interface using practical usability principles related to response, feedback, simplicity, readability, consistency, navigation, error prevention and job protection.
  • Relation the main milestones of the evolution of web design with its effects on structure, presentation, interaction and multi-device adaptation.
  • Apply direction, position, space and visual gravity to build coherent reading hierarchies and paths.
  • Identify and implement the principles of perception of Gestalt, UX Laws and UI component interaction states (hover, focus, disabled).
  • Structure design systems based on Atomic Design and Design Tokens using CSS variables.
  • Develop and maintain a web style guide documenting identity, color, typography, images, iconography, voice tone, components and their translation into code.
  • Planning UX research with User People, Card Sorting and Tree Testing before developing the navigation architecture.
  • Uncouple the visual architecture of information in front of the web indexing files (sitemap.xml) and tracing directives (robots.txt).
  • Apply strategy Mobile-First and minimal touch area recommendations (Target Size 44x44 px / 48x48 px).
  • Build Web interface prototypes (wireframes and mockups) integrating usability patterns into forms and perceived performance optimization (Core Web Vitals).

1.1. Historical evolution of web design

The web design has not evolved solely because of aesthetic changes. Each stage responds to new technical capabilities, devices, connection speeds and usage expectations. The Web went from organizing linked and almost exclusively textual documents to offering interactive, accessible, adaptive and even immersive applications. Understanding this evolution allows us to distinguish between visual tendency a real improvement in communication, usability or performance.

1.2. Key milestone timeline

Period Technical or cultural milestone A consequence for design
1989–1991 Tim Berners-Lee proposes the World Wide Web and implements its pillars: URL, HTTP and HTML. In 1991 the Web software began to spread outside CERN. Text documents, links and a very simple information hierarchy predominate. The priority is to access and connect information.
1992–1994 Browsers are multiplied; Mosaic facilitates the incorporation of images. The tables are also used to force visual compositions. In 1994 the W3C was born. The page is no longer just text, but the presentation is still mixed with the structure. Standards begin to look for interoperability between browsers.
1995–1998 JavaScript adds browser behavior; Flash popularizes animations and multimedia; CSS1 becomes a recommendation in 1996 and CSS2 in 1998. PHP drives dynamic server generation. Content and presentation are progressively separated, reactive interfaces and dynamic sites appear. The abuse of animations and complements also introduces problems of loading and accessibility.
2000–2009 The so-called Web 2.0 consolidates blogs, wikis, social networks and content provided by users. AJAX allows updating parts of a page without reloading it completely. Smartphones generalize tactile browsing. The Web becomes a social and application platform. Design must communicate states, facilitate participation and operate outside the desktop.
2010–2014 The concept Responsive Web Design is formulated in 2010 using fluid grids, flexible images and half queries. Approaches popularized mobile-first and the frameworks Responsive. The same interface adapts to a continuous display size. The content and hierarchy must be prioritized before deciding on a fixed composition.
2015–2022 Planar design and Material Design, component-based architectures, single-page applications, PWAs and technologies such as WebAssembly are strengthened. Web products are designed as coherent and reusable systems. It increases the importance of speed, installation, operation with limited connectivity and consistency between screens.
2023 onwards Artificial intelligence, multimodal interfaces, 3D content, WebXR, customization, dark mode, and increasingly automated design and development tools coexist. The technological novelty must be incorporated with progressive improvement, privacy, accessibility, sustainability and human control. Not every trend is suitable for any project.
Historical accuracy

Publicizing chronologies usually group processes that lasted several years. For example, CSS1 was recommended by the W3C in 1996, JavaScript reached Netscape in 1995 and the term Responsive Web Design The dates should be interpreted as milestones of adoption, not as absolute borders.

2. Person-Computer interaction

2.1. User Interface (UI) and Person-Computer Interaction (IPO/HCI)

2.1.1 Definition and scope of the IU (Graphical Interfaces - GUI)

The User Interfaces (User Interfaces o IU) encompass the set of hardware and software elements that act as a communication boundary between human beings and machines. In the digital design ecosystem, the interface encompasses screens, windows, menus, controls, iconography, documentation and online help systems.

Historically, the interaction was based on command line interfaces (CLI, Command Line Interface) structured under a pattern Action-Object, where the person first indicated the command and then the file or object to be modified. With the first commercial implantation by Xerox in 1981 and its subsequent popularization through Apple, the User Graphic Interfaces (GUI, Graphical User Interfaces).

GUIs revolutionized the sector by introducing technology WYSIWYG (What You See Is What You GetWhat you see is what you get) and the interaction paradigm Object-Action. In this model, the person first selects the visual object on screen (e.g. a file or image) and then executes the desired action on it (such as removing, moving or editing).

Figure 1.1: Evolution of graphical interfaces (GUI) and the visual interaction paradigm Object-Action.

2.1.2. Person-Computer Interaction (IPO / HCI)

The Person-Computer interaction (IPO, or HCI English Human-Computer Interaction) is the discipline in charge of studying how humans interact with computer technologies. Its fundamental objective is to make systems efficient, safe and intuitive.

Figure 1.2: Multidisciplinary character of Person-Computer Interaction (IPO/HCI).

2.2. User Interface (UI) vs. User Experience (UX)

2.2.1. Technical differentiation between IU and UX

In the software industry it is common to confuse the concepts of UI and UX, although they represent complementary planes:

  • User Interface (IU): It focuses on creating the visual and interactive components of the screen (buttons, fonts, colors, HTML/CSS layout).
  • User Experience (UX): It refers to the global experience and the degree of usability perceived by the person when interacting with the digital system. It encompasses emotions, information architecture and interaction design (IxD).
“Something that looks great but is difficult to use represents a large UI with a poor UX. While something very usable that looks terrible is an example of a great UX with a poor UI” — Helga Moreno.

2.3. Usability and accessibility

2.3.1. Key attributes and user profiles

The usability defines the extent to which the design of an interface takes into consideration human psychology and physiology to ensure that the use of the system is effective, efficient and satisfactory.

Usability Attribute Technical description
Learning curve Easy for novice users to adapt to the system and perform basic tasks.
Use efficiency The speed with which experienced users execute their objectives after mastering the interface.
Percentage of errors Frequency and severity of mistakes made; directly affects frustration.
Easy to remember Ability to successfully reuse the system after a period of inactivity without re-learning it.
User satisfaction Subjective feeling of comfort, utility and pleasantness after interaction.

2.3.2. Web Accessibility (WCAG 2.2 / EN 301 549)

The Usability optimizes the experience for a particular user profile within a context of use. Web Accessibility ensures that digital content is usable by all people, regardless of their physical, sensory or cognitive abilities, or the assistive technologies employed (screen readers, adapted keyboards).

To ensure accessibility and comply with European legislation (EN 301 549 / Royal Decree 1112/2018 in Spain), the principles apply POUR of the guidelines WCAG 2.2 (Perceptible, Operable, Understandable, Robust).

2.3.3. Practical user-centred usability principles

Design with the user in the center It involves continuously checking how each decision affects effectiveness, efficiency and satisfaction. The following principles serve as a guide for designing and auditing web applications; they must be applied according to tasks, the public and the actual context of use.

Principle Application in the interface Example:
1. Agile response
Two-second guidance rule		 Optimize the load and avoid unnecessary waits. If an operation cannot be completed immediately, confirm that the system is working. Show the main content quickly and then load the secondary items.
2. Information feedback Communicate the outcome and status of each action through messages, visual changes or progress indicators. After submitting a form, temporarily deactivate the button, display progress and confirm the shipment.
3. Real value functionality Remove controls, contents and services that do not contribute to the user's tasks or to the product's objectives. Do not include a calendar or weather widget in a store if they do not intervene in the purchase.
4. Space between elements Use blank space to separate groups, reduce visual noise and facilitate scanning. Group shipping and payment data into differentiated blocks within the purchase process.
5. Legibility of texts Take care of typography, size, contrast, line length, interline and structure using titles and short paragraphs. Adaptable body text, minimum contrast WCAG and reading lines that do not occupy an entire wide screen.
6. Consistency and consistency Maintain stable color patterns, iconography, terminology, distribution and behavior. Always use the same color and format for errors, warnings, confirmations and main actions.
7. Direct access to content
Guidance rule of the three clicks		 Reduce unnecessary steps and place frequent functions in visible and understandable paths. Allow to access the tracking of an order from the account and also from the confirmation mail.
8. Mistake management and recovery Prevent errors when possible and provide understandable messages, causes and recovery actions. A 404 page maintains the identity of the site and offers search, home and useful links.
9. Controlled cognitive load
Principle of 7 ± 2		 Group related options and submit information in stages so as not to require too many elements to be remembered simultaneously. Organize an extensive menu in recognizable categories instead of displaying a flat list.
10. Labour protection Keep data and allow undoing, recovering or continuing an interrupted task. Automatically save a draft and keep the cart after a payment error.
11. Real world correspondence Use words, sequences and family conventions for the target audience. In a library, use “loans”, “renew” and “return” instead of internal system codes.
12. Minimum learning curve Take advantage of known patterns, progressively reveal complexity and offer contextual help. Identify the search with a magnifying glass accompanied by a clear label.
13. Fast navigation between sections Provide guidance, return routes and mechanisms appropriate to the volume of content. Combine main menu, breadcrumbs, search, pagination and status of the active section.
14. Intentional symmetry and asymmetry Use symmetry to provide balance and asymmetry to direct attention without breaking the hierarchy. Highlight a call to action by size or color within a stable composition.
Guidance rules to be validated

The values of two seconds, three clicks and 7 ± 2 elements They help detect potential problems, but they are not normative criteria or universal limits. The number of clicks matters less than the clarity of each step, and Miller's work studies immediate memory, does not set a mandatory maximum of menu options. Decisions must be checked by analytics, performance tests and user tests.

2.3.4. The 10 heuristics of Jakob Nielsen

Jakob Nielsen established ten principles for heuristically evaluating the usability of interfaces:

  1. System status visibility: Report what happens by feedback in a reasonable time.
  2. Match between the system and the real world: Use the user's usual language with familiar concepts.
  3. Control and freedom of the user: Provide clear exits, undo and redo actions.
  4. Consistency and standards: Follow the platform conventions so as not to generate uncertainty.
  5. Prevention of errors: Design mechanisms to avoid failures before they occur.
  6. Recognition before I remember: Minimize cognitive load by making visible objects, actions, and options.
  7. Flexibility and efficiency of use: Provide shortcuts and accelerators for advanced users.
  8. Aesthetic and minimalist design: Remove irrelevant or redundant information.
  9. Helps recognize, diagnose, and fix errors: Clear messages with solutions.
  10. Aid and documentation: Have simple guides focused on the user's tasks.

The interface design articulates four hierarchical levels of elements:

  • Visual elements: Shape, Measurement, Color, Texture and Typography (what is perceived on screen).

  • Practical elements: Representation, Meaning and Function (purpose of communication).

3.3. Design systems and methodology Atomic Design

In modern frontend development, isolated pages are not built, but Design Systems (Design Systems) Scalables based on methodology Atomic Design (Brad Frost). This methodology divides the IU into 5 hierarchical levels:

Figure 1.5: Methodological levels of Atomic Design (Brad Frost).
  • Atoms: Individual UI elements (buttons, inputs, tags, icons).
  • Molecules: Groups of united atoms that perform a basic function (e.g. an input + a button = search form).
  • Agencies: Sets of molecules that form a whole section (e.g. the full header or a product card).
  • Templates (Templates): Structural layout (layout) without actual data.
  • Pages: Final instance of the system filled with actual content for production.
Design Tokens in CSS

The core of a design system is the Design Tokens: variables that store fundamental visual values (colours, fonts, spacings) reusable in CSS/Sass (e.g. --color-primary: #1e3a8a;, --spacing-md: 16px;).

3.3.1. Design Tokens: The basis of agile and interoperable development

The Design Tokens (design tokens) are agnostic variables to the platform that store the fundamental visual values of a design system — such as hexadecimal chromatic codes, rem typographic sizes, pixel spacing, border radius and animation durations. unique source of truth (Single Source of Truth) that connects the visual design created in tools like Figma with the implementation in frontend code (CSS, Sass, React, iOS, Android).

Figure 1.5.1: Layered structure of Design Tokens: from pure global values to semantic tokens and code integration.

Tokens are usually organized into three levels of abstraction:

  • Global tokens (or primitive): They store direct design values without a specific use context (e.g. color-blue-900: #1e3a8a, size-16: 16px).
  • semantic tokens: They assign a clear function or intent to token according to context (e.g. --color-primary-brand: var(--color-blue-900) o --color-feedback-error: #b91c1c).
  • Component tokens: Define the specific properties of an interface element (e.g. --button-primary-bg-hover).

Thanks to this decoupling, if the company decides to update the corporate color or scale of rounded edges, only the central value of the token is modified; automatically, all web applications, Android and iOS synchronize the new appearance without needing to manually refactor each stylesheet.

4. Visual perception

4.1. Gestalt Psychology

The visual perception is the active interpretation performed by the brain of the light stimuli. Gestalt ("form" or "configuration") formulated psychological laws that explain how the mind visually groups individual elements to perceive a structured "all".

Figure 1.3: Gestalt Laws applied to grouping and visual perception on screens.

4.1.1. Main Gestalt laws applied to IU

  • Proximity Act: Objects placed close to each other are perceived as a unified group. IU: Form entry tags are placed pasted to their corresponding fields.
  • Law of Similarity (Similarity): Elements with equal shape or colour are perceived as belonging to the same category. IU: Primary buttons of the same color.
  • Closure Act (Clausura): The mind tends to complete incomplete figures. IU: Carousel cards trimmed at the edge to suggest scrolling.
  • Law of Continuity: The eye follows a fluid path. IU: Lists of vertically aligned elements.
  • Figure and Background Act: We separate the featured object from the surrounding space. IU: Modals with darkened background (overlay).
  • symmetry and order law (Prägnanz): The brain simplifies complex forms. IU: Layout in grids or grids.
  • Common Region Act: Elements delimited by a closed edge are perceived as a set. IU: Cards (cards).
  • Common Destination Act: Elements that move together are perceived as unified. IU: Animated dropdown menus.

4.2. Basic Laws of UX (Laws of UX)

The Laws of UX (compiled by Jon Yablonski) integrate psychological principles that govern interactive cognitive behavior.

Laws of UX Educational resource
Explore the compendium of psychological principles applied to interface design compiled by Jon Yablonski, with visual examples and animations.
Visit Laws of UX (Spanish)
1. Jakob (Jakob's Law) Act

Users prefer that your site works just like other sites they already know. Reducing novel patterns avoids mental overload.

2. Fitts' Law Act

The time to reach a target depends on the distance and its size. The main buttons (CTA) must be large and touchable.

3. Hick's Law Act

Decision time increases with the number of options. It should be simplified by dividing complex processes into steps (wizards).

4. Miller's Law

The working memory keeps active an average of 7 (± 2) elements. Group in blocks (chunking) facilitates processing.

5. Aesthetic-Useability Effect

Attractive designs are intuitively perceived as more usable and tolerant of small technical failures.

6. Postel Act (Robust Principles)

Be liberal in what you accept and conservative in what you send. The interface must automatically format imperfect data entries.

7. Tesler Act (Conservation of Complexity)

Every system has inherent complexity that must be assumed by the developer internally to simplify end-use.

8. Doherty Threshold

Productivity is maximized when the system responds in less than 400 ms. Higher responses require load screens (skeleton screens).

9. Von Restorff effect (Insulation)

Among similar elements, the one that differs visually is the most remembered (e.g., highlight the recommended subscription plan).

10. Pico-Final Rule (Peak-End Rule)

Experiences are judged by the sense of the climax (peak) and the final outcome.

11. Zeigarnik effect

Incomplete tasks are remembered more. Progress bars motivate you to finish user profiles.

12. Parkinson ' s Act

A task will consume all the time available. Setting time limits on purchases increases the conversion rate.

4.5.4. Visual Performance Metrics (Core Web Vitals & Layout Shift)

The user experience does not depend solely on the graphic aspect, but on the Perceived yieldGoogle and the W3C standardize three key metrics (Core Web Vitals):

  • CLS (Cumulative Layout Shift): Measure visual instability. It occurs when elements jump unexpectedly when uploading images without dimension attributes (width and height), causing accidental clicks.
  • LCP (Largest Contentful Paint): Main visual element rendering time (must be < 2.5 s).
  • INP (Interaction to Next Paint): Measure the response speed of the IU after a user click (< 200 ms).

Usability Patterns in Web Forms (WCAG 3.3)

Forms are the nerve point of interaction in web applications. To maximize usability you must follow three key patterns:

  1. Real-time Inline Validation: Report errors or successes immediately when losing the field focus (event blur), without waiting for the global submission of the form.
  2. Explicit labelling (<label>): Always link tags to your entries by for="id". Never replace the label with a placeholderas it disappears when writing and destroys accessibility.
  3. Masks and Automatic Format: Apply guided formatting for complex data (IBAN, phones, dates) by lightening user load.

5. Web interface style and design guide

One web style guide —also known as the look and feel o Visual interface manual—documents visual, verbal, typographical, chromatic and interactive decisions of a digital product. Its purpose is for designers, frontend developers, content editors (UX Writers) and future maintenance personnel to apply standardized and consistent criteria without having to reinterpret the brand on each new screen or module.

Figure 1.9: Structure of contents and modular blocks of a Web Interface Style Guide.

Style guide versus design system

The style guide describes and rules the visual rules: corporate identity, color palette, typography, photographic style, iconography, voice tone and interactive behavior. design system expands this technical documentation by integrating Design Tokens, reusable code components (React, Vue, Web Components), interaction patterns, accessibility tests and governance mechanisms. Therefore, the guide is the normative basis within the design system studied in section 3.3, but does not replace it.

5.1. Purpose, scope and essential content

The guide must be sufficiently precise to produce results consistent with different devices and flexible enough to evolve with the product. Each rule must include its purpose, exact values, examples of correct use, uses to be avoided (Do's and Don'ts) and technical verification criteria.

Module What to Document Verifiable evidence
Identity and branding Purpose, personality, values, logo, isotype, imagotype, variants, area of respect and incorrect uses. SVG master archives and examples of clear, dark and photographic backgrounds.
Colorimetry Brand colors, neutrals and functional states with HEX, RGB and HSL values. Design Tokens table and combinations with contrast ratios WCAG (4.5:1 and 3:1) tested.
Type Families, hierarchical scale (H1–H6), weights, line height (line-height), line length and rules of use. Samples of H1–H6, body, links, tags, aids and error messages in rem/em.
Images and Photography Photographic style, vector illustration, proportions (aspect-ratium), framing, treatments and formats. Examples of WebP/AVIF, thumbnails, hero images, explicit dimensions and alternative texts (alt).
Iconography Visual family (line/fill), base grid (16/24/32px), thickness, color, meaning and accessibility. Library of SVG icons and rules for informative, decorative (aria-hidden) and actuable icons.
Tone and voice (UX Writing) Degree of formality, terminology, inclusive language, clarity and microcopy style in interface. Examples of button tags, confirmations, aids, empty states and error messages.
Components IU Anatomy, sizes, spacing and specification of the 6 states (Default, Hover, Focus, Active, Disabled, Loading). Specifications of buttons, text fields, navigation, cards, manners and touch area (Target Size).

5.2. Creation process in seven steps

  1. Define identity: concrete mission, vision, values, personality and communicative attributes that the interface must transmit.
  2. Build the chromatic palette: select primary, secondary, neutral and semantic state colours, indicating when each is applied with its WCAG ratios.
  3. Set the typographical system: choose legible families (preferably Sans-Serif for screens) and define a coherent proportional scale.
  4. Regularize images and graphics: determine style, aspect relationships, framing, compression, performance optimization and textual alternatives.
  5. Define tone and writing style (UX Writing): fix formality, terminology, active voice, inclusive language and system message writing.
  6. Standardize iconography: choose a coherent family, vector grid, standardized sizes and ARIA accessibility rules.
  7. Specify UI components: document buttons, input fields, cards and manners with anatomy, variants, interactive states and CSS code.
Living Document and Continuous Evolution

The guide should not be stagnated in a static document. It needs a maintenance officer, version number, update date, changelog and a procedure to propose, review, test and remove rules. Any modification must synchronize the visual design, code and documentation.

5.4. Documentation of the typographic system

The typography determines the reading hierarchy, the processing speed of information and the personality of the interface. The guide should favor fluid scaling, readability on high density screens and a clear hierarchy.

Typographical family Visual characteristics Usual use in Web Interface
Serif (Founded) It has ornamental endings or endings in the strokes. Editorial titles, digital press, blogs or prestigious institutional brands.
Sans-serif (Drywood) Clean, straight and uncut strokes; excellent digital sharpness. Text body, control elements, navigation menus and buttons.
Script (Caligraphic) Imitates handwritten writing and has high expressive load. Brand details or signatures; never for text body or long paragraphs.
Display / Decorative A striking and personalized design designed for large size. Headers, campaign banners, large format titles and short messages.
Monospaced (Monospace) Each character occupies exactly the same horizontal width. Code blocks, numerical data tables and technical terminals.
  • Usually use a maximum of one or two well-checked families to avoid slowing down web load.
  • Define font sizes using relative units (rem o em) to allow scaling according to user preference.
  • Ensure a line height (line-height) suitable for approx. 1.5 for the text body and control the maximum line length (50-75 characters).
  • Book supported, bold and italic capitals to emphasize short sentences; the emphasis should be reserved exclusively for interactive links.
  • Document backup fonts (system failbacks), web fonts (Google Fonts / Typekit), upload strategy (font-display: swap) and licenses.

6. UX Research, Design Thinking and Prototyping

The process of designing and developing people-centred digital products is based on methodology Design Thinking (Design Thinking). This agile, iterative and non-linear methodology is articulated in 5 consecutive stages: Empathize, Define, Idea, Prototyping and Testar.

Figure 1.10: Methodological cycle of the 5 phases of Design Thinking in digital interface projects.

Iterative Nature of Design Thinking

Unlike traditional cascading models, Design Thinking is deeply iterative and flexible. By testing a prototype in phase 5 with real users, the findings may reveal that the problem was not well defined (which forces you to return to phase 2) or that new solutions are required (phase 3). This continuous feedback loop reduces exponentially the risk of developing software that no one wants or is impossible to use.

6.1. Deepening the 5 Phases of Design Thinking

Phase 1: Empathize (Understand the User in its Context)

The goal of this phase is to immerse yourself in the reality of users to understand their deep needs, motivations, patterns of behavior, emotions and pain points (Pain points) It avoids presupposing or imposing the vision of the developer.

  • Interviews in Depth: Semi-structured conversations to explore how the user currently solves his tasks.
  • Contextual Observation (Shadowing): Direct study of the user in its natural environment using digital or physical tools.
  • Map of Empathy (Empathy Map): Visual matrix organizing what the user Says, Think., It does. and Feel, identifying their efforts (frustrations) and their results (targets).

Phase 2: Define (Synthesize the Problem and Frame the Solution)

Qualitative and quantitative information collected during empathy is analyzed to identify the central problem from the user's perspective (Point of View - POV). Key questions of the type are asked "How could we..." (How Might We - HMW).

  • User People: Arquetypes of fictitious users built with real data that summarizes objectives, demographic context and frustrations.
  • Customer Journey Map: Map of the user's journey documenting the interaction sequence before, during and after the application's use, identifying critical drop points.
  • Card Sorting: Open or closed tests where real users group content into categories to discover their mental model.
  • Tree Testing: Content tree test without visual elements to validate if the proposed menu structure is understandable.

6.1.1. Card Sorting: Organization of Information Architecture

The Card Sorting (card classification) is a quantitative and qualitative user research technique used in the Empathize and Define. Its main purpose is to discover mental model users to organize, categorize and label the contents of a website or application as intuitively as possible before defining the final structure of the menu or navigation map.

Card Sorting Open: The user groups and names categories. • Card Sorting Closed: Categories prefixed by the team. • Card Sorting Hybrid: Mix both. 3. UX Navigation Map Menu "My Account" Personal Data Invoicing and Payments Validated mental model
Figure 1.10.1: Card Sorting Dynamics: from isolated cards to navigation menu sorting.

During a Card Sorting session, participants receive a set of cards (paper or digital physics using tools such as Optimal Workshop) with concepts, contents or functionalities of the web and are asked to organize them in groups that make sense to them:

  • Card Sorting Open: Users group cards freely and create their own names for each category. It is ideal in early stages to discover new nomenclatures and group patterns.
  • Card Sorting Closed: Participants organize cards within fixed categories preset by the design team. It serves to assess whether the existing structure is understandable.
  • Card Sorting Hybrid: Users have prefixed categories but are allowed to create new tags if they consider that some content does not fit.

Once the study has been completed, the results are analyzed using similarity matrices and dendrograms to construct the Information Architecture (IA) and the final navigation map of the web application.

Phase 3: Idea (Generate Creative Alternatives and Define Style Guide)

In the ideation phase, the massive generation of ideas and solutions is encouraged without judging them prematurely. Once the best ideas are selected, they are translated into the visual architecture and identity of the project.

  • Brainstorming and SCAMPER: Group dynamization techniques to diversify interface and navigation proposals.
  • Definition of the Style Guide: Manufacture of visual identity, semantic palette, typographical scale and Design Tokens studied in paragraph 5.
  • Information Architecture (IA): Preparation of the navigation map that organizes the main flows and screens of the web application.

Phase 4: Prototyping (Give Tangible Form to Ideas)

Tangible representations of the solutions are built so that the user or client can interact with them. Prototyping is progressive and fast so as not to invest excessive resources before validating the idea.

  • Low Fidelity Prototypes (Wireframes): Black and white static schematics (made on paper or with tools such as Wireframe.cc) focused exclusively on the distribution of information.
  • High Fidelity Prototypes (Mockups in Figma): Displays with complete aesthetic design applying the style guide and the Atomic Design system.
  • Interactive Functional Prototypes: Interactive layout with links, transitions and components that simulate the actual logic of the system.

Phase 5: Test (Evaluate, Measure, and Iterate with Users)

The functional prototype is subjected to real tests with representative users to observe how they interact, detect usability problems, measure task execution times and collect direct feedback.

  • Moderate / Non-Moderate Usability Tests: Sessions where the user performs key tasks (e.g. making a purchase) while thinking aloud (Think Aloud Protocol).
  • Heuristic Audit of Nielsen: Expert evaluation using the 10 usability principles explained in section 2.3.4.
  • Accessibility Audit WCAG 2.2: Check contrast ratios, keyboard focus, compatibility with screen readers and Target Size.
  • Visually-Perceived Performance Measurement (Core Web Vitals): Verification of LCP metrics, INP and absence of visual jumps (CLS).

Main design failures UI/UX

  • Remove the focus border (`outline: none`): Hiding focus state destroys keyboard accessibility (WCAG 2.4.7).
  • Replace the label ` The placeholder disappears when writing, confusing the user and violating accessibility in forms.
  • Cause visual instability (Layout Shift - CLS): Upload images or banners without defining `width` and `height`, causing the text to jump when uploading the web.

11. Summary

Figure 1.15: Synthesis of the methodological and technical pillars of Theme 1 for professional web software creation.

Key ideas

  1. The evolution of web design moves from linked and textual documents to interactive, adaptive and multi-device systems; each visual change is conditioned by the technology and context of use.
  2. Key milestones include the birth of the Web (1989–1991), standardization through W3C, the incorporation of JavaScript and CSS, the Web 2.0 and the responsive design formulated in 2010.
  3. Expressive typography, SVG, narrative scroll, WebXR, neomorphism and large visual resources are only suitable if they preserve utility, accessibility, performance and coherence.
  4. The IU addresses visual elements; UX the global usability experience.
  5. The GUI operate under the paradigm Object-Action.
  6. The usability principles require clear feedback and response, relevant functions, readability, consistency, understandable browsing, error recovery and protection of the user's work.
  7. The rules of the two seconds, the three clicks and the 7 ± 2 are guidance heuristics: must be validated with metrics and user tests, not applied as absolute limits.
  8. Accessibility WCAG requires numerical contrast ratios: 4.5:1 (normal text) and 3:1 (large text and UI components).
  9. The Laws of Gestalt and the Laws of UX The perceptive and interactive organization is governed.
  10. Trademarks are classified in Logo, Isotype, Imagotype e Isologotype.
  11. The relation elements —direction, position, space and visual gravity—they organize the path of the look, the location, the separation and the perceptive weight of the shapes.
  12. Atomic Design organizes the UI in Atoms, Molecules, Organisms, Templates and Pages through Design Tokens.
  13. The style guide is a living document that normalizes identity, color, typography, images, icons, voice tone and component behavior.
  14. A design system expands the guide with tokens, reusable components, code, versioning and a governance process.
  15. Any interactive UI component must define its 6 states (Default, Hover, Focus, Active, Disabled, Loading) respecting the keyboard focus (WCAG 2.4.7).
  16. The Strategy Mobile-First requires minimal tactile areas (Target Size 24px WCAG / 44-48px recommended).
  17. Visual performance is evaluated with Core Web Vitals, preventing screen breaks (CLS).
  18. The forms require inline validation and explicit labelling (<label>) not dependent on placeholder.
  19. Architecture is researched with User People, Card Sorting and Tree Testing.
  20. The navigation map of UX is independent of sitemap.xml and robots.txt.
  21. Prototyping evolves: Wireframe → Mockup → Functional Prototype.
