1. Introduction to JavaScript

JavaScript (JS) is a programming language that allows processing data and giving behavior to a web page. With it you can perform calculations, check data from a form and update the content in response to the actions of the user.

In this unit you will work with JavaScript in the browserThe concepts will be practiced through short examples and independent activities.

1.1. Origin and evolution

JavaScript was created by Brendan Eich in 1995, during his work on Netscape. His initial purpose was to incorporate small interactions into the pages and execute instructions in the user's browser.

The appearance of different implementations required a common standard. These milestones summarize their evolution; the characteristics mentioned will be developed throughout the module.

  1. 1995 · Birth in Netscape

    Brendan Eich creates the language to incorporate interaction into web pages. Initially it is called Mocha, then LiveScript and finally JavaScript.

  2. 1997 · First ECMASScript standard

    Ecma International publishes ECMA-262 to establish common rules between implementations.

  3. 1999 · ECMASScript 3

    It incorporates regular expressions and exception handling. It becomes the base of JavaScript during the following decade.

  4. 2009 · ECMASScript 5

    Add strict mode, native JSON support and new methods to work with arrays.

  5. 2015 · ECMASScript 2015 (ES6)

    An important renewal: let, const, arrow functions, chain templates, classes, modules and promises.

  6. 2016 · Annual editions

    The annual publication cycle begins. Language incorporates gradual improvements through the proposal process of the TC39 committee.

  7. 2017 · Asynchronous functions

    async y await They will be studied in later units.

  8. 2020 · New Language Resources

    Optional chaining is incorporated (?.), the null coalescence operator (??) and BigInt.

1.3. Language characteristics

  • Dynamic typing. A fixed rate is not declared for each variable. Values have a type, and a variable can contain values of different types during execution. This does not eliminate the rules on which transactions each value supports.
  • Multiparadigm. It allows you to organize a program using instructions, functions and objects. In this unit instructions and functions will be used mainly.
  • I work with objects. The objects group data and related operations. In the browser they are used to represent, among other elements, the document and its controls. Their model is based on prototypes, which will be studied later.
  • Execution in different environments. In addition to browsers, there are environments like Node.js. The language is the same, but the tools available depend on the environment.

On the web pages it is common event-directed programming: sets which instructions to execute when something happens, such as pressing a button or modifying a field. The function that responds to that event is called event handler.

2.5. Loading and executing scripts

The browser processes HTML progressively. If a script is executed before the item you need exists, you will not be able to find it. Therefore, it is necessary to choose when the script should be executed.

The main loading options are:

  • Classic script without attributes: stops HTML analysis to load and execute the code.
  • defer: downloads an external classic script while continuing the analysis and executes it when HTML is already processed. Keeps the order between deferred scripts.
  • async: download in parallel and run when available. It does not guarantee that HTML is finished or the order between scripts.
  • Script at the end of <body>: you can access the elements written before it.
  • type="module": load code as a module and it differs its execution by default. The modules will be developed in another unit.

In this practice it will be used <script src="ej02-javascriptExterno.js" defer></script>. defer has no effect on classic scripts written inside HTML and does not imply waiting for all images to be downloaded.

Other options: Load eventsEnlargement

The syntax sets how a valid program is written. Style conventions help make that program legible and easy to modify. In the examples in this section the file will be used ej02-javascriptExterno.js prepared by separating JavaScript from HTML in 2.4.

3.1. Values, expressions, instructions and blocks

A value is a data that the program works with, like the number 12the text "Hola" or the logical value true. When written directly into the code a literal.

One expression is a construction that is evaluated and produces a value. 8 + 4 produces 12. A literal can also constitute an expression.

console.log(8 + 4);

In this example, 8 + 4 is the expression that calculates the result. The whole line is a instruction who calls console.log() to show it. An instruction represents a step of the program.

A block group instructions between keys. In this example the two instructions are executed in order:

{
    console.log("Inicio del bloque");
    console.log("Fin del bloque");
}

Blocks will be used later in control structures and functions. Keys define the block; bleeding allows visual recognition of its contents.

3.2. Shifts, comments and signs of delimitation

JavaScript differentiates between upper and lowercase. Therefore, console.log y console.Log are different names. An incorrect letter can prevent an instruction from working.

Comments document the code and are not executed:

// Comentario de una línea.
console.log("Bienvenido");

/*
   Comentario que ocupa
   varias líneas.
*/
console.log("Fin del programa");

// starts a comment until the end of the line. /* y */ delimit a comment that can occupy several lines. The latter cannot be nested.

It is appropriate to distinguish the signs that have already appeared:

  • Dates: define texts, such as "Bienvenido".
  • Parenthesis: in a call, contain arguments, as in console.log("Bienvenido").
  • Keys: in the above examples, define a block.

Good practice from the first programme. Keep a uniform indentation to recognize the blocks, type an instruction per line, and use spaces that facilitate reading. Choose descriptive names and add brief comments that explain decisions, keeping them up to date. Format coherence and readability make it easy to review and modify the code.

4. Variables and types of data

4.1. Declaration, initialization and reassignment

Declare a variable inserts its name into the program. Initialize is to set its initial value. reallocation replaces the value it had for another.

let puntuacion = 10; // Declaración e inicialización.
console.log(puntuacion); // 10

puntuacion = 15; // Reasignación.
console.log(puntuacion); // 15

The sign = assigns a value; it does not express a comparison. When reassigning the name is written without repeating let.

With let it is possible to separate the statement from the first assignment. As long as no other value is assigned, the variable contains undefined:

let mensaje;
console.log(mensaje); // undefined

mensaje = "Bienvenido";
console.log(mensaje); // Bienvenido

Declares the variables before using them. Using a name that has not been declared causes a ReferenceError; is not the same as reading a declared variable whose value is undefined.

4.2. Descriptive identifiers and names

A identifier is a name that allows referring to a program element, such as a variable or a function. When declaring a variable, you choose your identifier, which must respect the rules of the language and express its meaning.

  • You can start with a letter, a bass script (_) or the sign $. Many Unicode letters are also supported.
  • You may include numbers, but don't start with them.
  • It cannot contain spaces or medium scripts.
  • No reserved words are used as if, class o return.
  • The capital letters distinguish names: nombreUsuario y NombreUsuario They're different identifiers.

To be used camelCase: the first word starts in lowercase and the following in uppercase, as nombreUsuario, numeroIntentos o mostrarMensaje.

The name must express its meaning. numeroIntentos communicates more information than n. For functions that perform an action it is advisable to use a verb, such as mostrarMensajeA consistent language approach will be maintained.

4.3. Choosing between Const and Let

Use const as usual option y let when the program needs to be reassigned the variable.

const nombreCurso = "DWEC";
let intentosRestantes = 3;

intentosRestantes = 2;
console.log(nombreCurso, intentosRestantes);
  • const requires an initial value in your statement and does not allow it to be reassigned.
  • let allows you to set an initial value and change it later.
  • Neither allows the same name to be re-declared in the same area.

In previous code you can appear var. Its rules of scope are different; in this unit will be used const y let.

5.3. Logical operators

7. Control structures

A program executes its instructions in order, but may need to choose between several actions or repeat a task. control structures allow these decisions to be made. Execute each example separately in ej13-tomarDecisiones.js and changes the data to check the different possibilities.

7.1. Conditions and values of trusty and falsey

One condition is an expression whose value is interpreted as true or false. It can be a comparison, as edad >= 18, or a boolean variable, such as sesionActiva.

If the value is not boolean, JavaScript interprets it according to the rules of Boolean():

  • Falsy: values that are interpreted as false. Among the types studied are false, 0 (also -0), "", null, undefined y NaN.
  • True: values that are interpreted as true. For example, a number other than zero or a non-empty string, including "0", "false" y " ".

When a particular data is checked, an explicit condition usually better expresses the intention: cantidad === 0 checks a zero, while !cantidad accepts any value falsy.

7.2. if, else if and else

if executes a block when the condition is interpreted as true. Optional block else is executed otherwise:

const edad = 16;

if (edad >= 18) {

} else {
    console.log("Menor de edad");
}

To distinguish more alternatives is added else if. The conditions are checked from top to bottom and only the first corresponding branch is executed:

const temperatura = 24;

if (temperatura < 15) {
    console.log("Temperatura baja");
} else if (temperatura < 25) {
    console.log("Temperatura moderada");
} else {
    console.log("Temperatura alta");
}

When the second case comes, it is already known that the temperature is not lower than 15. Order matters: placing an overly general condition first may prevent the following from being achieved.

The writing of the conditions. Use keys even if the block contains a single instruction. Don't write ; between the condition and the opening key. To compare uses ===, not the allocation =.
