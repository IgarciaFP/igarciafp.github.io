UD02 Fundamentos de JavaScript

El lenguaje que permite programar el comportamiento de una página web

1. Introducción a JavaScript

JavaScript (JS) es un lenguaje de programación que permite procesar datos y dotar de comportamiento a una página web. Con él se pueden realizar cálculos, comprobar datos de un formulario y actualizar el contenido en respuesta a las acciones del usuario.

En esta unidad se trabajará con JavaScript en el navegador. Los conceptos se practicarán mediante ejemplos breves y actividades independientes.

1.1. Origen y evolución

JavaScript fue creado por Brendan Eich en 1995, durante su trabajo en Netscape. Su finalidad inicial era incorporar pequeñas interacciones a las páginas y ejecutar instrucciones en el navegador del usuario.

La aparición de distintas implementaciones hizo necesario un estándar común. Estos hitos resumen su evolución; las características que se mencionan se desarrollarán a lo largo del módulo.

  1. 1995 · Nacimiento en Netscape

    Brendan Eich crea el lenguaje para incorporar interacción a las páginas web. Inicialmente se denomina Mocha, después LiveScript y finalmente JavaScript.

  2. 1997 · Primer estándar ECMAScript

    Ecma International publica ECMA-262 para establecer unas reglas comunes entre implementaciones.

  3. 1999 · ECMAScript 3

    Incorpora expresiones regulares y manejo de excepciones. Se convierte en la base de JavaScript durante la década siguiente.

  4. 2009 · ECMAScript 5

    Añade el modo estricto, soporte nativo de JSON y nuevos métodos para trabajar con arrays.

  5. 2015 · ECMAScript 2015 (ES6)

    Una renovación importante: let, const, funciones flecha, plantillas de cadena, clases, módulos y promesas.

  6. 2016 · Ediciones anuales

    Comienza el ciclo anual de publicación. El lenguaje incorpora mejoras graduales mediante el proceso de propuestas del comité TC39.

  7. 2017 · Funciones asíncronas

    async y await facilitan expresar operaciones asíncronas. Se estudiarán en unidades posteriores.

  8. 2020 · Nuevos recursos del lenguaje

    Se incorporan el encadenamiento opcional (?.), el operador de coalescencia nula (??) y BigInt.

La evolución continúa con ediciones anuales. Para ampliar: historia de las ediciones en la introducción de ECMA-262.

Java y JavaScript son lenguajes diferentes. La semejanza del nombre responde al contexto comercial de su origen. Aprender JavaScript no requiere conocer Java.

1.2. JavaScript y ECMAScript

ECMAScript es la especificación que define las reglas del lenguaje: su sintaxis, sus tipos de datos y sus operaciones. Se publica como el estándar ECMA-262 de Ecma International y evoluciona mediante el trabajo del comité TC39. Los motores JavaScript implementan estas reglas.

El navegador añade herramientas para trabajar con la página, como el DOM y los eventos. Estas herramientas forman parte de las APIs web y se definen en estándares propios.

En esta unidad, JavaScript moderno se refiere al uso de prácticas actuales y características consolidadas. La evolución del lenguaje conserva compatibilidad con mucho código anterior; por ello, la documentación puede mostrar distintas formas de resolver una misma tarea.

1.3. Características del lenguaje

  • Tipado dinámico. No se declara un tipo fijo para cada variable. Los valores tienen un tipo, y una variable puede contener valores de distintos tipos durante la ejecución. Esto no elimina las reglas sobre qué operaciones admite cada valor.
  • Multiparadigma. Permite organizar un programa mediante instrucciones, funciones y objetos. En esta unidad se utilizarán principalmente instrucciones y funciones.
  • Trabajo con objetos. Los objetos agrupan datos y operaciones relacionadas. En el navegador se utilizan para representar, entre otros elementos, el documento y sus controles. Su modelo se basa en prototipos, que se estudiarán más adelante.
  • Ejecución en distintos entornos. Además de los navegadores, existen entornos como Node.js. El lenguaje es el mismo, pero las herramientas disponibles dependen del entorno.

En las páginas web es habitual la programación dirigida por eventos: se establece qué instrucciones deben ejecutarse cuando sucede algo, como pulsar un botón o modificar un campo. La función que responde a ese suceso se denomina manejador del evento.

Ejemplo: pulsar un botón → ejecutar las instrucciones asociadas → mostrar un mensaje.

2. Entorno de trabajo y primer programa

Para comenzar se necesitan un editor y un navegador. El objetivo de este apartado es preparar los archivos, ejecutar instrucciones sencillas y comprobar qué sucede durante su ejecución.

2.1. Herramientas y organización del proyecto

  • Visual Studio Code: permite editar y organizar los archivos del proyecto.
  • Chrome: carga la página y ejecuta su JavaScript.
  • DevTools: son las herramientas de desarrollo integradas en el navegador. Se abren con F12 o desde el menú de Chrome, en Más herramientas → Herramientas para desarrolladores.

En DevTools se utilizarán principalmente Console (Consola), para ejecutar instrucciones y consultar mensajes; Sources (Fuentes), para examinar y depurar el código; y Network (Red), para comprobar la carga de los archivos.

2.2. Primeras formas de mostrar y recoger información

Estas herramientas permiten observar los primeros programas. Escribe las instrucciones de los ejemplos una a una en la consola de una página de práctica. El texto entre comillas representa una cadena.

Mensajes en la consola

console.log("Comienza el programa");
console.log(8 + 4);

console.log() muestra información en DevTools sin añadirla a la página. En este ejemplo aparecen un mensaje y el resultado 12. Si la consola muestra también undefined, es el valor devuelto por la llamada; no indica que haya fallado.

Diálogos del navegador

alert("Bienvenido a JavaScript");
console.log(prompt("¿Cómo te llamas?"));
console.log(confirm("¿Quieres continuar?"));
  • alert() muestra un aviso que el usuario debe cerrar.
  • prompt() solicita un texto. Devuelve una cadena al aceptar, una cadena vacía si se acepta sin escribir, o null al cancelar. Incluso cuando se escribe un número, se recibe texto.
  • confirm() solicita una decisión. Devuelve true al aceptar o false al cancelar.

En los dos últimos ejemplos se obtiene primero la respuesta del diálogo y después se muestra con console.log(). Los tipos de estos valores se estudiarán en el apartado 4.

Los diálogos son modales: mientras permanecen abiertos impiden interactuar con el resto de la página. Resultan útiles para estas primeras pruebas; en las páginas interactivas se utilizarán también campos y mensajes del documento.

Referencia histórica: document.write(). Escribe en el flujo de un documento HTML. Si se utiliza después de cargar la página puede sustituir su contenido. Su uso está desaconsejado y no se empleará en la práctica. Más adelante se actualizarán elementos del DOM mediante herramientas como textContent. Consultar la explicación de MDN.

2.3. Primer contacto con la depuración

Depurar consiste en localizar y comprender los errores de un programa. Conviene distinguir un mensaje que escribe el programador de un error detectado por el navegador:

console.log("Información de seguimiento");
console.warn("Aviso de prueba");
console.error("Mensaje de error de prueba");

console.warn() y console.error() presentan mensajes con distinta importancia visual. Llamar a console.error() no provoca por sí mismo una excepción ni detiene el programa.

Cuando aparece un error real, la consola suele indicar su tipo, una descripción y el archivo y la línea relacionados. El enlace a esa línea ayuda a localizarlo. Si no aparecen mensajes, comprueba los filtros de la consola.

2.4. Formas de incluir JavaScript

El elemento HTML <script> permite incluir instrucciones en el documento o cargar un archivo externo.

Código dentro del documento

<script>
    console.log("Hola desde el documento HTML");
</script>

Esta forma resulta útil para ejemplos pequeños. El código se escribe entre las etiquetas de apertura y cierre.

Archivo externo

<script src="app.js" defer></script>

El atributo src indica la ruta al archivo. Dentro de app.js se escriben únicamente instrucciones JavaScript, sin etiquetas <script>. Esta será la organización de los ejercicios, con el enlace situado en <head>.

Cuando un elemento <script> tiene src, no se añade también código entre sus etiquetas. En ejemplos antiguos pueden aparecer atributos como onclick con instrucciones dentro del HTML; en esta unidad los eventos se registrarán desde JavaScript con addEventListener().

2.5. Carga y ejecución de los scripts

El navegador procesa el HTML progresivamente. Si un script se ejecuta antes de que exista el elemento que necesita, no podrá encontrarlo. Este fragmento permite observar el problema:

<script>
    console.log(document.querySelector("#saludo"));
</script>
<p id="saludo">Hola, mundo</p>

La consulta devuelve null porque el párrafo todavía no se ha procesado. Basta con interpretar la consulta como «buscar el elemento cuyo identificador es saludo»; el DOM se estudiará en el apartado 6.

Las principales opciones de carga son:

  • Script clásico sin atributos: detiene el análisis del HTML para cargar y ejecutar el código.
  • defer: descarga un script clásico externo mientras continúa el análisis y lo ejecuta cuando el HTML ya está procesado. Conserva el orden entre scripts diferidos.
  • async: descarga en paralelo y ejecuta cuando está disponible. No garantiza que el HTML esté terminado ni el orden entre scripts.
  • Script al final de <body>: puede acceder a los elementos escritos antes de él.
  • type="module": carga código como módulo y difiere su ejecución por defecto. Los módulos se desarrollarán en otra unidad.

En esta práctica se utilizará <script src="app.js" defer></script>. defer no tiene efecto en scripts clásicos escritos dentro del HTML y no implica esperar a que se descarguen todas las imágenes.

Otras opciones: eventos de cargaAmpliación

También se puede aplazar una acción hasta que ocurra un evento de carga:

  • DOMContentLoaded: se dispara cuando el HTML está procesado y los scripts diferidos han terminado. No espera a las imágenes; suele ser suficiente para comenzar a trabajar con el DOM.
  • load: espera además a recursos como imágenes y hojas de estilo, salvo los cargados de forma diferida. Puede manejarse mediante window.onload o window.addEventListener("load", manejador).

onload es la propiedad que recibe el manejador; el nombre del evento es load. Una nueva asignación a window.onload sustituye el manejador anterior; addEventListener() permite registrar varios.

Estos eventos no cambian cómo se descarga el script: retrasan la acción registrada. El manejador debe registrarse antes de que ocurra el evento. Se practicarán al estudiar funciones y eventos; por ahora se utilizará defer.

2.6. Hola, mundo

Crea una carpeta llamada ejercicios-js y ábrela en VS Code. Dentro, crea los archivos index.html y app.js.

Escribe en index.html esta página mínima:

<!DOCTYPE html>
<html lang="es">
<head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Primer programa JavaScript</title>
    <script src="app.js" defer></script>
</head>
<body>
    <h1>Primer programa JavaScript</h1>
    <p id="saludo">Abre la consola para consultar los mensajes.</p>
</body>
</html>

Escribe estas instrucciones en app.js, guarda ambos archivos y abre index.html en Chrome:

console.log("Hola, mundo");
console.log("El archivo JavaScript se ha ejecutado");

Consulta la consola de Chrome. Los dos mensajes confirman que el archivo se ha cargado y ejecutado; el contenido visible de la página sigue siendo el definido en el HTML.

Si los mensajes no aparecen: comprueba que has guardado app.js, que la ruta de src coincide con su ubicación y que has recargado la página. En Network, una respuesta 404 al solicitar el archivo indica que no se ha encontrado.

3. Sintaxis básica y buenas prácticas iniciales

La sintaxis establece cómo se escribe un programa válido. Las convenciones de estilo ayudan a que ese programa resulte legible y fácil de modificar. En los ejemplos de este apartado se utilizará el archivo app.js creado anteriormente.

3.1. Valores, expresiones, instrucciones y bloques

Un valor es un dato con el que trabaja el programa, como el número 12, el texto "Hola" o el valor lógico true. Cuando se escribe directamente en el código se utiliza un literal.

Una expresión es una construcción que se evalúa y produce un valor. Por ejemplo, 8 + 4 produce 12. Un literal también puede constituir una expresión.

console.log(8 + 4);

En este ejemplo, 8 + 4 es la expresión que calcula el resultado. La línea completa es una instrucción que llama a console.log() para mostrarlo. Una instrucción representa un paso del programa.

Un bloque agrupa instrucciones entre llaves. En este ejemplo se ejecutan las dos instrucciones en orden:

{
    console.log("Inicio del bloque");
    console.log("Fin del bloque");
}

Los bloques se utilizarán más adelante en estructuras de control y funciones. Las llaves delimitan el bloque; el sangrado permite reconocer visualmente su contenido.

3.2. Mayúsculas, comentarios y signos de delimitación

JavaScript distingue entre mayúsculas y minúsculas. Por tanto, console.log y console.Log son nombres diferentes. Una letra incorrecta puede impedir que una instrucción funcione.

Los comentarios documentan el código y no se ejecutan:

// Comentario de una línea.
console.log("Bienvenido");

/*
   Comentario que ocupa
   varias líneas.
*/
console.log("Fin del programa");

// inicia un comentario hasta el final de la línea. /* y */ delimitan un comentario que puede ocupar varias líneas. Estos últimos no se pueden anidar.

Conviene distinguir los signos que ya han aparecido:

  • Comillas: delimitan textos, como "Bienvenido".
  • Paréntesis: en una llamada, contienen los argumentos, como en console.log("Bienvenido").
  • Llaves: en los ejemplos anteriores, delimitan un bloque.

Buenas prácticas desde el primer programa. Mantén una indentación uniforme para reconocer los bloques, escribe una instrucción por línea y utiliza espacios que faciliten la lectura. Elige nombres descriptivos y añade comentarios breves que expliquen decisiones, manteniéndolos actualizados. La coherencia de formato y la legibilidad facilitan revisar y modificar el código. 4. Variables y tipos de datos

Las variables permiten asociar un nombre a un valor y utilizarlo a lo largo del programa. En los ejemplos se emplearán const y let, junto con nombres descriptivos en camelCase.

Prueba cada fragmento por separado en app.js y recarga la página. Así evitarás declarar varias veces el mismo nombre al reunir ejemplos independientes.

4.1. Declaración, inicialización y reasignación

Declarar una variable introduce su nombre en el programa. Inicializarla consiste en establecer su valor inicial. Una reasignación sustituye el valor que tenía por otro.

let puntuacion = 10; // Declaración e inicialización.
console.log(puntuacion); // 10

puntuacion = 15; // Reasignación.
console.log(puntuacion); // 15

El signo = asigna un valor; no expresa una comparación. Al reasignar se escribe el nombre sin repetir let.

Con let es posible separar la declaración de la primera asignación. Mientras no se asigne otro valor, la variable contiene undefined:

let mensaje;
console.log(mensaje); // undefined

mensaje = "Bienvenido";
console.log(mensaje); // Bienvenido

Declara las variables antes de utilizarlas. Usar un nombre que no se ha declarado provoca un ReferenceError; no es lo mismo que leer una variable declarada cuyo valor es undefined.

4.2. Identificadores y nombres descriptivos

Un identificador es un nombre que permite referirse a un elemento del programa, como una variable o una función. Al declarar una variable se elige su identificador, que debe respetar las reglas del lenguaje y expresar su significado.

  • Puede comenzar por una letra, un guion bajo (_) o el signo $. También se admiten muchas letras Unicode.
  • Puede incluir números, pero no comenzar por ellos.
  • No puede contener espacios ni guiones medios.
  • No se utilizan palabras reservadas como if, class o return.
  • Las mayúsculas distinguen nombres: nombreUsuario y NombreUsuario son identificadores diferentes.

Se empleará camelCase: la primera palabra comienza en minúscula y las siguientes en mayúscula, como nombreUsuario, numeroIntentos o mostrarMensaje.

El nombre debe expresar su significado. Por ejemplo, numeroIntentos comunica más información que n. Para funciones que realizan una acción conviene utilizar un verbo, como mostrarMensaje. Se mantendrá un criterio de idioma coherente.

4.3. Elegir entre const y let

Utiliza const como opción habitual y let cuando el programa necesite reasignar la variable.

const nombreCurso = "DWEC";
let intentosRestantes = 3;

intentosRestantes = 2;
console.log(nombreCurso, intentosRestantes);
  • const requiere un valor inicial en su declaración y no permite reasignarlo.
  • let permite establecer un valor inicial y cambiarlo posteriormente.
  • Ninguna de las dos permite volver a declarar el mismo nombre en el mismo ámbito.

En código anterior puede aparecer var. Sus reglas de ámbito son diferentes; en esta unidad se utilizarán const y let.

const con funciones y otros valoresAmpliación

const puede asociar un nombre a una función, ya que las funciones también son valores. Se usa tanto con expresiones de función como con funciones flecha:

const saludar = function () {
    console.log("Hola");
};

const despedir = () => console.log("Hasta pronto");

saludar();
despedir();

Los nombres saludar y despedir permiten invocar las funciones y no pueden reasignarse. Las llamadas se sitúan después de las declaraciones. Su sintaxis se explicará en el apartado de funciones.

También se utiliza para referencias a elementos del DOM, objetos, arrays y valores de configuración. Impide sustituir el valor asociado al nombre, pero permite modificar el contenido de un objeto o array:

const usuario = { nombre: "Ana" };
usuario.nombre = "Luis";
console.log(usuario.nombre); // Luis

Los objetos y arrays se estudiarán más adelante. Para constantes de configuración puede emplearse MAYUSCULAS_CON_GUIONES_BAJOS, como MAX_INTENTOS; declarar con const no obliga a escribir todos los nombres en mayúsculas.

MDN · const y sus usos

4.4. Tipos de datos de uso inicial

El tipo describe la clase de valor con la que trabaja el programa. En estos primeros ejercicios se utilizarán los siguientes:

  • number: representa números, tanto enteros como decimales. Ejemplos: 18 y 7.5. El separador decimal en el código es el punto.
  • string: representa texto delimitado por comillas. Ejemplos: "Ana", "18" y "". Un número entre comillas es texto; una cadena vacía también es texto.
  • boolean: admite los valores true y false, escritos sin comillas. Permite representar estados como «activo» o «inactivo».
  • undefined: es el valor de una variable declarada con let a la que todavía no se ha asignado otro valor.
  • null: se utiliza para representar de forma explícita la ausencia de un valor.
const edad = 18;
const nombre = "Ana";
const matriculaActiva = true;
let observaciones;
const tutorAsignado = null;

console.log(edad, nombre, matriculaActiva);
console.log(observaciones, tutorAsignado);

undefined puede aparecer también en otras situaciones, como el resultado de una llamada a console.log(). null expresa una ausencia explícita, como ocurre al cancelar prompt(). Ninguno equivale a un texto vacío.

4.5. Tipado dinámico y typeof

JavaScript tiene tipado dinámico: una variable no queda asociada a un tipo fijo. El operador typeof consulta el tipo de un valor y devuelve una cadena con su nombre.

let dato = 42;
console.log(typeof dato); // "number"

dato = "cuarenta y dos";
console.log(typeof dato); // "string"

La reasignación es válida, pero conviene mantener un significado y un tipo coherentes para cada variable cuando sea posible. Esto facilita entender el programa.

console.log(typeof 7.5);      // "number"
console.log(typeof "7.5");    // "string"
console.log(typeof false);    // "boolean"
console.log(typeof undefined); // "undefined"
console.log(typeof null);     // "object"

El caso de null. Por una particularidad histórica, typeof null devuelve "object". Sin embargo, null es un valor primitivo que representa ausencia, no un objeto con propiedades.

4.2. Predecir y comprobar tipos

Antes de ejecutarlas, indica qué devuelven typeof 25, typeof "25", typeof true, typeof "true" y typeof "". Comprueba tus respuestas y explica el efecto de las comillas.

4.6. Cadenas e interpolación

Las cadenas sencillas pueden escribirse con comillas dobles o simples. El delimitador de cierre debe coincidir con el de apertura. Las comillas de otro tipo pueden formar parte del texto:

const saludo = "Hola";
const aviso = 'Pulsa "Aceptar" para continuar';
console.log(saludo, aviso);

El operador + permite concatenar, es decir, unir cadenas. Las plantillas de cadena utilizan acentos graves (`) y permiten insertar valores mediante ${expresion}.

const nombre = "Ana";
const curso = "DWEC";

console.log("Hola, " + nombre + ". Bienvenida a " + curso + ".");
console.log(`Hola, ${nombre}. Bienvenida a ${curso}.`);

Ambas instrucciones muestran el mismo mensaje. La interpolación facilita leer textos que combinan varias variables. Las comillas simples y dobles no interpretan ${...}.

4.3. Construir un mensaje

Declara nombre, modulo y grupo. Construye un mensaje con esos datos mediante concatenación y mediante una plantilla de cadena. Cambia los valores y comprueba que el texto se actualiza al volver a ejecutar el programa.

4.7. Ámbito de bloque

El ámbito determina desde dónde se puede utilizar una variable. Una variable declarada con let o const dentro de un bloque está disponible en ese bloque y en los que contiene, pero no fuera de él.

const centro = "IES Ejemplo";

{
    const grupo = "2DAW";
    console.log(centro); // IES Ejemplo
    console.log(grupo);  // 2DAW
}

console.log(centro); // IES Ejemplo
// console.log(grupo); // Fuera del bloque: ReferenceError.

El bloque puede acceder a centro, declarado en el ámbito exterior. En cambio, el código exterior no puede acceder a grupo. Conviene declarar cada variable cerca de donde se utiliza y limitar su ámbito a lo necesario.

4.4. Comprobar la visibilidad

Ejecuta el ejemplo anterior. Después, activa la última instrucción retirando // y explica el error. Vuelve a comentarla y añade otro bloque con su propia variable grupo. Comprueba que cada bloque puede utilizar su propio nombre sin interferir con el otro.
