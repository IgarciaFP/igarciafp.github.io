Chrome DevTools: laboratorio guiado

Aprenderás desde cero y paso a paso. Cada ticket te indica dónde hacer clic, qué acción realizar y qué resultado debes ver antes de escribir tu respuesta.

  • Nivel: iniciación, sin experiencia previa
  • Duración: dos sesiones de clase
  • Modalidad: individual o parejas
  • Entrega: respuestas + informe generado

Qué vas a aprender

  • Encontrar una etiqueta HTML.
  • Probar cambios de CSS.
  • Leer mensajes y errores.
  • Detener JavaScript para observarlo.
  • Ver archivos descargados por la web.
  • Revisar móvil, datos y calidad.

Cómo completar un ticket

  1. Lee todos los pasos antes de empezar.
  2. Busca el panel indicado en la barra superior.
  3. Realiza una sola acción cada vez.
  4. Comprueba que aparece el resultado esperado.
  5. Escribe una respuesta corta y marca el ticket.

Seguridad: escribe solo los comandos que aparecen en esta práctica. No introduzcas contraseñas ni datos personales.

Antes de empezar: cómo orientarte

DevTools es una ventana de herramientas que aparece junto a la página. No importa si se abre a la derecha o en la parte inferior: las funciones son las mismas.

1 · Abrir las herramientas

  1. Usa Google Chrome y abre esta página.
  2. Pulsa F12. Si no funciona, pulsa Ctrl + Mayús + I.
  3. También puedes hacer clic derecho en la página y elegir Inspeccionar.

2 · Encontrar un panel

  1. Busca sus nombres en la barra superior de DevTools.
  2. Si un nombre no aparece, pulsa » para ver los paneles ocultos.
  3. Puedes ensanchar DevTools arrastrando el borde que lo separa de la página.

DEV-101

Abre DevTools y encuentra una etiqueta HTML

Elements8 min

Descubre que cada parte visible de una web corresponde a una etiqueta HTML.

Dónde está: Elements suele ser la primera pestaña. El selector tiene forma de cursor dentro de un cuadrado y está en la esquina superior izquierda de DevTools.

  1. Abre DevTools con F12 y pulsa la pestaña Elements.
  2. Pulsa el icono del selector. También puedes usar Ctrl + Mayús + C.
  3. Mueve el ratón por la página: verás rectángulos de colores sobre cada elemento.
  4. Haz clic sobre el texto Facturación calculada. En DevTools quedará marcada una línea que comienza por <article.
  5. Dentro de esa línea, abre la etiqueta y haz doble clic sobre el texto Facturación calculada. Escribe Facturación revisada y pulsa Enter.
  6. Abre Sources, pulsa Ctrl + F y busca Facturación calculada. El archivo conserva el texto original porque solo has cambiado el DOM que Chrome muestra en este momento.

Debes ver: el nuevo texto en la página y el texto original dentro de Sources.

Responde: ¿qué etiqueta y qué clases tenía el elemento seleccionado?

DEV-102

Prueba colores y tamaños con CSS

Elements · Styles8 min

Comprueba cómo una regla CSS cambia el aspecto de un elemento.

Dónde está: permanece en Elements. A la derecha del HTML busca la pestaña Styles. Si no la ves, ensancha DevTools.

  1. Usa el selector para elegir la tarjeta que muestra Facturación calculada.
  2. En Styles, busca el bloque element.style { }, situado normalmente arriba.
  3. Haz clic dentro de las llaves, escribe color: crimson y pulsa Enter.
  4. En la línea siguiente escribe padding: 30px y pulsa Enter.
  5. Pulsa la pestaña Computed, junto a Styles. Baja hasta el dibujo de una caja: las zonas son content, padding, border y margin.
  6. Desmarca la casilla situada junto a padding: 30px y observa cómo vuelve el tamaño anterior.

Debes ver: el texto de color rojo y la tarjeta más grande mientras la regla está activada.

Responde: ¿qué propiedad cambió el color y qué zona del modelo de caja hizo crecer la tarjeta?

Se guarda automáticamente en este navegador.
DEV-103

Escribe un comando y encuentra un error

Console8 min

Usa Console para hacer una pregunta a la página y para leer un error.

Dónde está: pulsa Console en la barra superior. La línea para escribir aparece abajo, junto al símbolo >.

  1. Pulsa Sincronizar pedidos en la página. Deben aparecer cuatro filas en la tabla.
  2. Abre Console y busca la línea inferior que comienza por >.
  3. Escribe a mano document.querySelectorAll('#orders-body tr').length y pulsa Enter.
  4. Chrome contestará con el número de filas encontradas.
  5. Pulsa Provocar error HTTP en la página y vuelve a mirar Console.
  6. Busca el mensaje rojo que contiene HTTP 404. El enlace azul situado a la derecha indica el archivo y la línea donde se produjo.

Debes ver: el número 4 y, después, un mensaje rojo con el código 404.

Responde: ¿cuántas filas encontró el comando y qué significa que el mensaje sea rojo?

Se guarda automáticamente en este navegador.
DEV-104

Detén JavaScript para mirar sus valores

Sources10 min

Aprende qué es un breakpoint: una pausa colocada por ti dentro del programa.

Dónde está: abre Sources. Los archivos aparecen a la izquierda, el código en el centro y las variables a la derecha.

  1. Pulsa Ctrl + P, escribe p0101_v2.html y selecciona el archivo.
  2. Pulsa Ctrl + F, busca total = subtotal y cierra la caja de búsqueda con Esc.
  3. Haz clic sobre el número de esa línea. Aparecerá una marca azul: es el breakpoint.
  4. Pulsa Recalcular total en la página. El programa se detendrá y la línea aparecerá resaltada.
  5. En la zona derecha abre Scope y después Local. Busca las variables subtotal y total.
  6. Pulsa el botón azul de continuar, con forma de triángulo ▶, situado arriba del código. Si vuelve a detenerse, púlsalo hasta que termine.
  7. Haz clic otra vez en el número de línea para quitar el breakpoint.

Debes ver: el código detenido y los valores numéricos de subtotal y total.

Responde: escribe los dos valores que viste. ¿Crees que total = subtotal suma o sustituye?

Se guarda automáticamente en este navegador.
DEV-105

Observa cómo llegan los datos

Network9 min

Distingue una petición que funciona de otra que falla.

Dónde está: abre Network. Las peticiones aparecen en una tabla central; los filtros, como Fetch/XHR, están encima.

  1. Abre Network y pulsa el icono de limpiar, un círculo atravesado, situado arriba a la izquierda de la tabla.
  2. Pulsa el filtro Fetch/XHR y después Sincronizar pedidos.
  3. Haz clic en la fila llamada p0101_v2_data.json.
  4. En el panel que se abre, elige Headers. Busca Request Method y Status Code.
  5. Abre Response para ver los datos que llegaron.
  6. Pulsa Provocar error HTTP. Selecciona la nueva fila p0101_v2_missing.json y comprueba su código.

Debes ver: una petición con estado 200 y otra con estado 404.

Responde: ¿qué archivo funcionó, cuál falló y qué código tuvo cada uno?

Se guarda automáticamente en este navegador.
DEV-106

Mira la página como si fuera un móvil

Device Mode8 min

Comprueba la página con una pantalla estrecha y una conexión más lenta.

Dónde está: el icono de móvil y tableta está en la esquina superior izquierda de DevTools, junto al selector de elementos.

  1. Pulsa el icono de móvil y tableta. También puedes usar Ctrl + Mayús + M.
  2. En la barra que aparece sobre la página, elige Responsive.
  3. Escribe 360 en el campo de anchura y 800 en el de altura.
  4. Observa el panel de pedidos. La parte ancha obliga a desplazarse horizontalmente: esa es la incidencia que buscamos.
  5. Abre Network. En el menú que indica No throttling, elige una conexión lenta como Slow 4G o Fast 3G.
  6. Pulsa Sincronizar pedidos y anota el tiempo mostrado en la tarjeta Tiempo de respuesta.
  7. Vuelve a seleccionar No throttling y desactiva el modo móvil con el mismo icono.

Debes ver: una página estrecha, desplazamiento horizontal y un tiempo de respuesta medible.

Responde: ¿qué tamaño de pantalla y qué conexión utilizaste? ¿Qué problema viste?

Se guarda automáticamente en este navegador.
DEV-107

Encuentra los datos guardados por la página

Application9 min

Localiza un dato en Local Storage, otro en Session Storage y una cookie.

Dónde está: abre Application desde la barra superior o desde ». Los almacenes están en la columna izquierda.

  1. En la columna izquierda, abre Local Storage con su pequeño triángulo y pulsa la dirección de esta web.
  2. En la tabla de la derecha busca la clave opsboard.theme. Su valor inicial es light.
  3. Haz doble clic sobre light, escribe contrast y pulsa Enter.
  4. Abre Console, escribe aplicarPreferencias() y pulsa Enter. Aparecerá un borde oscuro alrededor del panel.
  5. Vuelve a Application. En Session Storage busca opsboard.session y en Cookies busca opsboard_lab.

Debes ver: opsboard.theme → contrast, opsboard.session → training y opsboard_lab → enabled.

Responde: copia las tres parejas de clave y valor e indica en qué apartado estaba cada una.

DEV-108

Comprueba si un botón tiene un nombre claro

Accessibility9 min

Entiende que los lectores de pantalla necesitan nombres, no solo iconos.

Dónde está: selecciona primero un elemento en Elements. Después busca Accessibility en la zona derecha; puede estar dentro de ».

  1. Usa el selector de elementos y pulsa el botón que solo muestra una papelera.
  2. Abre Accessibility y busca Computed Properties.
  3. Comprueba que el rol es button y observa el campo Name. Está vacío porque el icono se oculta a los lectores de pantalla.
  4. Vuelve al HTML seleccionado. Haz doble clic en un espacio dentro de la etiqueta de apertura y añade aria-label="Eliminar último pedido".
  5. Regresa a Accessibility: ahora Name debe mostrar Eliminar último pedido.
  6. Selecciona el texto gris que hay bajo el buscador. En Styles, pulsa el pequeño cuadrado de su propiedad color y observa el aviso de contraste.

Debes ver: el botón pasa de no tener nombre a tener el nombre que has añadido.

Responde: ¿por qué un botón con un dibujo necesita también un nombre accesible?

DEV-109

Graba una tarea que bloquea la página

Performance10 min

Observa qué ocurre cuando JavaScript mantiene ocupado el navegador demasiado tiempo.

Dónde está: abre Performance desde la barra superior o desde ». El botón redondo de grabación está arriba a la izquierda.

  1. Pulsa el botón redondo Record para iniciar la grabación.
  2. En la página, pulsa Ejecutar tarea lenta. Durante medio segundo la página responderá peor.
  3. Vuelve a Performance y pulsa Stop.
  4. Espera a que Chrome dibuje la grabación. Busca en la fila Main un bloque largo con una marca roja.
  5. Haz clic en ese bloque. En la información inferior busca el nombre ejecutarTareaLenta y una duración cercana a 550 ms.

Debes ver: una tarea larga de aproximadamente medio segundo.

Responde: ¿cómo se llamaba la función y cuánto tiempo ocupó aproximadamente?

DEV-110

Observa cómo aumenta la memoria

Memory10 min

Comprueba que guardar objetos sin liberarlos hace crecer la memoria usada.

Dónde está: abre Memory desde ». Si no aparece, usa el menú de tres puntos ⋮, More tools → Memory.

  1. En Memory elige Heap snapshot y pulsa Take snapshot.
  2. Espera a que aparezca Snapshot 1 en la columna izquierda.
  3. Pulsa tres veces Retener memoria en la página. El contador debe indicar Retenciones: 3.
  4. Vuelve a Memory y toma otra instantánea. Aparecerá Snapshot 2.
  5. Compara el tamaño que Chrome muestra junto a las dos instantáneas.
  6. Abre Console, escribe window.devtoolsLab.retenciones.length y pulsa Enter.

Debes ver: el número 3 en Console y una segunda instantánea de memoria.

Responde: ¿cuántos objetos quedaron guardados y qué instantánea ocupaba más?

DEV-111

Explora la parte PWA de la aplicación

Application10 min

Encuentra el manifiesto, el Service Worker y los archivos guardados en caché.

Dónde está: abre Application. Usa su columna izquierda para elegir Manifest, Service Workers y Cache Storage.

  1. Pulsa Manifest. Busca App name y Start URL.
  2. Pulsa Service Workers. Busca p0101_v2_sw.js y comprueba que su estado sea activated o running.
  3. Abre Cache Storage con su triángulo y selecciona la caché que comienza por opsboard-lab-.
  4. En la tabla de la derecha deben aparecer el HTML, el JSON y el manifiesto.
  5. Vuelve a Service Workers y marca Offline. Pulsa Sincronizar pedidos y observa el mensaje de red.
  6. Desmarca Offline al terminar para recuperar la conexión normal.

Debes ver: un Service Worker activo, tres recursos principales en caché y un error de red durante la prueba offline.

Responde: escribe el nombre del Service Worker y los tres archivos que encontraste en la caché.

DEV-112

Pide a Lighthouse una revisión automática

Lighthouse10 min

Obtén cuatro puntuaciones y lee una recomendación sencilla.

Dónde está: abre Lighthouse desde ». Si no aparece, usa ⋮, More tools → Lighthouse.

  1. En Mode elige Navigation y en Device elige Mobile.
  2. Marca las categorías Performance, Accessibility, Best Practices y SEO.
  3. Pulsa Analyze page load y espera. Chrome realizará la prueba automáticamente.
  4. Al terminar verás cuatro círculos con puntuaciones de 0 a 100.
  5. Busca una recomendación marcada en naranja o rojo, ábrela y lee su explicación.

Debes ver: cuatro puntuaciones y una lista de recomendaciones.

Responde: copia las cuatro puntuaciones y resume una recomendación con tus palabras.

RETO FINAL GUIADO · 15 MIN

Explica tres descubrimientos

Ya conoces los paneles principales. Ahora repite tres comprobaciones sencillas y descríbelas con tus palabras.

Qué debes comprobar

  1. En Network, muestra una petición con estado 200.
  2. En Console, muestra el error HTTP 404.
  3. En Elements, selecciona el botón de papelera y explica por qué necesita un nombre.

Cómo explicarlo

  • Nombra el panel que utilizaste.
  • Cuenta dónde hiciste clic.
  • Escribe qué resultado apareció.
  • No incluyas cuentas, contraseñas ni datos personales.

Informe final
