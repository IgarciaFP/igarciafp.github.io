UD03. Objetos, estructuras de datos y eventos

Organizar datos y construir interfaces que responden al usuario

Practica escribiendo el código. La copia de contenido está desactivada, como en las demás unidades de DWEC. Escribe los ejemplos en tu editor y comprueba sus resultados. Los bloques que continúan un ejemplo se ejecutan juntos; los ejemplos independientes se prueban por separado.

1. Objetos: definición y construcción

Una aplicación necesita representar entidades: usuarios, productos, reservas o tareas. Cada una reúne datos relacionados y puede tener operaciones propias.

Podríamos representar un producto con variables independientes:

const nombre = "Teclado";
const precio = 35;
const stock = 8;

Pero, al añadir más productos, sería difícil mantener organizados sus datos. Un objeto permite agruparlos bajo una misma identidad:

const producto = {
  nombre: "Teclado",
  precio: 35,
  stock: 8
};

Cada dato es una propiedad, formada por una clave y un valor. Cuando una propiedad contiene una función, hablamos de un método.

Ya hemos utilizado objetos como document: leemos propiedades y llamamos a métodos para trabajar con la página. Ahora aprenderemos a construir nuestros propios objetos.

Los ejemplos de cada subapartado son independientes. Ejecútalos por separado para evitar repetir declaraciones con const o nombres de clases.

1.1. Objetos literales

Un objeto literal se crea escribiendo sus propiedades entre llaves. Las propiedades se separan con comas y cada clave se separa de su valor mediante dos puntos.

const producto = {
  nombre: "Teclado",
  precio: 35,
  disponible: true
};

Esta forma resulta adecuada para representar datos concretos o configuraciones sin definir previamente una clase.

Acceder a una propiedad

Podemos utilizar un punto o corchetes:

console.log(producto.nombre);     // Teclado
console.log(producto["precio"]);  // 35

El punto se utiliza cuando conocemos el nombre de la propiedad. Los corchetes permiten calcularlo o tomarlo de una variable:

const campo = "precio";

console.log(producto[campo]); // 35
console.log(producto.campo);  // undefined

producto.campo busca una propiedad llamada literalmente campo; no utiliza el contenido de la variable.

Modificar, añadir y eliminar propiedades

producto.precio = 40;         // Modifica una propiedad.
producto.categoria = "PC";    // Añade una propiedad.
delete producto.disponible;   // Elimina una propiedad.

Declarar un objeto con const no impide modificar sus propiedades. Impide asignar otro valor a esa variable:

producto.precio = 45; // Permitido.

// producto = {};    // Error: no podemos reasignar una constante.

Propiedades abreviadas

Si la clave y la variable que aporta el valor tienen el mismo nombre, podemos escribirlo una sola vez:

const nombre = "Ratón";
const precio = 20;

const producto = { nombre, precio };

// Equivale a:
// const producto = { nombre: nombre, precio: precio };

Objetos dentro de objetos

Una propiedad también puede contener otro objeto:

const alumno = {
  nombre: "Lucía",
  contacto: {
    email: "lucia@example.com",
    localidad: "Granada"
  }
};

console.log(alumno.contacto.email); // lucia@example.com

Los objetos literales, las propiedades y los métodos constituyen la base de este modelo. Referencia: objetos en JavaScript, MDN.

1.2. Referencias y copia

Si asignamos un objeto a otra variable, ¿tenemos dos objetos?

const original = { nombre: "Teclado", precio: 35 };
const alias = original;

alias.precio = 50;

console.log(original.precio); // 50

No se ha creado otro objeto. Ambas variables permiten acceder al mismo: la asignación copia la referencia.

Esto explica por qué modificar el objeto mediante una variable también afecta a lo que observamos mediante la otra.

Comparar objetos

=== comprueba si las referencias corresponden al mismo objeto, no si sus propiedades tienen iguales valores:

const a = { precio: 35 };
const b = { precio: 35 };
const c = a;

console.log(a === b); // false: son objetos diferentes.
console.log(a === c); // true: es el mismo objeto.

Copia superficial con ...

La sintaxis de expansión permite crear un objeto nuevo a partir de las propiedades de otro:

const original = { nombre: "Teclado", precio: 35 };
const copia = { ...original };

copia.precio = 50;

console.log(original.precio); // 35
console.log(copia.precio);    // 50

También permite copiar y cambiar determinadas propiedades:

const oferta = { ...original, precio: 25 };

El orden importa: si una clave se repite, prevalece el último valor.

Esta copia es superficial: los objetos anidados siguen compartidos.

const original = {
  nombre: "Teclado",
  proveedor: { ciudad: "Granada" }
};

const copia = { ...original };
copia.proveedor.ciudad = "Málaga";

console.log(original.proveedor.ciudad); // Málaga

Se ha copiado el objeto exterior, pero ambos conservan una referencia al mismo proveedor.

Copia profunda de datos

Para estructuras de datos compatibles, structuredClone() permite copiar también los objetos anidados:

const original = {
  nombre: "Teclado",
  proveedor: { ciudad: "Granada" }
};

const copia = structuredClone(original);
copia.proveedor.ciudad = "Málaga";

console.log(original.proveedor.ciudad); // Granada

No es una herramienta universal para duplicar cualquier objeto: no admite funciones ni nodos del DOM, y no conserva los prototipos personalizados como los de nuestras clases. Aquí la utilizaremos con objetos de datos. Referencia: structuredClone(), MDN.

Al pasar un objeto a una función, también se copia el valor de su referencia. La función puede modificar el objeto compartido; reasignar su parámetro no reasigna la variable del código que la llamó.

1.3. Métodos y this

Un método reúne una operación con los datos sobre los que actúa.

const producto = {
  nombre: "Teclado",
  precio: 35,

  calcularTotal(unidades) {
    return this.precio * unidades;
  }
};

console.log(producto.calcularTotal(3)); // 105

En la llamada producto.calcularTotal(3), this se refiere a producto, el objeto desde el que se invoca el método.

Utilizar this.precio permite que la operación trabaje con el precio del objeto que recibe la llamada.

this depende de cómo se llama a la función

Un método no queda ligado permanentemente al objeto en el que se escribió:

const otroProducto = {
  precio: 10,
  calcularTotal: producto.calcularTotal
};

console.log(otroProducto.calcularTotal(3)); // 30

Es la misma función, pero ahora this corresponde a otroProducto.

Si guardamos el método en una variable y lo llamamos sin objeto, perdemos ese receptor:

const calcular = producto.calcularTotal;

// calcular(3);
// En modo estricto, this sería undefined y el acceso a precio fallaría.

Esto también importa al utilizar métodos como callbacks. Una función flecha puede conservar explícitamente la llamada que necesitamos:

const calcularTres = () => producto.calcularTotal(3);

console.log(calcularTres()); // 105

Funciones flecha como métodos

Las funciones flecha no crean su propio this: utilizan el del contexto donde se definieron.

Por eso, para los métodos de un objeto literal que necesitan acceder al propio objeto mediante this, utilizaremos la sintaxis:

calcularTotal(unidades) {
  return this.precio * unidades;
}

1.4. Encadenamiento opcional ?.

No todos los objetos contienen los mismos datos. Un usuario, por ejemplo, puede no haber indicado su dirección.

const usuario = { nombre: "Lucía" };

// usuario.direccion.ciudad;
// Error: direccion es undefined.

El encadenamiento opcional permite detener el acceso si el valor situado a su izquierda es null o undefined. En ese caso, la expresión produce undefined:

console.log(usuario.direccion?.ciudad); // undefined

Podemos combinarlo con ?? para proporcionar un valor alternativo:

const ciudad = usuario.direccion?.ciudad ?? "Sin indicar";

console.log(ciudad); // Sin indicar

Cada posición potencialmente ausente necesita su protección:

const usuario = null;

console.log(usuario?.direccion?.ciudad ?? "Sin indicar");

También puede utilizarse con propiedades calculadas o métodos opcionales:

const campo = "email";
const contacto = null;

console.log(contacto?.[campo]); // undefined

const panel = {};
panel.cerrar?.(); // No llama al método porque no existe.

cerrar?.() no comprueba que cualquier valor sea una función: si cerrar existe pero contiene, por ejemplo, un número, la llamada falla.

Utiliza ?. cuando la ausencia sea una situación prevista. No sustituye la validación de datos obligatorios, no permite acceder a variables sin declarar y no puede colocarse como destino de una asignación. Referencia: encadenamiento opcional, MDN.

1.5. Funciones constructoras y new

Un objeto literal resuelve bien un caso concreto. Si necesitamos crear muchos objetos con la misma estructura, podemos definir cómo se construyen.

Una función constructora inicializa los datos de cada objeto. Por convenio, su nombre comienza con mayúscula:

function Producto(nombre, precio) {
  this.nombre = nombre;
  this.precio = precio;
}

const teclado = new Producto("Teclado", 35);
const raton = new Producto("Ratón", 20);

console.log(teclado.nombre); // Teclado
console.log(raton.nombre);   // Ratón

Para una constructora como esta, new:

  1. Crea un objeto.
  2. Lo enlaza con el prototipo de la constructora.
  3. Ejecuta la función utilizando el objeto como this.
  4. Devuelve el objeto creado.

Cada objeto construido es una instancia y mantiene sus propios datos:

teclado.precio = 40;

console.log(raton.precio); // 20

Las constructoras ayudan a entender el funcionamiento del lenguaje y aparecen en código existente. Para definir tipos con datos y métodos, también disponemos de la sintaxis class, que estudiaremos después de los prototipos.

No omitas new: una llamada normal no realiza estos pasos y, en modo estricto, este constructor fallaría al intentar escribir en this.

1.6. Prototipos y herencia

Si todos los productos necesitan calcular un total, no hace falta crear una función distinta dentro de cada objeto. Podemos compartirla mediante un prototipo.

Un prototipo es otro objeto al que JavaScript recurre cuando no encuentra una propiedad en el objeto consultado.

function Producto(nombre, precio) {
  this.nombre = nombre;
  this.precio = precio;
}

Producto.prototype.calcularTotal = function (unidades) {
  return this.precio * unidades;
};

const teclado = new Producto("Teclado", 35);
const raton = new Producto("Ratón", 20);

console.log(teclado.calcularTotal(2)); // 70
console.log(raton.calcularTotal(2));   // 40

console.log(
  teclado.calcularTotal === raton.calcularTotal
); // true: comparten la función.

Al evaluar teclado.calcularTotal, JavaScript busca primero en teclado. Como allí no encuentra el método, continúa en Producto.prototype.

La búsqueda puede continuar por más prototipos hasta llegar a null. Esta secuencia se denomina cadena de prototipos y permite la herencia.

Propiedad propia y propiedad heredada

console.log(Object.hasOwn(teclado, "nombre"));        // true
console.log(Object.hasOwn(teclado, "calcularTotal")); // false

console.log("calcularTotal" in teclado); // true

Object.hasOwn() comprueba si la propiedad pertenece directamente al objeto. in también tiene en cuenta las heredadas.

Crear un objeto con un prototipo concreto

Object.create() permite elegir directamente el prototipo:

const funcionesProducto = {
  describir() {
    return `${this.nombre}: ${this.precio} €`;
  }
};

const producto = Object.create(funcionesProducto);
producto.nombre = "Monitor";
producto.precio = 180;

console.log(producto.describir()); // Monitor: 180 €

Para consultar el prototipo utilizamos Object.getPrototypeOf():

console.log(
  Object.getPrototypeOf(producto) === funcionesProducto
); // true

No confundas Producto.prototype, la propiedad de la constructora que se utiliza al crear instancias, con el enlace interno al prototipo que tiene cada instancia.

1.7. Clases

Una clase reúne la inicialización y los métodos de un tipo de objeto en una definición.

class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  calcularTotal(unidades) {
    return this.precio * unidades;
  }
}

const producto = new Producto("Teclado", 35);

console.log(producto.calcularTotal(2)); // 70

constructor() se ejecuta al crear una instancia con new. Los métodos de instancia definidos así se comparten mediante el prototipo.

JavaScript sigue utilizando prototipos: las clases ofrecen una sintaxis para trabajar con ese modelo. Sus métodos se ejecutan en modo estricto. Referencia: clases, MDN.

Getters y setters

Permiten ejecutar código al leer o asignar una propiedad. Sirven, por ejemplo, para calcular un valor o controlar una modificación.

class Producto {
  #precio = 0;

  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio; // Utiliza el setter.
  }

  get precio() {
    return this.#precio;
  }

  set precio(nuevoPrecio) {
    if (typeof nuevoPrecio === "number" &&
        nuevoPrecio >= 0 &&
        nuevoPrecio < Infinity) {
      this.#precio = nuevoPrecio;
    }
  }

  get precioConIVA() {
    return this.#precio * 1.21;
  }
}

const producto = new Producto("Teclado", 100);

console.log(producto.precio);       // 100
console.log(producto.precioConIVA); // 121

producto.precio = 200;
console.log(producto.precioConIVA); // 242

producto.precio = -5;
console.log(producto.precio);       // 200

#precio es un campo privado: solo puede accederse a él desde el cuerpo de la clase. El setter controla los cambios y, en este ejemplo, conserva el valor anterior cuando recibe un dato no válido.

Los getters y setters se utilizan como propiedades, sin paréntesis.

El setter escribe en this.#precio. Si escribiera en this.precio, volvería a invocarse a sí mismo indefinidamente.

Miembros estáticos

Un miembro estático pertenece a la clase. Resulta útil para operaciones o valores comunes que no necesitan una instancia concreta.

class Producto {
  static IVA = 0.21;

  static calcularPrecioFinal(precio) {
    return precio * (1 + Producto.IVA);
  }
}

console.log(Producto.IVA);                    // 0.21
console.log(Producto.calcularPrecioFinal(100)); // 121

Se accede a ellos mediante Producto, sin crear un objeto con new. static no significa que el valor sea constante.

Herencia con extends y super

La herencia permite definir una especialización de otra clase. Por ejemplo, un producto digital es un producto que, además, tiene una dirección de descarga:

class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
  }

  describir() {
    return `${this.nombre}: ${this.precio} €`;
  }
}

class ProductoDigital extends Producto {
  constructor(nombre, precio, urlDescarga) {
    super(nombre, precio);
    this.urlDescarga = urlDescarga;
  }

  describir() {
    return `${super.describir()} · Descarga digital`;
  }
}

const curso = new ProductoDigital(
  "Curso de JavaScript",
  30,
  "/descargas/curso.zip"
);

console.log(curso.describir());
// Curso de JavaScript: 30 € · Descarga digital

extends establece la herencia. super(...) ejecuta el constructor de la clase base y debe llamarse antes de utilizar this en el constructor derivado. super.describir() reutiliza su método.

Utiliza herencia cuando exista una relación clara de especialización. Si un objeto simplemente contiene otro —un pedido contiene productos—, represéntalo mediante propiedades.

1.8. Desestructuración

La desestructuración permite extraer valores y guardarlos en variables mediante un patrón. Evita repetir accesos cuando necesitamos varios datos.

Desestructurar objetos

const producto = {
  nombre: "Teclado",
  precio: 35,
  stock: 8
};

const { nombre, precio } = producto;

console.log(nombre); // Teclado
console.log(precio); // 35

En los objetos, la selección se realiza por el nombre de la propiedad; el orden no importa.

Podemos cambiar el nombre de la variable y establecer un valor predeterminado:

const {
  nombre: nombreProducto,
  descuento = 0
} = producto;

console.log(nombreProducto); // Teclado
console.log(descuento);      // 0

nombre: nombreProducto lee la propiedad nombre y crea la variable nombreProducto. No modifica el objeto.

El valor predeterminado se utiliza cuando el dato es undefined; no sustituye null, 0, false ni una cadena vacía.

Desestructurar arrays

En los arrays, la selección se realiza por posición:

const coordenadas = [120, 80];

const [x, y] = coordenadas;

console.log(x); // 120
console.log(y); // 80

Podemos omitir posiciones o recoger las restantes:

const colores = ["rojo", "verde", "azul", "negro"];

const [primero, , tercero] = colores;
const [principal, ...resto] = colores;

console.log(tercero); // azul
console.log(resto);   // ["verde", "azul", "negro"]

En este contexto, ...resto recoge los elementos restantes y debe aparecer al final del patrón.

Desestructurar parámetros

Una función puede extraer directamente las propiedades que necesita:

function mostrarProducto({ nombre, precio }) {
  console.log(`${nombre}: ${precio} €`);
}

mostrarProducto({
  nombre: "Teclado",
  precio: 35,
  stock: 8
});

Si es válido llamar a la función sin argumentos, podemos proporcionar un objeto vacío predeterminado:

function configurarPanel({
  tema = "claro",
  compacto = false
} = {}) {
  console.log(tema, compacto);
}

configurarPanel();                  // claro false
configurarPanel({ tema: "oscuro" }); // oscuro false

Desestructurar no crea copias profundas: si extraemos un objeto anidado, conservamos una referencia a él. Tampoco podemos desestructurar directamente null o undefined. Referencia: desestructuración, MDN.

1.9. Recorrer un objeto: claves, valores y entradas

A veces necesitamos procesar todas las propiedades de un objeto: mostrar una ficha, revisar una configuración o construir una tabla.

Estas operaciones convierten sus propiedades propias enumerables con clave de texto en arrays:

Operación Contenido del array
Object.keys(objeto) Claves
Object.values(objeto) Valores
Object.entries(objeto) Parejas [clave, valor]

En los objetos literales de estos ejemplos, las propiedades que hemos definido son enumerables.

const producto = {
  nombre: "Teclado",
  precio: 35,
  stock: 8
};

console.log(Object.keys(producto));
// ["nombre", "precio", "stock"]

console.log(Object.values(producto));
// ["Teclado", 35, 8]

console.log(Object.entries(producto));
// [["nombre", "Teclado"], ["precio", 35], ["stock", 8]]

Recorrer las claves

for (const clave of Object.keys(producto)) {
  console.log(clave);
}

Recorrer los valores

for (const valor of Object.values(producto)) {
  console.log(valor);
}

Recorrer claves y valores

La desestructuración permite separar cada pareja:

for (const [clave, valor] of Object.entries(producto)) {
  console.log(`${clave}: ${valor}`);
}

// nombre: Teclado
// precio: 35
// stock: 8

Diferencia con for...in

for...in también recorre claves de texto enumerables, pero incluye las heredadas. Si queremos únicamente las propias, debemos filtrarlas:

for (const clave in producto) {
  if (Object.hasOwn(producto, clave)) {
    console.log(clave, producto[clave]);
  }
}

Para recorrer los datos propios de un objeto, Object.keys(), Object.values() y Object.entries() expresan directamente qué necesitamos.

Un objeto literal corriente no puede recorrerse directamente con for...of. En estos ejemplos, for...of recorre los arrays que devuelven esos métodos.

2. Tipos primitivos y sus objetos

En una página web trabajamos continuamente con números y textos: precios, cantidades, nombres, contraseñas o búsquedas. JavaScript proporciona operaciones para comprobarlos, transformarlos y mostrarlos.

Antes de utilizarlas, debemos resolver una aparente contradicción: si una cadena es un valor primitivo, ¿por qué podemos llamar a sus métodos?

const nombre = "Lucía";

console.log(typeof nombre);        // string
console.log(nombre.toUpperCase()); // LUCÍA

2.1. Objetos envoltorio

Los valores primitivos no son objetos. JavaScript tiene siete tipos primitivos: string, number, bigint, boolean, undefined, symbol y null.

Cuando accedemos a una propiedad o método de un primitivo que lo admite, JavaScript lo trata temporalmente mediante su objeto envoltorio. Así podemos utilizar las operaciones de String, Number o Boolean sin crear esos objetos manualmente.

const texto = "JavaScript";
const precio = 12.5;

console.log(texto.length);      // 10
console.log(precio.toFixed(2)); // "12.50"

texto sigue siendo una cadena y precio sigue siendo un número. null y undefined no tienen envoltorio y no permiten acceder directamente a propiedades. Referencia: valores primitivos, MDN.

Convertir un valor no es lo mismo que crear un objeto

Utilizaremos String(), Number() y Boolean() sin new para realizar conversiones:

console.log(String(25));      // "25"
console.log(Number("25"));    // 25
console.log(Boolean(0));      // false

Con new, se crean objetos envoltorio explícitos:

const numero = 25;
const objeto = new Number(25);

console.log(typeof numero); // number
console.log(typeof objeto); // object

console.log(numero === objeto); // false

Estos objetos pueden producir resultados inesperados. Por ejemplo, cualquier objeto es verdadero en un contexto booleano, aunque envuelva false:

const activo = new Boolean(false);

if (activo) {
  console.log("Esta instrucción se ejecuta");
}

Para representar textos, números y booleanos, utiliza valores primitivos. El acceso automático a sus métodos hace innecesario crear objetos envoltorio.

2.2. Números y Math

El tipo number representa tanto números enteros como decimales:

const unidades = 3;
const precio = 19.95;

console.log(typeof unidades); // number
console.log(typeof precio);   // number

Para trabajar con ellos distinguiremos tres tareas: convertir datos, comprobarlos y realizar operaciones.

Convertir texto en números

Los datos de un formulario suelen llegar como texto. Antes de calcular, debemos convertirlos explícitamente.

const entrada = "25.50";
const precio = Number(entrada);

console.log(precio + 5); // 30.5

Number() intenta convertir el contenido completo:

console.log(Number("25.50"));   // 25.5
console.log(Number("25 euros")); // NaN
console.log(Number(""));        // 0
console.log(Number("   "));     // 0

Una cadena vacía se convierte en cero. Por eso, convertir no basta para validar un campo obligatorio.

Number.parseInt() y Number.parseFloat() permiten interpretar un número al principio de una cadena:

console.log(Number.parseInt("24px", 10));   // 24
console.log(Number.parseFloat("19.95 €"));  // 19.95
console.log(Number.parseFloat("precio 19")); // NaN

En parseInt(), el segundo argumento indica la base: 10 corresponde al sistema decimal.

Estas funciones son útiles cuando queremos extraer un prefijo numérico. No sirven para comprobar que todo el texto sea un número válido.

La coma tampoco se interpreta como separador decimal:

console.log(Number("19,95"));            // NaN
console.log(Number.parseFloat("19,95")); // 19

Comprobar un número

Operación Qué comprueba
Number.isNaN(valor) Si el valor es exactamente NaN
Number.isFinite(valor) Si es un número finito
Number.isInteger(valor) Si es un número entero
Number.isSafeInteger(valor) Si es un entero dentro del intervalo de representación segura 
console.log(Number.isNaN(Number("hola"))); // true
console.log(Number.isFinite(25));         // true
console.log(Number.isFinite(Infinity));   // false
console.log(Number.isFinite("25"));       // false
console.log(Number.isInteger(3.5));       // false

Estos métodos no convierten automáticamente cadenas en números.

Para comprobar NaN, no utilices una comparación de igualdad:

console.log(NaN === NaN);       // false
console.log(Number.isNaN(NaN)); // true

Una comprobación de un precio obligatorio puede separar ausencia, conversión y rango:

const entrada = " 19.95 ";
const texto = entrada.trim(); // Elimina espacios de los extremos.
const precio = Number(texto);

if (texto === "") {
  console.log("Introduce un precio.");
} else if (!Number.isFinite(precio) || precio < 0) {
  console.log("El precio debe ser un número finito no negativo.");
} else {
  console.log(`Precio aceptado: ${precio}`);
}

Precisión y presentación

Los números utilizan representación binaria de coma flotante. Algunos decimales no pueden almacenarse exactamente:

console.log(0.1 + 0.2);         // 0.30000000000000004
console.log(0.1 + 0.2 === 0.3); // false

toFixed() permite obtener un texto con un número determinado de decimales:

const total = 0.1 + 0.2;
const texto = total.toFixed(2);

console.log(texto);        // "0.30"
console.log(typeof texto); // string

toFixed() sirve para presentar un resultado; no cambia la precisión del número original.

En operaciones sencillas con importes que tienen dos decimales, trabajar con cantidades enteras de céntimos ayuda a evitar estos errores:

const precioCentimos = 1995;
const unidades = 3;

const totalCentimos = precioCentimos * unidades;

console.log((totalCentimos / 100).toFixed(2)); // "59.85"

Los cálculos con impuestos o descuentos también requieren decidir cómo y cuándo redondear.

Operaciones con Math

Math es un objeto que agrupa constantes y funciones matemáticas. No se utiliza con new.

Operación Utilidad Ejemplo
Math.round(n) Redondear al entero más próximo Math.round(4.6) → 5
Math.floor(n) Redondear hacia menos infinito Math.floor(4.9) → 4
Math.ceil(n) Redondear hacia más infinito Math.ceil(4.1) → 5
Math.trunc(n) Eliminar la parte decimal Math.trunc(-4.9) → -4
Math.abs(n) Obtener el valor absoluto Math.abs(-8) → 8
Math.min(...) Obtener el menor valor Math.min(8, 3, 5) → 3
Math.max(...) Obtener el mayor valor Math.max(8, 3, 5) → 8

floor() y trunc() no son equivalentes para números negativos:

console.log(Math.floor(-4.9)); // -5
console.log(Math.trunc(-4.9)); // -4

En los empates, Math.round() elige el entero situado hacia más infinito:

console.log(Math.round(4.5));  // 5
console.log(Math.round(-4.5)); // -4

También disponemos de constantes como Math.PI:

const radio = 3;
const area = Math.PI * radio ** 2;

console.log(area.toFixed(2)); // "28.27"

Números pseudoaleatorios

Math.random() devuelve un número mayor o igual que 0 y menor que 1.

Podemos transformarlo para simular un dado:

const dado = Math.floor(Math.random() * 6) + 1;

console.log(dado); // Un entero entre 1 y 6.

Multiplicar por seis produce un valor desde 0 hasta menos de 6; floor() obtiene un entero entre 0 y 5; sumar uno desplaza el intervalo a 1–6.

Es adecuado para juegos y simulaciones sencillas. No debe utilizarse para generar contraseñas o tokens de seguridad.

Las operaciones numéricas y las funciones matemáticas forman parte de las herramientas estándar del lenguaje. Referencia: números y cadenas, MDN.

2.3. Cadenas

Una cadena representa texto. Podemos escribirla con comillas simples, dobles o plantillas de cadena:

const nombre = "Lucía";
const modulo = 'DWEC';
const mensaje = `${nombre} estudia ${modulo}.`;

console.log(mensaje); // Lucía estudia DWEC.

Las plantillas permiten insertar expresiones mediante ${...} y escribir texto en varias líneas.

Longitud y acceso por posición

Las posiciones empiezan en cero:

const texto = "JavaScript";

console.log(texto.length); // 10
console.log(texto[0]);     // J
console.log(texto.at(-1)); // t
console.log(texto[20]);    // undefined

at() admite posiciones negativas: -1 indica la última posición.

Técnicamente, length cuenta unidades UTF-16. Algunos símbolos ocupan más de una, por lo que no siempre coincide con la cantidad de caracteres que percibimos:

console.log("😊".length); // 2

Las cadenas son inmutables

Sus métodos no modifican la cadena original: devuelven un resultado nuevo.

const nombre = "Lucía";

nombre.toUpperCase();
console.log(nombre); // Lucía

const mayusculas = nombre.toUpperCase();
console.log(mayusculas); // LUCÍA

Si queremos conservar una transformación en la misma variable, debemos poder reasignarla:

let nombre = "Lucía";
nombre = nombre.toUpperCase();

console.log(nombre); // LUCÍA

Limpiar y transformar

Operación Utilidad
trim() Eliminar espacios y otros caracteres de espacio de ambos extremos
trimStart() Eliminarlos del inicio
trimEnd() Eliminarlos del final
toLowerCase() Convertir a minúsculas
toUpperCase() Convertir a mayúsculas 
const entrada = "  JavaScript  ";
const busqueda = entrada.trim().toLowerCase();

console.log(busqueda); // javascript
console.log(entrada);  // "  JavaScript  "

Podemos encadenar estos métodos porque cada uno devuelve otra cadena.

trim() conserva los espacios interiores:

console.log("  Ana María  ".trim()); // "Ana María"

Buscar texto

const archivo = "informe.pdf";

console.log(archivo.includes("forme"));  // true
console.log(archivo.startsWith("info")); // true
console.log(archivo.endsWith(".pdf"));   // true
console.log(archivo.indexOf("."));       // 7
console.log(archivo.indexOf("x"));       // -1

Utiliza includes() si solo necesitas saber si aparece un fragmento. Utiliza indexOf() si necesitas su posición.

Estas búsquedas distinguen mayúsculas y minúsculas:

const titulo = "Curso de JavaScript";

console.log(titulo.includes("javascript")); // false
console.log(titulo.toLowerCase().includes("javascript")); // true

No utilices directamente el resultado de indexOf() como condición: 0 es una posición válida, pero se interpreta como falso; -1 indica ausencia, pero se interpreta como verdadero.

Extraer fragmentos

slice(inicio, fin) devuelve un fragmento desde inicio hasta antes de fin:

const codigo = "DWEC-2026";

console.log(codigo.slice(0, 4)); // DWEC
console.log(codigo.slice(5));    // 2026
console.log(codigo.slice(-4));   // 2026

Si omitimos fin, continúa hasta el final. Los índices negativos cuentan desde el final.

Reemplazar contenido

Cuando recibe una cadena como búsqueda, replace() sustituye únicamente la primera aparición. replaceAll() sustituye todas:

const texto = "rojo, rojo, azul";

console.log(texto.replace("rojo", "verde"));
// verde, rojo, azul

console.log(texto.replaceAll("rojo", "verde"));
// verde, verde, azul

Separar una cadena

split() divide el texto utilizando un separador y devuelve un array:

const modulos = "DWEC,DIW,SSII";
const lista = modulos.split(",");

console.log(lista);    // ["DWEC", "DIW", "SSII"]
console.log(lista[0]); // DWEC

Trabajaremos con esos arrays en el apartado 3.

Completar una longitud

padStart() y padEnd() añaden texto hasta alcanzar una longitud mínima:

const numero = "7";

console.log(numero.padStart(3, "0")); // "007"
console.log(numero.padEnd(3, "."));   // "7.."

Resultan útiles para presentar códigos o numeraciones. Si la cadena ya alcanza esa longitud, no la recortan.

La inmutabilidad y la representación UTF-16 son importantes para interpretar correctamente estas operaciones. Referencia: String, MDN.

2.4. Expresiones regulares

Los métodos de cadenas resuelven búsquedas concretas, como comprobar si un texto contiene "JavaScript". Pero algunas necesidades describen una forma, no un texto fijo:

  • Un código debe tener tres letras mayúsculas, un guion y cuatro cifras.
  • Queremos localizar cualquier secuencia de dígitos.
  • Necesitamos sustituir varios espacios consecutivos por uno.

Una expresión regular es un patrón que permite reconocer esas coincidencias. En JavaScript se representa mediante un objeto RegExp.

Crear y comprobar un patrón

La forma literal utiliza barras:

const patron = /javascript/i;

console.log(patron.test("Curso de JavaScript")); // true
console.log(patron.test("Curso de CSS"));        // false

test() devuelve un booleano. La bandera i permite ignorar diferencias entre mayúsculas y minúsculas.

También existe el constructor:

const patron = new RegExp("javascript", "i");

Utiliza la forma literal para patrones conocidos al escribir el programa. El constructor permite construirlos a partir de cadenas; esas cadenas se interpretan como patrones, no como texto literal.

Elementos básicos

Sintaxis Significado
^ Inicio del texto, sin la bandera m
$ Final del texto, sin la bandera m
[abc] Un carácter: a, b o c
[A-Z] Una letra entre A y Z, sin incluir Ñ ni letras acentuadas
[0-9] o \d Un dígito del 0 al 9
\s Un carácter de espacio, como espacio, tabulación o salto de línea
. Un carácter, salvo terminadores de línea por defecto
? Cero o una repetición del elemento anterior
* Cero o más repeticiones
+ Una o más repeticiones
{n} Exactamente n repeticiones
{n,m} Entre n y m repeticiones
(abc) Agrupa y captura ese fragmento
a|b Una alternativa: a o b

Los símbolos especiales deben escaparse con \ cuando queremos buscarlos literalmente. Por ejemplo, \. representa un punto.

Validar un código completo

const patron = /^[A-Z]{3}-\d{4}$/;

console.log(patron.test("ABC-2026"));  // true
console.log(patron.test("AB-2026"));   // false
console.log(patron.test("abc-2026"));  // false
console.log(patron.test("ABC-2026X")); // false

El patrón se interpreta así:

  1. ^: comienza el texto.
  2. [A-Z]{3}: aparecen tres letras mayúsculas entre A y Z.
  3. -: aparece un guion.
  4. \d{4}: aparecen cuatro dígitos.
  5. $: termina el texto.

Sin los límites ^ y $, test() busca una coincidencia en cualquier parte:

console.log(/\d{4}/.test("Referencia 2026 pendiente")); // true
console.log(/^\d{4}$/.test("Referencia 2026 pendiente")); // false

Banderas habituales

Bandera Efecto
i Ignora diferencias entre mayúsculas y minúsculas
g Permite buscar todas las coincidencias en operaciones como match() o replace()
m Hace que ^ y $ también reconozcan límites de línea
s Permite que . coincida con terminadores de línea
u Activa el tratamiento Unicode del patrón

Las banderas pueden combinarse, como en /javascript/gi.

Extraer coincidencias

match() puede buscar todas las secuencias de dígitos de una cadena:

const texto = "Pedido 125: 3 unidades";
const numeros = texto.match(/\d+/g);

console.log(numeros); // ["125", "3"]

El resultado contiene cadenas. Si no hay coincidencias, match() devuelve null:

console.log("Sin cantidades".match(/\d+/g)); // null

Reemplazar mediante un patrón

Podemos convertir cualquier secuencia de espacios, tabulaciones o saltos de línea en un único espacio:

const entrada = "  Ana    María  ";
const nombre = entrada.trim().replace(/\s+/g, " ");

console.log(nombre); // Ana María

La bandera g hace que replace() sustituya todas las coincidencias del patrón.

Extraer partes con grupos

Los paréntesis permiten capturar fragmentos:

const resultado = /^([A-Z]{3})-(\d{4})$/.exec("ABC-2026");

if (resultado !== null) {
  console.log(resultado[0]); // ABC-2026: coincidencia completa.
  console.log(resultado[1]); // ABC: primer grupo.
  console.log(resultado[2]); // 2026: segundo grupo.
}

exec() devuelve información de una coincidencia o null. Los grupos permiten trabajar por separado con las partes reconocidas.

Dos errores frecuentes

Al construir el patrón desde una cadena, la barra inversa debe escaparse también en la cadena:

const literal = /^\d{4}$/;
const constructor = new RegExp("^\\d{4}$");

console.log(literal.test("2026"));     // true
console.log(constructor.test("2026")); // true

Además, las expresiones con g conservan una posición de búsqueda en lastIndex. Reutilizarlas con test() puede producir resultados distintos entre llamadas:

const patron = /\d/g;

console.log(patron.test("7")); // true
console.log(patron.test("7")); // false

Para comprobar repetidamente si cada valor cumple un formato, utiliza un patrón sin g:

const patron = /^\d$/;

console.log(patron.test("7")); // true
console.log(patron.test("7")); // true

Una expresión regular comprueba un patrón textual. Si un código coincide con ABC-2026, eso no demuestra que exista en nuestra aplicación. La comprobación del formato y la comprobación del significado son tareas distintas. Referencia: expresiones regulares, MDN.

3. Arrays

Un objeto permite reunir los datos de un producto. Para representar un catálogo necesitamos, además, una colección de productos.

Un array almacena una secuencia de elementos a los que accedemos mediante su posición:

const productos = ["Teclado", "Ratón", "Monitor"];

console.log(productos[0]); // Teclado

Podemos recorrerlos, añadir o eliminar elementos, buscar coincidencias y obtener nuevas colecciones.

Antes de utilizar un método, debemos identificar qué devuelve y si modifica el array original. Un método puede cambiar el array y devolver un dato diferente, como su nueva longitud.

3.1. Estructura y recorrido

Crear un array y acceder a sus elementos

La forma habitual de crear un array es escribir sus elementos entre corchetes, separados por comas:

const modulos = ["DWEC", "DIW", "SSII"];
const pendientes = [];

console.log(modulos[0]);     // DWEC
console.log(modulos[2]);     // SSII
console.log(modulos.length); // 3
console.log(modulos.at(-1)); // SSII

El primer índice es 0. En un array sin huecos, el último es length - 1.

at() permite utilizar posiciones negativas para contar desde el final. Los corchetes no interpretan -1 como la última posición:

console.log(modulos[-1]);    // undefined
console.log(modulos.at(-1)); // SSII

Acceder a una posición inexistente devuelve undefined.

Arrays de objetos

Un array puede contener valores de cualquier tipo. Para representar una colección, normalmente utilizaremos elementos con una estructura coherente:

const productos = [
  { id: 1, nombre: "Teclado", precio: 35 },
  { id: 2, nombre: "Ratón", precio: 20 },
  { id: 3, nombre: "Monitor", precio: 180 }
];

console.log(productos[1].nombre); // Ratón

Primero seleccionamos un elemento mediante su índice; después accedemos a una propiedad del objeto.

Comprobar si un valor es un array

Los arrays son objetos, por lo que typeof no permite distinguirlos:

console.log(typeof []); // object

Utilizamos Array.isArray():

console.log(Array.isArray([])); // true
console.log(Array.isArray({})); // false

Recorrer los valores con for...of

Es una opción clara cuando necesitamos trabajar con cada elemento:

const precios = [35, 20, 180];

for (const precio of precios) {
  console.log(`${precio} €`);
}

Podemos utilizar break para detener el recorrido y continue para pasar a la siguiente iteración.

Recorrer mediante índices

Un for clásico permite controlar directamente la posición:

const modulos = ["DWEC", "DIW", "SSII"];

for (let i = 0; i < modulos.length; i++) {
  console.log(`${i}: ${modulos[i]}`);
}

La condición utiliza <, no <=: la posición modulos.length queda fuera de los elementos existentes.

También podemos obtener índices y valores con entries() y desestructuración:

for (const [indice, modulo] of modulos.entries()) {
  console.log(`${indice}: ${modulo}`);
}

Recorrer con forEach()

forEach() ejecuta una función para cada elemento existente:

const modulos = ["DWEC", "DIW", "SSII"];

modulos.forEach((modulo, indice) => {
  console.log(`${indice}: ${modulo}`);
});

La función que recibe es un callback: el método la llama durante el recorrido, proporcionándole el elemento, su índice y el propio array. Declaramos solo los parámetros que necesitamos.

forEach() devuelve undefined. Es adecuado para realizar una acción con cada elemento, pero no para construir un nuevo array con los resultados.

No admite break. Un return dentro de su callback termina esa llamada concreta, no todo el recorrido.

Para recorrer arrays, utiliza for...of, un for clásico o sus métodos. for...in recorre nombres de propiedades y puede incluir propiedades adicionales o heredadas.

3.2. Modificar

Un array declarado con const puede modificar su contenido. Lo que no podemos hacer es reasignar la variable:

const tareas = ["Estudiar"];

tareas[0] = "Repasar";
tareas.push("Practicar");

// tareas = []; // Error: reasignación de una constante.

Añadir y eliminar en los extremos

Método Acción sobre el array Valor que devuelve
push(elemento) Añade al final Nueva longitud
pop() Elimina el último Elemento eliminado
unshift(elemento) Añade al principio Nueva longitud
shift() Elimina el primero Elemento eliminado 
const tareas = ["Estudiar"];

const longitud = tareas.push("Practicar");

console.log(tareas);   // ["Estudiar", "Practicar"]
console.log(longitud); // 2

const retirada = tareas.pop();

console.log(retirada); // Practicar
console.log(tareas);   // ["Estudiar"]

En un array vacío, pop() y shift() devuelven undefined.

Insertar, eliminar y sustituir con splice()

Su estructura básica es:

array.splice(inicio, cantidadAEliminar, ...elementosNuevos);

Modifica el array y devuelve otro array con los elementos eliminados.

const tareas = ["Leer", "Programar", "Revisar"];

const eliminadas = tareas.splice(1, 1);

console.log(tareas);     // ["Leer", "Revisar"]
console.log(eliminadas); // ["Programar"]

Si la cantidad que eliminamos es cero, insertamos sin retirar elementos:

tareas.splice(1, 0, "Practicar");

console.log(tareas); // ["Leer", "Practicar", "Revisar"]

Podemos eliminar e insertar en la misma operación:

tareas.splice(0, 1, "Investigar");

console.log(tareas); // ["Investigar", "Practicar", "Revisar"]

Evitar huecos

delete elimina una propiedad, pero no desplaza los elementos ni reduce la longitud:

const letras = ["A", "B", "C"];

delete letras[1];

console.log(letras.length); // 3
console.log(letras[1]);     // undefined
console.log(1 in letras);   // false: la posición no existe.

Asignar un valor a un índice muy alejado también crea huecos. Para mantener una lista continua, utiliza métodos como push() y splice().

Invertir y ordenar

reverse() invierte el orden actual:

const numeros = [3, 1, 2];

numeros.reverse();

console.log(numeros); // [2, 1, 3]

sort() ordena el array, pero sin una función de comparación utiliza el orden de las representaciones textuales:

const numeros = [8, 100, 25];

numeros.sort();

console.log(numeros); // [100, 25, 8]

Para ordenar números finitos de menor a mayor:

numeros.sort((a, b) => a - b);

console.log(numeros); // [8, 25, 100]

La función de comparación devuelve:

  • Un número negativo si a debe ir antes que b.
  • Un número positivo si a debe ir después.
  • Cero si ambos tienen la misma prioridad de ordenación.

Para ordenar de mayor a menor, utilizamos (a, b) => b - a.

Con objetos podemos comparar una propiedad:

const productos = [
  { nombre: "Monitor", precio: 180 },
  { nombre: "Ratón", precio: 20 },
  { nombre: "Teclado", precio: 35 }
];

productos.sort((a, b) => a.precio - b.precio);

Para ordenar nombres según las reglas de un idioma, podemos utilizar localeCompare():

const nombres = ["Zoe", "Álvaro", "Beatriz"];

nombres.sort((a, b) => a.localeCompare(b, "es"));

console.log(nombres); // ["Álvaro", "Beatriz", "Zoe"]

sort() y reverse() modifican el original y devuelven ese mismo array. Referencia: ordenación con sort(), MDN.

Alternativas que conservan el original

JavaScript dispone de métodos que devuelven una nueva versión del array:

Modifica el original Devuelve un nuevo array
sort(comparador) toSorted(comparador)
reverse() toReversed()
splice(inicio, cantidad, ...) toSpliced(inicio, cantidad, ...)
array[indice] = valor array.with(indice, valor) 
const precios = [35, 20, 180];

const ordenados = precios.toSorted((a, b) => a - b);
const actualizados = precios.with(0, 40);

console.log(precios);      // [35, 20, 180]
console.log(ordenados);    // [20, 35, 180]
console.log(actualizados); // [40, 20, 180]

toSpliced() devuelve el array resultante de aplicar los cambios, mientras que splice() devuelve los elementos retirados.

Estas copias son superficiales: los objetos contenidos siguen compartidos. Referencia: arrays y métodos de copia, MDN.

3.3. Buscar

Elegimos el método según el resultado que necesitamos: una respuesta booleana, un elemento o su posición.

Comprobar si aparece un valor

includes() devuelve true o false:

const modulos = ["DWEC", "DIW", "SSII"];

console.log(modulos.includes("DIW")); // true
console.log(modulos.includes("diw")); // false

Obtener la posición de un valor

indexOf() devuelve el índice de la primera coincidencia o -1 si no la encuentra:

const modulos = ["DWEC", "DIW", "SSII"];

console.log(modulos.indexOf("DIW")); // 1
console.log(modulos.indexOf("FOL")); // -1

No utilices el resultado directamente como condición: el índice 0 se interpreta como falso y -1 como verdadero.

Buscar mediante una condición

Para buscar un objeto por una propiedad, utilizamos find():

const productos = [
  { id: 1, nombre: "Teclado", precio: 35 },
  { id: 2, nombre: "Ratón", precio: 20 },
  { id: 3, nombre: "Monitor", precio: 180 }
];

const encontrado = productos.find(producto => producto.id === 2);

console.log(encontrado?.nombre ?? "Producto no encontrado");
// Ratón

find() devuelve el primer elemento que cumple la condición. Si ninguno la cumple, devuelve undefined.

El callback actúa como un criterio de selección: devuelve verdadero cuando el elemento nos interesa.

findIndex() realiza la misma búsqueda, pero devuelve el índice o -1:

const indice = productos.findIndex(producto => producto.id === 2);

if (indice !== -1) {
  productos.splice(indice, 1);
}

La comprobación es necesaria: splice(-1, 1) eliminaría el último elemento aunque no hubiéramos encontrado el producto.

Para buscar desde el final disponemos de findLast() y findLastIndex():

const notas = [4, 7, 3, 8];

console.log(notas.findLast(nota => nota < 5));      // 3
console.log(notas.findLastIndex(nota => nota < 5)); // 2

Comprobar si alguno o todos cumplen una condición

const notas = [6, 8, 4];

console.log(notas.some(nota => nota < 5));   // true
console.log(notas.every(nota => nota >= 5)); // false
  • some() responde si al menos uno cumple la condición.
  • every() responde si todos la cumplen.

Ambos pueden terminar antes de recorrer todo el array, en cuanto conocen la respuesta.

En un array vacío, some() devuelve false y every() devuelve true. Si necesitamos que existan elementos y que todos cumplan una condición, comprobamos también la longitud:

const notas = [];

const todosAprobados =
  notas.length > 0 && notas.every(nota => nota >= 5);

console.log(todosAprobados); // false

Buscar objetos no equivale a comparar sus propiedades

const producto = { id: 1 };
const productos = [producto];

console.log(productos.includes(producto));  // true
console.log(productos.includes({ id: 1 })); // false

El segundo objeto tiene el mismo contenido, pero es otro objeto. Para buscar por el identificador, utilizamos find() o some() con una condición.

3.4. Transformar

Transformar una colección consiste en obtener otros datos a partir de ella: seleccionar productos, calcular precios, extraer nombres o sumar un pedido.

Extraer una parte con slice()

slice(inicio, fin) devuelve un nuevo array desde inicio hasta antes de fin:

const letras = ["A", "B", "C", "D"];

console.log(letras.slice(1, 3)); // ["B", "C"]
console.log(letras.slice(-2));  // ["C", "D"]
console.log(letras);            // ["A", "B", "C", "D"]

No confundas los nombres: slice() extrae sin modificar; splice() modifica.

Copiar y combinar

Podemos utilizar la expansión ...:

const obligatorios = ["DWEC", "DIW"];
const optativos = ["Inglés"];

const copia = [...obligatorios];
const todos = [...obligatorios, ...optativos];

console.log(todos); // ["DWEC", "DIW", "Inglés"]

También podemos combinar con concat():

const todos = obligatorios.concat(optativos);

Estas operaciones crean un array nuevo, pero no duplican los objetos que contiene:

const originales = [{ nombre: "Teclado", precio: 35 }];
const copia = [...originales];

copia[0].precio = 50;

console.log(originales[0].precio); // 50

Transformar cada elemento con map()

map() construye un array con el resultado que devuelve el callback para cada elemento:

const precios = [10, 20, 30];

const duplicados = precios.map(precio => precio * 2);

console.log(duplicados); // [20, 40, 60]
console.log(precios);    // [10, 20, 30]

Sirve, por ejemplo, para extraer una propiedad:

const productos = [
  { nombre: "Teclado", precio: 35 },
  { nombre: "Ratón", precio: 20 }
];

const nombres = productos.map(producto => producto.nombre);

console.log(nombres); // ["Teclado", "Ratón"]

Si la función flecha utiliza llaves, debemos escribir return:

const nombres = productos.map(producto => {
  return producto.nombre;
});

Sin return, cada llamada devolvería undefined.

Para obtener objetos modificados sin alterar los originales, creamos un objeto nuevo en cada llamada:

const ofertas = productos.map(producto => ({
  ...producto,
  precio: producto.precio * 0.9
}));

Los paréntesis permiten devolver directamente un objeto literal desde la función flecha.

map() crea un array nuevo, pero el callback puede modificar objetos compartidos si escribimos en sus propiedades. La ausencia de modificaciones depende también del código del callback. Referencia: map(), MDN.

Seleccionar elementos con filter()

filter() devuelve un array con todos los elementos que cumplen una condición:

const notas = [4, 7, 9, 3, 5];

const aprobadas = notas.filter(nota => nota >= 5);

console.log(aprobadas); // [7, 9, 5]
console.log(notas);     // [4, 7, 9, 3, 5]

Si no hay coincidencias, devuelve [].

La diferencia con find() es el resultado: find() devuelve un único elemento o undefined; filter() siempre devuelve un array.

Cuando filtramos objetos, el nuevo array conserva referencias a los objetos seleccionados.

Acumular un resultado con reduce()

reduce() combina los elementos para obtener un resultado acumulado. Una aplicación habitual es calcular un total:

const importes = [35, 20, 180];

const total = importes.reduce((acumulado, importe) => {
  return acumulado + importe;
}, 0);

console.log(total); // 235

El segundo argumento, 0, es el valor inicial del acumulador:

Paso Acumulado anterior Importe Nuevo acumulado
1 0 35 35
2 35 20 55
3 55 180 235

Cada valor devuelto por el callback se utiliza como acumulador en la siguiente llamada.

En un carrito podemos sumar el importe de cada línea:

const carrito = [
  { nombre: "Teclado", precio: 35, unidades: 2 },
  { nombre: "Ratón", precio: 20, unidades: 1 }
];

const total = carrito.reduce(
  (acumulado, producto) =>
    acumulado + producto.precio * producto.unidades,
  0
);

console.log(total); // 90

Proporcionar un valor inicial también permite procesar un array vacío: en este caso, el resultado será 0. Sin valor inicial, reduce() falla si el array está vacío. Referencia: reduce(), MDN.

Convertir un array en texto con join()

join() une los elementos utilizando el separador indicado:

const modulos = ["DWEC", "DIW", "SSII"];

console.log(modulos.join(", ")); // DWEC, DIW, SSII

Es útil para presentar una lista como texto. Si no indicamos separador, utiliza una coma.

Combinar operaciones

Cada método expresa una tarea. Podemos encadenarlos cuando el resultado de uno sirve como entrada del siguiente:

const productos = [
  { nombre: "Teclado", precio: 35, stock: 8 },
  { nombre: "Ratón", precio: 20, stock: 0 },
  { nombre: "Monitor", precio: 180, stock: 3 }
];

const listado = productos
  .filter(producto => producto.stock > 0)
  .toSorted((a, b) => a.precio - b.precio)
  .map(producto => producto.nombre)
  .join(", ");

console.log(listado); // Teclado, Monitor

El proceso selecciona los productos disponibles, los ordena por precio, extrae sus nombres y construye el texto final.

4. Fecha y hora

Una aplicación utiliza fechas para gestionar reservas, ordenar publicaciones o comprobar si una entrega está dentro de plazo.

Antes de programar, debemos distinguir dos necesidades:

  • Representar un instante: cuándo se envió un formulario.
  • Representar una fecha de calendario: el día de un cumpleaños, sin una hora concreta.

En este apartado utilizaremos Date. Un objeto Date representa un instante mediante los milisegundos transcurridos desde el 1 de enero de 1970 a las 00:00:00 UTC.

UTC es una referencia horaria común. El mismo instante puede mostrarse con horas e incluso fechas distintas según la zona horaria.

4.1. Crear fechas y leer sus componentes

Obtener la fecha y hora actuales

const ahora = new Date();

console.log(ahora);

El resultado depende del momento de ejecución. El objeto conserva ese instante: no se actualiza automáticamente mientras pasa el tiempo.

Date.now() devuelve directamente la marca temporal actual en milisegundos:

const marcaTemporal = Date.now();

console.log(typeof marcaTemporal); // number

Utilizamos new Date() cuando necesitamos un objeto con métodos para consultar o presentar la fecha; Date.now(), cuando necesitamos el valor numérico.

Crear una fecha a partir de sus componentes

const clase = new Date(2026, 10, 11, 9, 30);

Los argumentos corresponden a:

new Date(año, mes, día, horas, minutos, segundos, milisegundos);

Este constructor interpreta los componentes en la zona horaria local del entorno.

Los meses comienzan en cero: enero es 0 y diciembre es 11. Por tanto, el ejemplo representa el 11 de noviembre de 2026 a las 09:30.

Si omitimos la hora, se utiliza medianoche:

const fecha = new Date(2026, 10, 11);

En la construcción por componentes, los años entre 0 y 99 se interpretan como años entre 1900 y 1999. En estos ejemplos utilizaremos años completos de cuatro cifras.

Crear una fecha a partir de texto

Para representar un instante sin ambigüedad, utilizaremos una cadena de fecha y hora con zona explícita:

const envio = new Date("2026-11-11T09:30:00Z");

La T separa la fecha de la hora y la Z indica UTC.

También podemos indicar un desplazamiento respecto a UTC:

const a = new Date("2026-11-11T09:30:00Z");
const b = new Date("2026-11-11T10:30:00+01:00");

console.log(a.getTime() === b.getTime()); // true

Ambas cadenas representan el mismo instante.

Un desplazamiento como +01:00 describe la diferencia con UTC en ese instante; no incluye las reglas de una zona geográfica como Europe/Madrid.

Evita formatos ambiguos como "11/12/2026": no debes depender de que todos los entornos interpreten igual el orden del día y del mes.

Cuidado con las cadenas sin zona horaria

Estas dos expresiones siguen reglas diferentes:

new Date("2026-11-11");          // Fecha sin hora: medianoche UTC.
new Date("2026-11-11T09:30:00"); // Fecha y hora sin zona: hora local.

La primera puede mostrarse como el día anterior en una zona situada al oeste de UTC.

Para una fecha de calendario sin hora, como un cumpleaños, suele ser preferible conservar el texto "2026-11-11" o sus componentes hasta que realmente necesitemos realizar operaciones con ellos.

Leer componentes

const fecha = new Date(2026, 10, 11, 9, 30);
Método Resultado en el ejemplo Significado
getFullYear() 2026 Año
getMonth() 10 Mes, desde 0 hasta 11
getDate() 11 Día del mes
getDay() 3 Día de la semana: domingo 0, sábado 6
getHours() 9 Hora
getMinutes() 30 Minutos
getSeconds() 0 Segundos
getMilliseconds() 0 Milisegundos 
console.log(fecha.getMonth() + 1); // 11: mes para mostrar al usuario.

No confundas getDate() con getDay(): el primero obtiene el día del mes y el segundo, el de la semana.

Estos métodos consultan los componentes locales. Sus variantes UTC, como getUTCFullYear() o getUTCHours(), consultan el mismo instante utilizando UTC.

getTime() devuelve la marca temporal en milisegundos, independientemente de la zona utilizada para mostrarla.

Detectar una fecha no válida

const fecha = new Date("texto sin fecha");

console.log(fecha.toString());           // Invalid Date
console.log(Number.isNaN(fecha.getTime())); // true

Una fecha no válida sigue siendo un objeto Date; por eso debemos comprobar su valor temporal.

Además, el constructor por componentes normaliza los desbordamientos:

const fecha = new Date(2026, 1, 30);

console.log(fecha.getMonth()); // 2: marzo.
console.log(fecha.getDate());  // 2.

El 30 de febrero se transforma en el 2 de marzo. Por tanto, obtener un Date válido no demuestra que los componentes originales correspondieran a una fecha existente. Para validar una entrada por componentes, debemos comprobar sus rangos y comparar los valores resultantes con los introducidos.

Las diferencias entre hora local, UTC y normalización forman parte del comportamiento de Date. Referencia: Date, MDN.

4.2. Operar con fechas

Comparar instantes

Las marcas temporales permiten ordenar fechas o comprobar si ha vencido un plazo:

const entrega = new Date("2026-11-11T18:00:00Z");
const limite = new Date("2026-11-11T20:00:00Z");

console.log(entrega.getTime() <= limite.getTime()); // true

Dos objetos distintos pueden representar el mismo instante. Para comprobarlo, comparamos sus marcas temporales:

const a = new Date("2026-11-11T09:00:00Z");
const b = new Date("2026-11-11T09:00:00Z");

console.log(a === b);                     // false
console.log(a.getTime() === b.getTime()); // true

Como vimos con los objetos, === entre dos fechas comprueba su identidad, no su contenido.

Calcular tiempo transcurrido

La diferencia entre marcas temporales se expresa en milisegundos:

const inicio = new Date("2026-11-11T09:00:00Z");
const fin = new Date("2026-11-11T11:30:00Z");

const diferenciaMs = fin.getTime() - inicio.getTime();
const minutos = diferenciaMs / (1000 * 60);
const horas = diferenciaMs / (1000 * 60 * 60);

console.log(minutos); // 150
console.log(horas);   // 2.5

Las unidades deben quedar claras:

Unidad Milisegundos
Un segundo 1000
Un minuto 1000 * 60
Una hora 1000 * 60 * 60
Un periodo de 24 horas 1000 * 60 * 60 * 24

Dividir entre los milisegundos de 24 horas calcula periodos de esa duración. No siempre calcula correctamente días de calendario locales, porque los cambios de hora pueden producir días de 23 o 25 horas.

Modificar componentes

Los métodos que comienzan por set modifican el objeto:

const cita = new Date(2026, 10, 11, 9, 30);

cita.setHours(10, 45, 0, 0);

console.log(cita.getHours());   // 10
console.log(cita.getMinutes()); // 45

Algunos métodos habituales son:

Método Modifica
setFullYear(año) Año
setMonth(mes) Mes, desde 0
setDate(día) Día del mes
setHours(horas, minutos, segundos, ms) Hora y componentes indicados
setTime(milisegundos) Marca temporal completa

Los argumentos opcionales que omitimos suelen conservar el componente actual. En el ejemplo hemos indicado segundos y milisegundos para dejarlos en cero.

Estos métodos devuelven la nueva marca temporal, no un objeto Date. Por eso no debemos encadenarlos como si devolvieran la fecha.

Copiar antes de modificar

Asignar una fecha a otra variable no la duplica:

const original = new Date(2026, 10, 11);
const alias = original;

alias.setDate(15);

console.log(original.getDate()); // 15

Para conservar el original, creamos otro objeto con la misma marca temporal:

const original = new Date(2026, 10, 11);
const copia = new Date(original.getTime());

copia.setDate(15);

console.log(original.getDate()); // 11
console.log(copia.getDate());    // 15

Añadir días de calendario

Podemos sumar días utilizando getDate() y setDate(). El objeto ajusta los cambios de mes y año:

const inicio = new Date(2026, 10, 28, 9, 0);
const vencimiento = new Date(inicio.getTime());

vencimiento.setDate(vencimiento.getDate() + 7);

console.log(vencimiento.getFullYear()); // 2026
console.log(vencimiento.getMonth());    // 11: diciembre.
console.log(vencimiento.getDate());     // 5.
console.log(vencimiento.getHours());    // 9.

Esta operación trabaja con el calendario local. Si cruza un cambio de horario, la duración transcurrida puede no ser exactamente 7 × 24 horas. Además, una hora local inexistente o repetida durante ese cambio requiere que el entorno la resuelva. Referencia: setDate() y cambios de horario, MDN.

Añadir una duración exacta

Si el requisito dice «dentro de 48 horas», sumamos milisegundos:

const inicio = new Date("2026-11-11T09:00:00Z");
const duracionMs = 48 * 60 * 60 * 1000;

const fin = new Date(inicio.getTime() + duracionMs);

console.log(fin.toISOString());
// "2026-11-13T09:00:00.000Z"

La elección depende del requisito:

  • «Dentro de dos días, a la misma hora local»: operación de calendario.
  • «Cuando hayan transcurrido 48 horas»: operación sobre la marca temporal.

Sumar meses exige decidir qué hacer al final del mes

const fecha = new Date(2026, 0, 31);

fecha.setMonth(fecha.getMonth() + 1);

console.log(fecha.getMonth()); // 2: marzo.
console.log(fecha.getDate());  // 3.

Al intentar mantener el día 31 en febrero, la fecha desborda a marzo.

Para una cuota mensual, puede que la regla correcta sea utilizar el último día de febrero. Esa decisión pertenece a la aplicación: no debemos asumir que setMonth() la aplica automáticamente.

4.3. Mostrar fechas

Una fecha debe presentarse de forma comprensible para quien utiliza la aplicación. El orden de día, mes y año, los nombres de los meses y el formato horario dependen del idioma y de la región.

Presentación local sencilla

const fecha = new Date(2026, 10, 11, 9, 30);

console.log(fecha.toLocaleDateString("es-ES"));
console.log(fecha.toLocaleTimeString("es-ES"));
console.log(fecha.toLocaleString("es-ES"));

Estos métodos permiten mostrar, respectivamente, la fecha, la hora o ambas.

Sin opciones de zona horaria, utilizan la del entorno. El formato exacto puede variar ligeramente según la implementación y sus datos de localización.

Configurar el formato con Intl.DateTimeFormat

Podemos crear un formateador y reutilizarlo:

const formato = new Intl.DateTimeFormat("es-ES", {
  dateStyle: "long",
  timeStyle: "short",
  timeZone: "Europe/Madrid"
});

const fecha = new Date("2026-11-11T09:30:00Z");

console.log(formato.format(fecha));
// Una presentación como: "11 de noviembre de 2026, 10:30".

Aquí distinguimos dos decisiones:

  • "es-ES" establece las convenciones de presentación.
  • "Europe/Madrid" establece la zona horaria.

Elegir español no implica utilizar la hora de España. Debemos indicar la zona si queremos que todos los usuarios vean el instante según la misma referencia.

Intl.DateTimeFormat aplica las reglas de la zona elegida, incluidos sus cambios de horario. Formatear no modifica el objeto Date. Referencia: Intl.DateTimeFormat, MDN.

Elegir componentes concretos

También podemos indicar qué información necesitamos:

const formato = new Intl.DateTimeFormat("es-ES", {
  weekday: "long",
  day: "numeric",
  month: "long",
  year: "numeric",
  timeZone: "Europe/Madrid"
});

const fecha = new Date("2026-11-11T09:30:00Z");

console.log(formato.format(fecha));
// Una presentación como: "miércoles, 11 de noviembre de 2026".

Para mostrar únicamente horas y minutos:

const formatoHora = new Intl.DateTimeFormat("es-ES", {
  hour: "2-digit",
  minute: "2-digit",
  hourCycle: "h23",
  timeZone: "Europe/Madrid"
});

console.log(formatoHora.format(fecha)); // "10:30"

Utiliza los estilos generales dateStyle y timeStyle, o las opciones de componentes como year, month y hour. No combines ambos enfoques en el mismo formateador.

Representar un instante como texto ISO

toISOString() devuelve una cadena estandarizada en UTC:

const fecha = new Date("2026-11-11T10:30:00+01:00");

console.log(fecha.toISOString());
// "2026-11-11T09:30:00.000Z"

Resulta útil para intercambiar instantes entre aplicaciones. Para mostrar fechas a las personas, utilizaremos formatos localizados.

No uses toISOString().slice(0, 10) para obtener automáticamente el día local: al convertir a UTC, el día puede cambiar.

const fecha = new Date("2026-11-11T00:30:00+01:00");

console.log(fecha.toISOString());
// "2026-11-10T23:30:00.000Z"

En la zona indicada por el texto original ya era día 11, mientras que en UTC todavía era día 10.

Ejemplo: mostrar un plazo de entrega

const limite = new Date("2026-11-30T22:59:00Z");

const formato = new Intl.DateTimeFormat("es-ES", {
  dateStyle: "full",
  timeStyle: "short",
  timeZone: "Europe/Madrid"
});

const plazoAbierto = Date.now() <= limite.getTime();

console.log(`Entrega hasta: ${formato.format(limite)}`);
console.log(plazoAbierto ? "Plazo abierto" : "Plazo cerrado");

La comparación utiliza marcas temporales y la presentación utiliza una zona explícita. Así, el límite representa el mismo instante aunque quien abra la página tenga otra configuración horaria.

En una aplicación real, esta comprobación sirve para informar en la interfaz. La aceptación de una entrega debe comprobarse también en el servidor, porque el reloj del dispositivo del usuario puede ser incorrecto.

5. Iterables y colecciones

Un array permite guardar una secuencia de elementos, pero no todas las colecciones tienen las mismas necesidades:

  • Para conservar una lista ordenada de tareas, utilizamos un array.
  • Para asociar cada identificador con su producto, podemos utilizar un Map.
  • Para almacenar etiquetas sin repeticiones, podemos utilizar un Set.

Estas estructuras comparten una característica: son iterables, por lo que podemos recorrer sus elementos con for...of.

5.1. Iterables

Un iterable es un valor que proporciona un mecanismo para obtener sus elementos de forma secuencial.

Ya hemos trabajado con dos tipos de iterables: arrays y cadenas.

const modulos = ["DWEC", "DIW", "SSII"];

for (const modulo of modulos) {
  console.log(modulo);
}

for (const letra of "Web") {
  console.log(letra);
}

Ser iterable no significa tener índices ni una propiedad length. Significa que JavaScript sabe cómo solicitar sus elementos durante un recorrido.

Operaciones que utilizan iterables

Además de for...of, podemos utilizar la expansión y la desestructuración:

const texto = "Web";

const letras = [...texto];
const [primera, segunda] = texto;

console.log(letras);  // ["W", "e", "b"]
console.log(primera); // W
console.log(segunda); // e

También podemos convertir un iterable en array mediante Array.from():

const letras = Array.from("Web");

console.log(letras); // ["W", "e", "b"]

Esto resulta útil cuando necesitamos métodos de array, como map() o filter(), sobre una colección que no los proporciona.

Un objeto literal corriente no es iterable

const producto = {
  nombre: "Teclado",
  precio: 35
};

// for (const dato of producto) { ... }
// Error: producto no es iterable.

Podemos obtener un array con sus entradas y recorrerlo:

for (const [clave, valor] of Object.entries(producto)) {
  console.log(clave, valor);
}

La expansión dentro de un array y dentro de un objeto realiza operaciones distintas:

const copia = { ...producto }; // Copia propiedades.

// const datos = [...producto];
// Error: requiere que producto sea iterable.

Cómo funciona el recorrido

Un iterable proporciona un método identificado mediante Symbol.iterator. Este devuelve un iterador, cuyo método next() permite solicitar el siguiente elemento.

No necesitamos implementar este mecanismo para utilizar las colecciones habituales, pero podemos observarlo:

const modulos = ["DWEC", "DIW"];
const iterador = modulos[Symbol.iterator]();

console.log(iterador.next());
// { value: "DWEC", done: false }

console.log(iterador.next());
// { value: "DIW", done: false }

console.log(iterador.next());
// { value: undefined, done: true }

value contiene el valor obtenido y done indica si el recorrido ha terminado. for...of gestiona estas llamadas automáticamente. Referencia: iterables e iteradores, MDN.

5.2. Map

Un Map almacena asociaciones de clave y valor. Cada clave aparece una sola vez y permite recuperar el valor asociado.

Resulta útil cuando la operación principal es buscar datos por un identificador:

const productos = new Map();

productos.set(101, "Teclado");
productos.set(102, "Ratón");

console.log(productos.get(101)); // Teclado

A diferencia de las propiedades de un objeto, las claves de un Map pueden ser valores de cualquier tipo, incluidos números y objetos.

Crear un Map con datos iniciales

El constructor admite un iterable de parejas [clave, valor]:

const productos = new Map([
  [101, "Teclado"],
  [102, "Ratón"],
  [103, "Monitor"]
]);

console.log(productos.size); // 3

Utilizamos size para consultar el número de entradas; no length.

Operaciones básicas

Operación Utilidad Devuelve
set(clave, valor) Añadir o actualizar una entrada El propio Map
get(clave) Consultar un valor El valor o undefined
has(clave) Comprobar si existe una clave Un booleano
delete(clave) Eliminar una entrada Si existía y se eliminó
clear() Eliminar todas las entradas undefined
size Consultar el número de entradas Un número 
const precios = new Map();

precios.set("teclado", 35);
precios.set("raton", 20);
precios.set("teclado", 40); // Actualiza la clave existente.

console.log(precios.size);           // 2
console.log(precios.get("teclado"));  // 40
console.log(precios.has("monitor")); // false

console.log(precios.delete("raton")); // true
console.log(precios.size);            // 1

Si guardamos undefined como valor, get() no permite distinguirlo de una clave inexistente. Para comprobar la existencia, utilizamos has():

const datos = new Map([
  ["telefono", undefined]
]);

console.log(datos.get("telefono")); // undefined
console.log(datos.has("telefono")); // true
console.log(datos.has("email"));    // false

Las claves conservan su tipo

const datos = new Map();

datos.set(1, "Identificador numérico");
datos.set("1", "Identificador textual");

console.log(datos.size);   // 2
console.log(datos.get(1)); // Identificador numérico

Esto importa al utilizar datos de formularios: el texto "1" y el número 1 son claves diferentes.

Para trabajar con las entradas debemos utilizar los métodos del mapa:

const precios = new Map();

precios.set("teclado", 35); // Entrada del Map.

Escribir precios["teclado"] = 35 añadiría una propiedad al objeto, pero no una entrada gestionada por get(), has() o size.

Recorrer un Map

El recorrido produce parejas [clave, valor] en orden de inserción:

const precios = new Map([
  ["Teclado", 35],
  ["Ratón", 20]
]);

for (const [nombre, precio] of precios) {
  console.log(`${nombre}: ${precio} €`);
}

Actualizar una clave existente no cambia su posición. Si la eliminamos y volvemos a insertarla, queda al final.

Podemos recorrer solo las claves o los valores:

for (const nombre of precios.keys()) {
  console.log(nombre);
}

for (const precio of precios.values()) {
  console.log(precio);
}

Y convertirlos en arrays:

const nombres = [...precios.keys()];
const importes = [...precios.values()];
const entradas = [...precios];

console.log(nombres); // ["Teclado", "Ratón"]
console.log(importes); // [35, 20]

Objetos como claves

Cuando la clave es un objeto, se compara su identidad:

const alumno = { nombre: "Lucía" };
const notas = new Map();

notas.set(alumno, 8);

console.log(notas.get(alumno));              // 8
console.log(notas.get({ nombre: "Lucía" })); // undefined

El segundo objeto tiene las mismas propiedades, pero es otro objeto.

Ejemplo: contar apariciones

Un mapa permite asociar cada módulo con el número de veces que aparece:

const matriculas = ["DWEC", "DIW", "DWEC", "SSII", "DIW"];
const recuento = new Map();

for (const modulo of matriculas) {
  const cantidad = recuento.get(modulo) ?? 0;
  recuento.set(modulo, cantidad + 1);
}

console.log(recuento.get("DWEC")); // 2
console.log(recuento.get("DIW"));  // 2
console.log(recuento.get("SSII")); // 1

Si todavía no existe la clave, get() devuelve undefined y ?? 0 proporciona el valor inicial.

Un objeto resulta natural para representar una entidad con propiedades conocidas; un Map, para gestionar asociaciones cuyas claves añadimos, consultamos o eliminamos durante la ejecución. Referencia: Map, MDN.

5.3. Set

Un Set almacena valores únicos. Es útil cuando necesitamos evitar duplicados o comprobar si un valor pertenece a una colección.

const etiquetas = new Set();

etiquetas.add("JavaScript");
etiquetas.add("HTML");
etiquetas.add("JavaScript");

console.log(etiquetas.size); // 2

Añadir de nuevo un valor existente no crea otra entrada.

Crear un conjunto con datos iniciales

const modulos = new Set(["DWEC", "DIW", "DWEC", "SSII"]);

console.log(modulos.size); // 3

Operaciones básicas

Operación Utilidad Devuelve
add(valor) Añadir un valor El propio Set
has(valor) Comprobar si contiene un valor Un booleano
delete(valor) Eliminar un valor Si existía y se eliminó
clear() Vaciar el conjunto undefined
size Consultar el número de valores Un número 
const favoritos = new Set([101, 103]);

favoritos.add(105);

console.log(favoritos.has(103)); // true

favoritos.delete(101);

console.log(favoritos.size); // 2

Un Set no proporciona acceso por índice:

console.log(favoritos[0]); // undefined

Para comprobar la presencia de un valor utilizamos has().

Recorrer y convertir en array

Los valores se recorren en orden de inserción:

const etiquetas = new Set(["HTML", "CSS", "JavaScript"]);

for (const etiqueta of etiquetas) {
  console.log(etiqueta);
}

const lista = [...etiquetas];

console.log(lista); // ["HTML", "CSS", "JavaScript"]

Eliminar valores repetidos de un array

const modulos = ["DWEC", "DIW", "DWEC", "SSII", "DIW"];
const unicos = [...new Set(modulos)];

console.log(unicos); // ["DWEC", "DIW", "SSII"]

El conjunto elimina las repeticiones y la expansión convierte el resultado en un array.

Se conserva el orden de la primera aparición de cada valor.

Qué se considera repetido

No se convierten los tipos ni se ignoran las mayúsculas:

const valores = new Set([1, "1", "HTML", "html"]);

console.log(valores.size); // 4

Si necesitamos tratar textos equivalentes como un único valor, debemos normalizarlos según las reglas de la aplicación:

const entradas = [" HTML ", "html", "CSS"];

const etiquetas = new Set(
  entradas.map(texto => texto.trim().toLowerCase())
);

console.log([...etiquetas]); // ["html", "css"]

Los objetos se comparan por identidad:

const a = { id: 1 };
const b = { id: 1 };

const objetos = new Set([a, a, b]);

console.log(objetos.size); // 2

Por tanto, new Set(productos) no elimina objetos distintos que simplemente tengan el mismo identificador.

En Map y Set, NaN se considera igual a otro NaN para identificar entradas; 0 y -0 también se consideran iguales. Referencia: Set, MDN.

Operaciones entre conjuntos

Los conjuntos permiten expresar relaciones entre grupos:

const grupoA = new Set(["Ana", "Luis", "Marta"]);
const grupoB = new Set(["Luis", "Eva"]);
Operación Método Resultado en el ejemplo
Unión: valores de cualquiera de los dos grupoA.union(grupoB) Ana, Luis, Marta, Eva
Intersección: valores comunes grupoA.intersection(grupoB) Luis
Diferencia: valores de A que no están en B grupoA.difference(grupoB) Ana, Marta
Diferencia simétrica: valores que están en uno solo grupoA.symmetricDifference(grupoB) Ana, Marta, Eva

Estos métodos devuelven conjuntos nuevos:

const comunes = grupoA.intersection(grupoB);

console.log([...comunes]); // ["Luis"]
console.log(grupoA.size);  // 3: el original se conserva.

También podemos comprobar relaciones:

const seleccion = new Set(["Ana", "Luis"]);

console.log(seleccion.isSubsetOf(grupoA));   // true
console.log(grupoA.isSupersetOf(seleccion)); // true
console.log(grupoA.isDisjointFrom(grupoB));  // false
  • isSubsetOf() comprueba si todos los valores están en el otro conjunto.
  • isSupersetOf() comprueba si contiene todos los valores del otro.
  • isDisjointFrom() comprueba si no comparten ninguno.

Si una aplicación debe funcionar en navegadores antiguos, debemos comprobar la compatibilidad de estos métodos. Las operaciones también pueden expresarse con las herramientas ya estudiadas:

const comunes = new Set(
  [...grupoA].filter(nombre => grupoB.has(nombre))
);

5.4. WeakMap y WeakSet — Ampliación

Un programa crea objetos y deja de necesitarlos. El motor de JavaScript puede liberar su memoria cuando ya no son alcanzables desde el código activo: este proceso se denomina recolección de basura.

Las colecciones normales conservan referencias a sus objetos. Por ejemplo, guardar un objeto en un Set puede mantenerlo en memoria aunque hayamos dejado de utilizarlo en otras partes del programa.

WeakMap y WeakSet permiten asociar información o registrar pertenencia sin mantener por sí solos esos objetos en memoria.

En los ejemplos utilizaremos objetos. Estas colecciones también admiten símbolos no registrados, pero no cadenas ni números como claves de WeakMap o elementos de WeakSet.

WeakMap: asociar información a un objeto

const estados = new WeakMap();

let tarea = { titulo: "Revisar formulario" };

estados.set(tarea, {
  revisada: false,
  intentos: 0
});

console.log(estados.get(tarea).revisada); // false
console.log(estados.has(tarea));         // true

El objeto tarea actúa como clave. El valor asociado puede ser de cualquier tipo.

Si eliminamos las demás referencias a esa tarea, el WeakMap no impide que se libere:

tarea = null;

Esto no ordena borrar inmediatamente el objeto. El motor decide cuándo realizar la recolección.

WeakMap permite consultar una clave conocida con get() y has(), añadir asociaciones con set() y eliminarlas con delete().

Es útil para guardar información auxiliar de objetos —por ejemplo, estados asociados a elementos del DOM— sin añadirles propiedades y sin prolongar su vida únicamente por estar registrados en la colección. Referencia: WeakMap, MDN.

WeakSet: registrar objetos

Un WeakSet permite marcar qué objetos pertenecen a un grupo, sin asociarles otro valor:

const procesados = new WeakSet();

const tarea = { titulo: "Validar formulario" };

procesados.add(tarea);

console.log(procesados.has(tarea)); // true

Podemos utilizarlo para evitar procesar dos veces el mismo objeto:

const procesados = new WeakSet();

function procesar(tarea) {
  if (procesados.has(tarea)) {
    return;
  }

  console.log(`Procesando: ${tarea.titulo}`);
  procesados.add(tarea);
}

const tarea = { titulo: "Validar formulario" };

procesar(tarea); // Muestra el mensaje.
procesar(tarea); // No vuelve a procesarla.

Otro objeto con el mismo título se considera diferente. WeakSet registra identidades, no compara propiedades. Referencia: WeakSet, MDN.

Por qué no se pueden recorrer

Estas colecciones no proporcionan size, no son iterables y no permiten listar sus entradas. Si pudieran enumerarse, su contenido observable dependería de cuándo decide el motor liberar memoria.

Para consultarlas necesitamos conservar una referencia al objeto concreto.

Necesidad Estructura adecuada
Guardar una secuencia y acceder por posición Array
Representar una entidad con propiedades Objeto
Asociar claves con valores y recorrerlos Map
Mantener valores únicos y recorrerlos Set
Asociar información a objetos sin retenerlos por esa asociación WeakMap
Registrar objetos sin retenerlos por su pertenencia WeakSet

Utiliza las colecciones débiles cuando necesites ese comportamiento de memoria. Si necesitas listar, contar o mostrar sus elementos, utiliza Map o Set.

6. JSON

Los objetos y arrays permiten organizar datos mientras se ejecuta el programa. Sin embargo, para enviarlos a otra aplicación o conservarlos como texto necesitamos una representación que pueda reconstruirse después.

JSON (JavaScript Object Notation) es un formato de texto para representar datos estructurados. Aunque su sintaxis procede de JavaScript, se utiliza en muchos lenguajes.

{
  "nombre": "Teclado",
  "precio": 35,
  "disponible": true
}

JSON representa datos; no contiene métodos ni código que deba ejecutarse.

6.1. Convertir objetos en texto y viceversa

Un objeto JavaScript y un texto JSON son valores diferentes

const producto = {
  nombre: "Teclado",
  precio: 35
};

const texto = '{"nombre":"Teclado","precio":35}';

console.log(typeof producto); // object
console.log(typeof texto);    // string

Podemos acceder a producto.nombre. Para trabajar con los datos de texto, primero debemos interpretarlo.

Reglas de JSON

JSON admite objetos, arrays, cadenas, números, booleanos y null.

Sus reglas son más estrictas que las de un objeto literal JavaScript:

  • Las claves y las cadenas utilizan comillas dobles.
  • No se permiten comentarios.
  • No se permite una coma después del último elemento.
  • No admite undefined, funciones, símbolos, BigInt, NaN ni Infinity.
{
  "nombre": "Lucía",
  "modulos": ["DWEC", "DIW"],
  "activo": true,
  "telefono": null
}

Un documento JSON no tiene que contener necesariamente un objeto. Un array, un número o null también pueden ser JSON válidos.

Convertir a texto con JSON.stringify()

La serialización consiste en transformar datos en una representación que podamos almacenar o transmitir:

const producto = {
  nombre: "Teclado",
  precio: 35,
  disponible: true
};

const texto = JSON.stringify(producto);

console.log(texto);
// {"nombre":"Teclado","precio":35,"disponible":true}

console.log(typeof texto); // string

Para obtener un texto legible podemos indicar la sangría:

const texto = JSON.stringify(producto, null, 2);

console.log(texto);

El segundo argumento permite personalizar la selección o transformación de datos. Aquí utilizamos null para no aplicar esa personalización. El tercero indica dos espacios de sangría.

Recuperar datos con JSON.parse()

La operación inversa interpreta el texto y construye los valores correspondientes:

const texto = '{"nombre":"Teclado","precio":35}';
const producto = JSON.parse(texto);

console.log(producto.nombre); // Teclado
console.log(producto.precio); // 35

JSON.parse() interpreta datos; no ejecuta el texto como código. No debemos sustituirlo por eval().

Qué información no se conserva

JSON no representa todos los valores y comportamientos de JavaScript:

const datos = {
  nombre: "Teclado",
  descuento: undefined,
  calcularPrecio() {
    return 35;
  }
};

console.log(JSON.stringify(datos));
// {"nombre":"Teclado"}

En las propiedades de objetos, undefined, las funciones y los símbolos se omiten. En posiciones de arrays se convierten en null:

console.log(JSON.stringify([10, undefined, 20]));
// [10,null,20]

Otros casos importantes:

Valor original Resultado habitual
NaN o Infinity null
Un objeto Date válido Cadena con la fecha en formato ISO
Un Map o un Set sin personalización {}
Un BigInt sin personalización Lanza un error
Una referencia circular Lanza un error

Por eso, convertir a JSON y volver a interpretar no es una copia general de cualquier objeto. No restaura automáticamente clases, métodos ni todas las estructuras originales. Referencia: JSON.stringify(), MDN.

Podemos preparar explícitamente las colecciones estudiadas:

const etiquetas = new Set(["HTML", "CSS"]);
const texto = JSON.stringify([...etiquetas]);

const recuperadas = new Set(JSON.parse(texto));

console.log(recuperadas.has("CSS")); // true

Con un Map, podemos representar sus entradas:

const precios = new Map([
  ["Teclado", 35],
  ["Ratón", 20]
]);

const texto = JSON.stringify([...precios]);
const recuperados = new Map(JSON.parse(texto));

console.log(recuperados.get("Teclado")); // 35

En este ejemplo las claves son cadenas. Si fueran objetos, los objetos reconstruidos tendrían identidades nuevas.

6.2. Gestionar errores: try...catch...finally y throw

Un texto recibido puede estar incompleto o mal formado. Si JSON.parse() no puede interpretarlo, lanza una excepción:

const texto = '{"nombre": "Teclado",}';

// JSON.parse(texto);
// SyntaxError: la coma final no está permitida.

Una excepción interrumpe el flujo normal de ejecución. Podemos capturarla para informar del problema o aplicar una recuperación prevista.

Capturar un error

const texto = '{"nombre": "Teclado",}';

try {
  const producto = JSON.parse(texto);
  console.log(producto.nombre);
} catch (error) {
  console.error("No se pudo interpretar el contenido.");
  console.error(error.message);
}

console.log("El programa continúa.");
  • try contiene la operación que puede fallar.
  • catch se ejecuta si se lanza una excepción durante esa operación.
  • error recibe el valor lanzado; en este caso, un objeto SyntaxError.

Cuando ocurre el error, se omiten las instrucciones restantes del try. Si el catch termina normalmente, la ejecución continúa después de la estructura.

Comprobar también el contenido

Un JSON puede ser correcto sintácticamente y contener datos que nuestra aplicación no acepta:

const texto = '{"nombre":"Teclado","precio":"gratis"}';

const producto = JSON.parse(texto); // No produce un error.

Interpretar JSON no valida automáticamente los tipos, rangos ni campos obligatorios.

Podemos utilizar throw para comunicar que una función ha encontrado datos no válidos:

function leerProducto(texto) {
  const producto = JSON.parse(texto);

  if (
    producto === null ||
    typeof producto !== "object" ||
    Array.isArray(producto)
  ) {
    throw new TypeError("Se esperaba un objeto de producto.");
  }

  if (
    typeof producto.nombre !== "string" ||
    producto.nombre.trim() === ""
  ) {
    throw new TypeError("El producto necesita un nombre.");
  }

  if (
    !Number.isFinite(producto.precio) ||
    producto.precio < 0
  ) {
    throw new RangeError("El precio debe ser un número finito no negativo.");
  }

  return producto;
}

La función devuelve un producto válido o lanza una excepción. El código que la utiliza decide cómo responder:

try {
  const producto = leerProducto(
    '{"nombre":"Teclado","precio":35}'
  );

  console.log(`${producto.nombre}: ${producto.precio} €`);
} catch (error) {
  console.error("No se pudo cargar el producto:", error.message);
}

Utilizamos objetos de error para conservar información útil:

Tipo Uso habitual
Error Problema general
TypeError Tipo o estructura no adecuados
RangeError Valor fuera del rango admitido
SyntaxError Sintaxis incorrecta, como un JSON mal formado

throw detiene la función en ese punto. No debemos seguir trabajando con datos que ya hemos identificado como inválidos.

Ejecutar una acción final con finally

finally permite realizar una acción al salir de la estructura, tanto si la operación termina correctamente como si falla:

let procesando = false;

try {
  procesando = true;

  const producto = leerProducto(
    '{"nombre":"Teclado","precio":35}'
  );

  console.log(producto);
} catch (error) {
  console.error(error.message);
} finally {
  procesando = false;
}

Puede utilizarse para restablecer un estado o volver a habilitar un control después de una operación.

finally es opcional. No debemos colocar en él mensajes de éxito, porque también se ejecuta cuando hay un error. Evita además return o throw dentro de finally: pueden sustituir un resultado o error anterior. Referencia: try...catch...finally, MDN.

Cuándo utilizar cada mecanismo

Una condición con if es suficiente para situaciones normales, como un campo vacío que queremos señalar al usuario. throw permite que una función comunique que no puede completar su trabajo.

Captura errores donde puedas darles una respuesta útil. Un catch vacío oculta el problema y dificulta encontrarlo.

6.3. Personalizar la conversión: toJSON() y reviver

A veces la representación que necesitamos guardar no coincide exactamente con el objeto utilizado durante la ejecución.

Por ejemplo, una instancia puede tener métodos, datos internos y propiedades que no queremos incluir en el texto.

Elegir la representación con toJSON()

Si un objeto tiene un método toJSON(), JSON.stringify() utiliza el valor que devuelve:

class Producto {
  constructor(nombre, precio) {
    this.nombre = nombre;
    this.precio = precio;
    this.seleccionado = false;
  }

  toJSON() {
    return {
      nombre: this.nombre,
      precio: this.precio
    };
  }
}

const producto = new Producto("Teclado", 35);
producto.seleccionado = true;

console.log(JSON.stringify(producto));
// {"nombre":"Teclado","precio":35}

Aquí guardamos los datos del producto y omitimos un estado temporal de la interfaz.

toJSON() devuelve los datos que deben serializarse, no una cadena JSON construida manualmente.

Al recuperarlos, no se reconstruye la clase automáticamente:

const texto = JSON.stringify(producto);
const datos = JSON.parse(texto);

console.log(datos instanceof Producto); // false

Si necesitamos una instancia, debemos validar los datos y construirla explícitamente.

Las fechas ya utilizan este mecanismo

const entrega = {
  titulo: "Práctica de objetos",
  enviadaEn: new Date("2026-11-12T09:30:00Z")
};

const texto = JSON.stringify(entrega);

console.log(texto);
// {"titulo":"Práctica de objetos","enviadaEn":"2026-11-12T09:30:00.000Z"}

Después de interpretar el texto, la fecha será una cadena:

const recuperada = JSON.parse(texto);

console.log(typeof recuperada.enviadaEn); // string

Transformar valores al recuperar con reviver

El segundo argumento de JSON.parse() puede ser una función que transforma los valores interpretados:

const texto =
  '{"titulo":"Práctica","enviadaEn":"2026-11-12T09:30:00.000Z"}';

const entrega = JSON.parse(texto, (clave, valor) => {
  if (clave === "enviadaEn") {
    if (typeof valor !== "string") {
      throw new TypeError("La fecha debe estar representada como texto.");
    }

    const fecha = new Date(valor);

    if (Number.isNaN(fecha.getTime())) {
      throw new RangeError("La fecha guardada no es válida.");
    }

    return fecha;
  }

  return valor;
});

console.log(entrega.enviadaEn instanceof Date); // true
console.log(entrega.enviadaEn.getUTCFullYear());  // 2026

En este formato hemos acordado que enviadaEn contiene una fecha. No intentamos convertir cualquier cadena que se parezca a una.

El reviver procesa los valores anidados antes que sus contenedores. El valor que devuelve sustituye al original; si devuelve undefined, la propiedad se elimina. Por eso es importante escribir return valor para los datos que queremos conservar.

También se llama para el resultado completo, con una clave vacía. Referencia: JSON.parse() y reviver, MDN.

6.4. Caso de uso: conservar datos con localStorage

Las variables se pierden cuando recargamos la página. localStorage permite guardar pequeñas cantidades de información en el navegador y recuperarlas en visitas posteriores.

Resulta útil para preferencias de interfaz o borradores locales.

Almacena claves y valores como texto

Operación Utilidad
localStorage.setItem(clave, texto) Guardar o sustituir un valor
localStorage.getItem(clave) Leer un texto; devuelve null si no existe
localStorage.removeItem(clave) Eliminar una entrada
localStorage.clear() Eliminar todas las entradas del origen 
localStorage.setItem("dwec:tema", "oscuro");

const tema = localStorage.getItem("dwec:tema");

console.log(tema); // oscuro

Para guardar objetos debemos convertirlos a JSON:

const preferencias = {
  tema: "oscuro",
  compacto: true
};

localStorage.setItem(
  "dwec:preferencias",
  JSON.stringify(preferencias)
);

Guardar directamente un objeto no conserva su estructura: provoca su conversión a texto, habitualmente "[object Object]".

Dónde se guardan los datos

El almacenamiento pertenece al origen, definido por protocolo, dominio y puerto. Las rutas del mismo origen comparten localStorage.

Por ejemplo, distintas páginas de https://igarciafp.github.io comparten ese espacio. Utilizar claves como "dwec:ud03:preferencias" ayuda a evitar colisiones.

Los datos normalmente sobreviven a las recargas y al cierre del navegador, pero el usuario puede borrarlos. Tampoco se sincronizan automáticamente con otros dispositivos.

El acceso puede fallar por restricciones del navegador o falta de espacio. Prueba los ejemplos desde el servidor de desarrollo, no abriendo el HTML mediante file://, cuyo comportamiento de almacenamiento no está definido de forma uniforme. Referencia: localStorage, MDN.

Ejemplo completo: guardar y recuperar preferencias

Este ejemplo distingue tres situaciones: todavía no hay datos, existen datos válidos o se produce un error.

const CLAVE = "dwec:ud03:preferencias";

function preferenciasIniciales() {
  return {
    tema: "claro",
    compacto: false
  };
}

function validarPreferencias(datos) {
  if (
    datos === null ||
    typeof datos !== "object" ||
    Array.isArray(datos)
  ) {
    throw new TypeError("Las preferencias deben ser un objeto.");
  }

  if (datos.tema !== "claro" && datos.tema !== "oscuro") {
    throw new RangeError("El tema guardado no es válido.");
  }

  if (typeof datos.compacto !== "boolean") {
    throw new TypeError("La opción compacto debe ser booleana.");
  }

  // Conservamos únicamente las propiedades que utiliza la aplicación.
  return {
    tema: datos.tema,
    compacto: datos.compacto
  };
}

function guardarPreferencias(datos) {
  try {
    const preferencias = validarPreferencias(datos);
    const texto = JSON.stringify(preferencias);

    localStorage.setItem(CLAVE, texto);
    return true;
  } catch (error) {
    console.error("No se pudieron guardar las preferencias:", error);
    return false;
  }
}

function cargarPreferencias() {
  try {
    const texto = localStorage.getItem(CLAVE);

    if (texto === null) {
      return preferenciasIniciales();
    }

    const datos = JSON.parse(texto);
    return validarPreferencias(datos);
  } catch (error) {
    console.error("No se pudieron recuperar las preferencias:", error);
    return preferenciasIniciales();
  }
}

La ausencia de una entrada es una situación normal: devolvemos la configuración inicial.

Si el texto está dañado o contiene datos no admitidos, informamos del problema y utilizamos valores iniciales para que la aplicación pueda continuar. La lectura no sobrescribe automáticamente el contenido guardado.

Podemos utilizar las funciones así:

const preferencias = cargarPreferencias();

console.log("Preferencias al iniciar:", preferencias);

const guardado = guardarPreferencias({
  tema: "oscuro",
  compacto: true
});

if (guardado) {
  console.log("Preferencias guardadas.");
} else {
  console.log("Los cambios no se han guardado.");
}

El mensaje de éxito se muestra únicamente si setItem() ha terminado sin lanzar una excepción.

Comprobar la persistencia

  1. Ejecuta las funciones y guarda las preferencias.
  2. Recarga la página.
  3. Ejecuta cargarPreferencias() sin volver a guardar.
  4. Comprueba que recuperas "oscuro" y true.
  5. Inspecciona la entrada en DevTools, en Application → Local Storage.

Para eliminar únicamente los datos de este ejemplo:

try {
  localStorage.removeItem(CLAVE);
} catch (error) {
  console.error("No se pudieron eliminar las preferencias:", error);
}

Evita clear() si solo quieres restablecer esta práctica: borraría también las demás entradas del mismo origen.

Límites de uso

localStorage es síncrono: sus operaciones se realizan durante la ejecución del código y no es adecuado para grandes volúmenes de datos.

Tampoco es una copia de seguridad ni un almacén de secretos. El usuario y los scripts del mismo origen pueden acceder a sus datos. Al recuperarlos, debemos validarlos antes de utilizarlos, aunque los haya escrito previamente nuestra aplicación.

7. Objetos del navegador

JavaScript proporciona elementos del lenguaje como objetos, arrays y funciones. El navegador añade herramientas para trabajar con la página y su entorno: consultar la dirección actual, programar acciones o conocer el idioma preferido del usuario.

Estas herramientas forman parte de las APIs del navegador. No debemos asumir que estarán disponibles en cualquier entorno donde se ejecute JavaScript.

window Acceder al contexto de la ventana y a funciones del navegador
document Consultar y modificar el documento
location Consultar la URL actual y navegar
history Gestionar el historial de navegación de la pestaña

7.1. window y temporizadores

window representa la ventana o el contexto de navegación en el que se ejecuta la página.

Muchas herramientas que ya utilizamos están disponibles a través de él:

console.log(window.document === document);   // true
console.log(window.location === location);   // true
console.log(window.navigator === navigator); // true

En el código de una página podemos omitir habitualmente el prefijo window:

window.setTimeout(() => {
  console.log("Hola");
}, 1000);

Es equivalente a utilizar setTimeout() directamente.

Esto no significa que cualquier variable que declaremos se convierta en una propiedad de window. En particular, las declaraciones globales con let y const no lo hacen, y las variables de un módulo permanecen en su ámbito. Referencia: window, MDN.

Consultar el espacio visible

console.log(window.innerWidth);
console.log(window.innerHeight);

Estas propiedades expresan el tamaño del área de visualización de la ventana en píxeles CSS, incluyendo las barras de desplazamiento cuando están presentes.

Podemos responder a sus cambios:

window.addEventListener("resize", () => {
  console.log(`Ancho actual: ${window.innerWidth}px`);
});

Para adaptar únicamente el diseño, utilizaremos normalmente CSS y sus consultas de medios. JavaScript resulta útil cuando el tamaño afecta al comportamiento del programa.

Programar una acción con setTimeout()

setTimeout() programa una función para que pueda ejecutarse después de un tiempo:

console.log("Inicio");

setTimeout(() => {
  console.log("Han pasado al menos dos segundos");
}, 2000);

console.log("Fin del código inmediato");

El orden será:

Inicio
Fin del código inmediato
Han pasado al menos dos segundos

El tiempo se expresa en milisegundos. El temporizador no detiene el programa: registra la acción y permite continuar con las siguientes instrucciones.

Debemos pasar una función, sin ejecutarla:

function avisar() {
  console.log("Tiempo terminado");
}

setTimeout(avisar, 2000); // Correcto.

// setTimeout(avisar(), 2000);
// Incorrecto: ejecutaría avisar inmediatamente.

Si necesitamos pasar argumentos, podemos utilizar una función flecha:

function saludar(nombre) {
  console.log(`Hola, ${nombre}`);
}

setTimeout(() => saludar("Lucía"), 1000);

No pases código como una cadena de texto. Utiliza funciones.

Cancelar un temporizador

setTimeout() devuelve un identificador que podemos utilizar con clearTimeout():

const temporizador = setTimeout(() => {
  console.log("Este mensaje no llegará a mostrarse");
}, 3000);

clearTimeout(temporizador);

Cancelar sirve, por ejemplo, cuando una acción deja de ser necesaria antes de que llegue el momento previsto.

El retraso no es una cita exacta

El tiempo indicado establece cuándo puede ejecutarse la función, pero esta puede hacerlo más tarde si el navegador está ocupado o limita los temporizadores de una pestaña en segundo plano.

Incluso con un retraso de cero, la función no interrumpe el código actual:

console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");

// A
// C
// B

El navegador ejecutará el callback cuando termine el código actual y pueda atender esa tarea. Referencia: setTimeout(), MDN.

Repetir una acción con setInterval()

setInterval() programa llamadas repetidas:

let repeticiones = 0;

const intervalo = setInterval(() => {
  repeticiones++;
  console.log(`Repetición ${repeticiones}`);

  if (repeticiones === 3) {
    clearInterval(intervalo);
  }
}, 1000);

La primera llamada se programa después del intervalo indicado, no inmediatamente.

clearInterval() detiene las siguientes repeticiones. Debemos conservar el identificador y cancelar el intervalo cuando deje de ser necesario.

Evitar temporizadores duplicados

Si un botón puede iniciar repetidamente una acción, debemos impedir que cada pulsación cree otro intervalo:

let intervalo = null;

function iniciar() {
  if (intervalo !== null) {
    return;
  }

  intervalo = setInterval(() => {
    console.log(new Date().toLocaleTimeString("es-ES"));
  }, 1000);
}

function detener() {
  if (intervalo === null) {
    return;
  }

  clearInterval(intervalo);
  intervalo = null;
}

null indica que no hay ningún intervalo activo.

Medir tiempo no es contar ejecuciones

Si necesitamos una cuenta atrás, no conviene restar uno en cada llamada: los retrasos pueden acumularse. Es mejor calcular cuánto falta respecto al instante final:

const fin = Date.now() + 10_000;

const intervalo = setInterval(() => {
  const restanteMs = Math.max(0, fin - Date.now());
  const segundos = Math.ceil(restanteMs / 1000);

  console.log(`Quedan ${segundos} segundos`);

  if (restanteMs === 0) {
    clearInterval(intervalo);
  }
}, 250);

El temporizador decide cuándo actualizamos la información; la diferencia entre marcas temporales determina cuánto tiempo queda. Este ejemplo depende del reloj del dispositivo.

7.2. location e history

Ambos objetos están relacionados con la navegación, pero resuelven tareas diferentes: location representa la dirección actual y history permite trabajar con las entradas del historial.

Consultar la URL con location

Supongamos que la página tiene esta dirección:

https://ejemplo.com/catalogo.html?categoria=teclados#ofertas
Propiedad Valor
location.href URL completa
location.protocol "https:"
location.hostname "ejemplo.com"
location.origin "https://ejemplo.com"
location.pathname "/catalogo.html"
location.search "?categoria=teclados"
location.hash "#ofertas" 
console.log(location.href);
console.log(location.pathname);

search contiene los parámetros de consulta. hash contiene el fragmento, que suele utilizarse para identificar una sección del documento.

Leer parámetros con URLSearchParams

No necesitamos separar manualmente la dirección con split():

const parametros = new URLSearchParams(location.search);
const categoria = parametros.get("categoria");

console.log(categoria);

get() devuelve una cadena o null si no existe el parámetro:

const parametros = new URLSearchParams("?categoria=teclados");

console.log(parametros.get("categoria")); // teclados
console.log(parametros.get("orden"));     // null
console.log(parametros.has("categoria")); // true

Los valores siguen siendo texto. Si esperamos un número, debemos convertirlo y validarlo:

const parametros = new URLSearchParams(location.search);
const texto = parametros.get("pagina");

let pagina = 1;

if (texto !== null) {
  const numero = Number(texto);

  if (Number.isSafeInteger(numero) && numero >= 1) {
    pagina = numero;
  }
}

console.log(pagina);

Navegar a otra dirección

Estas operaciones provocan navegación; ejecútalas únicamente cuando quieras abandonar la página actual:

location.assign("/catalogo.html");

assign() permite volver con el botón Atrás. Asignar una URL a location.href produce un efecto equivalente.

location.replace("/inicio.html");

replace() sustituye la entrada actual del historial. Es útil cuando no queremos que Atrás vuelva a esa página, por ejemplo después de una redirección.

location.reload();

reload() recarga la página actual.

Para un enlace normal, utiliza un elemento <a>: conserva las funciones habituales del navegador, como abrir en otra pestaña. Reserva la navegación programática para acciones que realmente dependan del código.

Moverse por el historial

history.back();    // Retrocede una entrada.
history.forward(); // Avanza una entrada.
history.go(-2);    // Retrocede dos entradas.

Estas llamadas pueden abandonar la página. Si no existe una entrada en la dirección solicitada, no se produce el desplazamiento.

history.length indica el número de entradas del historial de sesión, pero no proporciona sus direcciones ni permite consultar libremente el historial del usuario.

Cambiar la URL sin recargar

Una aplicación puede representar su estado en la dirección sin cargar otro documento:

const url = new URL(location.href);
url.searchParams.set("categoria", "teclados");

history.pushState(
  { categoria: "teclados" },
  "",
  url
);

pushState() añade una entrada al historial. Sus argumentos son:

  1. El estado asociado, con datos que el navegador pueda serializar.
  2. Una cadena vacía para el segundo parámetro.
  3. La nueva URL, que debe pertenecer al mismo origen.

El cambio de dirección no actualiza automáticamente el contenido. La aplicación debe mostrar los datos correspondientes.

replaceState() realiza una operación similar, pero sustituye la entrada actual:

const url = new URL(location.href);
url.searchParams.set("orden", "precio");

history.replaceState({ orden: "precio" }, "", url);

Podemos consultar el estado de la entrada activa mediante history.state.

Responder a Atrás y Adelante

Al recorrer entradas del mismo documento, el evento popstate permite actualizar la interfaz:

function mostrarCategoriaActual() {
  const parametros = new URLSearchParams(location.search);
  const categoria = parametros.get("categoria") ?? "todas";

  console.log(`Mostrar categoría: ${categoria}`);
}

window.addEventListener("popstate", mostrarCategoriaActual);

mostrarCategoriaActual();

Las llamadas a pushState() y replaceState() no disparan por sí mismas popstate. Después de utilizarlas, debemos actualizar la vista explícitamente.

Si la URL puede abrirse o recargarse directamente, la página también debe reconstruir su estado inicial a partir de ella. Referencia: API de historial, MDN.

7.3. navigator y screen

Estos objetos proporcionan información sobre el entorno. Debemos utilizarla para una necesidad concreta, sin asumir que describe de forma completa o infalible el dispositivo.

Consultar preferencias de idioma

console.log(navigator.language);
console.log(navigator.languages);

language indica el idioma preferido del navegador. languages contiene una lista de preferencias, por ejemplo:

["es-ES", "es", "en"]

Podemos utilizarla al presentar una fecha:

const formato = new Intl.DateTimeFormat(navigator.languages, {
  dateStyle: "long"
});

console.log(formato.format(new Date()));

La preferencia de idioma no identifica la ubicación física ni la nacionalidad del usuario.

Consultar el estado de conexión

console.log(navigator.onLine);

El navegador informa de si considera que dispone de conexión. Podemos escuchar sus cambios:

window.addEventListener("offline", () => {
  console.log("El navegador indica que no hay conexión.");
});

window.addEventListener("online", () => {
  console.log("El navegador indica que hay conexión.");
});

navigator.onLine === true no garantiza acceso a Internet ni a nuestro servidor. Puede existir conexión con una red local y fallar el acceso al servicio.

Utiliza esta información como orientación para la interfaz. El resultado de cada operación de red deberá gestionarse cuando se realice.

Detectar capacidades

Antes de utilizar una API opcional, podemos comprobar su presencia:

if ("geolocation" in navigator) {
  console.log("El navegador dispone de la API de geolocalización.");
} else {
  console.log("Esta API no está disponible.");
}

La existencia de la API no garantiza que una operación vaya a autorizarse: algunas requieren un contexto seguro, permisos o una acción del usuario.

Evita decidir capacidades analizando navigator.userAgent. Esa cadena puede ser reducida, modificada o incluir nombres de varios navegadores. Es preferible comprobar la herramienta que realmente necesitamos. Referencia: navigator, MDN.

Consultar información de la pantalla

console.log(screen.width);
console.log(screen.height);
console.log(screen.availWidth);
console.log(screen.availHeight);
Propiedad Información
width Anchura de la pantalla en píxeles CSS
height Altura de la pantalla en píxeles CSS
availWidth Anchura disponible para ventanas
availHeight Altura disponible para ventanas

El espacio disponible puede excluir zonas reservadas por el sistema operativo.

Pantalla y área de visualización no son lo mismo

console.log(`Pantalla: ${screen.width}px`);
console.log(`Área de la página: ${window.innerWidth}px`);

Una pantalla puede ser grande y contener una ventana estrecha. Por eso, screen.width no es una medida adecuada para decidir cómo distribuir el contenido de la página.

Tampoco expresa necesariamente la cantidad de píxeles físicos del panel: estas medidas utilizan píxeles CSS. Referencia: screen, MDN.

const consulta = window.matchMedia("(max-width: 600px)");

      : "Área de visualización amplia"
  );
}

informarModo();
consulta.addEventListener("change", informarModo);

La condición se evalúa sobre el área de visualización, no sobre el tamaño completo de la pantalla. El evento change se produce cuando cambia el resultado de la consulta.

8. Gestión avanzada de eventos

En una página dinámica, los elementos pueden aparecer, cambiar o desaparecer después de cargar el documento. Una lista de tareas, por ejemplo, necesita crear elementos y responder a sus botones aunque todavía no existieran al iniciar la aplicación.

Para organizar estas interacciones debemos comprender cómo se propagan los eventos y dónde conviene registrar sus manejadores.

Los ejemplos de cada subapartado son independientes. Carga su JavaScript mediante un módulo para que se ejecute después de analizar el HTML:

<script type="module" src="app.js"></script>

8.1. Crear y eliminar nodos

Hasta ahora hemos seleccionado y modificado elementos existentes. También podemos construir nuevos elementos desde JavaScript.

Crear no significa insertar

document.createElement() crea un elemento, pero todavía no lo incorpora a la página:

const parrafo = document.createElement("p");

parrafo.textContent = "Nueva tarea";
parrafo.classList.add("tarea");

El objeto existe en memoria. Para mostrarlo, debemos insertarlo en el documento. Referencia: createElement(), MDN.

Crear una lista de tareas

Partimos de este HTML:

<ul id="tareas"></ul>

Podemos construir un elemento completo antes de insertarlo:

const lista = document.querySelector("#tareas");

const tarea = document.createElement("li");
tarea.dataset.id = "1";

const texto = document.createElement("span");
texto.textContent = "Repasar los objetos";

const boton = document.createElement("button");
boton.type = "button";
boton.textContent = "Eliminar";
boton.dataset.accion = "eliminar";

tarea.append(texto, " ", boton);
lista.append(tarea);

append() añade nodos o texto al final del elemento.

dataset permite trabajar con atributos data-*:

console.log(tarea.dataset.id); // "1"

El resultado incluye:

<li data-id="1">
  <span>Repasar los objetos</span>
  <button type="button" data-accion="eliminar">Eliminar</button>
</li>

Los valores de dataset son cadenas. Si representan números, debemos convertirlos cuando lo necesitemos.

Elegir dónde insertar

Operación Posición
contenedor.append(nodo) Al final, dentro del contenedor
contenedor.prepend(nodo) Al principio, dentro del contenedor
referencia.before(nodo) Antes del elemento de referencia
referencia.after(nodo) Después del elemento de referencia
referencia.replaceWith(nodo) Sustituye el elemento de referencia

Insertar un nodo que ya está en el documento lo mueve, no crea una copia:

lista.prepend(tarea); // Mueve la tarea al principio.

Eliminar elementos

tarea.remove();

remove() desconecta el elemento de su padre. Si conservamos una referencia, el objeto sigue disponible y podemos volver a insertarlo.

Para vaciar un contenedor:

lista.replaceChildren();

También podemos sustituir todos sus hijos por otros:

const aviso = document.createElement("li");
aviso.textContent = "No hay tareas pendientes.";

lista.replaceChildren(aviso);

Texto del usuario: textContent

Si el contenido procede de un formulario, debe incorporarse como texto:

const textoUsuario = "<strong>Repasar</strong>";
const tarea = document.createElement("li");

tarea.textContent = textoUsuario;

Se mostrarán literalmente las etiquetas. Con innerHTML, el navegador las interpretaría como HTML.

Además, reconstruir un contenedor con innerHTML reemplaza sus descendientes: los nuevos nodos no conservan los manejadores registrados directamente en los anteriores. Utilizar métodos del DOM permite controlar qué elementos se crean, conservan o eliminan.

8.2. Propagación: burbujeo, captura y stopPropagation()

Si pulsamos un botón dentro de una tarjeta, ¿también hemos pulsado la tarjeta?

Un evento puede recorrer los antecesores del elemento donde se produjo. Por eso, una pulsación puede activar manejadores registrados en distintos niveles del documento.

Consideremos este HTML:

<div id="panel">
  <button id="accion" type="button">Pulsar</button>
</div>

Las fases del recorrido

Para un evento como click, distinguimos:

  1. Captura: el evento recorre los antecesores hacia el elemento de destino.
  2. Destino: se ejecutan los manejadores correspondientes en el elemento de destino.
  3. Burbujeo: el evento recorre los antecesores en sentido ascendente.

Por defecto, los manejadores de los antecesores registrados con addEventListener() escuchan durante el burbujeo:

const panel = document.querySelector("#panel");
const boton = document.querySelector("#accion");

panel.addEventListener("click", () => {
  console.log("Panel");
});

boton.addEventListener("click", () => {
  console.log("Botón");
});

Al pulsar el botón, aparece:

Botón
Panel

El segundo manejador se ejecuta porque el evento burbujea hasta el panel.

Escuchar durante la captura

Utilizamos la opción capture: true:

panel.addEventListener("click", () => {
  console.log("Panel: captura");
}, { capture: true });

Junto con los manejadores anteriores, el orden será:

Panel: captura
Botón
Panel

La captura resulta útil cuando necesitamos observar un evento antes de que llegue al destino. En la mayoría de las interacciones habituales utilizaremos el comportamiento predeterminado. Referencia: propagación de eventos, MDN.

Diferenciar target y currentTarget

panel.addEventListener("click", (evento) => {
  console.log(evento.target);
  console.log(evento.currentTarget);
});

En este ejemplo, al pulsar el botón:

  • target identifica el elemento donde se originó el evento: el botón.
  • currentTarget identifica el elemento cuyo manejador se está ejecutando: el panel.

Si el botón contiene un <span> y pulsamos sobre él, target puede ser ese <span>.

Detener la propagación

Podemos impedir que el evento continúe hacia otros elementos:

boton.addEventListener("click", (evento) => {
  evento.stopPropagation();
  console.log("Se ha pulsado el botón");
});

Este ejemplo es una alternativa al manejador anterior del botón. Evita que el clic llegue al manejador de burbujeo del panel. No deshace los manejadores de captura que ya se hayan ejecutado.

stopPropagation() tampoco impide que se ejecuten otros manejadores del mismo evento registrados en el mismo elemento. Para detener también los siguientes manejadores de ese elemento existe stopImmediatePropagation().

No detengas la propagación por costumbre: otros componentes pueden necesitar observar el evento.

Propagación y comportamiento predeterminado son distintos

Método Efecto
stopPropagation() Detiene la propagación hacia otros elementos
preventDefault() Cancela el comportamiento predeterminado, si el evento lo permite
stopImmediatePropagation() Detiene los siguientes manejadores del mismo elemento y la propagación

Por ejemplo, detener la propagación de un clic en un enlace no evita por sí mismo la navegación. Para eso se utiliza preventDefault().

No todos los eventos burbujean

click y input burbujean. focus y blur no lo hacen; para observar cambios de foco desde un antecesor podemos utilizar focusin y focusout, que sí burbujean, o escuchar durante la captura.

Controlar la duración de los manejadores

Podemos registrar una acción que se ejecute una sola vez:

boton.addEventListener("click", () => {
  console.log("Primer clic");
}, { once: true });

Para eliminar manualmente un manejador necesitamos conservar la misma función:

function informar() {
  console.log("Clic registrado");
}

boton.addEventListener("click", informar);

// Cuando deje de ser necesario:
boton.removeEventListener("click", informar);

Una función nueva, aunque tenga el mismo código, no elimina la anterior. Al retirar el manejador también debe coincidir la opción de captura con la utilizada al registrarlo. Referencia: addEventListener(), MDN.

8.3. Delegación de eventos

Si una lista contiene muchos botones, podríamos registrar un manejador en cada uno. Sin embargo, los botones que añadamos después necesitarían su propio registro.

La delegación de eventos consiste en registrar un manejador en un antecesor estable y utilizar el destino del evento para decidir qué elemento atender.

Un manejador para toda la lista

<ul id="tareas">
  <li data-id="1">
    <span>Repasar objetos</span>
    <button type="button" data-accion="eliminar">
      <span>Eliminar</span>
    </button>
  </li>

  <li data-id="2">
    <span>Practicar arrays</span>
    <button type="button" data-accion="eliminar">
      <span>Eliminar</span>
    </button>
  </li>
</ul>

const lista = document.querySelector("#tareas");

lista.addEventListener("click", (evento) => {
  if (!(evento.target instanceof Element)) {
    return;
  }

  const boton = evento.target.closest(
    'button[data-accion="eliminar"]'
  );

  if (boton === null || !lista.contains(boton)) {
    return;
  }

  const tarea = boton.closest("li[data-id]");

  if (tarea === null || tarea.parentElement !== lista) {
    return;
  }

  tarea.remove();
});

El manejador realiza cuatro comprobaciones:

  1. El destino permite utilizar métodos de elementos.
  2. El clic procede de un botón de eliminar o de alguno de sus descendientes.
  3. El botón pertenece a la lista.
  4. La tarea es un hijo directo de esta lista.

Por qué utilizamos closest()

evento.target.closest('button[data-accion="eliminar"]');

closest() comprueba el propio elemento y después sus antecesores hasta encontrar una coincidencia.

Así, el código funciona tanto si pulsamos el botón como si pulsamos el <span> que contiene. Comprobar únicamente evento.target.tagName === "BUTTON" no cubriría el segundo caso.

También funciona con elementos nuevos

Después de registrar el manejador anterior, podemos añadir una tarea:

const tarea = document.createElement("li");
tarea.dataset.id = "3";

const texto = document.createElement("span");
texto.textContent = "Practicar eventos";

const boton = document.createElement("button");
boton.type = "button";
boton.dataset.accion = "eliminar";
boton.textContent = "Eliminar";

tarea.append(texto, " ", boton);
lista.append(tarea);

No necesitamos registrar otro manejador. El clic del nuevo botón también burbujea hasta lista.

La delegación sigue funcionando mientras conservemos el contenedor donde registramos el manejador. Si sustituimos la propia lista por otro nodo, debemos registrar el manejador en la nueva lista o delegar desde un antecesor que permanezca.

La interfaz y los datos deben mantenerse sincronizados

En el ejemplo, la tarea existe únicamente en el DOM. Si también tenemos un array de tareas, eliminar el elemento visual no modifica ese array.

En ese caso, debemos identificar la tarea mediante data-id, actualizar los datos y reflejar el cambio en la interfaz.

Cuándo delegar

La delegación resulta especialmente útil en listas, tablas o menús con elementos que se crean y eliminan.

Para un botón único y estable, un manejador directo suele ser suficiente. Elige un contenedor cercano a los elementos que gestiona: no es necesario delegar todos los clics de la aplicación en document.

8.4. Eventos personalizados

Los eventos del navegador describen acciones como click, input o submit. Una aplicación también puede necesitar comunicar sucesos propios:

  • Se ha añadido una tarea.
  • Se ha actualizado un carrito.
  • Se ha cambiado una preferencia.

Un evento personalizado permite anunciar un suceso para que otras partes del programa reaccionen sin que el emisor tenga que llamar directamente a todas ellas.

Crear un evento con datos

const evento = new CustomEvent("tarea:creada", {
  detail: {
    id: 1,
    titulo: "Repasar objetos"
  },
  bubbles: true
});

El primer argumento es el nombre del evento. Conviene utilizar un nombre que describa lo sucedido.

detail contiene los datos asociados. bubbles: true permite que el evento se propague hacia los antecesores del nodo donde lo emitimos.

Los eventos personalizados no burbujean por defecto. Referencia: CustomEvent, MDN.

Escuchar antes de emitir

Partimos de este HTML:

<section id="gestor">
  <h2>Tareas</h2>
  <ul id="tareas"></ul>
  <p id="estado" role="status"></p>
</section>

Registramos un manejador en la sección:

const gestor = document.querySelector("#gestor");
const lista = document.querySelector("#tareas");
const estado = document.querySelector("#estado");

gestor.addEventListener("tarea:creada", (evento) => {
  estado.textContent = `Añadida: ${evento.detail.titulo}`;
});

Después podemos crear tareas y anunciar el resultado:

let siguienteId = 1;

function crearTarea(titulo) {
  const texto = titulo.trim();

  if (texto === "") {
    return;
  }

  const id = siguienteId++;

  const tarea = document.createElement("li");
  tarea.dataset.id = String(id);
  tarea.textContent = texto;

  lista.append(tarea);

  tarea.dispatchEvent(new CustomEvent("tarea:creada", {
    detail: { id, titulo: texto },
    bubbles: true
  }));
}

crearTarea("Repasar objetos");

La tarea se inserta antes de emitir el evento. Así, el evento puede recorrer sus antecesores hasta llegar a gestor.

crearTarea() se ocupa de crear y anunciar. El manejador de la sección decide cómo actualizar el mensaje.

Podemos registrar otros manejadores del mismo evento sin cambiar la función que crea las tareas.

dispatchEvent() ejecuta los manejadores de forma síncrona

gestor.addEventListener("prueba", () => {
  console.log("B");
});

console.log("A");
gestor.dispatchEvent(new CustomEvent("prueba"));
console.log("C");

// A
// B
// C

Los manejadores se ejecutan antes de que continúe la instrucción posterior a dispatchEvent(). Esto es diferente de programar una función con setTimeout(). Referencia: dispatchEvent(), MDN.

Solicitar una acción que pueda cancelarse

Un evento puede anunciar algo que ya ha ocurrido o solicitar una acción que todavía podemos impedir.

Para permitir la cancelación, utilizamos cancelable: true:

gestor.addEventListener("tarea:antes-de-eliminar", (evento) => {
  if (evento.detail.protegida) {
    evento.preventDefault();
    estado.textContent = "La tarea está protegida.";
  }
});

La función que emite el evento debe comprobar el resultado:

function eliminarTarea(tarea, protegida) {
  const permitido = tarea.dispatchEvent(
    new CustomEvent("tarea:antes-de-eliminar", {
      detail: {
        id: tarea.dataset.id,
        protegida
      },
      bubbles: true,
      cancelable: true
    })
  );

  if (!permitido) {
    return;
  }

  tarea.remove();
}

Si un manejador cancela el evento mediante preventDefault(), dispatchEvent() devuelve false.

Cancelar el evento no deshace una operación realizada ni detiene automáticamente nuestra función. En este ejemplo, la eliminación se evita porque comprobamos permitido antes de llamar a remove().

Podemos probarlo sobre una tarea existente:

const tarea = lista.querySelector("li");

if (tarea !== null) {
  eliminarTarea(tarea, true); // El manejador impide la eliminación.
}

Los datos de detail no se copian automáticamente

Si incluimos un objeto existente, los manejadores reciben una referencia a ese objeto. Modificar sus propiedades puede afectar a quien lo emitió.

Por eso conviene comunicar únicamente los datos necesarios y tratar el contenido recibido como información del evento.

Elegir entre una función y un evento

Utiliza una llamada directa cuando una parte del programa necesita ejecutar una operación concreta y obtener su resultado.

Utiliza un evento personalizado cuando una parte anuncia un suceso y otras pueden reaccionar de forma independiente. El evento expresa lo ocurrido; cada manejador decide qué hacer con esa información.
