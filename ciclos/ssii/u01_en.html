1. Introduction and previous definitions

1.1. Hardware and Software

We understand by architecture of a computer the parts that compose it, so we can talk about two basic components in a computer:

► Physical componentsalso called as a whole hardware and consisting of all the circuitry and electronic components of the computer.

► Logical components, also called together software and which is made up of the intangible components of a computer; that is, the programs that run on the computer, as well as the information or data that are processed. A computer without software would make no sense, it would only be a machine that would do nothing.

Remember:

If we can touch it it is hardware (physical component), if it is intangible it is software (logical component).

1.2. Computers and Computers

The computer science is the science that studies the acquisition, representation, processing and transmission of information, automatically using machines called computers.

The term information In computer science it has a broad meaning, and refers to a set of symbols that represent facts, objects or ideas.

The computer is a machine, usually electronic and digital, capable of accepting input data, carrying out with them a series of mathematical and logical operations and providing the resulting information through an output medium; all without human intervention, using a set of instructions, that is, a program previously stored in the computer memory.

Did you know that...?

The term "informatics" comes from the French informatique, implemented by the engineer Philippe Dreyfus in the early 1960s. The word is, in turn, an acronym for information and automation.

The concept of information exceeds that of “data” (“Antecedent necessary to get to the accurate knowledge of something or to deduce the legitimate consequences of an event”, or “Information arranged in a suitable way for its treatment by a computer”).

Remember:

A computer is an electronic and digital device that processes information following instructions (stored program).

Black box model.

In systems theory, a black box model is a system that receives a series of input data, processes them and emits an output information. We can therefore consider a computer as a black box - since for now it is not our responsibility what happens within it - that will receive a series of input data and will emit useful information for the user as output.

1.3. Digital

Digital vs analog.

It is important to consider that this flow of information is usually done digitally. The term digit = finger gives us an approximate idea that representation is not going to take any real world value (analogue signals) but only a discrete number of them as the number of fingers is limited.

Bit concept

Intimately linked to the internal representation of information is the concept of bit. By simplicity and speed, computers internally will only be able to store two states (voltage or absence of this, magnetized or not, reflects a laser or not, etc.) that mathematically we will represent with a zero or a one. 2. Communication of information

2.1 Elements of a communication system

The basic elements involved in the communication process are:

  • Issuer: The entity transmitting the information.

  • Receiver: You receive the information.

  • Channel: Means by which the information is transmitted, will inevitably contain noise.

  • Message: Set of signals, signs and symbols that are the object of communication.

  • Protocols and standards: Finally, it is necessary for communication to be effective, for both issuer and receiver to follow a certain set of rules in communication. These are called protocols. Currently there are many protocols, and many of them are standardized, as is the case with the TCP/IP protocol set.

Thus, the transmission of information between the human being and the computer can be done in many ways:

  • Using alphanumeric characters (letters, numbers and graphic characters)

  • Through sounds

  • Using images and video

In each case it is different, and to proceed with the communication of the data it is necessary to change the way in which these are represented.

Therefore, the data should always be coded.

Optionally the data can also be encryption, tablets and you can add it redundant information for detection and/or correction of errors or for synchronization.

With all this, we can define information as the representation of facts, objects, values, ideas, etc., which allow communication between sender and receiver and the acquisition of knowledge of things.

3.1.4 Conversion of storage and transmission units

Converting a measure consists of expressing the same amount with another unit. In this section we use decimal scale: each unit is 1000 times For example, 1 kB = 1000 B, 1 MB = 1000 kB and 1 GB = 1000 MB.

  • Towards a smaller unit (down on the scale): we multiply by 1000 for each jump. The numeric value increases because we need more small units to express the same amount.
  • Towards a larger unit (up on the scale): we divide by 1000 for each jump. The numerical value decreases because we need fewer large units.
  • If there is n jumps, we multiply or divide by 1000n. First identify the units of origin and destination and count the jumps.
Storage examples
  • From GB to MB: 2.5 GB × 1000 = 2500 MB (a jump to a smaller unit).
  • From MB to GB: 750 MB < 1000 = 0.75 GB (a jump to a larger unit).
  • From MB to B: 3 MB × 1000 × 1000 = 3 000 000 B (two jumps: MB → kB → B).
  • From kB to GB: 2 500 000 kB = 10002 2.5 GB (two jumps: kB → MB → GB).
Examples of transmission

At a transmission rate we maintain ‘per second’ and convert the information unit. We use the same factors of 1000 both in bit/s and in B/s. Mbps y Gbps equals Mbit/s and Gbit/s.

  • From Gbit/s to Mbit/s: 1.2 Gbit/s × 1000 = 1200 Mbit/s.
  • From kbit/s to Mbit/s: 50 000 kbit/s = < 1000 50 Mbit/s.
  • From MB/s to B/s: 4 MB/s × 10002 = 4 000 000 B/s.
Attention: bits and bytes are different drives

b means bit and B means byte; 1 B = 8 bits. To switch from bytes to bits we multiply by 8; to move from bits to bytes we divide by 8. This also applies to rates, provided we keep the same prefix: 100 Mbit/s 8 = 12.5 MB/s, and 20 MB/s × 8 = 160 Mbit/s.

If you change the prefix and the type of unit, we do both steps: 1 Gbit/s = 1000 Mbit/s = 125 MB/s. This equivalence expresses a theoretical rate; useful transfer may be reduced by overloading protocols and connection conditions.

If storage and transmission are mixed: to estimate the time, express the size and rate in supported drives and divide. 500 MB a 100 Mbit/s = 12.5 MB/s takes ideally 500 = 12,5 = 40 seconds.

3.2.1 Numerical representation

A first approach to the problem of representing a designated number of n-bits is representation in Sign and Magnitude:

  • The MSB is used to represent the number that, per convention: a 0 denotes a positive number, and a 1 denotes a negative number;

  • The remaining (n-1)-bits to represent the meaning that is the magnitude of the number in absolute value.

One problem of this representation is the need for a conditional operation when operating with them to determine their sign and another the double representation of zero (1000000 and 0000000)

Much more used is representation in Pluginswhich allows us to have a simpler arithmetic.

  • Plugin to 1 (to the base minus 1): Zeros and ones of meaning are reversed - it is equivalent to subtracting the base minus 1- , which allows us to operate arithmetically, although transport must be taken into account and still has double representation for zero. It is used by TCP, UDP, ICMP protocols, and others. e.g.: 1010)2 = -5)10

  • Plugin to 2 (to the base): 1 is added to the complement to 1 of the number, which gives us a very effective notation to operate arithmetically. It is the most used notation. e.g.: 1011)2 = -5)10

To represent numbers real or very large the floating point notation, which is based on the property that every n number can be represented by n=m*Be where m is the mantisa, B is the base (it is not necessary to explain this value) and e is the exponent.

There is currently the standard IEEE 754 virtually universal acceptance, which represents real number with 32 or 64 bits.

3.2.2. Alphanumeric representation (Texts): I/O codes

For numerical representation, the so called Input/output encoding, that associates each character a certain combination of bits.

According to the author J. Glenn Brookshear, in his book Introduction to Computing, in the 40s and 50s a very wide variety of different I/O codes were used, which generated the existence of communication problems, which is why they are currently used Standard I/O codesfor example:

  • BCD (Binary Coded Decimal) To represent numbers in decimal digit to digit we use 4 bits. This greatly simplifies the hardware. It has several variants such as the Aiken code or the XS3 - Excess to 3.

  • EBCDIC (Extended BCD Interchange Code): Use 8 bits. Represents lowercase, uppercase, special symbols and control characters.

  • ASCII (American Standard Code for Information Interchange): There are two versions, the first Use 7 bits of data and 1 parity. The second is the extended ASCII code that uses 8 bits for data.

  • UNICODE: the symbols are organized by pages, which correspond to different languages or a set of symbols. Use a variable number of bits (8, 16 or 32) depending on the UTF -Unicode Transformation Format- used, as this way we can operate with less information for known codes without being limited in the number of potentially representative symbols. Currently it is the code most used.

It should be added that the specific form taken by the letter is to be determined by what is called “source of letter”.

3.2.3. Representation of instructions

The instructions of a high-level language or assembly language are given in text form, represented accordingly by an I/O code, and the corresponding translator, whether a compiler or an interpreter, is responsible for transforming them into machine instructions that will internally be represented as a bit string.

3.2.4. Image and video representation

The encoding of static images can be done in ways: by means of bitmaps (indicating for each bit of the screen its color) or by vector representation (Indicating only the vertices and color of each polygon we want to generate).

Each pixel will be represented using an RGB color scale (Red, Green and Blue) or CMYK (Cyan, Magenta, Yellow, blacK -for printers-) thus reducing to three numbers (4 in the case of printing) that symbolize the amount of each color that will be mixed to generate the resulting color.

On-screen colours can be incorporated into a fourth value that represents the transparency of the image, and is known as the “Alpha channel”.

The resolution of an image is therefore determined by the number of points we are going to use to represent it, but also by the amount of colors that allows us the palette we are using, depending on the number of bits that we dedicate to each basic color. For example, if we use 8 bits for the palette, we can represent 2 bits.8 different combinations, i.e. 256 colors, but if we use 16 bits, 65536. The number of bits used is called “color depth”.

It is also common to compress images so that they are smaller by reducing the color depth, resolution of the image, or the number of pixels to be represented by the bit zone approach of the same colour.

A video is always going to be formed from static images, being important the number of images (frames) that are represented FPS and taking into account that compression can also be performed by transitions between images, that is, keeping the elements that do not change and saving information from those that do.

3.2.4.1. Depth of color

The color depth indicates how many bits are used to encode the color of each pixel. n bits per pixel can be represented up to 2n different values. For example, 1 bit allows 2 colors and 8 bits allow 256 values, which can correspond to shades of gray or colors of a palette.

In an image 24 bit RGB per pixel, each channel (red, green and blue) uses 8 bits: 256 levels, from 0 to 255. Combining the three channels is obtained 256 × 256 × 256 = 16,777,216 possible coloursThat's why you have to distinguish between bits. per pixel and bits per channel.

A greater depth allows to represent more nuances and reduces the visible jumps in the gradients (banding). Does not increase resolution: The resolution indicates how many pixels the image has; the depth indicates how many color values each can represent. Same resolution and without compression, more bits per pixel require more storage space.

What about the 32-bit images? In a regular format, 32-bit RGBA, 24 bits are used for color and 8 bits for alpha channel (transparency). Those additional 8 bits do not increase the number of RGB colors.

4.1. Word length

The word length is the number of bits that the CPU handles as a natural unit in certain operations. In a 64-bit architecture, general purpose logs usually allow transactions with values of that size. This does not mean that all instructions, all buses or all addresses are 64 bits.

Frequent error: "64 bits means double speed"

The word length describes a feature of the architecture. Running time also depends on the program, CPU design, memory and other factors. We cannot deduce that a 64-bit computer is twice as fast as a 32-bit computer.

4.2. Main memory: RAM

RAM keeps instructions and data from running programs. Its capacity is expressed in bytes and multiples. It is a memory volatile: loses its contents when the equipment is turned off.

Example: opening multiple applications and documents increases the memory required. If the available RAM is insufficient, the system can resort to storage, usually much slower. Adding RAM can help in that situation, but does not speed up all tasks equally.

The main RAM is usually DRAM: each cell contains an access transistor and a capacitor. As the load is lost over time, you need RefresherThe controller coordinates the accesses; inside the chip, the circuits select rows and columns and detect or write the data.

4.4. Bandwidth

The bandwidth indicates the amount of information that can be transmitted per unit of time. MB/s (megabytes per second) or Mb/s (megabits per second).Remember: one byte contains eight bits.

Example solved: How long does a transfer take?

To transfer a 600 MB file at a constant speed of 100 Mb/s, we first unify the drives: 100 8 = 12.5 MB/s. Then we calculate the time: 600 = 12.5 = 48 seconds.

It is an ideal calculation with decimal units: it does not include communication overloads, waits or device limits. The actual transfer may take longer.

To enlarge: GT/s and latency

GT/s expresses billions of transfers per second. To convert it into a data rate you need to know the useful bits of each transfer, the number of lines and the encoding of the link. Latency measures the waiting time until you get a response; it is not the same as bandwidth.

4.5. Clock frequency

The clock provides a signal that coordinates processing steps. Frequency indicates cycles per second: 1 MHz = 1 million cycles/s; 1 GHz = 1 billion cycles/s.

A 3 GHz processor performs three billion cycles per second. does not equal three billion instructions per second: An instruction may require several cycles and a CPU may overlap instructions or complete several in one cycle. Architecture, cores, memory and workload are also influenced.

4.6. MIPS: a measure with limits

To expand: millions of instructions per second

MIPS indicates how many millions of instructions are executed per second in a test. Not all instructions do the same job, and architectures may need different amounts of instructions to solve a task. Therefore, it is not a universal sorting of processors.

4.7. MFLOPS: floating point calculation

To expand: millions of floating-point operations per second

MFLOPS expresses millions of floating-point operations per second. It is used in numerical calculation loads. The accuracy used and whether the value is theoretical or measured must be indicated. Do not predict for itself the speed when opening a browser or document.

4.8. Processor technologies

Frequency does not describe a CPU by itself. To interpret a datasheet it is appropriate to distinguish how you deal the work, how you adjust your speed, and how you make it. These technologies can be combined into the same processor.

Multiple cores and multiple threads

A kernel is a processing unit within the CPU. A multi-core processor can run parallel work: multiple applications or parts of a program. Improvement depends on the software being able to split that work; duplicating the cores does not automatically reduce time by half.

A execution thread is a sequence of instructions from a program. SMT (simultaneous multi-thread), a kernel supports multiple hardware threads and shares its resources among them. Hyper-Threading is an Intel implementation. Logical processors seen by the operating system are not additional physical nuclei.

Dynamic frequency and cores of different types

Technologies turbo or boost adjust the frequency according to the load and the power and temperature limits. The maximum frequency announced is not a permanent speed nor does it have to be reached in all the cores at once.

A design hybrid combines kernel types with different targets, for example performance and efficiency. The operating system distributes the threads between them. Not all cores have the same performance and not all support SMT: the specific model needs to be consulted.

Manufacture and integration

The manufacturing process or node is the technology with which the chip transistors are built. It influences the density, consumption and design possibilities. Its commercial name is not enough to compare the speed of two processors: it also matters its design, cooling and the program used.

A SoC (system in a chip) integrates CPU and other components, such as controllers and, depending on the model, GPU or accelerators. Integrate more functions does not mean adding more CPU cores. GPUs and AI accelerators are studied in the paragraph 5.2.3.

Example: interpret 6 cores and 12 threads

Suppose the six cores of a CPU support two hardware threads each: the system sees 12 Logical ProcessorsYou can improve the use of your resources when there is enough work, not equivalent to twelve physical cores. To know how much a task improves, we need to measure it.

5. Physical Components. Von Neumann Architecture

5.1. The stored programme

In the Von Neumann model, instructions and data are stored in a common main memory. The CPU gets instructions from that memory, interprets them and coordinates their execution. Input/output allows you to exchange information with the outside.

This model will help us reason about the basic functioning. Current computers incorporate many improvements and do not literally reproduce all the details of the scheme.

To enlarge: Von Neumann and Harvard

The Harvard model separates memories and access paths for instructions and data. The essential difference is that separation, not that one model necessarily has wired programming. Some CPUs combine common main memory with separate caches for instructions and data.

5.2. CPU components and operation

The control unit (UC) coordination; arythmetic-logical unit (ALU) operates with the data; records temporarily retain values within the CPU. First look at the set and then follow the example.

5.2.1. Control unit: search, decode and execute

  1. Find: the program counter (PC) indicates where to obtain the following instruction. This is copied into the instruction log (IR). In a sequential execution, the PC moves to the direction of the next instruction.
  2. Decodify: UC interprets the operation and its operands. For example, in a sum instruction identifies the operation and the data you should work with.
  3. Run: UC emits signals to read the data, activate the ALU and write the result where appropriate. The cycle is then repeated.

An instruction includes an operating code and may include operands or references to them. Its number and format depends on the architecture. Jumps can change the next PC address.

To expand: other UC records and organization
  • MAR: in the didactic model, it contains the address of the memory position to which it is accessed.
  • MDR or MBR: temporarily retains the data that is read or written. In some materials it appears as MIR.
  • Status log: collects indicators as zero result, carry or overflow, according to the architecture.
  • Decoder and sequencer: interpret the instruction and order the necessary signals, coordinated by the clock.
  • Control wired or microprogrammed: Signals can be generated by circuit logic or microinstructions. This does not in itself determine that the processor is general or specific in purpose. The ability to update the microcode depends on the design.

5.2.2. ALU: Data operations

The ALU performs arithmetic and logical operations, such as adding, subtracting, comparing, applying AND, OR or XOR and scrolling bits. 0101 AND 0011 = 0001: Only 1 position remains if both input bits are 1.

Concrete capabilities depend on the CPU. Floating point operations can be performed in specialized units; we should not imagine the entire CPU as a single scientific calculator.

5.2.3. GPU and AI cores: specialized processors

GPU (Graphics Processing Unit): It is designed to perform many similar operations in parallel. For example, it can calculate the color of numerous pixels in a scene. In addition to generating graphics, it is used in scientific calculation and in artificial intelligence. It can be integrated into the processor or be part of a dedicated graphics card; GPU and graphics card are not exactly the same.

What is an ‘AI core’? It is a general expression for circuits specialized in frequent calculations of neural networks, such as multiplications and matrix sums. It does not amount to a CPU core nor does it have a unique definition among manufacturers. It can refer to computation units within a GPU or a specific accelerator.

NPU (Neural Processing Unit): is a accelerator specialized in neural networks. On a personal computer it is usually oriented to execute models already trained — what is called inference— with low consumption. It may contain several units of calculation: an NPU is not necessarily a single 'AI core'.

Example: a video call

The CPU executes the application and coordinates the work; the GPU can draw the interface and process images; a compatible NPU can run the model that blurs the background or reduces noise. Distribution depends on the computer and the program: not all applications use the NPU.

Remember: AI can also be run on CPU and GPU. These accelerators do not "think" on their own: they perform software-defined calculations. Having more announced kernels does not allow direct comparison of CPU, GPU and NPU; it matters what task they accelerate and whether the program can use them.

5.2.4. CISC vs RISC Architecture

The instruction set (ISA) is the repertoire of operations that a CPU offers to the software. CISC and RISC are two design approaches to that repertoire; they do not describe all internal circuits of the processor by themselves.

CISC (Complex Instruction Set Computer): includes instructions that can combine several steps, such as accessing memory and performing an arithmetic operation. x86, used by numerous Intel and AMD processors, is an example.

RISC (Reduced Instruction Set Computer): favors regular operations and a load/storage model: arithmetic operations usually work with records, while specific instructions read and write memory. Arm and RISC-V are examples. "Reduced" refers to the design approach; it does not mean that a modern CPU has only a few instructions.

Two Ways to Organize Instructions
LookCISC (example: x86)RISC (example: Arm A64)
Operations and MemorySome arithmetic instructions support operands in memory.Load and storage are separated from arithmetical operations between registers.
FormatThe x86 instructions have variable length.The A64 instructions have fixed length. It is not a universal rule of all RISC ISAs.
A taskIt can be expressed with an instruction that combines several steps.It may require a simpler sequence of operations.

Example: Add a memory data

Imagine that a record contains 7 and a memory position contains 5. A CISC approach can allow an instruction that reads that data and adds it to the record. In a RISC loading/storage approach, first the 5 is loaded into another record and then both records are added. The result is 12 in both cases. It is a conceptual example, not a CPU code.

Less instructions does not imply less time. Neither CISC nor RISC alone guarantee higher performance or lower consumption. They influence the implementation of the processor, caches, compiler and task. Nor does RISC mean "an instruction always takes a cycle." Comparing equipment requires measuring comparable workloads.

Solved example: open, edit and save a document

Ana has a document saved in the SSD. She opens it, changes a paragraph and saves the new version. Let's see where the information is at every moment:

  1. Before opening: the file remains in storage, which keeps the data without power.
  2. When opening: the program loads the necessary data into RAM. The CPU works with information in caches and logs.
  3. When editing it: changes are kept in memory. The saved file can still contain the previous version.
  4. When saving: changes are written in storage.

If the power is cut off before saving, Ana may lose changes that were only in volatile memory. A persistent copy created by self-saved may allow to recover part or all of the work.

5.4. Buses: address, data and control

In the simplified model, buses communicate CPU, memory and input/output. For example, reading a value 7 stored in position 20 requires three types of information: where read (direction 20), what operation perform (reading) and what value transfer (7).

5.4.1. Data Bus: the content

It carries instructions and data. In a reading, the memory delivers the requested content; in a writing, it receives the value that you want to store.

5.4.2. Address bus: position

Select the position you access. With n bits of address can be identified 2n positions. To calculate the capacity we need to know how much each position holds.

Solved example: positions and bytes

With 8 bits of direction there are 28 = 256 positions, numbered from 0 to 255. If each position contains a byte, the addressable capacity is 256 bytes. If each position contained two bytes, it would be 512 bytes. The number of positions does not change.

It carries signals such as reading, writing and synchronization to coordinate exchanges. A direction and data are not enough: it is also necessary to indicate which operation is requested and when it should be carried out.

5.5. Peripherals: connecting and using

Peripherals exchange information with the computer. entry provide data; exit present results; input/output they do both, like a touch screen, an external unit, or a network adapter.

The interface defines connection and communication; controller is the circuit that manages the device; driver is the software that allows the operating system to use it. The driver can be integrated into the system or provided separately.

6.2. Creating programs: compiling is not checking everything

  • Editor: allows you to write and modify code.
  • Compilation: translates code to another representation and can detect certain errors, such as syntax or types according to language.
  • Interpreter: executes instructions using a program that processes them. Environments can combine interpretation and compilation.
  • Debugger: allows you to stop execution and inspect values to locate errors.
  • IDE: integrates several development tools into an environment.

Solved example: the wrong discount

We want to apply a 10% discount to 100 €. The correct formula is precio * 0.90, which gives 90€. If we write precio * 1.10, we get 110€.

The two expressions can be valid for the compiler. The second has a logic error: calculates a surcharge. Compiling without errors does not guarantee that a program works properly or that meets its requirements.

6.3. Libraries and APIs: reuse and communicate

One library contains reusable code, for example functions to generate documents. API (application programming interface) defines how a program can use functions or services from another component: available operations, data to provide, and responses to receive.

An API is not an editor: the editor is used to write code; the API is the interface that that code uses. It may belong to a library, operating system or remote service. Not all APIs are Internet services.

Solved example: consult stocks

The web of the store needs to know if there are any notebooks left. Use the inventory system API to request the inventory of a product. The system consults your data and returns a response, for example "there are 8 units left".

The API documentation specifies which identifier to send, how to interpret the response, and which errors or permissions to consider. The website does not need to know all the internal details of the inventory.

6.4. CRM, ERP and DSS: starting from a need


CRM (Customer Relationship Management, Customer Relations Management): is a system that organizes information and interactions with customers and potential customers. It allows you to register contacts, queries, sales opportunities and follow-up actions so that the business and customer support team shares a history.


ERP (Enterprise Resource Planning): integrates internal processes of an organization, such as purchases, sales, inventory, billing and accounting. Its modules share information to reduce duplications and coordinate work: a sale can be reflected in the warehouse and invoicing.


DSS (Decision Support System, decision support system): It combines data and analysis tools to compare alternatives and study scenarios. It helps to decide, for example, how much stock to buy, but the final decision is for people and depends on the quality of the data and assumptions.
