UD03 Direccionamiento IP y servicios de red

IPv4, IPv6, subredes y servicios · 1.º DAW

¿Cómo sabe un equipo a dónde enviar los datos? En esta unidad interpretarás direcciones y máscaras, configurarás redes y comprobarás cómo DHCP, DNS y HTTP permiten utilizar sus servicios. Recupera los conceptos y dispositivos de la UD02 cuando los necesites.

1. Direccionamiento IP

Conectar un equipo al switch o al WiFi no basta para que pueda comunicarse. Necesita una dirección IP y un prefijo de red coherentes; para llegar a otras redes también necesita una ruta. En una aplicación web, estos datos ayudan a distinguir un fallo de conexión de un problema del servidor o del nombre de dominio.

1.1. IPv4, IPv6 y MAC: qué identifica cada dirección

IP significa Internet Protocol. Una dirección IP se asigna a una interfaz de red: un portátil puede tener direcciones distintas en Ethernet y WiFi, y una interfaz puede tener varias. La dirección puede cambiar al conectarse a otra red.

Direcciones que conviven en una red
DirecciónFormato y ejemploPara qué sirve
IPv432 bits: cuatro octetos decimales de 0 a 255. 192.168.10.34.Direccionar paquetes entre redes. Se interpreta junto a una máscara o prefijo.
IPv6128 bits, en hexadecimal. 2001:db8:10::34 es un ejemplo de documentación.Proporcionar un espacio de direcciones mucho mayor. Puede coexistir con IPv4 mediante doble pila.
MACHabitualmente 48 bits en Ethernet/WiFi. 02:11:22:33:44:55.Identificar interfaces en el enlace local. Puede modificarse o aleatorizarse; no es una identidad personal permanente.

En IPv6 se pueden omitir ceros iniciales de cada grupo y usar :: una sola vez para abreviar grupos consecutivos de ceros. ::1 es loopback; fe80::/10 identifica direcciones de enlace local. En las LAN habituales se utiliza un prefijo /64. IPv6 no tiene broadcast: utiliza multicast para varias funciones de descubrimiento.

1.2. Máscara y prefijo: red, host y broadcast

La máscara separa los bits de red de los bits disponibles dentro de ella. En 192.168.10.34/24, los primeros 24 bits identifican la red y quedan 8 bits para direcciones dentro del bloque. /24 equivale a 255.255.255.0: 24 unos seguidos de 8 ceros en binario.

Determinar la red con la máscara

Si un equipo tiene la dirección 172.16.4.1/24, ¿qué parte identifica su red? El prefijo /24 indica que los primeros 24 bits de la máscara valen 1. Como cada octeto tiene 8 bits, en este ejemplo la parte de red ocupa los tres primeros octetos.

Dirección, máscara y resultado en decimal y binario
ValorRed · primeros 24 bitsHost · últimos 8 bits
Dirección IP172101011001600010000400000100100000001
Máscara255111111112551111111125511111111000000000
Red (IP AND máscara)172101011001600010000400000100000000000

La operación AND compara cada bit de la IP con el bit de la máscara que ocupa la misma posición. Donde la máscara vale 1, se conserva el bit de la IP. Donde vale 0, el resultado es 0. Así se conservan 172.16.4 y el último octeto pasa de 1 a 0. La dirección de red es 172.16.4.0/24.

Ejemplo resuelto: 192.168.10.34/24

  • Red: 192.168.10.0. Se obtiene aplicando AND bit a bit entre IP y máscara.
  • Broadcast: 192.168.10.255, con todos los bits de host a uno.
  • Direcciones asignables: de 192.168.10.1 a 192.168.10.254.
  • Capacidad: 28 = 256 direcciones; 254 asignables en esta subred convencional.

192.168.10.200/24 pertenece a la misma subred; 192.168.11.20/24 pertenece a otra. Compartir switch no cambia ese cálculo.

Número de hosts de una red

Si quedan n bits para los hosts, hay 2n direcciones posibles. En una subred IPv4 convencional se reservan dos, una para identificar la red y otra para enviar a todos sus equipos (broadcast). Por eso quedan 2n − 2 direcciones asignables. En el ejemplo anterior, los 8 bits de host permiten asignar 28 − 2 = 254 direcciones.

Hay dos casos especiales. En un enlace punto a punto con prefijo /31, cada extremo puede usar una de las dos direcciones. Un prefijo /32 identifica una única dirección IPv4.

Direccionamiento por clases (classful)

Originalmente, IPv4 agrupaba las redes en clases con tamaños fijos. Los primeros bits de la dirección identificaban la clase y su máscara predeterminada, antes de subdividir la red:

Clases A, B y C: máscaras predeterminadas históricas
ClasePrimer octetoMáscara predeterminadaBits de host
A1–126*255.0.0.0 · /824
B128–191255.255.0.0 · /1616
C192–223255.255.255.0 · /248

*Se excluyen 0 y 127 por sus usos especiales. La clase no indica si una dirección es pública o privada.

El problema: estos tamaños eran poco flexibles. Una red de clase C ofrecía 254 direcciones asignables; una B, 65.534. Muchas organizaciones necesitaban un tamaño intermedio.

Direccionamiento sin clases (classless)

El direccionamiento actual utiliza un prefijo explícito para indicar qué bits identifican la red, sin deducirlo de la antigua clase. Permite ajustar los bloques a las necesidades y agrupar rutas.

Por ejemplo, 192.168.10.0/26 deja 6 bits de host: 64 direcciones, de las cuales 62 son asignables en una subred convencional. Aunque empiece por 192, su máscara es 255.255.255.192, no la antigua máscara de clase C. La notación CIDR expresa ese prefijo.

Referencia: RFC 4632: del direccionamiento por clases a CIDR.

Notación CIDR

La notación CIDR (Classless Inter-Domain Routing) escribe la longitud del prefijo después de una barra. En 192.168.10.34/24, el /24 indica que los primeros 24 de los 32 bits identifican la red. Los 8 restantes corresponden al host. Las clases históricas A, B y C utilizaban máscaras predeterminadas. Con CIDR, la máscara se obtiene del prefijo indicado.

1.3. Direcciones privadas, públicas y especiales

Las direcciones privadas se reutilizan en redes distintas y no se encaminan por la Internet pública. Una dirección pública puede ser globalmente enrutable, pero su accesibilidad depende de las rutas y del cortafuegos. Pública/privada y fija/dinámica son criterios diferentes.

Bloques privados IPv4 definidos en RFC 1918
BloqueRango completoMáscara del bloque
10.0.0.0/810.0.0.0 – 10.255.255.255255.0.0.0
172.16.0.0/12172.16.0.0 – 172.31.255.255255.240.0.0
192.168.0.0/16192.168.0.0 – 192.168.255.255255.255.0.0

Estos bloques pueden dividirse en subredes más pequeñas. Por ejemplo, pertenecer a 10.0.0.0/8 no obliga a configurar todos los equipos con /8.

  • Loopback: 127.0.0.0/8; se suele usar 127.0.0.1 para acceder al propio equipo.
  • Enlace local: 169.254.0.0/16. Puede aparecer por autoconfiguración cuando no se obtiene respuesta DHCP. No es un cuarto bloque privado RFC 1918 y no sirve para llegar a otras redes.
  • Dirección no especificada: 0.0.0.0, utilizada en determinados contextos antes de disponer de una IP. La ruta 0.0.0.0/0 significa ruta por defecto.

NAT/PAT: en un acceso doméstico IPv4, el router suele traducir direcciones y puertos para que varios dispositivos compartan una IPv4 pública. El operador también puede usar CGNAT. NAT no asigna la IP local —eso puede hacerlo DHCP— ni sustituye al cortafuegos.

1.5. Direccionamiento IPv6

Al consultar la configuración de un portátil puedes encontrar varias direcciones IPv6 en la misma tarjeta Wi-Fi. Una le permite comunicarse con el router en ese enlace. Otra puede servirle para llegar a equipos de otras redes. Para interpretarlas conviene fijarse en el prefijo y el alcance de la dirección.

Cómo leer y abreviar una dirección

Una dirección IPv6 tiene 128 bits. Se escribe en ocho grupos de 16 bits separados por dos puntos. Cada grupo ocupa hasta cuatro cifras hexadecimales, del 0 al 9 y de la a a la f. Observa la dirección de este portátil ficticio. Usaremos el bloque 2001:db8::/32, reservado para documentación.

Primero se eliminan los ceros iniciales de cada grupo. Así, 0db8 pasa a db8 y 0010 a 10. Después se sustituye la secuencia más larga de dos o más grupos a cero por ::. Si dos secuencias tienen la misma longitud, se abrevia la primera. El resultado es 2001:db8:10:2::34/64. Solo se utiliza :: una vez por dirección para poder recuperar sin ambigüedad los ocho grupos.

Cómo saber si dos equipos comparten el prefijo

La subred del portátil es 2001:db8:10:2::/64. Una impresora con 2001:db8:10:2::50/64 comparte sus primeros cuatro grupos. Un servidor con 2001:db8:10:3::50/64 ya pertenece a otra subred, porque cambia el cuarto grupo. En esta LAN, el portátil puede entregar los datos directamente a la impresora y necesita un router para alcanzar el servidor.

Qué indica el alcance de una dirección

Una dirección de enlace local pertenece a fe80::/10. Por ejemplo, fe80::1 puede ser la dirección del router que el portátil utiliza como siguiente salto. Solo tiene sentido en ese enlace. Una dirección unicast global puede utilizarse entre redes cuando existen las rutas correspondientes. Una dirección multicast identifica un grupo de receptores. Por ejemplo, ff02::1 alcanza a todos los nodos IPv6 del enlace.

En Ubuntu, ip -6 addr show muestra las direcciones de cada interfaz y su alcance. Para comprobar por dónde saldría el tráfico hacia otras redes, consulta ip -6 route show default. Una salida como default via fe80::1 dev wlan0 indica que el portátil envía ese tráfico al router fe80::1 a través de la interfaz wlan0.

1.7. Dividir una red: subnetting

Dividir un bloque permite planificar direcciones para varias redes. Al aumentar el prefijo, quedan menos bits por subred. Para separar dominios de broadcast también se necesitan segmentos físicos distintos o VLAN: cambiar la máscara no crea por sí solo una barrera de seguridad.

Ejemplo: dividir 192.168.10.0/24 en cuatro /26

Tomamos 2 bits más para la red: obtenemos 22 = 4 subredes. Quedan 6 bits: 64 direcciones por bloque y 62 asignables. La máscara es 255.255.255.192 y el salto entre redes es 64.

RedHosts asignablesBroadcast
192.168.10.0/26.1 – .62.63
192.168.10.64/26.65 – .126.127
192.168.10.128/26.129 – .190.191
192.168.10.192/26.193 – .254.255

Todos los valores abreviados pertenecen a 192.168.10.x. Para 192.168.10.70/26, la red es .64 y el broadcast .127; el primer host no es .1.

  1. Para 192.168.20.130/26, calcula máscara, red, broadcast, rango y capacidad.
  2. Divide 192.168.30.0/24 en dos /25 y propón una IP de puerta de enlace para cada una.
  3. Decide si 192.168.30.100/25 y 192.168.30.150/25 pertenecen a la misma subred. Justifica con los intervalos.

Práctica de ampliación: DHCP, HTTP y DNS en Packet Tracer

Continúa tras la primera red de Packet Tracer. La finalidad es observar tres servicios distintos: DHCP configura clientes, DNS resuelve nombres y HTTP sirve páginas. Utiliza esta versión adaptada de las fichas del curso.

  1. Conecta cuatro PC y un Server-PT a un switch. Configura el servidor con 10.0.0.2 y máscara 255.255.255.0. La red es aislada: no necesita router ni una puerta de enlace ficticia.
  2. En Services → DHCP, activa un pool con inicio 10.0.0.10, máscara 255.255.255.0, máximo de 91 usuarios y DNS 10.0.0.2. Mantén la puerta de enlace sin configurar (o 0.0.0.0 si el simulador requiere un valor). Selecciona DHCP en los clientes y registra sus direcciones.
  3. Activa HTTP en el servidor y edita la página inicial. Desde un cliente abre http://10.0.0.2 y comprueba la respuesta.
  4. En Services → DNS, crea un registro A para www.aula.test con dirección 10.0.0.2. Abre http://www.aula.test en el cliente y compara con el acceso por IP.
  5. En modo Simulation, observa DHCP, DNS y HTTP. Ejecuta también ping 10.0.0.2: utiliza ICMP, no UDP, y no demuestra por sí solo que HTTP funcione.
  6. Desactiva solo HTTP y compara ping con la apertura de la web. Restáuralo; desactiva DNS y repite acceso por IP y nombre. Si el nombre sigue funcionando, considera la caché y prueba con un cliente que no lo haya resuelto antes. Restaura los servicios al terminar.
