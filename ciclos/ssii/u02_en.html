1. Introduction to networked systems

A computer network connects devices to exchange information and share resources: files, printers, applications or access to other systems. Representing and transmitting data enables different devices to work together.

To design or maintain a network, we need to identify what we want to communicate, through which medium, using which devices and following which rules. A network can work without an Internet connection; the Internet is an interconnection of networks.

In this unit you will learn to: recognise the elements of communication, classify networks and topologies, distinguish media and technologies, identify services and devices, and relate their functions to the OSI and TCP/IP models.

2.1. Elements of communication

  • Sender: creates and transmits the information.
  • Receiver: receives and interprets the information.
  • Channel: the medium through which the signal travels, such as copper, optical fibre or the space through which radio waves propagate. It can be affected by noise, interference and attenuation.
  • Message: the information being communicated. It is represented using an encoding, such as UTF-8 for text. It can also be compressed or encrypted; these operations serve different purposes.
  • Protocol: a set of rules governing message format, order and processing. Sender and receiver need compatible rules.

A standard sets common specifications that support interoperability. A protocol is different from the organisation or document that standardises it. IEEE develops standards such as Ethernet; the IETF publishes Internet protocol specifications in RFC documents.

2.2. Classifying communication systems

By transmission medium

  • Guided: use a physical medium that guides the signal. Twisted pair and coaxial cable carry electrical signals; optical fibre carries light. Performance depends on the cable type, interfaces, distance and installation.
  • Unguided or wireless: use electromagnetic waves without a cable between sender and receiver. Coverage can be omnidirectional or directional, depending on antennas and link design. Wi-Fi does not necessarily use an omnidirectional antenna; microwave and laser links are usually directional.

By transmission direction

Direction of communication
ModeHow it worksExample
SimplexOne direction only.Radio broadcasting to a receiver.
Half-duplexBoth directions, taking turns.A walkie-talkie.
Full-duplexBoth directions simultaneously.A switched Ethernet link configured for full-duplex operation.

By synchronisation

During synchronous transmission, sender and receiver maintain coordinated timing to interpret symbols. During asynchronous transmission, blocks or characters can start at independent times; for example, a UART (Universal Asynchronous Receiver/Transmitter: a circuit that sends and receives serial data without a shared clock line) uses start and stop bits. Asynchronous does not mean there is no timing: both ends must correctly interpret the duration of the bits.

By signal type

An analogue signal represents information through continuous variations. A digital representation uses a discrete set of symbols, usually bits. The physical signal is always affected by the medium: digital communication can also suffer errors. Regeneration and error detection or correction mechanisms help handle them.

3. Network classification

A network can have several labels at the same time: it can be local, private and wireless, and use client–server services. Each classification answers a different question.

3.1. Relationships between nodes

A node is an element connected to the network. An end device can also be called a host; this term does not refer exclusively to servers.

  • Client–server: the client requests a service and the server provides it. A browser requests a page from a web server. The load can be shared among several servers; the client also processes information.
  • Peer-to-peer (P2P): participants can both offer and request resources. BitTorrent is an example of file distribution between peers. Some P2P systems use central services to locate participants: P2P does not guarantee that the entire architecture is serverless.

The arrows represent logical communication, not direct cables. P2P can use supporting servers to locate participants; not every peer needs to connect to every other peer.

3.3. Ownership, access and virtual networks

  • Public network: provides communication services to multiple users, such as a service provider's network. “Public” does not mean that all its data is accessible to everyone.
  • Private network: its use is restricted to an organisation or group. It may use its own infrastructure or contracted services.
  • Intranet: an organisation's internal services based on Internet technologies, such as an employee portal.
  • Extranet: controlled access for external people, such as suppliers or customers, to specific resources within the organisation.
  • VPN: a virtual private network built over other infrastructure. Remote-access VPNs usually create encrypted tunnels; some provider VPNs offer isolation without necessarily including end-to-end encryption.

A VPN can connect a user to their company network or connect different sites. Its security depends on the protocol, authentication and configuration. It does not guarantee anonymity or prevent every threat on its own.

3.4. Transporting and distributing information

Circuit, message and packet switching

  • Circuits: a path or resources are reserved for the duration of the communication. This is the traditional approach in switched telephony.
  • Messages: each node stores the entire message before forwarding it. This can require substantial memory and add delay.
  • Packets: information is divided into smaller units transmitted over shared links. The Internet uses packet switching; packets may be lost, delayed or arrive out of order.
Further reading: Frame Relay, ATM and xDSL

Frame Relay and ATM are historical switching technologies; ATM uses fixed-size cells. xDSL is an access technology over copper, not a switching category. Switching alone does not determine how many recipients receive a transmission.

Unicast, broadcast and multicast

Recipients of a transmission
TypeRecipientsKey idea
UnicastOne.One device sends to another; traffic may cross several routers.
BroadcastAll devices in the relevant broadcast domain.This does not mean sending to the entire Internet.
MulticastMembers of a group.The network distributes traffic to interested receivers when the infrastructure supports it.

In a conventional IPv4 subnet with broadcast, the address with all host bits set to 1 is the broadcast address; there are exceptions, such as /31 links. IPv4 multicast address space is 224.0.0.0/4, from 224.0.0.0 to 239.255.255.255, with ranges reserved for specific uses.

IPv6 does not use broadcast; it uses multicast for many of those functions. Its multicast addresses start with FF00::/8. IPv6 also supports unicast and anycast. Internet video can be delivered using unicast: streaming does not necessarily mean multicast.

3.5. Peer-to-peer and privacy-oriented networks

Peer-to-peer (P2P) networks allow computers to share resources directly: each can receive and provide data. Other networks and services aim to reduce exposure of users' identities or traffic origins. Their purposes differ:

  • BitTorrent: a P2P protocol for distributing files. Participants exchange pieces of the same file, sharing the load across multiple computers. A seed has the complete file and shares it. BitTorrent is used to distribute large files; to participate, use a compatible client and a .torrent file or magnet link. It does not provide anonymity on its own: other participants may see your IP address.
  • Tor: routes traffic through several relays using layered encryption. As data travels, each relay removes only its own layer to find the next hop, without knowing both the original sender and final destination. Hence the name onion routing: onion refers to the layers of an onion. Tor also provides access to .onion services within its network. When visiting an external website, HTTPS is still needed to protect traffic between the exit relay and the website.
  • VPN: can hide the source address from the destination site, but shifts some trust to the VPN provider or administrator.

Decentralisation, encryption and anonymity are not synonyms; none can promise absolute privacy.

4. Network topologies

The physical topology describes how nodes and links are connected. The logical topology describes how information flows. They may differ. They are chosen with functionality, growth, cost and fault tolerance in mind.

4.1. Wired topologies

Circles represent nodes and lines represent links. These are simplified physical diagrams; in a bus, several nodes share the same medium.

  • Star: each device connects to a central element, usually a switch. A failure in one device's link does not disconnect everyone; failure of the central element can.
  • Bus: nodes share a common medium. This is a historical coaxial Ethernet topology, with terminators at its ends. Shared access requires coordination.
  • Ring: each node connects to its neighbours to form a closed loop. Some variants include a second ring or recovery mechanisms.
  • Tree: a hierarchical structure connecting groups of devices through several levels of equipment. It supports growth, but upper-level links concentrate traffic.
  • Partial mesh: some nodes have several paths available. This improves redundancy, although it does not guarantee continuity under every failure.
  • Full mesh: each node connects to every other node. With n nodes, n × (n − 1) / 2 bidirectional point-to-point links are needed. Redundancy increases cost and complexity.
  • Hybrid: combines several topologies, such as stars connected through a hierarchy of switches.

4.2. Wireless topologies

A wireless topology describes how devices are organised and how they communicate. Choosing it well helps provide coverage, share resources and maintain access to applications.

Connected to Wi-Fi, but no Internet? Yes, it is possible. Wi-Fi provides access to a local network; the Internet is a separate connection. If the web server is on your network and accessible, you can use its application even if the Internet connection fails, provided it does not depend on external services.

4.2.1. Infrastructure: one access point

In infrastructure mode, clients associate with an access point (AP). It receives and transmits wireless communications and usually links the WLAN to the wired network. This is the usual Wi-Fi arrangement in a classroom or home.

  • AP: provides wireless access to the network.
  • Switch: connects devices on the LAN and forwards frames to the appropriate port.
  • Router: connects different networks, such as the local network and the Internet.

The device we call a “home router” often combines all three functions. Being in the same box does not make them the same function.

4.2.2. Multiple access points: coverage and mobility

One AP may not cover an entire school or have enough capacity for its users. We can deploy several APs wired to the LAN. This extends the service area; their placement and channels must be planned to avoid coverage gaps and reduce interference.

  • SSID: the Wi-Fi network name users see, such as “Classroom”.
  • BSSID: the identifier of a Wi-Fi cell, usually in MAC address format. One physical AP can provide several BSSIDs.
  • Roaming: a client changing its association from one AP to another as it moves.

In a WLAN with several APs, they can advertise the same SSID and security policy. Copying the name and password does not guarantee a seamless handover: the client's decision, coverage, authentication and network configuration all matter. A device may remain connected to a distant AP longer than expected.

4.2.3. Mesh networks: connecting the nodes

A home mesh Wi-Fi system combines a main node and one or more coordinated satellite nodes to extend coverage using the same network name (SSID) and password. It is useful in homes with several floors or areas with weak signals.

How it works:

  • Main node: connects to the provider's modem, ONT or router, depending on the installation. It can act as a router or run in access point mode if the system supports it.
  • Satellite nodes: are placed around the home and link to the main node or other available nodes. They do not all need direct connections to one another.
  • Intelligent roaming: the system helps compatible devices switch nodes as they move, without manually selecting another network. Handover also depends on the client and coverage: the strongest signal and completely uninterrupted connections are not always guaranteed.
  • Self-healing: if a node or link fails, the system can seek another path if an alternative route is available. It cannot restore an isolated node or replace Internet access if the only main node fails.

To understand how traffic reaches its destination, we must distinguish two connections:

  • Access: the Wi-Fi link between a phone or laptop and the node it connects to.
  • Backhaul: the connection carrying traffic from the nodes to the rest of the network. Depending on the system, it may use radio, Ethernet cable or a combination.

The mesh can be partial: not every node connects directly to every other node. Path selection depends on the system and available links. Several wired APs do not automatically become a mesh simply because they share an SSID.

Mesh and repeaters: a repeater extends a signal by retransmitting traffic; a mesh system usually coordinates its nodes and link selection. The “mesh” label alone does not guarantee higher speed or perfect roaming. When backhaul shares radio resources with clients, they compete for them; additional hops can also increase latency.

More coverage does not mean more capacity. Having a signal in more rooms does not increase the bandwidth of your Internet subscription. Performance depends on distance, obstacles, interference, medium utilisation and backhaul capacity. Nor is there a universal rule that every repeater always halves the speed.

Good practice: place nodes where they still receive a suitable backhaul connection; a node in a dead zone cannot retransmit a connection it does not receive. If the system supports it and cabling is available, Ethernet backhaul frees up radio resources.

4.2.4. Direct connections: ad hoc and Wi-Fi Direct

When we only need to connect nearby devices, external Wi-Fi infrastructure may be unnecessary.

  • Classic ad hoc (IBSS): devices form a network without an infrastructure AP. This is an important reference for understanding peer-to-peer organisation; do not assume that all current devices support this mode.
  • WiFi Direct: compatible devices form a group without an external AP. One takes the role of Group Owner or coordinator, similar to an AP for that group. It is therefore not identical to classic ad hoc mode.

Application: printing from a laptop to a compatible printer without using the school's Wi-Fi. Actual support depends on both devices and the software. Sharing a phone's Internet connection is a different case: the phone normally creates an access point, not a classic ad hoc network.

5. Network technologies and media

The physical medium, communication standard and contracted service are different concepts. For example, Ethernet can run over copper or fibre, while Wi-Fi provides access to a local network and does not require an Internet connection.

5.1. Guided media

The signal follows a physical medium: electricity through copper or light through fibre. Choose the medium according to distance, required speed and the environment. The connector must match the cable and the equipment port.

Twisted pair

Common in classrooms. Four twisted copper pairs reduce interference and crosstalk (interference between pairs).

Connector: 8P8C, commonly called RJ45. Connects computers, switches and access points.

Coaxial

A shielded centre conductor. The shield shares the same axis as the centre conductor and helps limit interference.

Connectors: F, threaded, commonly used for TV and cable modems; BNC, bayonet-style, used in video and instrumentation. Match impedance and application: 50 Ω and 75 Ω cannot simply be interchanged.

Optical fibre

Light for high-capacity links. Fibre is immune to electromagnetic interference and is useful between buildings and network cabinets.

Connectors: LC is small and common on transceivers; SC is larger and common in FTTH access. Connector shape does not determine speed.

Simplified diagrams, not to scale. Colours identify the parts; always check the product markings.

Twisted pair: category, shielding and installation

The category specifies transmission performance, not your Internet connection speed. MHz expresses cable bandwidth; Gbit/s expresses the Ethernet link's data rate.

Recognise the connection

RJ45 plug: eight contacts and a retaining clip. Outlet or keystone jack: a female connector where the fixed cable terminates. Patch panel: groups these terminations in the cabinet.

Fixed cable usually has solid conductors; patch leads are usually stranded and more flexible. The plug must match the category, diameter and conductor type.

What to check when buying

  • Copper: check the material; CCA (copper-clad aluminium) is not equivalent to copper and has higher resistance, especially relevant for PoE.
  • Jacket: indoor or outdoor use, environmental resistance and the fire performance required for the installation. LSZH (Low Smoke Zero Halogen) means low smoke and halogen-free: it describes jacket materials that produce little smoke when burning and avoid releasing corrosive halogen gases. They help reduce these risks in occupied spaces. This marking does not indicate speed or by itself guarantee fire resistance.
  • Performance: request a data sheet and test the installed link. Price or colour does not certify quality.

LC and SC describe the connector format. They can be used with different fibres. An SFP/SFP+ module is a transceiver inserted into equipment; it is not a connector name and does not by itself guarantee compatibility.

5.2. Unguided media

Information travels through electromagnetic waves without a cable to guide them. They support mobility and links where running cable is difficult. Wi-Fi, Bluetooth and mobile networks use this medium; light can also communicate without fibre.

Radio: shared coverage

Waves propagate through space. They can pass through some materials, but become weaker. Several devices share the radio environment.

Useful for mobility, local networks and peripherals. Coverage depends on antennas, power, frequency and obstacles.

Radio link: towards a destination

Directional antennas concentrate energy towards another point. They connect places where laying cable is difficult.

Pointing them at each other is not enough: the space around the path (the Fresnel zone) also needs clearance. Distance, interference and link conditions must be assessed.

Light: infrared and visible

Optical wireless communication uses light, such as infrared remote controls or visible-light communication systems.

It needs a suitable optical path, direct or reflected depending on the system. Opaque obstacles and ambient light can limit it.

Conceptual diagrams, not to scale. Radio waves and light belong to the same electromagnetic spectrum.

Frequency, channel and speed: three different quantities

Frequency · GHz

The number of wave oscillations per second. 2.4 GHz does not mean 2.4 Gbit/s. A band is a region of the spectrum used by a technology.

Channel width · MHz

The portion of spectrum used by a transmission. A wider channel can carry more data, but occupies more spectrum and leaves less room for other links.

Data rate · Mbit/s

The number of bits transmitted per second. It also depends on modulation, signal quality, spatial streams and equipment. Useful throughput is lower because of protocol overheads, waiting and retransmissions.

The table's abbreviations, in plain language

  • MIMO (Multiple Input, Multiple Output): uses several antennas to send and receive data. It can transmit multiple streams in parallel and make better use of the link.
  • MU-MIMO (Multi-User MIMO): lets the access point communicate with several devices at once using different spatial streams.
  • OFDMA (Orthogonal Frequency Division Multiple Access): divides the channel into small groups of frequencies assigned to different devices. They can then share a transmission, which is useful when many devices each send small amounts of data.
  • QAM (Quadrature Amplitude Modulation): combines changes in wave amplitude and phase to represent bits. A higher number, such as 4096-QAM, packs more bits into each symbol but requires a cleaner signal.
  • TWT (Target Wake Time): the device and access point agree when to communicate. The device can leave its radio asleep between those times to save battery power.
  • MLO (Multi-Link Operation): coordinates several Wi-Fi links in one or more bands. Depending on the equipment, it can spread traffic across them or choose the most suitable one to reduce delays and improve connectivity.

Antennas ≠ streams: an antenna is a physical element; a spatial stream is a data sequence transmitted in parallel. N streams require at least N suitable radio chains and antenna elements at each end, but more antennas do not guarantee more streams. A 2×2:2 client transmits and receives using two chains and supports two streams, even if the access point has eight.

Example: Wi-Fi 6 with two streams and 80 MHz reaches a link rate of about 1.20 Gbit/s under ideal conditions; with 160 MHz, about 2.40 Gbit/s. Useful throughput is lower. These features improve the Wi-Fi link but do not by themselves increase the speed of your Internet subscription.

The table summarises common WLAN generations, not every IEEE 802.11 variant. Older Wi-Fi 7 figures of around 46 Gbit/s assumed 16 streams from initial proposals; this table uses 8 streams and a single link.

Why is my connection slow even though I have a signal?

Distance and obstacles

The signal weakens as it travels. Walls, metal and people can weaken or reflect it. Place the access point in an unobstructed location and check coverage where it will be used.

Signal strength in dBm: −50 dBm is stronger than −75 dBm. These are examples for comparison, not universal quality thresholds.

Interference and shared access

Other transmitters can interfere with reception. Clients using the same radio share transmission time: more active users may reduce each user's throughput.

Counting networks is not enough: their activity, signal strength and channel occupancy also matter.

The rest of the path

A strong signal does not prove that Internet access, DNS or the server works. The link from the access point to the switch or the operator's connection may also limit performance.

Check each part: Wi-Fi connection, local access and Internet access.

Antennas and spatial streams: MIMO uses multiple antennas to exploit different paths. You cannot infer speed by counting antennas: the access point and client must support the streams and modes used. Protect access with WPA3 where supported, or WPA2 with AES for compatible devices that require it; avoid obsolete WEP and WPA.

WEP, WPA, WPA2 and WPA3 are protection systems. PSK, SAE and 802.1X/EAP describe how participants authenticate or establish keys. RC4 and AES are encryption algorithms; TKIP, CCMP and GCMP specify how frames are protected.

6.2. Intermediaries and security

Forward and reverse proxies

A proxy acts as an intermediary in communications. A forward proxy receives client requests and forwards them to other servers; a reverse proxy receives requests for a service and distributes them to internal servers. Depending on its functions, it can apply policies, caching or load balancing.

An HTTP proxy works with the application protocol; it should not always be described as a layer 4 device. It can be software or part of specialised equipment. It does not guarantee anonymity either: that depends on what information it records or forwards. A reverse proxy is not necessarily transparent, and proxying and NAT are different mechanisms.

Firewalls and WAFs

A firewall allows or blocks traffic according to rules. It can inspect addresses, ports, connection states or application characteristics. It may be installed on an end device or protect network segments. It is not universally limited to a single OSI layer.

A WAF specialises in web application traffic and helps filter malicious requests. Protection against denial-of-service attacks may require additional services and measures. A DMZ is a segment typically used for exposed services, separated by access controls.

Monitoring, IDS and IPS

  • Protocol analyser: captures traffic and lets you examine it; Wireshark is an example. Only capture traffic in authorised environments.
  • IDS: detects suspicious activity and generates alerts. It does not necessarily block traffic automatically.
  • IPS: can intervene to block traffic; it normally sits in the communication path.

Snort and Suricata can be used for detection and, with an appropriate deployment, prevention. No tool replaces updates, configuration and alert review.

6.3. Load balancing and link aggregation

Link aggregation combines several physical connections into one logical interface. Depending on the mode, it provides redundancy and combined capacity. LACP negotiates compatible aggregations between endpoints. A single connection does not necessarily gain the combined speed of all links: traffic is usually distributed by flow.

The load-balancing mechanism distributes work among resources, such as servers or WAN links. Having two providers can improve availability, but failover and combining throughput depend on the solution. Server load balancing should not be confused with Ethernet link aggregation.

There are also mechanisms that combine mobile and wireless access, such as LWA for LTE and WLAN. Do not assume that every phone automatically combines Wi-Fi and mobile data, or that two SIM cards add their speeds together.

6.4. Interconnection devices

A device's function helps place it within a layered model. One commercial device can combine several functions; for example, a home router often includes a switch, an AP and a firewall.

How a switch works

A switch learns the source MAC address of received frames and associates it with a port and a VLAN. If it knows the destination MAC address, it forwards through the relevant port. Broadcast traffic and unknown destinations may be flooded through other ports in that VLAN, according to the device's rules. It does not create and remove a connection for each transmission.

Switched full-duplex Ethernet links avoid the collisions associated with shared media. A layer 2 switch does not use the IP subnet mask to decide which port should receive a frame. Communication between subnets requires a routing function, provided by a router or a layer 3 switch.

Further reading: PoE · data and power through one cable

PoE (Power over Ethernet) carries data and electrical power over the same copper Ethernet cable. It supports Wi-Fi access points, IP cameras and network phones without a power socket beside each device.

How it works: a PoE switch or injector supplies power (PSE); the compatible device receives it (PD). With standardised PoE, the source detects the device before supplying power.

  • Power: 802.3af allows up to 15.4 W at the source port; 802.3at (PoE+), 30 W; and 802.3bt, up to 60 W (Type 3) or 90 W (Type 4). Less reaches the device because of cable losses.
  • Compatibility: check the device's required standard and power, the per-port capacity and the switch's total power budget. A switch with many ports may not power all of them at full power simultaneously.
  • Cabling: use suitable cable and terminations. So-called passive PoE may apply voltage without standardised detection: do not connect it without checking voltage, polarity and compatibility.
Read Cisco's PoE guide

Further reading: WoL · wake a computer over the network

WoL (Wake-on-LAN) activates a computer remotely, for example to prepare classroom computers before a lesson or carry out maintenance.

How it works: another computer sends a magic packet containing the destination MAC address. The network card, still receiving standby power, recognises it and requests that the computer wake up.

  • Requirements: a compatible network card and motherboard; WoL enabled in BIOS/UEFI and in the operating system or driver settings. The computer must retain power and its network connection.
  • Supported states: it may work from sleep and, on some computers, from hibernation or soft shutdown. This depends on hardware and settings; it cannot work if power is completely disconnected.
  • Scope: typically used on the local network. Reaching across other networks requires a configured mechanism, such as a management agent on the LAN; the magic packet does not itself authenticate its sender.

The key difference: PoE supplies power to a device; WoL sends a wake-up request to a computer that already has standby power.

Interfaces and connectors

  • RJ45 / 8P8C: the common name for connectors used in Ethernet over twisted pair. Speed depends on the standard, cable and ports.
  • SC and LC: examples of optical fibre connectors. Their shape alone does not determine speed.
  • SFP, SFP+ and other families: slots and transceiver modules for compatible interfaces. Optical and copper variants exist; the module, device and cable must be compatible. GBIC is an older, larger form factor.

Ethernet supports many speeds; it is not limited to 10, 100, 1000 or 10000 Mbit/s. An optical interface does not necessarily mean Fibre Channel either: that is a different set of technologies, common in storage.

Historical reference: Token Ring and MAU

Token Ring uses token passing to regulate access to the medium. An MAU can physically connect stations in a star while maintaining a logical ring. This shows why physical and logical topologies do not always match. An MAU should not be confused with a modern Ethernet switch.

Routing and gateways

A router selects the next hop using its routing table. Routes can be connected, configured statically or learned through dynamic routing protocols. NAT and CGNAT translate addresses, but they are not required for routing packets.

  • RIP: uses hop count as its metric; RIPv2 includes subnet mask information and supports VLSM.
  • IGRP and EIGRP: IGRP is a historical Cisco protocol; EIGRP includes more advanced mechanisms. VLANs and trunk links are data link concepts, not what defines a routing protocol.
  • OSPF: a link-state protocol that calculates routes using Dijkstra's algorithm and organises the domain into areas.

The default gateway is usually the router to which a device sends traffic destined for other networks. An application gateway, by contrast, can translate messages between different systems. They are not necessarily the same device. Remote administration should use protected channels such as HTTPS or SSH when available.

7.1. Why use layers?

An architecture defines rules, functions and relationships so that different systems can communicate. Dividing the work into layers makes complexity manageable: each layer provides services to the one above and uses those below through defined interfaces.

Equivalent layers on two devices follow a common protocol. This communication is logical: actual data passes through the sender's stack, the medium and the receiver's stack. A change in one implementation can remain independent of other layers if the interfaces and expected behaviour are preserved.

7.2. Encapsulation and decapsulation

When information is sent, protocols add control data such as headers and, in some cases, trailers. On reception, each layer interprets and removes the information that belongs to it. Not every layer necessarily adds a separate header.

Simplified path: application data → TCP segment or UDP datagram → IP packet → link-layer frame → signals in the medium. The receiver performs the reverse process.

A layer 2 switch makes decisions about frames; a router interprets the IP packet and carries it in a new frame over the next link. Intermediate devices do not need to run the destination application to forward traffic.

7.3. The seven OSI layers

OSI is a reference model developed within ISO and also covered by ITU-T recommendation X.200. It describes functions, not a mandatory list of specific products or protocols.

Connecting a device to a switch or Wi-Fi is not enough for communication. It needs a consistent IP address and network prefix; reaching other networks also requires a route. For a web application, these settings help distinguish connection problems from server or domain-name problems.

8.1. IPv4, IPv6 and MAC: what each address identifies

IP stands for Internet Protocol. An IP address is assigned to a network interface: a laptop can have different addresses on Ethernet and Wi-Fi, and an interface can have several addresses. Its address may change when joining another network.

8.2. Mask and prefix: network, host and broadcast

The mask separates network bits from the bits available within the network. In 192.168.10.34/24, the first 24 bits identify the network, leaving 8 bits for addresses within the block. /24 equals 255.255.255.0: 24 ones followed by 8 zeros in binary.

Worked example: 192.168.10.34/24

  • Network: 192.168.10.0, obtained by applying bitwise AND to the IP and mask.
  • Broadcast: 192.168.10.255, with all host bits set to one.
  • Assignable addresses: from 192.168.10.1 to 192.168.10.254.
  • Capacity: 28 = 256 addresses; 254 assignable in this conventional subnet.

192.168.10.200/24 belongs to the same subnet; 192.168.11.20/24 belongs to another. Sharing a switch does not change this calculation.

In a conventional IPv4 subnet with h host bits, there are 2h − 2 assignable addresses. This does not apply unchanged to the special /31 and /32 cases. The current notation is CIDR: the prefix is explicit. Classes A, B and C are historical references, not a way to infer the mask of a current configuration.

Private addresses are reused in different networks and are not routed on the public Internet. A public address may be globally routable, but reachability depends on routes and firewall rules. Public/private and static/dynamic are separate criteria.

8.5. Dividing a network: subnetting

Dividing a block lets you plan addresses for several networks. A longer prefix leaves fewer bits per subnet. Separating broadcast domains also requires separate physical segments or VLANs: changing a mask does not create a security barrier by itself.

Example: split 192.168.10.0/24 into four /26 subnets

Use 2 more network bits to obtain 22 = 4 subnets. There are 6 bits left: 64 addresses per block, 62 assignable. The mask is 255.255.255.192 and network addresses increase by 64.

NetworkAssignable hostsBroadcast
192.168.10.0/26.1 – .62.63
192.168.10.64/26.65 – .126.127
192.168.10.128/26.129 – .190.191
192.168.10.192/26.193 – .254.255

All shortened values belong to 192.168.10.x. For 192.168.10.70/26, the network is .64 and broadcast is .127; the first host is not .1.

Activity: calculate before configuring

  1. For 192.168.20.130/26, calculate the mask, network, broadcast, range and capacity.
  2. Split 192.168.30.0/24 into two /25 subnets and suggest a gateway IP for each.
  3. Decide whether 192.168.30.100/25 and 192.168.30.150/25 belong to the same subnet. Justify your answer using the ranges.

Further reading: variable-length subnet masks (VLSM)

VLSM allocates differently sized blocks according to requirements. For 50, 25 and 10 interfaces within 192.168.40.0/24, allocate the largest network first: 192.168.40.0/26, then 192.168.40.64/27 and 192.168.40.96/28. They support 62, 30 and 14 host addresses respectively.

Complete each broadcast address and range, check that the blocks do not overlap, and identify the remaining space. If the device count excludes the router interface, include its address before choosing a prefix.

IP practice 1. Same infrastructure, different subnets

  1. Connect three switches together and attach four PCs, all in the default VLAN. Use Packet Tracer's automatic cable selection.
  2. Under Desktop → IP Configuration, assign 172.30.1.10/24, 172.30.1.11/24, 172.30.2.10/24 and 172.30.2.11/24. Leave gateways blank: there is no router.

IP practice 2. DHCP and Wi-Fi clients

  1. In a new simulation, connect a switch, a Server-PT and two PCs. Give the server 172.30.3.2/24. Do not add a router: leave gateway and DNS blank or use 0.0.0.0 if the interface requires a value.
  2. Under Server → Services → DHCP, enable the service and save a pool starting at 172.30.3.100, with mask 255.255.255.0 and a maximum of 50 users. Remove or adjust any default pool that could provide different settings.
