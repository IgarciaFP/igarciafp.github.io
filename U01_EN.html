Topic 1: Web Interface Planning and Design

1. Introduction

Developing modern digital applications requires designing user interaction long before writing server-side code or database schemas. This topic covers the theoretical, methodological, and visual foundations of user interface (User Interface or UI) planning and user experience (User Experience or UX) engineering.

In today's professional landscape for Senior Technicians in Web Application Development (DAW), developers must do more than write functional code; they must ensure that screens are intuitive, accessible, coherent, and aesthetically balanced. Understanding interaction models, visual perception laws (Gestalt), fundamental UX laws, the Atomic Design methodology, normative WCAG numerical contrast ratios, and adaptive layout structures is essential for creating software products that are efficient and easy to interpret for any user.

Prior knowledge of HTML layout and CSS stylesheets, as well as general Web architecture principles, is recommended for this module. Content is aligned with Learning Outcomes focused on designing, planning, and prototyping high-quality adaptive web interfaces.

By the end of this topic, you will be able to...

  • Differentiate between UI, UX, usability, and accessibility using technical terminology and WCAG contrast ratios (4.5:1 / 3:1).
  • Identify and apply Gestalt perception principles, UX Laws, and UI component interaction states (hover, focus, disabled).
  • Structure design systems based on Atomic Design and Design Tokens using CSS variables.
  • Plan UX research with User Personas, Card Sorting, and Tree Testing prior to building navigation architecture.
  • Decouple visual information architecture from search indexing files (sitemap.xml) and crawler directives (robots.txt).
  • Apply the Mobile-First strategy and touch target size guidelines (Target Size 44x44 px / 48x48 px).
  • Build web interface prototypes (wireframes and mockups) integrating form usability patterns and perceived performance optimization (Core Web Vitals).

2. Content Development

2.1. Fundamentals of User Interface (UI) and Human-Computer Interaction (HCI)

2.1.1. Definition and Scope of UI (Graphical User Interfaces - GUI)

User Interfaces (UI) comprise the hardware and software components acting as the communication boundary between humans and computers. In digital design, interface scope spans screens, windows, menus, controls, iconography, documentation, and online help systems.

Historically, interaction relied on command-line interfaces (CLI, Command Line Interface) structured around an Action-Object pattern, where users specified the command first and the target file or object second. Commercialized by Xerox in 1981 and popularized by Apple, Graphical User Interfaces (GUI) transformed software interaction.

GUIs revolutionized software design by introducing WYSIWYG (What You See Is What You Get) technology and the Object-Action interaction paradigm. Under this model, users select an object on screen first (such as a file or image) and then perform an action upon it (such as delete, move, or edit).

Figure 1.1: Evolution of Graphical User Interfaces (GUI) and the Object-Action interaction paradigm.

2.1.2. Human-Computer Interaction (HCI)

Human-Computer Interaction (HCI) is the multidisciplinary field focused on analyzing how humans interact with computational technologies. Its main goal is making digital systems effective, safe, usable, and intuitive.

Figure 1.2: Multidisciplinary domain of Human-Computer Interaction (HCI).

2.2. User Interface (UI) vs. User Experience (UX), Usability, and Accessibility

2.2.1. Technical Distinctions Between UI and UX

In software development, UI and UX are often confused, despite addressing distinct dimensions of digital design:

  • User Interface (UI): Concentrates on crafting visual and interactive screen elements (buttons, typography, color palettes, HTML/CSS layout).
  • User Experience (UX): Encompasses overall user perception, emotional response, information architecture, and interaction design (IxD) across the entire product lifecycle.
«Something that looks great but is difficult to use is an example of great UI and poor UX. Something very usable that looks terrible is an example of great UX and poor UI» — Helga Moreno.

2.2.2. Usability: Key Attributes and User Profiles

Usability measures how effectively, efficiently, and satisfactorily a target user group can achieve specified goals within a defined context of use.

Usability Attribute Technical Description
Learnability How easily novice users accomplish basic tasks upon encountering the interface for the first time.
Efficiency How quickly experienced users perform tasks once they have learned the system layout.
Error Frequency & Severity How many errors users make, how severe these errors are, and how easily users recover from them.
Memorability How easily returning users re-establish proficiency after a period of non-use.
User Satisfaction The subjective comfort, perceived utility, and acceptability of the system during interaction.

2.2.3. Web Accessibility (WCAG 2.2 / EN 301 549) and Contrast Ratios

While Usability optimizes experiences for specific target profiles, Web Accessibility ensures digital content remains usable by everyone, regardless of physical, sensory, or cognitive impairments, or reliance on assistive technologies (screen readers, adaptive keyboards).

To comply with European legislation (EN 301 549 / Royal Decree 1112/2018 in Spain), web products must satisfy the POUR principles of WCAG 2.2 (Perceivable, Operable, Understandable, Robust) along with mandatory numerical color contrast ratios.

Complete Guide to WCAG Numerical Contrast Ratios

WCAG contrast ratios evaluate the difference in relative luminance between text (or graphic elements) and their background color. The mathematical scale ranges from 1:1 to 21:1:

  • Ratio 1:1 (No contrast): Occurs when foreground and background colors are identical (e.g., white text on a white background), rendering text completely invisible.
  • Ratio 21:1 (Maximum contrast): Represents maximum visual contrast (pure black text #000000 on pure white background #FFFFFF).
Understanding the Numerical Scale

The first number measures relative lightness, while 1 represents background darkness. A ratio of 4.5:1 means the foreground color is 4.5 times lighter (or darker) than its background, ensuring legibility.

Mandatory Minimum Ratios (WCAG Level AA)
Visual Element Type Minimum Ratio Web Application & Implementation Rule
Normal Text (< 18pt / 24px or < 14pt / 19px bold) 4.5:1 Mandatory for body paragraphs, input labels, menu links, and small button text.
Large Text (≥ 18pt / 24px or ≥ 14pt / 19px bold) 3.0:1 Permitted for high-size headings where stroke width compensates for contrast reduction.
UI Components & Graphical Objects 3.0:1 Required for input borders, active icons, and focus rings for keyboard navigation.
WCAG Conformance Levels
  • Level AA (Legal Requirement): Requires a minimum ratio of 4.5:1 for normal text. Mandatory across public administration and corporate web portals.
  • Level AAA (Enhanced Accessibility): Raises mandatory text contrast to 7.0:1 (and 4.5:1 for large text), recommended for healthcare and senior care software.

2.2.4. Jakob Nielsen's 10 Usability Heuristics

Jakob Nielsen formulated ten general principles for user interface design:

  1. Visibility of system status: Keep users informed about what is going on through appropriate feedback within a reasonable time.
  2. Match between system and the real world: Speak the user's language using words, phrases, and concepts familiar to them.
  3. User control and freedom: Provide a clearly marked "emergency exit" to leave unwanted states, supporting undo and redo.
  4. Consistency and standards: Follow platform and industry conventions so users do not have to wonder whether different words or actions mean the same thing.
  5. Error prevention: Prevent problems from occurring in the first place through careful design and confirmation options.
  6. Recognition rather than recall: Minimize memory load by making objects, actions, and options visible.
  7. Flexibility and efficiency of use: Provide accelerators and shortcuts for expert users while supporting novices.
  8. Aesthetic and minimalist design: Omit irrelevant or rarely needed information that competes with vital content.
  9. Help users recognize, diagnose, and recover from errors: Express error messages in plain language with constructive solutions.
  10. Help and documentation: Ensure help documentation is easy to search, task-focused, and concise.

2.3. Psychology of Visual Perception: Gestalt Laws

Visual perception is the process by which the brain organizes and interprets sensory information. The Gestalt school of psychology ("form" or "pattern") identified fundamental principles explaining how human vision groups discrete elements into structured visual wholes.

Figure 1.3: Gestalt laws applied to visual grouping and screen hierarchy.

2.3.1. Primary Gestalt Laws Applied to UI Design

  • Law of Proximity: Visual elements placed near one another are perceived as belonging to the same functional group. UI Application: Placing input field labels directly above their input containers.
  • Law of Similarity: Elements sharing visual attributes (color, shape, size) are perceived as having identical functions. UI Application: Styling primary call-to-action buttons consistently.
  • Law of Closure: Human vision completes incomplete visual shapes. UI Application: Cropping carousel cards at screen edges to indicate scrollable content.
  • Law of Continuity: The eye naturally follows a continuous line or path. UI Application: Aligning form inputs along a single vertical axis.
  • Law of Figure and Ground: The brain separates foreground elements from background space. UI Application: Dimming background content when modal dialogs trigger.
  • Law of Symmetry and Order (Prägnanz): Complex visual structures are interpreted in their simplest form. UI Application: Structuring pages using rigid layout grids.
  • Law of Common Region: Elements enclosed within a shared border are perceived as a distinct group. UI Application: Wrapping related elements inside card components.
  • Law of Common Fate: Elements moving in the same direction at the same velocity are perceived as unified. UI Application: Animating dropdown navigation menus.

2.4. Fundamental Laws of UX (Laws of UX)

Compiled by Jon Yablonski, the Laws of UX summarize psychological principles governing human cognition during interactive software use.

Laws of UX (Interactive Portal) Educational Resource
Explore Jon Yablonski's curated collection of psychological principles for user interface design, featuring visual examples and interactive animations.
Visit Laws of UX
1. Jakob's Law

Users spend most of their time on other websites. This means users prefer your site to work the same way as all the other sites they already know.

2. Fitts's Law

The time to acquire a target is a function of the distance to and size of the target. Primary action buttons (CTA) should be large and placed within easy touch reach.

3. Hick's Law

The time it takes to make a decision increases with the number and complexity of choices. Simplify complex choices by breaking multi-step processes into wizard flows.

4. Miller's Law

The average person can only keep 7 (± 2) items in working memory. Organize content into smaller, logical chunks to aid cognitive processing.

5. Aesthetic-Usability Effect

Users often perceive aesthetically pleasing design as design that’s more usable and tolerant of minor technical glitches.

6. Postel's Law (Robustness Principle)

Be liberal in what you accept, and conservative in what you send. Interfaces should automatically normalize and sanitize imperfect user inputs.

7. Tesler's Law (Law of Conservation of Complexity)

Every system has an inherent amount of complexity that cannot be removed; it must be absorbed by either the system or the developer to simplify end-user tasks.

8. Doherty Threshold

Productivity soars when a computer and its users interact at a pace (< 400ms) that ensures neither has to wait on the other. Use skeleton screens for longer operations.

9. Von Restorff Effect (Isolation Effect)

When multiple similar objects are present, the one that differs from the rest is most likely to be remembered (e.g., highlighting a recommended pricing tier).

10. Peak-End Rule

People judge an experience largely based on how they felt at its peak (most intense point) and at its end, rather than the average of every moment.

11. Zeigarnik Effect

People remember uncompleted or interrupted tasks better than completed tasks. Progress bars motivate users to complete onboarding profiles.

12. Parkinson's Law

Any task will inflate in size until all available time is spent. Setting clear checkout time limits increases conversion rates.

2.5. Graphic Design Elements Applied to the Web

Interface design organizes four hierarchical levels of visual elements:

  • Conceptual Elements: Point, Line, Plane, and Volume (abstract non-physical geometric concepts).
  • Visual Elements: Shape, Size, Color, Texture, and Typography (perceivable screen assets).
  • Relational Elements: Direction, Position, Space, and Visual Weight (governing composition).
  • Practical Elements: Representation, Meaning, and Function (communicative intent).

2.6. Visual Identity, Branding, and Design Systems (Atomic Design)

2.6.1. Categorization of Visual Brand Assets

Web developers must understand corporate branding classifications when translating brand assets to code:

Figure 1.4: Technical taxonomy of visual brand assets for digital interface design.
  • Logotype: Brand identity expressed purely through custom lettering or stylized text (e.g., Google).
  • Isotype: Standalone graphic symbol or emblem functioning without text (e.g., Apple's apple mark).
  • Imagotype: Icon and text combined into a single mark, capable of operating independently.
  • Isologotype: Icon and text permanently integrated into a unified visual graphic.

2.6.2. Iconography and Resolution Independence

Vector graphics (SVG) guarantee resolution independence across mobile screens and 4K displays. Iconography should follow established conventions (magnifying glass for search, shopping cart for checkout) paired with clear text labels for primary actions.

2.6.3. Design Systems and Atomic Design Methodology

Modern frontend development replaces standalone page building with scalable Design Systems based on Brad Frost's Atomic Design methodology. Atomic Design structures UIs into 5 distinct levels:

Figure 1.5: Atomic Design methodology levels (Brad Frost).
  • Atoms: Fundamental, irreducible UI building blocks (buttons, form inputs, labels, icons).
  • Molecules: Groups of atoms bonded together functioning as a simple component (e.g., label + input + button = search form).
  • Organisms: Relatively complex UI components composed of groups of molecules and/or atoms (e.g., website header or product card grid).
  • Templates: Page-level objects that place components into a layout and articulate an application's underlying content structure.
  • Pages: Specific instances of templates filled with real production data.
Design Tokens in CSS

Design Tokens are sub-atomic design decisions stored as named CSS custom properties (e.g., --color-primary: #1e3a8a;, --spacing-md: 16px;), enabling multi-platform design synchronization.

2.7. Color Theory and Visual Composition

2.7.1. RGB Color Model and Hexadecimal Notation

Digital displays generate colors by additively combining Red, Green, and Blue channels represented in hexadecimal (00 to FF / 0 to 255 decimal):

  • Pure Red: #FF0000 | Pure Green: #00FF00 | Pure Blue: #0000FF
  • Darker tones are produced by proportionately reducing channel values (e.g., Dark Red: #CC0000).

Critical Error: Removing Keyboard Focus (`outline: none`)

Removing default browser focus rings using CSS (outline: none) without providing a high-contrast replacement is a severe error. It destroys accessibility for keyboard users navigating via Tab, violating WCAG Criterion 2.4.7 (Focus Visible).

2.8.3. Mobile-First Strategy and Touch Target Size

The Mobile-First approach dictates designing and developing for small touchscreens first—where physical space is constrained—before progressively enhancing layouts for desktop screens.

Figure 1.7: Touch Target Size standards for mobile user interfaces.

2.8.4. Visual Performance Metrics (Core Web Vitals & Layout Shift)

User experience depends heavily on perceived performance. Google and the W3C evaluate user-centric performance using three key metrics (Core Web Vitals):

  • CLS (Cumulative Layout Shift): Measures visual stability. Occurs when page elements shift unexpectedly during image loading due to missing width and height attributes.
  • LCP (Largest Contentful Paint): Render time of the largest main content block (< 2.5 s).
  • INP (Interaction to Next Paint): Measures interface responsiveness following user interaction (< 200 ms).

Web Form Usability Patterns (WCAG 3.3)

Forms represent primary interactive conversion touchpoints. High-usability forms follow three fundamental patterns:

  1. Inline Real-Time Validation: Provide immediate feedback upon input blur (blur event), rather than delaying error reporting until final form submission.
  2. Explicit Labeling (<label>): Always link field labels explicitly using for="id". Never replace label tags with placeholder text, as placeholders disappear during typing, harming accessibility.
  3. Input Formatting Masks: Use guided formatting for complex inputs (IBAN, phone numbers, dates) to reduce user data-entry errors.

2.10. Work Methodology: UX Research, Design Thinking, and Prototyping

Modern web engineering follows the Design Thinking framework across 5 sequential phases: Empathize, Define, Ideate, Prototype, and Test.

2.10.1. UX Research Techniques

During Empathize and Define stages, product teams rely on empirical research tools rather than assumptions:

  • User Personas: Data-informed semi-fictional archetypes representing primary user goals, behavior patterns, and pain points.
  • Card Sorting: Research technique where participants categorize items into logical groups, uncovering their mental models for menu structuring.
  • Tree Testing: Usability technique for validating site navigation hierarchy before visual design begins.

3. Practical Examples

Example 1: Implementing Atomic Design and Design Tokens

Scenario: An enterprise engineering team needs to unify visual branding across 3 independent web applications built by separate frontend teams.

Technical Solution: The team creates a centralized Design Token CSS file defining root custom properties (--color-primary: #1e3a8a, --btn-radius: 6px). Following Atomic Design, buttons are encapsulated as atoms and search forms as reusable molecules.

Outcome: Absolute brand consistency and instant global styling updates by modifying root design token variables.

Example 2: Applying Accessible Focus and Touch Target Sizes

Scenario: An e-commerce mobile site exhibits high cart abandonment rates and fails automated WCAG accessibility audits.

Technical Solution: The team increases button dimensions to 48x48 px (Target Size) and implements a high-contrast focus ring (3:1 contrast ratio) targeting :focus-visible for keyboard users.

Outcome: Eliminates accidental mobile touches and ensures full compliance with WCAG Criterion 2.4.7.

4. Common Pitfalls

Major UI/UX Implementation Mistakes

  • Stripping Keyboard Focus (`outline: none`): Removing visual focus indicators destroys accessibility for keyboard-only users (WCAG 2.4.7).
  • Replacing ` Placeholder text disappears when users type, confusing users and violating accessibility standards.
  • Causing Cumulative Layout Shift (CLS): Loading images or banner ads without defining explicit width and height dimensions causes layout shifts.
  • Confusing Navigation Maps with `robots.txt`: Assuming `robots.txt` builds menus. It only sets crawler access rules.
  • Neglecting Interaction States: Designing UI components exclusively in their idle (*Default*) state while ignoring *Hover*, *Focus*, *Active*, and *Disabled* states.

5. Integrated Case Study: Complete "Migas Amigas" Project

Guided Engineering of the "Migas Amigas" E-Commerce Platform

Professional Context: "Migas Amigas" is an artisanal bakery operating multiple local bakeries. To meet growing online demand for sourdough bread and custom cakes, company management commissions your 2nd Year DAW team to design and prototype an adaptive e-commerce platform spanning 5 functional web pages.

Business Challenge: The previous site was an outdated single-page site with poor mobile conversion, unoptimized images causing high CLS, form fields missing explicit <label> tags, a blurry logo, and broken keyboard navigation due to missing focus indicators.

To deliver an enterprise-grade solution, students must execute all 5 phases of Design Thinking, applying the complete Topic 1 curriculum.

Phase 1: Empathize (User Research & Requirements Gathering)

The project begins with empirical research. Semi-structured interviews are conducted with 3 key stakeholder profiles: the master baker, a regular retail customer, and a B2B restaurant manager.

1. Key Interview Insights
  • Bakery Staff: Requires 24-hour advance ordering notice and clear allergen filtering (gluten, nuts).
  • Retail Customer: Wants real sourdough photos, clear ingredients, and a 3-step mobile checkout.
  • B2B Restaurant Manager: Needs downloadable product PDF spec sheets and recurring wholesale orders.
2. User Persona Profiles
User Persona Demographics / Profile Primary Goals Pain Points with Legacy Site
Carmen (Age 58) Retail customer, orders weekly via tablet/mobile. Pre-ordering specialty spelt bread with clear pickup window selection. Unlabeled icons and buttons too small for reliable thumb tapping.
Marcos (Age 34) Restaurant chef, frequent bulk purchaser. Placing daily burger bun wholesale orders at 07:00 AM. Unvalidated contact form that failed to submit or save input data.

Phase 2: Define (5-Page Information Architecture)

To structure site content, the team runs an Open Card Sorting session with 8 users. Based on card groupings and subsequent Tree Testing, the site navigation map is established for 5 standalone pages:

  1. Page 1: Home / Landing (index.html): Bakery presentation, artisanal value proposition, featured product carousel, central search bar, and primary CTA.
  2. Page 2: Product Catalog (catalogo.html): Interactive grid of breads, pastries, and savory items with allergen and category filter chips.
  3. Page 3: Product Detail Page (producto.html): High-resolution product imagery with explicit dimensions, nutrition facts, weight selector, allergen alerts, and "Add to Order" CTA.
  4. Page 4: About Us / Craftsmanship (nosotros.html): Bakery story, local bakery map, master baker profiles, and quality certifications.
  5. Page 5: Custom Orders & Contact (contacto.html): Order form featuring pickup date pickers, bakery location selection, and interactive map.
Decoupling Server Files

The UX Navigation Map structures the human user interface. Independently, the server generates a sitemap.xml file for Google indexing across these 5 URLs, while robots.txt restricts crawler access to admin routes (Disallow: /admin/).

During this stage, the team crafts the visual identity and design system, enforcing WCAG 2.2 accessibility standards.

4. The 6 Interaction States of the Order Button

Every interactive component is styled across 6 states, ensuring focus indicators are preserved (avoiding outline: none):

  • Default: Brown background #451a03 with white text.
  • Hover: Background darkens to #290e02 on hover.
  • Focus: Outer gold ring #d97706 (3px width) guaranteeing WCAG 2.4.7 focus visibility.
  • Active: Slight scale reduction simulating physical press.
  • Disabled: Muted gray background #cbd5e1 with a not-allowed cursor.
  • Loading: Animated spinner with "Processing order..." helper text.

Phase 4: Prototype (Wireframes, Figma & Atomic Design)

Prototyping evolves through 3 progressive deliverables prior to code implementation:

  1. Low-Fidelity Wireframes: Rapid structural sketching defining header placement, search bar position, 3-column product grids, and footer content.
  2. Figma High-Fidelity UI Kit (Mockup): Component creation in Figma applying Atomic Design:
    • Atoms: Buttons, text inputs, allergen badges.
    • Molecules: Product card component (image + title + price + CTA button).
    • Organisms: Complete website navigation header with responsive mobile drawer menu.
  3. Interactive Functional Prototype: Screen linking in Figma with transition animations simulating complete user checkout flows.

Phase 5: Test & Implement (Functional Code & Auditing)

In the final stage, the engineering team implements all 5 HTML5/CSS3 pages while auditing for usability and performance errors.

1. Preventing Visual Instability (CLS in Core Web Vitals)

To prevent layout jumps while loading product imagery, all <img> tags include explicit dimensions (width="400" height="300") alongside content-visibility: auto CSS rules.

6. Summary

Key Takeaways

  1. UI addresses visual screen assets; UX governs overall user interaction satisfaction.
  2. Graphical User Interfaces (GUI) operate under the Object-Action interaction model.
  3. WCAG accessibility requires strict contrast ratios: 4.5:1 for normal text and 3:1 for large text and UI controls.
  4. Gestalt Principles and Laws of UX dictate human visual perception and cognitive processing.
