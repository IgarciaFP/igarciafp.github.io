Tema 1: Planificación y Diseño de Interfaces Web

1. Introducción

El desarrollo de aplicaciones digitales modernas exige concebir la interacción con las personas antes de escribir cualquier línea de código de servidor o de base de datos. En este tema se estudian los fundamentos teóricos, metodológicos y visuales de la planificación de interfaces de usuario (User Interface o UI) y la experiencia de usuario (User Experience o UX).

En el entorno profesional actual del perfil de Técnico Superior en Desarrollo de Aplicaciones Web (DAW), un desarrollador no solo construye código funcional; debe garantizar que las pantallas sean intuitivas, accesibles, coherentes y estéticamente equilibradas. Comprender los modelos de interacción, las leyes de la percepción visual (Gestalt), las leyes fundamentales de UX, la metodología de Atomic Design, los ratios numéricos normativos de accesibilidad y las estructuras de maquetación adaptativa resulta imprescindible para que un producto digital sea funcional e interpretable por cualquier usuario.

Para abordar este módulo profesional es recomendable contar con conocimientos previos de maquetación HTML y hojas de estilo CSS, así como nociones generales sobre cómo funciona la web. Los contenidos se coordinan con los Resultados de Aprendizaje orientados al diseño, planificación y prototipado de interfaces adaptativas de alta calidad.

Al terminar este tema serás capaz de...

  • Diferenciar los conceptos de UI, UX, usabilidad y accesibilidad aplicando su terminología técnica y los ratios numéricos normativos WCAG (4.5:1 / 3:1).
  • Identificar y aplicar los principios de percepción de la Gestalt, las Leyes de UX y los estados de interacción de componentes UI (hover, focus, disabled).
  • Estructurar sistemas de diseño basados en Atomic Design y Design Tokens mediante variables CSS.
  • Planificar la investigación UX con User Personas, Card Sorting y Tree Testing antes de elaborar la arquitectura de navegación.
  • Desacoplar la arquitectura visual de información frente a los archivos de indexación web (sitemap.xml) y directivas de rastreo (robots.txt).
  • Aplicar la estrategia Mobile-First y las recomendaciones de área táctil mínima (Target Size 44x44 px / 48x48 px).
  • Construir prototipos de interfaz web (wireframes y mockups) integrando patrones de usabilidad en formularios y optimización de rendimiento percibido (Core Web Vitals).

2. Desarrollo de contenidos

2.1. Fundamentos de Interfaz de Usuario (UI) e Interacción Persona-Ordenador (IPO/HCI)

2.1.1. Definición y alcance de la UI (Interfaces Gráficas - GUI)

Las Interfaces de Usuario (User Interfaces o UI) engloban el conjunto de elementos hardware y software que actúan como frontera de comunicación entre el ser humano y las máquinas. En el ecosistema del diseño digital, la interfaz abarca pantallas, ventanas, menús, controles, iconografía, documentación y sistemas de ayuda en línea.

Históricamente, la interacción se basaba en interfaces de línea de comandos (CLI, Command Line Interface) estructuradas bajo un patrón Acción-Objeto, donde la persona primero indicaba el comando y después el archivo u objeto a modificar. Con la primera implantación comercial por parte de Xerox en 1981 y su posterior popularización a través de Apple, surgieron las Interfaces Gráficas de Usuario (GUI, Graphical User Interfaces).

Las GUI revolucionaron el sector introduciendo la tecnología WYSIWYG (What You See Is What You Get, lo que ves es lo que obtienes) y el paradigma de interacción Objeto-Acción. En este modelo, la persona selecciona primero el objeto visual en pantalla (por ejemplo, un archivo o una imagen) y posteriormente ejecuta la acción deseada sobre él (como eliminar, mover o editar).

Figura 1.1: Evolución de las interfaces gráficas (GUI) y el paradigma de interacción visual Objeto-Acción.

2.1.2. Interacción Persona-Ordenador (IPO / HCI)

La Interacción Persona-Ordenador (IPO, o HCI por sus siglas en inglés Human-Computer Interaction) es la disciplina encargada de estudiar cómo los seres humanos interactúan con las tecnologías informáticas. Su objetivo fundamental es lograr que los sistemas sean eficientes, seguros e intuitivos.

2.2. User Interface (UI) vs. User Experience (UX), Usabilidad y Accesibilidad

2.2.1. Diferenciación técnica entre UI y UX

En la industria del software es habitual confundir los conceptos de UI y UX, aunque representan planos complementarios:

  • User Interface (UI): Se enfoca en la creación de los componentes visuales e interactivos de la pantalla (botones, tipografías, colores, maquetación HTML/CSS).
  • User Experience (UX): Hace referencia a la experiencia global y al grado de usabilidad percibido por la persona al interactuar con el sistema digital. Engloba emociones, arquitectura de información y diseño de interacción (IxD).
«Algo que luce genial pero es difícil de usar representa una gran UI con una pobre UX. Mientras que algo muy usable que luce terrible es ejemplo de una gran UX con una pobre UI» — Helga Moreno.

2.2.2. Usabilidad: atributos clave y perfiles de usuario

La usabilidad define la medida en que el diseño de una interfaz toma en consideración la psicología y fisiología humanas para lograr que el uso del sistema resulte efectivo, eficiente y satisfactorio.

Atributo de Usabilidad Descripción Técnica
Curva de aprendizaje Facilidad con la que los usuarios novatos se adaptan al sistema y ejecutan tareas básicas.
Eficiencia de uso Rapidez con la que los usuarios experimentados ejecutan sus objetivos tras dominar la interfaz.
Porcentaje de errores Frecuencia y gravedad de las equivocaciones cometidas; afecta directamente a la frustración.
Facilidad para recordar Capacidad de reutilizar el sistema con éxito tras un período de inactividad sin re-aprenderlo.
Satisfacción del usuario Sensación subjetiva de comodidad, utilidad y agradabilidad tras la interacción.

2.2.3. Accesibilidad Web (WCAG 2.2 / EN 301 549) y Ratios Numéricos de Contraste

La Usabilidad optimiza la experiencia para un perfil de usuario determinado dentro de un contexto de uso. Por su parte, la Accesibilidad Web asegura que los contenidos digitales sean utilizables por todas las personas, independientemente de sus capacidades físicas, sensoriales o cognitivas, o de las tecnologías de asistencia empleadas (lectores de pantalla, teclados adaptados).

Para garantizar la accesibilidad y cumplir con la legislación europea (EN 301 549 / Real Decreto 1112/2018 en España), se aplican los principios POUR de las pautas WCAG 2.2 (Perceptible, Operable, Comprensible, Robusto) junto a sus ratios numéricos mínimos de contraste cromático.

Guía Completa de Ratios Numéricos de Contraste WCAG

Los ratios de contraste de la WCAG miden la diferencia de luminosidad percibida entre el texto (o elemento gráfico) y su fondo. Se calculan en una escala matemática que abarca desde 1:1 hasta 21:1:

  • Ratio 1:1 (Sin contraste): Ocurre cuando el texto y el fondo son exactamente idénticos (ej. texto blanco sobre fondo blanco). El contenido resulta completamente invisible.
  • Ratio 21:1 (Contraste Máximo): Representa el máximo contraste cromático posible en pantallas (texto negro puro #000000 sobre fondo blanco puro #FFFFFF).
¿Cómo se interpreta la cifra matemática?

El primer número indica la luminosidad del color más claro y el número 1 representa la del más oscuro. Por ejemplo, un ratio de 4.5:1 significa que el color del texto resalta o es 4.5 veces más luminoso que el fondo sobre el que se asienta.

Requisitos mínimos obligatorios por elemento (WCAG Nivel AA)
Tipo de Elemento Visual Ratio Mínimo Explicación y Aplicación en Interfaces Web
Texto Normal (< 18pt / 24px o < 14pt / 19px negrita) 4.5:1 Obligatorio para párrafos, etiquetas, elementos de menú y botones de texto pequeño.
Texto Grande (≥ 18pt / 24px o ≥ 14pt / 19px negrita) 3.0:1 Se permite menor ratio en títulos y encabezados de gran tamaño porque su grosor compensa la lectura.
Componentes de UI e Iconografía 3.0:1 Requerido para bordes de cajas de texto, iconos interactivos activos y anillos de foco por teclado.
Niveles de Conformidad WCAG
  • Nivel AA (Estándar Legal Obligatorio): Exige un ratio mínimo de 4.5:1 para texto normal. Es la exigencia normativa en la UE y en sitios corporativos o públicos.
  • Nivel AAA (Máxima Accesibilidad): Eleva la exigencia a un ratio de 7.0:1 para texto normal (y 4.5:1 para texto grande), recomendado en portales de salud o atención a la tercera edad.

2.2.4. Las 10 Heurísticas de Jakob Nielsen

Jakob Nielsen established diez principios para evaluar heurísticamente la usabilidad de las interfaces:

  1. Visibilidad del estado del sistema: Informar de lo que ocurre mediante retroalimentación en un tiempo razonable.
  2. Coincidencia entre el sistema y el mundo real: Utilizar el lenguaje habitual del usuario con conceptos familiares.
  3. Control y libertad del usuario: Proporcionar salidas claras, deshacer y rehacer acciones.
  4. Consistencia y estándares: Seguir las convenciones de la plataforma para no generar incertidumbre.
  5. Prevención de errores: Diseñar mecanismos que eviten los fallos antes de que se produzcan.
  6. Reconocimiento antes que recuerdo: Minimizar la carga cognitiva haciendo visibles objetos, acciones y opciones.
  7. Flexibilidad y eficiencia de uso: Ofrecer atajos y aceleradores para usuarios avanzados.
  8. Diseño estético y minimalista: Eliminar la información irrelevante o redundante.
  9. Ayuda a reconocer, diagnosticar y solucionar errores: Mensajes claros con soluciones.
  10. Ayuda y documentación: Disponer de guías sencillas enfocadas en las tareas del usuario.

2.3. Psicología de la Percepción Visual: Leyes de la Gestalt

La percepción visual es la interpretación activa que realiza el cerebro de los estímulos lumínicos. La escuela alemana de la Gestalt ("forma" o "configuración") formuló leyes psicológicas que explican cómo la mente agrupa visualmente elementos individuales para percibir un "todo" estructurado.

Figura 1.3: Leyes de la Gestalt aplicadas al agrupamiento y percepción visual en pantallas.

2.3.1. Principales Leyes de la Gestalt aplicadas a UI

  • Ley de Proximidad: Los objetos colocados cerca unos de otros se perciben como un grupo unificado. UI: Las etiquetas de entrada de formularios se colocan pegadas a sus campos correspondientes.
  • Ley de Semejanza (Similitud): Elementos con forma o color igual se perciben como pertenecientes a la misma categoría. UI: Botones primarios del mismo color.
  • Ley de Cierre (Clausura): La mente tiende a completar figuras incompletas. UI: Tarjetas de carrusel recortadas en el borde para sugerir desplazamiento.
  • Ley de Continuidad: El ojo sigue una trayectoria fluida. UI: Listas de elementos alineadas verticalmente.
  • Ley de Figura y Fondo: Separamos el objeto destacado del espacio circundante. UI: Modales con fondo oscurecido (overlay).
  • Ley de Simetría y Orden (Prägnanz): El cerebro simplifica formas complejas. UI: Maquetación en cuadrículas o retículas.
  • Ley de Región Común: Elementos delimitados por un borde cerrado se perciben como un conjunto. UI: Tarjetas (cards).
  • Ley de Destino Común: Elementos que se desplazan juntos se perciben unificados. UI: Menús desplegables animados.

2.4. Leyes Fundamentales de UX (Laws of UX)

Las Leyes de UX (compiladas por Jon Yablonski) integran principios psicológicos que gobiernan la conducta cognitiva interactiva.

Laws of UX (Portal interactivo) Recurso Didáctico
Explora el compendio de principios psicológicos aplicados al diseño de interfaz recopilados por Jon Yablonski, con ejemplos visuales y animaciones.
Visitar Laws of UX (Español)
1. Ley de Jakob (Jakob's Law)

Los usuarios prefieren que tu sitio funcione igual que los demás sitios que ya conocen. Reducir patrones novedosos evita sobrecarga mental.

2. Ley de Fitts (Fitts's Law)

El tiempo para alcanzar un objetivo depende de la distancia y su tamaño. Los botones principales (CTA) deben ser grandes y estar al alcance táctil.

3. Ley de Hick (Hick's Law)

El tiempo de decisión aumenta con el número de opciones. Se debe simplificar dividiendo procesos complejos en pasos (wizards).

4. Ley de Miller (Miller's Law)

La memoria de trabajo mantiene activa una media de 7 (± 2) elementos. Agrupar en bloques (chunking) facilita el procesamiento.

5. Efecto de Estética-Usabilidad

Los diseños atractivos se perciben intuitivamente como más usables y tolerantes a pequeños fallos técnicos.

6. Ley de Postel (Principio de Robustez)

Sé liberal en lo que aceptas y conservador en lo que envías. La interfaz debe formatear automáticamente entradas de datos imperfectas.

7. Ley de Tesler (Conservación de la Complejidad)

Todo sistema tiene complejidad inherente que debe asumir el desarrollador internamente para simplificar el uso final.

8. Umbral de Doherty (Doherty Threshold)

La productividad se maximiza cuando el sistema responde en menos de 400 ms. Respuestas superiores exigen pantallas de carga (skeleton screens).

9. Efecto Von Restorff (Aislamiento)

Entre elementos similares, aquel que difiere visualmente es el más recordado (p. ej., destacar el plan de suscripción recomendado).

10. Regla del Pico-Final (Peak-End Rule)

Las experiencias se juzgan por lo sentido en el punto culminante (pico) y en el desenlace final.

11. Efecto Zeigarnik

Las tareas incompletas se recuerdan más. Las barras de progreso motivan a finalizar perfiles de usuario.

12. Ley de Parkinson

Una tarea consumirá todo el tiempo disponible. Fijar límites temporales en compras aumenta la tasa de conversión.

2.5. Elementos del Diseño Gráfico Aplicados a la Web

El diseño de interfaces articula cuatro niveles jerárquicos de elementos:

  • Elementos conceptuales: Punto, Línea, Plano y Volumen (formas abstractas no físicas).
  • Elementos visuales: Forma, Medida, Color, Textura y Tipografía (lo que se percibe en pantalla).
  • Elementos de relación: Dirección, Posición, Espacio y Gravedad visual (gobiernan la distribución).
  • Elementos prácticos: Representación, Significado y Función (propósito de comunicación).

2.6. Identidad Visual, Marcas y Sistemas de Diseño (Atomic Design)

2.6.1. Categorización de marcas visuales

En el desarrollo de interfaces web es fundamental clasificar técnicamente la marca corporativa:

Figura 1.4: Clasificación técnica de marcas visuales para diseño de identidades digitales.
  • Logotipo: Representación basada únicamente en texto/tipografía (ej. Google).
  • Isotipo: Símbolo gráfico independiente sin texto (ej. la manzana de Apple).
  • Imagotipo: Unión de icono y texto que pueden funcionar de forma independiente.
  • Isologotipo: Integración indivisible de texto y símbolo gráfico dentro de una figura unificada.

2.6.2. Iconografía e independencia de resolución

Los gráficos vectoriales (SVG) garantizan escalabilidad infinita en pantallas móviles y monitores 4K. La iconografía debe inclinarse por convenciones conocidas (lupa para buscar, carrito para compra) combinada con etiquetas de texto en operaciones clave.

2.6.3. Sistemas de Diseño y Metodología Atomic Design

En el desarrollo frontend moderno no se construyen páginas aisladas, sino Sistemas de Diseño (Design Systems) escalables basados en la metodología Atomic Design (Brad Frost). Esta metodología divide la UI en 5 niveles jerárquicos:

Figura 1.5: Niveles metodológicos de Atomic Design (Brad Frost).
  • Átomos: Elementos UI indivisibles (botones, inputs, etiquetas, iconos).
  • Moléculas: Grupos de átomos unidos que ejecutan una función básica (ej. un input + un botón = formulario de búsqueda).
  • Organismos: Conjuntos de moléculas que forman una sección completa (ej. la cabecera completa o una tarjeta de producto).
  • Plantillas (Templates): Maquetación estructural (layout) sin datos reales.
  • Páginas: Instancia final del sistema rellena con contenido real para producción.
Design Tokens en CSS

El núcleo de un sistema de diseño son los Design Tokens: variables que almacenan valores visuales fundamentales (colores, fuentes, espaciados) reutilizables en CSS/Sass (ej. --color-primary: #1e3a8a;, --spacing-md: 16px;).

2.7. Teoría del Color y Composición Visual

2.7.1. Modelo RGB y Hexadecimal

Los colores digitales se sintetizan sumando Rojo (Red), Verde (Green) y Azul (Blue), con valores hexadecimales entre 00 y FF (0 a 255 decimal):

  • Rojo puro: #FF0000 | Verde puro: #00FF00 | Azul puro: #0000FF
  • Para oscurecer un tono, se reduce proporcionalmente el canal (ej. Rojo oscuro: #CC0000).

2.8. Composición, Estados UI, Mobile-First y Rendimiento

2.8.1. Equilibrio, simetría y tensión compositiva

El equilibrio formal utiliza simetría (horizontal, vertical, radial), mientras que el equilibrio informal (asimétrico) compensa el peso visual mediante variaciones de tamaño, color o posición. La tensión compositiva busca dirigir intencionadamente la mirada con técnicas sugestivas o rítmicas.

Error Crítico: Eliminación del Foco (`outline: none`)

Es un error habitual en maquetación eliminar el indicador visual de foco por teclado mediante CSS (outline: none). Esto destruye la accesibilidad para usuarios que navegan con la tecla Tab, violando directamente el Criterio WCAG 2.4.7 (Focus Visible).

2.8.3. Estrategia Mobile-First y Área Táctil Mínima (Target Size)

La estrategia Mobile-First establece que se debe diseñar e implementar primero la versión para pantallas pequeñas (con restricciones extremas de espacio) priorizando los contenidos esenciales, para posteriormente expandir la interfaz hacia pantallas de escritorio mediante Progressive Enhancement.

2.8.4. Métricas de Rendimiento Visual (Core Web Vitals & Layout Shift)

La experiencia de usuario no depende únicamente del aspecto gráfico, sino del rendimiento percibido. Google y la W3C estandarizan tres métricas clave (Core Web Vitals):

  • CLS (Cumulative Layout Shift): Mide la inestabilidad visual. Ocurre cuando elementos saltan inesperadamente al cargar imágenes sin atributos de dimensión (width y height), provocando clics accidentales.
  • LCP (Largest Contentful Paint): Tiempo de renderizado del elemento visual principal (debe ser < 2.5 s).
  • INP (Interaction to Next Paint): Mide la velocidad de respuesta de la UI tras una pulsación del usuario (< 200 ms).

Patrones de Usabilidad en Formularios Web (WCAG 3.3)

Los formularios son el punto neurálgico de interacción en aplicaciones web. Para maximizar la usabilidad deben seguir tres patrones clave:

  1. Validación Inline en Tiempo Real: Informar de errores o aciertos inmediatamente al perder el foco del campo (evento blur), sin esperar al envío global del formulario.
  2. Etiquetado Explícito (<label>): Vincular siempre las etiquetas a sus entradas mediante for="id". Nunca sustituir la etiqueta por un placeholder, ya que este desaparece al escribir y destruye la accesibilidad.
  3. Máscaras y Formato Automático: Aplicar formato guiado para datos complejos (IBAN, teléfonos, fechas) aligerando la carga del usuario.

2.10. Metodología de Trabajo: Investigación UX, Design Thinking y Prototipado

El proceso de creación web se fundamenta en la metodología Design Thinking dividida en 5 etapas secuenciales: Empatizar, Definir, Idear, Prototipar y Testar.

2.10.1. Técnicas de Investigación de Usuarios (UX Research)

En las fases iniciales de Empatizar y Definir no se debe presuponer el comportamiento del usuario. Se aplican tres herramientas empíricas fundamentales:

  • User Personas: Arquetipos de usuarios representativos basados en datos reales que resumen metas, patrones de uso y frustraciones.
  • Card Sorting (Clasificación de Tarjetas): Técnica donde los usuarios agrupan temas o categorías en tarjetas físicas o digitales. Permite descubrir su modelo mental para organizar los menús.
  • Tree Testing: Prueba para validar la jerarquía visual de un árbol de navegación antes de maquetar ninguna pantalla.

  • Sitemap XML (sitemap.xml): Lista de URLs del servidor para indexación en buscadores.

3. Ejemplos prácticos

Ejemplo 1: Aplicación de Atomic Design y Design Tokens

Situación: Una empresa requiere unificar los estilos de 3 aplicaciones web distintas construidas por equipos independientes.

Desarrollo razonado: Se crea un sistema de Design Tokens centralizado en un archivo CSS con variables (--color-primary: #1e3a8a, --btn-radius: 6px). Siguiendo Atomic Design, se empaquetan los botones como átomos y las barras de búsqueda como moléculas reutilizables.

Resultado: Coherencia estética absoluta y actualización instantánea de la marca modificando únicamente las variables de los tokens.

Ejemplo 2: Aplicación del Foco Accesible y Target Size

Situación: Alta tasa de error en compras móviles y rechazo en auditorías de accesibilidad.

Desarrollo razonado: Se amplia el área táctil del botón de compra a 48x48 px recomendados (Target Size) y se añade un borde destacado de alto contraste (3:1) en el estado :focus-visible para usuarios de teclado.

Resultado: Eliminación de clics erróneos en dispositivos móviles y cumplimiento estricto del criterio WCAG 2.4.7.

4. Errores frecuentes

Principales fallos en diseño UI/UX

  • Eliminar el borde de foco (`outline: none`): Ocultar el estado de foco destruye la accesibilidad por teclado (WCAG 2.4.7).
  • Sustituir la etiqueta ` El placeholder desaparece al escribir, confundiendo al usuario y violando la accesibilidad en formularios.
  • Provocar inestabilidad visual (Layout Shift - CLS): Cargar imágenes o banners sin definir `width` y `height`, provocando que el texto dé saltos al cargar la web.
  • Confundir mapa de navegación con `robots.txt`: Pensar que `robots.txt` crea menús. Solo da directivas de acceso a spiders.
  • Prescindir de los estados UI: Diseñar componentes únicamente en estado de reposo (*Default*) ignorando los estados *Hover*, *Focus*, *Active* y *Disabled*.

5. Caso práctico integrado: Proyecto Completo "Migas Amigas"

Desarrollo Guiado e Integral de la Plataforma Web "Migas Amigas"

Contexto Profesional: "Migas Amigas" es una panadería y repostería artesanal tradicional con varios obradores locales. Ante la alta demanda de encargo de pan de masa madre y tartas personalizadas, la dirección encarga a tu equipo de desarrollo web en 2º DAW el diseño y prototipado completo de su nuevo sitio e-commerce adaptativo de 5 páginas funcionales.

El Reto de la Empresa: Su web anterior consistía en una sola página estática desactualizada con baja tasa de conversión móvil, imágenes pesadas que provocaban saltos de pantalla (CLS alto), un formulario donde faltaba el etiquetado explícito <label> y un logotipo PNG borroso. Además, los usuarios de teclados o lectores de pantalla no podían navegar por falta de estados de foco claros.

Para resolver este proyecto con éxito profesional, el alumnado debe ejecutar en su totalidad las 5 fases del proceso de Design Thinking, integrando todos los contenidos y normativas estudiados en el Tema 1.

Fase 1: Empatizar (Investigación de Usuarios y Requerimientos)

El proyecto arranca con una toma de requisitos empírica. Se efectúa un guion de entrevista semiestructurada a 3 perfiles clave: el dueño del obrador, un cliente particular habitual y un gestor de hostelería que realiza pedidos al por mayor.

1. Hallazgos clave de las entrevistas
  • El Obrador: Necesita recibir encargos con al menos 24 horas de antelación y especificar intolerancias alérgenas (gluten, frutos secos).
  • Cliente Particular: Quiere ver fotos reales del pan recién horneado, conocer los ingredientes y pedir tartas desde el móvil en menos de 3 pasos.
  • Hostelería: Requiere descargar la ficha técnica de producto en PDF y disponer de una opción de encargo recurrente.

Desacoplamiento de Archivos de Servidor

En esta etapa se construye la identidad corporativa y el sistema de diseño garantizando la accesibilidad normada por la WCAG 2.2.

4. Los 6 Estados de Interacción del Botón de Encargo

Todo componente interactivo debe maquetarse en sus 6 estados, garantizando que el foco por teclado nunca sea eliminado (evitando outline: none):

  • Default: Botón marrón #451a03 con texto blanco.
  • Hover: Fondo oscurecido a #290e02 al pasar el cursor.
  • Focus: Anillo exterior dorado #d97706 de 3px con alto contraste (WCAG 2.4.7).
  • Active: Ligera contracción visual (compresión táctil).
  • Disabled: Fondo gris claro #cbd5e1 con cursor not-allowed.
  • Loading: Icono de spinner giratorio con el texto "Procesando encargo...".

Fase 4: Prototipar (Wireframe.cc, Figma y Atomic Design)

El prototipado evoluciona en 3 entregables progresivos antes del código final:

  1. Boceto inicial (Wireframing con wireframe.cc): Trazado rápido en baja fidelidad sin colores ni tipografías decorativas. Permite acordar con la panadería la ubicación del logo, el buscador, la parrilla de productos de 3 columnas y el pie de página.
  2. Diseño de componentes con Figma (Mockup): Creación del kit UI en Figma aplicando Atomic Design:
    • Átomos: Botones, inputs de texto, insignias de alérgenos.
    • Moléculas: Tarjeta de producto individual (imagen + título + precio + botón).
    • Organismos: Cabecera completa con menú móvil desplegable e imagotipo.
  3. Prototipo Funcional Interactivo: Enlazado de pantallas en Figma con animaciones de transición para simular el flujo completo desde la portada hasta la confirmación del encargo.

Fase 5: Testar e Implementar (Desarrollo Funcional e Inspección)

En la fase final, el equipo implementa las 5 páginas HTML5/CSS3 asegurando la ausencia de errores comunes de usabilidad y rendimiento.

1. Prevención de Inestabilidad Visual (CLS en Core Web Vitals)

Para evitar que el texto dé saltos cuando cargan las imágenes de los panes, todas las etiquetas <img> incluyen explícitamente sus atributos de anchura y altura (width="400" height="300") y la regla CSS content-visibility: auto.

Sometida la web a un test con 5 usuarios reales, se alcanza una satisfacción del 94%, verificando que la visibilidad del estado del sistema (Heurística 1) y el reconocimiento antes que el recuerdo (Heurística 6) reducen a cero los pedidos incompletos.

6. Resumen

Ideas clave

  1. La UI aborda elementos visuales; la UX la experiencia global de usabilidad.
  2. Las GUI operan bajo el paradigma Objeto-Acción.
  3. La accesibilidad WCAG exige ratios de contraste numérico: 4.5:1 (texto normal) y 3:1 (texto grande y componentes UI).
  4. Las Leyes de la Gestalt y las Leyes de UX rigen la organización perceptiva e interactiva.
  5. Las marcas se clasifican en Logotipo, Isotipo, Imagotipo e Isologotipo.
  6. Atomic Design organiza la UI en Átomos, Moléculas, Organismos, Plantillas y Páginas mediante Design Tokens.
  7. Todo componente UI interactivo debe definir sus 6 estados (Default, Hover, Focus, Active, Disabled, Loading) respetando el foco por teclado (WCAG 2.4.7).
  8. La estrategia Mobile-First requiere áreas táctiles mínimas (Target Size de 24px WCAG / 44-48px recomendado).
  9. El rendimiento visual se evalúa con Core Web Vitals, previniendo saltos de pantalla (CLS).
  10. Los formularios exigen validación inline y etiquetado explícito (<label>) sin depender de placeholder.
  11. La arquitectura se investiga con User Personas, Card Sorting y Tree Testing.
  12. El mapa de navegación de UX es independiente de sitemap.xml y robots.txt.
  13. El prototipado evoluciona: Wireframe → Mockup → Prototipo Funcional.
